# WarPC 掉落物品概率分析

基于 `TKS.exe` 反编译代码对 WarPC 三个掉落槽位的真实概率分析。

> **编辑器标签已于 2026-07-01 修正**：旧标签"必掉落/高概率/低概率"已改为"常规掉落(80%)/普通掉落(15%)/稀有掉落(5%)"。本文档全程使用新术语。

---

## 1. 数据结构

WarPC 每条记录 1054 字节，共 527 个 int16 字段。三个掉落槽位位于：

| 字段名 | 字段索引 | 字节偏移 | 编辑器标签 | 存储内容 |
|---|---|---|---|---|
| `drop_item0` | 270 | 540 | 常规掉落(80%) | 物品 ID（0=无） |
| `drop_item1` | 271 | 542 | 普通掉落(15%) | 物品 ID（0=无） |
| `drop_item2` | 272 | 544 | 稀有掉落(5%) | 物品 ID（0=无） |

这三个字段存储的是**物品 ID**（int16），不是概率值。概率逻辑完全硬编码在游戏引擎中。

对应的游戏内存数组（每个怪物独立）：

| 槽位 | 内存地址 | 填充优先级 |
|---|---|---|
| 常规槽（第1槽） | `word_9D7296[527 * monsterId]` | 最先填充 |
| 普通槽（第2槽） | `word_9D7298[527 * monsterId]` | 第二填充 |
| 稀有槽（第3槽） | `word_9D729A[527 * monsterId]` | 最后填充 |

## 2. 槽位分配逻辑

来源：`decompile/434510.c`（`sub_434510`，第 57-72 行）

```c
if ( word_9D7296[527 * word_9D6F58] )          // 常规槽（第1槽）已占用？
{
    if ( word_9D7298[527 * word_9D6F58] )       // 普通槽（第2槽）已占用？
    {
        if ( !word_9D729A[527 * word_9D6F58] )  // 稀有槽（第3槽）空？
            word_9D729A[527 * word_9D6F58] = itemId;  // → 稀有掉落(5%)
    }
    else
    {
        word_9D7298[527 * word_9D6F58] = itemId;       // → 普通掉落(15%)
    }
}
else
{
    word_9D7296[527 * word_9D6F58] = itemId;           // → 常规掉落(80%)
}
```

**分配规则**：按优先级从高到低依次填充（常规槽 → 普通槽 → 稀有槽）。怪物定义多个掉落物品时：

- 第 1 个物品 → 常规槽（第1槽）
- 第 2 个物品 → 普通槽（第2槽）
- 第 3 个物品 → 稀有槽（第3槽）

## 3. 掉落概率判定（核心）

来源：`decompile/4458B0.c`（`sub_4458B0`，第 502-531 行）

### 3.1 随机数生成

```c
v7 = sub_452AC0(1000);  // 生成均匀随机数，范围 0~999
```

`sub_452AC0`（`decompile/452AC0.c`）封装了自定义 PRNG `sub_452968`（`decompile/452968.c`），使用 249 字节状态表产生 16 位随机数，再取模映射到 `[0, 999]`。

### 3.2 级联判定逻辑

判定顺序：先检查稀有槽 → 再检查普通槽 → 最后检查常规槽。优先级与填充顺序相反——越稀有的槽位判定优先级越高。

```c
v7 = sub_452AC0(1000);

// 第一级：检查稀有槽（第3槽）—— 判定优先级最高
if ( word_9D729A[527 * v19] <= 0 || v7 >= 50 )
{
    // 第二级：检查普通槽（第2槽）
    if ( word_9D7298[527 * v19] <= 0 || v7 >= 200 )
    {
        // 第三级：检查常规槽（第1槽）—— 判定优先级最低
        if ( word_9D7296[527 * v19] > 0 && word_9D6F12 < 64 )
        {
            // 掉落常规物品(80%)
            word_9D6E12[2 * word_9D6F12] = word_9D7296[527 * v19];
            word_9D6E14[2 * word_9D6F12++] = 1;
            word_9D7296[527 * v19] = 0;  // 清空已掉落
        }
    }
    else if ( word_9D6F12 < 64 )
    {
        // 掉落普通物品(15%)
        word_9D6E12[2 * word_9D6F12] = word_9D7298[527 * v19];
        word_9D6E14[2 * word_9D6F12++] = 1;
        word_9D7298[527 * v19] = 0;
    }
}
else if ( word_9D6F12 < 64 )
{
    // 掉落稀有物品(5%)
    word_9D6E12[2 * word_9D6F12] = word_9D729A[527 * v19];
    word_9D6E14[2 * word_9D6F12++] = 1;
    word_9D729A[527 * v19] = 0;
}
```

### 3.3 概率换算

判定使用**级联优先制**（互斥），不是独立概率判定。每次战斗只掉落一件物品。

| 槽位 | 触发条件 | 范围 | 概率 | 填充优先级 | 判定优先级 |
|---|---|---|---|---|---|
| 稀有掉落(5%) | `v7 < 50` | 0 ~ 49 | **50/1000 = 5%** | 最低 | **最高**（最先判定） |
| 普通掉落(15%) | `50 ≤ v7 < 200` | 50 ~ 199 | **150/1000 = 15%** | 中 | 中 |
| 常规掉落(80%) | `v7 ≥ 200` | 200 ~ 999 | **800/1000 = 80%** | 最高 | **最低**（最后判定） |

> **注意**：填充优先级和判定优先级是相反的。稀有槽填充最晚（怪物物品多时才轮到它），但判定时最先检查；常规槽填充最早（怪物第一个物品必定进这里），但判定时最后检查。

### 3.4 空槽回退机制

关键是 `||` 短路求值。当判定优先级更高的槽位为空（值 ≤ 0）时，条件直接为真，自动回退到下一级。

| 场景 | 效果 |
|---|---|
| 三个槽都有物品 | 稀有 5% → 普通 15% → 常规 80%，完整分布 |
| 仅常规槽有物品 | 稀有→空跳过，普通→空跳过 → **常规 100%** |
| 常规+普通有物品 | 稀有→空跳过 → 普通 15% / **常规 85%** |
| 常规+稀有有物品 | 稀有 5% / **常规 95%** |
| 仅普通+稀有有物品 | 稀有 5% → 不中则普通 15% → 不中则常规（空）→ **无掉落** |

实际游戏中绝大多数怪物只在常规槽配置 1 个物品，普通槽和稀有槽均为空，因此常规槽**实际表现为 100% 掉落**。这也是旧标签"必掉落"的由来——在典型配置下它确实必定掉落。

## 4. 编辑器标签修正

旧标签的问题：

| 旧标签 | 问题 |
|---|---|
| 必掉落物品 | 暗示 100%，三槽全满时实际只有 80%，名不副实 |
| 高概率掉落 | 15% 算"高"勉强成立，但与 80% 档放在一起时"高""低"语义重叠 |
| 低概率掉落 | 5% 确实算低，但三个标签缺乏统一尺度 |

新标签的设计意图：

| 新标签 | 理由 |
|---|---|
| 常规掉落(80%) | "常规"描述掉落频率的常态，80% 量化概率，括号数字直接可读 |
| 普通掉落(15%) | "普通"与"稀有"形成清晰对比，15% 介于常规与稀有之间 |
| 稀有掉落(5%) | "稀有"名副其实，5% 是典型的稀有掉落阈值 |

新标签统一采用「频率形容词 + 百分比」的格式，编辑者无需查阅文档即可理解三个槽位的概率关系。

## 7. 掉落数量随机化

来源：`decompile/434510.c` 第 36-37 行

```c
if ( word_953932[2 * v6] < word_953934[2 * v6] )
    word_953932[2 * v6] += sub_452AC0(word_953934[2 * v6] - word_953932[2 * v6] + 1);
```

物品掉落数量在 `[word_953932, word_953934]` 范围内随机，这两个数组定义了每种物品的最小/最大掉落数量。

## 8. 总结

1. **级联互斥判定**：不是三个独立概率判定，而是一次随机数 `[0, 999]` 决定从哪个槽位掉落，每次战斗只掉一件。
2. **真实概率**：稀有 5%、普通 15%、常规 80%（仅当该槽有物品时）。
3. **空槽回退**：判定优先级高的槽位为空时，自动回退到下一个有物品的槽位。因此仅常规槽有物品时实际 100% 掉落。
4. **填充与判定优先级相反**：常规槽最先填充、最后判定；稀有槽最后填充、最先判定。
5. **编辑器只管理物品 ID**：概率在引擎中硬编码，编辑器无需也无法修改概率值。新标签已标注真实百分比。
