# WarPC 掉落物品概率分析

基于 `TKS.exe` 反编译代码对 WarPC 三个掉落槽位的真实概率分析。

---

## 1. 数据结构

WarPC 每条记录 1054 字节，共 527 个 int16 字段。三个掉落槽位位于：

| 字段名 | 字段索引 | 字节偏移 | 编辑器标签 | 存储内容 |
|---|---|---|---|---|
| `drop_item0` | 270 | 540 | 必掉落物品 | 物品 ID（0=无） |
| `drop_item1` | 271 | 542 | 高概率掉落 | 物品 ID（0=无） |
| `drop_item2` | 272 | 544 | 低概率掉落 | 物品 ID（0=无） |

这三个字段存储的是**物品 ID**（int16），不是概率值。概率逻辑完全硬编码在游戏引擎中。

对应的游戏内存数组（每个怪物独立）：

| 槽位 | 内存地址 | 语义 |
|---|---|---|
| 必掉落 | `word_9D7296[527 * monsterId]` | 优先填充的第一个槽 |
| 高概率 | `word_9D7298[527 * monsterId]` | 优先填充的第二个槽 |
| 低概率 | `word_9D729A[527 * monsterId]` | 优先填充的第三个槽 |

---

## 2. 槽位分配逻辑

来源：`decompile/434510.c`（`sub_434510`，第 57-72 行）

```c
if ( word_9D7296[527 * word_9D6F58] )          // 必掉落槽已占用？
{
    if ( word_9D7298[527 * word_9D6F58] )       // 高概率槽已占用？
    {
        if ( !word_9D729A[527 * word_9D6F58] )  // 低概率槽空？
            word_9D729A[527 * word_9D6F58] = itemId;  // → 低概率掉落
    }
    else
    {
        word_9D7298[527 * word_9D6F58] = itemId;       // → 高概率掉落
    }
}
else
{
    word_9D7296[527 * word_9D6F58] = itemId;           // → 必掉落
}
```

**分配规则**：按优先级从高到低依次填充。怪物定义多个掉落物品时：
- 第 1 个物品 → 必掉落槽
- 第 2 个物品 → 高概率槽
- 第 3 个物品 → 低概率槽

## 3. 掉落概率判定（核心）

来源：`decompile/4458B0.c`（`sub_4458B0`，第 502-531 行）

### 3.1 随机数生成

```c
v7 = sub_452AC0(1000);  // 生成均匀随机数，范围 0~999
```

`sub_452AC0`（`decompile/452AC0.c`）封装了自定义 PRNG `sub_452968`（`decompile/452968.c`），使用 249 字节状态表产生 16 位随机数，再取模映射到 `[0, 999]`。

### 3.2 级联判定逻辑

```c
v7 = sub_452AC0(1000);

// 第一级：检查低概率槽
if ( word_9D729A[527 * v19] <= 0 || v7 >= 50 )
{
    // 第二级：检查高概率槽
    if ( word_9D7298[527 * v19] <= 0 || v7 >= 200 )
    {
        // 第三级：检查必掉落槽
        if ( word_9D7296[527 * v19] > 0 && word_9D6F12 < 64 )
        {
            // 掉落必掉落物品
            word_9D6E12[2 * word_9D6F12] = word_9D7296[527 * v19];
            word_9D6E14[2 * word_9D6F12++] = 1;
            word_9D7296[527 * v19] = 0;  // 清空已掉落
        }
    }
    else if ( word_9D6F12 < 64 )
    {
        // 掉落高概率物品
        word_9D6E12[2 * word_9D6F12] = word_9D7298[527 * v19];
        word_9D6E14[2 * word_9D6F12++] = 1;
        word_9D7298[527 * v19] = 0;
    }
}
else if ( word_9D6F12 < 64 )
{
    // 掉落低概率物品
    word_9D6E12[2 * word_9D6F12] = word_9D729A[527 * v19];
    word_9D6E14[2 * word_9D6F12++] = 1;
    word_9D729A[527 * v19] = 0;
}
```

### 3.3 概率换算

判定使用**级联优先制**（互斥），不是独立概率判定。每次战斗只掉落一件物品。

| 槽位 | 触发条件 | 范围 | 概率 | 优先级 |
|---|---|---|---|---|
| 低概率掉落 | `v7 < 50` | 0 ~ 49 | **50/1000 = 5%** | 最高 |
| 高概率掉落 | `50 ≤ v7 < 200` | 50 ~ 199 | **150/1000 = 15%** | 中 |
| 必掉落 | `v7 ≥ 200` | 200 ~ 999 | **800/1000 = 80%** | 最低 |

### 3.4 空槽回退机制

关键是 `||` 短路求值。当高优先级槽位为空（值 ≤ 0）时，条件直接为真，自动回退到下一级。

| 场景 | 效果 |
|---|---|
| 三个槽都有物品 | 5% / 15% / 80% 完整分布 |
| 仅必掉落槽有物品 | 低概率→空跳过，高概率→空跳过 → **必掉落 100%** |
| 仅必掉落+高概率有物品 | 低概率→空跳过 → 15% / **85%**（必掉落覆盖剩余） |
| 仅必掉落+低概率有物品 | 5% / **95%** |
| 仅高概率+低概率有物品 | 低概率 5% → 若未中则高概率 15% → 若未中则必掉落（空）→**无掉落** |

|---|---|---|
| 必掉落物品 | ⚠️ 部分准确 | 三槽全满时仅 80% 概率；但仅此槽有物品时确实 100% 掉落 |

## 7. 掉落数量随机化

来源：`decompile/434510.c` 第 36-37 行

```c
if ( word_953932[2 * v6] < word_953934[2 * v6] )
    word_953932[2 * v6] += sub_452AC0(word_953934[2 * v6] - word_953932[2 * v6] + 1);
```

物品掉落数量在 `[word_953932, word_953934]` 范围内随机，这两个数组定义了每种物品的最小/最大掉落数量。

---

## 8. 总结

1. **级联互斥判定**：不是三个独立概率判定，而是一次随机数决定从哪个槽位掉落。
2. **真实概率**：低概率 5%、高概率 15%、必掉落 80%（仅当该槽有物品时）。
3. **空槽回退**：如果高优先级槽位为空，自动回退到下一个有物品的槽位。
4. **单槽 100% 特性**：游戏实际配置中大多数怪物只有 1 个掉落物品（位于必掉落槽），此时空槽回退机制保证 100% 掉落，因此编辑器标签"必掉落"在实际游戏中基本准确。
5. **编辑器无需修改**：概率在引擎中硬编码，编辑器只管理物品 ID，无需也无法修改概率值。
