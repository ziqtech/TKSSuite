### 2.5 孝谈版的核心机制（推测）

```
游戏入口（未修改）
  ↓
游戏正常初始化
  ↓
游戏调用被 hook 的函数
  ↓
JMP .test 跳转到 Thunk
  ↓
Thunk 检查辅助程序是否运行
  ├─ 不存在：弹出提示并退出
  └─ 存在：调用 WinExec("YinShiXing2013.exe", ...) 启动
  ↓
辅助程序运行时修改全局数据缓冲区：
  word_757Fxx (角色临时战斗属性)
  word_77CBCA (TKItem 物品缓存)
  word_7861CA (TKSkill/TKKon 技能效果缓存)
  byte_757FB8 (技能学习状态)
  ↓
游戏继续执行（带增强属性/物品/技能）
```

> ⚠️ 文档明确指出："不太可能直接修改战斗伤害计算"。孝谈版不是劫持游戏逻辑，而是在游戏数据缓冲区注入 modifier。
> 文档第 11 节进一步推测："Hook 很可能是游戏资源数据的运行时修改"。

## 四、关键差异结论

### 4.1 启动器与孝谈版的本质差异

| 维度 | 孝谈版 | 当前启动器 |
|---|---|---|
| 实现路径 | 修改 EXE 二进制 + 外部辅助程序 | 不修改 EXE 二进制，运行时进程内 patch |
| 代码注入位置 | `.test` 段（EXE 内置） | Cave 内存区（VirtualAllocEx 运行时分配） |
| 数据注入位置 | `.Newdata` 段（EXE 内置） | Cave 内存 / 进程内存直接写入 |
| 辅助程序 | `YinShiXing2013.exe` / `system.exe` / `closesystem.exe` | **无**（启动器不依赖外部 helper） |
| 启动条件 | 主 EXE 检测辅助程序，缺失则退出 | MOD 列表控制，缺失也能启动（仅运行原版补丁子集） |
| 兼容性 | 仅支持孝谈三国3终极版 | 兼容原版 + 孝谈版 + 未知 MOD 版（fallback_rva + override） |
| 用户交互 | 仅界面启动 | GUI 启动器 + CLI + 存档管理 + 模组合并/拆分/编辑 + 自定义音乐 UI |

### 4.2 启动器的覆盖广度对比

孝谈版 31 个 Hook：
- **9 个** 启动器已**完全覆盖**（存档/资源/角色管理/属性初始化/物品金钱）
- **10 个** 启动器**间接覆盖**（数据扩容 + 周边修复）
- **12 个** 启动器**未覆盖**（战斗公式细节、位置计算、随机判定、DirectSound）

### 4.3 启动器独有的能力（孝谈版没有）

- 存档健康检查（`save_manager.py`、`launcher_pipeline.py:ensure_save_directory_healthy`）
- MOD 合并/拆分/编辑（`core/mod_merger.py`、`ui/mod_merger_dialog.py` 等）
- 存档 ZIP 备份恢复（`core/save_manager.py`，记录补丁/MOD/tool 勾选状态）
- EXE 版本指纹缓存（`ExeProfileCache`，二次启动 -80ms）
- HookTable 内部冲突跟踪（`patch_engine.py:407`）
- Cave 越界硬校验 + 自动布局
- 孝谈版 profile + 颠动沧溟版差异在 profile 内通用处理
