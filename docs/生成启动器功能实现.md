# 生成启动器功能实现文档

> **功能**：将选中补丁烧录进原版 TKS.exe，生成独立可分发的修改版 exe
> **位置**：`tks_launcher_gui/core/exe_builder.py` + `tks_launcher_gui/ui/generate_exe_dialog.py`
> **入口**：主窗口 → MOD 工具 → 生成启动器

## 1. 功能概述

参照 `TKS_MOD.exe` 的补丁方式（新增 `.test` 节 + jmp hook），实现文件级补丁烧录：
- 无需运行时内存操作
- 生成的 exe 可直接分发给玩家
- 玩家无需安装启动器

**核心原则**：不支持的补丁类型在 `patches/` 目录内自身重写为文件级类型，
不在 `exe_builder.py` 里做按 ID 的类型转换。

## 2. 补丁类型

| 类型 | 数量 | 实现方式 |
| --- | --- | --- |
| cave_hook / patch_exp_lock | 22 | `.test` 节 + jmp rel32 hook |
| fixed_layout_cave | 1 | 多 hook 固定布局 cave（cave_code.py `build_cave_block`） |
| patch_bytes | 23 | 模式搜索 + 字节替换 |
| patch_imm32 | 7 | 多模式立即数替换（含 value_scan） |
| 配置驱动型 | 4 | drop_probability / font_config / animation_speed / summon_table |
| patch_data_expand | 3 | 数据段注入 + 基址/大小重定向 |
| **合计** | **60** | **全部支持** |

### 2.1 fixed_layout_cave

`summon_extend` 重写为本类型。`patch.json` 声明全部 hooks 与附带 bytes_patches；
`cave_code.py` 提供 `build_cave_block(cave_base, n)`，在计算出 `.test` 绝对地址后
动态生成含绝对跳转的完整 cave 块。

```json
{
  "type": "fixed_layout_cave",
  "summon_limit": 4,
  "cave_code_file": "cave_code.py",
  "cave_layout_size": 2048,
  "hooks": [
    {"name": "init", "pattern": "...", "hook_size": 14, "cave_entry_offset": 1664, "expect_count": 1}
  ],
  "bytes_patches": [
    {"pattern": "66 83 C0 02 66 89 45 FC", "replace": {"3": 4}, "expect_count": 1}
  ],
  "script_file": "script.py"
}
```

运行时仍走 `script.py`（VirtualAllocEx + apply_cave_hook）；文件级走 cave_code.py。

### 2.2 patch_data_expand

`tkact_expand` / `tkkon_expand` / `warpc_base_refs` 重写为本类型。
所有参数声明在 `patch.json`，对话框泛型读取，不按补丁 ID 硬编码。

```json
{
  "type": "patch_data_expand",
  "data_file": "TKAct.dat",
  "old_base": "0x9539CA",
  "old_size": 509600,
  "section_name": ".tkact",
  "needs_lzss": false,
  "script_file": "script.py"
}
```

文件级流程：读取游戏目录中的数据文件（可选 LZSS 解压）→ 作为新 PE 节注入 →
重定向代码中的 `old_base` / `old_size` 引用。

运行时：有 `script_file` 则执行（tkact/tkkon）；无 script 则由 WarPC 扩展流程
处理（warpc_base_refs）。

### 2.3 save_entry_check_fix

已重写为 `patch_bytes`（固定模式 `80 7B 0C 00 74 07 33 C0`，偏移 4 的 `74`→`EB`）。
残留的 `script.py` 已删除。

## 3. 技术实现

### 3.1 核心数据结构

```python
# cave_hook 型
CavePatchItem(patch_id, name, hook_pattern, hook_size, cave_code,
              fallback_rva, expect_count)

# fixed_layout_cave 型
FixedLayoutCave(patch_id, name, hooks, cave_block=None, build_fn=None,
                bytes_patches=None, cave_layout_size=0)
# build_fn(cave_base) -> bytes，在 .test 地址确定后调用

# patch_bytes 型
BytesPatchItem(patch_id, name, entries=[BytesPatchEntry(...)])

# patch_imm32 型
Imm32PatchItem(patch_id, name, new_value, entries=[Imm32PatchEntry(...)])

# 配置驱动型
ConfigPatchItem(patch_id, name, patch_type, config)

# patch_data_expand 型
DataSectionPatchItem(patch_id, name, data, old_base, old_size, section_name)
```

### 3.2 构建流程

```
1. 读取原版 TKS.exe
2. 数据段注入（patch_data_expand）→ 记录新基址，推进 VA 游标
3. 应用 patch_bytes / fixed_layout 附带 bytes_patches
4. 应用 patch_imm32
5. 重定向数据段基址/大小引用
6. 应用配置驱动型补丁
7. 定位所有 hook 点（fixed_layout + cave_hook）
8. 计算 .test 节布局：
   a. fixed_layout 块从偏移 0 开始（build_fn(test_abs) 生成）
   b. cave_hook 按 16 字节对齐顺序排在其后
9. 追加 .test 节，写入 cave 代码与 jmp hook
10. 统一更新 NumberOfSections / SizeOfImage
11. 输出修改版 exe
```

### 3.3 PE 结构修改

新增节：
- 数据段（`.tkact` / `.tkkon` / `.warpc`）：特征 `0xC0000040`（可读+可写）
- `.test` 节：特征 `0xE00000A0`（可执行+可读+包含代码）

RVA 按 SectionAlign 对齐，文件偏移按 FileAlign 对齐。

## 4. 使用说明

1. 打开启动器 → MOD 工具 → 生成启动器
2. 选择原版 TKS.exe
3. 勾选要烧录的补丁
4. 选择输出路径
5. 点击「生成」

## 5. 测试结果

| 补丁 | 类型 | 结果 |
| --- | --- | --- |
| summon_extend | fixed_layout_cave | ✓ 5 hook + 2 bytes_patch |
| exp_lock | cave_hook | ✓ hook @ 0x3B4F3 |
| attribute_char_limit_unlock | patch_bytes | ✓ |
| patch5 立即数 | bytes | ✓ `66 83 C0 04` |
| patch7 NOP | bytes | ✓ 6×90 |
| 混合构建 | cave+fixed+bytes | ✓ NumberOfSections=9 |
