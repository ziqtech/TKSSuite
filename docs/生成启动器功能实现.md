# 生成启动器功能实现文档

> **功能**：将选中补丁烧录进原版 TKS.exe，生成独立可分发的修改版 exe
> **位置**：`tks_launcher_gui/core/exe_builder.py` + `tks_launcher_gui/ui/generate_exe_dialog.py`
> **入口**：主窗口 → MOD 工具 → 生成启动器

## 1. 功能概述

参照 `TKS_MOD.exe` 的补丁方式（新增 `.test` 节 + call hook），实现文件级补丁烧录：
- 无需运行时内存操作
- 生成的 exe 可直接分发给玩家
- 玩家无需安装启动器

**核心原则**：不支持的补丁类型在 `patches/` 目录内自身重写为文件级类型，
不在 `exe_builder.py` 里做按 ID 的类型转换。

## 2. 补丁类型

| 类型 | 数量 | 实现方式 |
| --- | --- | --- |
| cave_hook / patch_exp_lock | 21 | `.test` 节 + call rel32 hook（E8，与运行时一致） |
| fixed_layout_cave | 2 | 多 hook 固定布局 cave（summon_extend / summon_exp_jp_accumulation_fix） |
| patch_bytes | 23 | 模式搜索 + 字节替换 |
| patch_imm32 | 7 | 多模式立即数替换（含 value_scan） |
| 配置驱动型 | 4 | drop_probability / font_config / animation_speed / summon_table |
| patch_data_expand | 3 | 数据段注入 + 基址/大小/字段锚定重定向 |
| **合计** | **60** | **全部支持** |

### 2.1 fixed_layout_cave

`summon_extend` 重写为本类型。`patch.json` 声明全部 hooks 与附带 bytes_patches；
`cave_code.py` 提供 `build_cave_block(cave_base, n)`，在计算出 `.test` 绝对地址后
动态生成含绝对跳转的完整 cave 块。

```json
{
  "type": "fixed_layout_cave",
  "summon_limit": 4,
  "cave_code_file": "cave_code.py",
  "cave_layout_size": 2048,
  "hooks": [
    {"name": "init", "pattern": "...", "hook_size": 14, "cave_entry_offset": 1664, "expect_count": 1}
  ],
  "bytes_patches": [
    {"pattern": "66 83 C0 02 66 89 45 FC", "replace": {"3": "$summon_limit"}, "expect_count": 1}
  ]
}
```

无 `script.py`。文件级与运行时均调用同一 `build_cave_block`。

### 2.2 patch_data_expand

`tkact_expand` / `tkkon_expand` / `warpc_base_refs` 重写为本类型。
所有参数声明在 `patch.json`，对话框泛型读取，不按补丁 ID 硬编码。

```json
{
  "type": "patch_data_expand",
  "data_file": "TKAct.dat",
  "old_base": "0x9539CA",
  "old_size": 509600,
  "section_name": ".tkact",
  "needs_lzss": false
}
```

无 `script.py`。文件级：数据作为新 PE 节注入并重定向引用。
运行时：引擎原生 VirtualAllocEx + 基址/大小重定向。

### 2.3 save_entry_check_fix

已重写为 `patch_bytes`（固定模式 `80 7B 0C 00 74 07 33 C0`，偏移 4 的 `74`→`EB`）。

## 3. 技术实现

### 3.1 核心数据结构

```python
# cave_hook 型
CavePatchItem(patch_id, name, hook_pattern, hook_size, cave_code,
              fallback_rva, expect_count)

# fixed_layout_cave 型
FixedLayoutCave(patch_id, name, hooks, cave_block=None, build_fn=None,
                bytes_patches=None, cave_layout_size=0)
# build_fn(cave_base) -> bytes，在 .test 地址确定后调用

# patch_bytes 型
BytesPatchItem(patch_id, name, entries=[BytesPatchEntry(...)])

# patch_imm32 型
Imm32PatchItem(patch_id, name, new_value, entries=[Imm32PatchEntry(...)])

# 配置驱动型
ConfigPatchItem(patch_id, name, patch_type, config)

# patch_data_expand 型
DataSectionPatchItem(patch_id, name, data, old_base, old_size, section_name)
```

### 3.2 构建流程

```
1. 读取原版 TKS.exe
2. 数据段注入（patch_data_expand）→ 记录新基址，推进 VA 游标
3. 应用 patch_bytes / fixed_layout 附带 bytes_patches
4. 应用 patch_imm32
5. 重定向数据段基址/大小引用（含 redirect_base_span 字段锚定扫描）
6. 应用配置驱动型补丁
7. 定位所有 hook 点（fixed_layout + cave_hook，支持 hook_offset）
8. 计算 .test 节布局：
   a. 各 fixed_layout 块按声明布局大小顺序独立排布（互不重叠）
   b. cave_hook 按 16 字节对齐顺序排在其后
9. 追加 .test 节，写入 cave 代码与 call hook（E8 rel32，与运行时约定一致）
10. 统一更新 NumberOfSections / SizeOfImage
11. 输出修改版 exe
```

### 3.2a hook 约定（2026-09-10 修复后）

- 引擎（`patch_engine.py` 与 `exe_builder.py`）统一写 **`E8 rel32`（CALL）+ NOP 填充**，
  进入 cave 时 `[esp]` = 返回地址（hook+5），cave 以 `ret` 回到 hook+5 的 NOP 槽。
  早期版本 exe_builder 写 `E9 jmp`，与全部 cave 代码的 CALL 约定不兼容（已废弃）。
- `hook_offset`：hook 写入点 = 模式起点 + hook_offset（awk_sprite_cave3/4 的模式
  含前一条 `EB 05` 的 2 字节，真正被覆盖指令在其后）。exe_builder 的
  `fallback_rva` 与运行时同口径（指向 hook 写入点，即模式起点 + hook_offset）。
- 多个 fixed_layout 共存：每块按 `cave_layout_size` 顺序独立排布（互不重叠），
  hook 的 `cave_entry_offset` 相对所属块起点，E8 目标 = `.test` + 块偏移 + entry
  （此前所有块都从 .test+0 开始，第二个 fixed_layout 的 hook 会指错块）。
- `redirect_base_span`（patch_data_expand 可选字段）：精确基址重定向之外，
  再把可执行节内 `(old_base, old_base+span)` 开区间的 4 字节立即数重定向为
  `new_base + (val - old_base)`——覆盖字段锚定型引用
  （如 WarPC `word_757F0C[527*i]`、TKKon `0x9D069E = 基址+6`，精确基址替换改不到）。
  tkkon_expand 声明 40（一条记录），warpc_base_refs 声明 1054（一条记录）。

### 3.3 PE 结构修改

新增节：
- 数据段（`.tkact` / `.tkkon` / `.warpc`）：特征 `0xC0000040`（可读+可写）
- `.test` 节：特征 `0xE00000A0`（可执行+可读+包含代码）

RVA 按 SectionAlign 对齐，文件偏移按 FileAlign 对齐。

## 4. 使用说明

1. 打开启动器 → MOD 工具 → 生成启动器
2. 选择原版 TKS.exe
3. 勾选要烧录的补丁
4. 选择输出路径
5. 点击「生成」

## 5. 测试结果

| 补丁 | 类型 | 结果 |
| --- | --- | --- |
| summon_extend | fixed_layout_cave | ✓ 5 hook + 2 bytes_patch |
| exp_lock | cave_hook | ✓ hook @ 0x3B4F3 |
| attribute_char_limit_unlock | patch_bytes | ✓ |
| patch5 立即数 | bytes | ✓ `66 83 C0 04` |
| patch7 NOP | bytes | ✓ 6×90 |
| 混合构建 | cave+fixed+bytes | ✓ NumberOfSections=9 |
