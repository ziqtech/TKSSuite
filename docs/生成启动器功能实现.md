# 生成启动器功能实现文档

> **功能**：将选中补丁烧录进原版 TKS.exe，生成独立可分发的修改版 exe
> **位置**：`tks_launcher_gui/core/exe_builder.py` + `tks_launcher_gui/ui/generate_exe_dialog.py`
> **入口**：主窗口 → MOD 工具 → 生成启动器

## 1. 功能概述

参照 `TKS_MOD.exe` 的补丁方式（新增 `.test` 节 + jmp hook），实现文件级补丁烧录：
- 无需运行时内存操作
- 生成的 exe 可直接分发给玩家
- 玩家无需安装启动器

## 2. 支持的补丁类型

### 2.1 已支持（55/60 = 91%）

| 类型 | 数量 | 实现方式 |
| --- | --- | --- |
| cave_hook / patch_exp_lock | 22 | `.test` 节 + jmp rel32 hook |
| patch_bytes | 22 | 模式搜索 + 字节替换 |
| patch_imm32 | 7 | 多模式立即数替换（含 value_scan） |
| patch_drop_probability | 1 | 硬编码 RVA 阈值修改 |
| patch_font_config | 1 | 字体描边参数修改 |
| patch_animation_speed | 1 | 动画帧延迟修改 |
| patch_summon_table | 1 | .data 段 + 代码段 imm16 写入 |

### 2.2 不支持（5/60）

| 类型 | 数量 | 原因 |
| --- | --- | --- |
| script | 4 | 需要运行时内存操作（VirtualAllocEx/WriteProcessMemory） |
| patch_warpc_addr | 1 | 由 WarPC 扩展流程统一处理，文件级无需单独支持 |

## 3. 技术实现

### 3.1 核心数据结构

```python
# cave_hook 型
@dataclass
class CavePatchItem:
    patch_id: str
    name: str
    hook_pattern: bytes    # 原始指令字节
    hook_size: int         # 被覆盖指令长度（>=5）
    cave_code: bytes       # cave 机器码
    fallback_rva: int      # 模式匹配失败时的回退 RVA
    expect_count: int

# patch_bytes 型
@dataclass
class BytesPatchItem:
    patch_id: str
    name: str
    entries: List[BytesPatchEntry]

@dataclass
class BytesPatchEntry:
    pattern: str           # 空格分隔十六进制，支持 ?? 通配
    replace: Dict[int, int]  # {偏移: 新字节值}
    expect_count: int

# patch_imm32 型
@dataclass
class Imm32PatchItem:
    patch_id: str
    name: str
    new_value: int
    entries: List[Imm32PatchEntry]

@dataclass
class Imm32PatchEntry:
    pattern: str
    value_offset: int
    expect_count: int
    value_size: int        # 4=imm32, 2=imm16

# 配置驱动型
@dataclass
class ConfigPatchItem:
    patch_id: str
    name: str
    patch_type: str        # drop_probability/font_config/animation_speed/summon_table
    config: dict           # JSON 配置内容
```

### 3.2 构建流程

```
1. 读取原版 TKS.exe
2. 应用 patch_bytes（直接修改现有节）
3. 应用 patch_imm32（直接修改现有节）
4. 应用配置驱动型补丁
5. 如有 cave_hook 型补丁：
   a. 定位所有 hook 点
   b. 计算 .test 节布局（16 字节对齐）
   c. 追加 .test 节到 PE 末尾
   d. 写入 cave 代码
   e. 在 hook 点写入 jmp rel32 + NOP 填充
   f. 更新 NumberOfSections / SizeOfImage
6. 输出修改版 exe
```

### 3.3 PE 结构修改

新增 `.test` 节：
- 特征：`0xE00000A0`（可执行 + 可读 + 包含代码）
- RVA：原最后一节之后，按 SectionAlign 对齐
- 文件偏移：文件末尾，按 FileAlign 对齐

## 4. 使用说明

1. 打开启动器 → MOD 工具 → 生成启动器
2. 选择原版 TKS.exe
3. 勾选要烧录的补丁
4. 选择输出路径
5. 点击「生成」

## 6. 已知限制

### 6.1 script 型补丁无法文件级实现

3 个 script 型补丁需要运行时内存操作，无法转换为 cave_hook：

| 补丁 | 原因 |
| --- | --- |
| tkact_expand | 需要 VirtualAllocEx 分配更大缓冲区，复制 TKAct.dat 后重定向引用 |
| summon_extend | 需要 VirtualAllocEx 分配更大缓冲区，复制召唤表后重定向引用 |
| tkkon_expand | 需要 VirtualAllocEx 分配更大缓冲区，复制 TKKon.dat 后重定向引用 |

**核心限制**：这三个 expand 补丁需要在运行时分配新内存并复制数据，这是文件级补丁无法实现的。

### 6.2 已转换的 script 补丁

`save_entry_check_fix` 已从 script 型转换为 patch_bytes 型：
- 原始：动态搜索 `cmp [reg+0Ch], 0` 并修改分支
- 转换后：固定模式 `80 7B 0C 00 74 07 33 C0`，替换偏移 4 的 `74`(je) 为 `EB`(jmp)

### 6.3 warpc_addr 由扩展流程处理

`patch_warpc_addr` 由 WarPC 扩展流程统一处理，文件级无需单独支持。

### 6.4 expand 型补丁的限制

**tkact_expand / tkkon_expand**：
- 需要 `VirtualAllocEx` 分配新缓冲区存放扩展数据
- 需要扩展后的数据文件（TKAct.dat.expanded / TKKon.dat.expanded）
- 文件级方案：可将扩展数据作为新 PE 节，但需要用户提供扩展数据文件

**summon_extend**：
- 已实现文件级烧录（FixedLayoutCave 支持）
- 预计算 .test 节地址（0xA7D000），固化 5 个 hook 的 cave 代码
- 测试通过：5 个 hook 全部正确跳转

**结论**：tkact_expand / tkkon_expand 需要启动器运行时应用；summon_extend 已支持文件级烧录。
