# 破兵状态攻击Bug逆向分析与修复

> 基于 `TKS.exe` (三国群侠传) 反编译代码的独立分析。
>
> 分析日期: 2026-06-27

---

## 0. 问题概述

### 症状

游戏中敌人处于 **破兵** 状态时完全不会攻击。玩家社区发现这是因为破兵状态的攻击力修正存在数值错误：

| 项目 | 设计意图 | 实际效果 |
|------|---------|---------|
| 攻击修正 | −30% | **−300%** |
| 结果 | 攻击力保留 70% | 攻击力变为负数（≈ −200%），归零后不攻击 |

### 根因一句话

代码中将 `30 * 攻击力 / 10` 写成了攻击力修正公式，实际效果是减去 **3 倍攻击力**（−300%）；正确写法应是 `3 * 攻击力 / 10`（−30%）。

### 1.2 状态位掩码存储

## 2. 状态施加 → 运行时标记

### 2.1 函数 `sub_442D44` — 状态施加处理

- **地址**: `0x442D44`
- **调用者**: `sub_4432EC`, `sub_4458B0`（技能执行主函数）, `sub_447DAC`
- **功能**: 对角色施加指定状态，设置运行时状态标记数组

**关键代码**（`442D44.c` 第 92–100 行）:

```c
// a1 = 角色索引, a2 = 状态索引
if ( byte_9E048E[32 * a1 + a2] )   // 状态已存在
{
    // 查找空闲槽位更新
    for ( i = 0; i < 8; ++i )
    {
        if ( SLOBYTE(word_9D707A[527 * a1 + 43 + i]) == a2 + 1 )
        {
            HIBYTE(word_9D707A[527 * a1 + 43 + i]) = byte_4EB790[2 * a2];
            byte_9E048E[32 * a1 + a2] = 1;    // ← 设置标记
            ...
        }
    }
}
```

当 `a2 = 0`（破兵）施加到角色 `a1` 时:
```
byte_9E048E[32 * a1 + 0] = 1
```

### 2.2 运行时标记数组 `byte_9E048E`

- **大小**: 1024 字节（`0x400`）
- **布局**: `byte_9E048E[32 * char_idx + status_idx]`
  - 每个角色 32 字节（对应 32 种状态）
  - 最多 32 个角色
- **初始化**: 在 `sub_436BD4`（战斗初始化）中 `memset(byte_9E048E, 0, 0x400u)` 清零

## 3. 伤害计算核心 `sub_43E980`

### 3.1 函数概览

- **地址**: `0x43E980`
- **调用者**: `sub_4359A4`（AI 技能评估）
- **功能**: 计算技能/攻击的实际伤害值和命中率

### 3.2 状态修正代码段

反编译代码（`43E980.c` 第 163–173 行）:

```c
if ( a1 >= 0 )
{
    v24 = word_9D6C58;                          // 保存原始攻击力基准值

    if ( byte_9E0493[32 * a1] )                 // 状态: 蓄力?
        word_9D6C58 += 3 * word_9D6C58 / 10;    // ✓ +30%

    if ( byte_9D6F84[a1] == -3 )                // 条件: 特殊标记
        word_9D6C58 += 3 * v24 / 10;            // ✓ +30%

    if ( byte_9E048E[32 * a1] )                 // 状态: 破兵 ← 状态索引 0
        word_9D6C58 -= 30 * v24 / 10;           // ✗ BUG: 30/10=3 → −300%

    if ( byte_9E04A6[32 * a1] )                 // 状态: 虚弱?
        word_9D6C58 -= 15 * v24 / 100;          // ✓ −15%
}
```

**关键对比**:

| 行号 | 状态 | 公式 | 数学结果 | 正确性 |
|------|------|------|---------|--------|
| 167 | 蓄力 | `3 * atk / 10` | `0.3 × atk` (+30%) | ✓ |
| 169 | 特殊标记 | `3 * v24 / 10` | `0.3 × v24` (+30%) | ✓ |
| **171** | **破兵** | **`30 * v24 / 10`** | **`3 × v24` (−300%)** | **✗** |
| 173 | 虚弱 | `15 * v24 / 100` | `0.15 × v24` (−15%) | ✓ |

第 171 行的乘数 `30` 比正确值多了 **10 倍**：应该是 `3`（配合 `/10` 得 30%）或保持 `30` 但除数应为 `100`（得 30%）。

## 4. 汇编级分析

### 4.1 Bug 代码（VA `0x43EFA1`, sub_43E980+0x621）

文件偏移: `0x3E9A1`

```asm
; ─── 状态检查 ───
0043EF93  0F BF 45 08       movsx eax, word [ebp+8]         ; eax = a1 (char index)
0043EF97  C1 E0 05          shl   eax, 5                     ; eax *= 32
0043EF9A  8A 90 8E 04 9E 00 mov   dl, [eax + 0x009E048E]    ; dl = byte_9E048E[32*a1]
0043EFA0  84 D2             test  dl, dl                     ; 破兵状态?
0043EFA2  74 1A             jz    0x43EFBE                   ; 否 → 跳过

; ─── 攻击力修正计算 (BUG) ───
0043EFA4  8B 45 C8          mov   eax, [ebp-38h]             ; eax = v24 (原始攻击力)
0043EFA7  03 C0             add   eax, eax                  ; ×2
0043EFA9  8D 04 40          lea   eax, [eax+eax*2]          ; ×3 → 总 ×6
0043EFAC  8D 04 80          lea   eax, [eax+eax*4]          ; ×5 → 总 ×30  ← BUG!
0043EFAF  B9 0A 00 00 00    mov   ecx, 0x0A                  ; 除数 = 10
0043EFB4  99                cdq                              ; 符号扩展
0043EFB5  F7 F9             idiv  ecx                        ; eax = v24×30÷10 = 3×v24
0043EFB7  66 29 05 58 6C 9D 00  sub  [word_9D6C58], ax      ; 攻击力 -= 300%
```

**LEA 链分析**:

```
初始:  eax = v24
add:   eax = v24 × 2          (03 C0)
lea1:  eax = v24 × 2 × 3 = v24 × 6   (8D 04 40)
lea2:  eax = v24 × 6 × 5 = v24 × 30  (8D 04 80)
idiv:  eax = v24 × 30 / 10 = v24 × 3
sub:   attack -= v24 × 3   →   −300%
```

### 4.2 正确参考（VA `0x43EF5C`, sub_43E980+0x5DC）

同一函数中 `+30%` 修正的正确实现：

```asm
; ─── 攻击力修正计算 (正确: +30%) ───
0043EF5C  8B 45 C8          mov   eax, [ebp-38h]             ; eax = v24
0043EF5F  8D 04 40          lea   eax, [eax+eax*2]          ; ×3 ← 正确!
0043EF62  B9 0A 00 00 00    mov   ecx, 0x0A
0043EF67  99                cdq
0043EF68  F7 F9             idiv  ecx                        ; eax = v24×3÷10 = 0.3×v24
0043EF6A  66 01 05 58 6C 9D 00  add  [word_9D6C58], ax      ; 攻击力 += 30% ✓
```

### 4.3 对比总结

```
        Bug (−300%)                    正确 (+30%)
        ───────────                    ──────────
        mov eax, [ebp-38h]            mov eax, [ebp-38h]
        add eax, eax     ; ×2         lea eax, [eax+eax*2]  ; ×3
        lea eax, [eax+eax*2] ; ×3
        lea eax, [eax+eax*4] ; ×5
        ─────────────────────          ─────────────────────
        总乘法: ×30                    总乘法: ×3
        /10 = ×3 (−300%)              /10 = ×0.3 (+30%)
```

**Bug 根因**: 编译器将 `30 * v24 / 10` 优化为 `(2×3×5) * v24 / 10 = 30 * v24 / 10`，通过 3 条指令链实现 ×30。正确写法 `3 * v24 / 10` 只需 1 条 LEA 实现 ×3。

## 5. 修复方案

### 5.1 字节级修改

| 项目 | 值 |
|------|-----|
| **文件偏移** | `0x3E9A4` |
| **RVA** | `0x3EFA4` |
| **VA** | `0x0043EFA4` |
| **原始字节** | `03 C0 8D 04 40 8D 04 80` |
| **修改字节** | `8D 04 40 90 90 90 90 90` |
| **修改长度** | 8 字节 |

### 5.2 汇编变更

```asm
; 修改前 (×30 链, 8 字节)
03 C0             add   eax, eax             ; ×2
8D 04 40          lea   eax, [eax+eax*2]     ; ×3
8D 04 80          lea   eax, [eax+eax*4]     ; ×5

; 修改后 (×3 + NOP 填充, 8 字节)
8D 04 40          lea   eax, [eax+eax*2]     ; ×3
90                nop
90                nop
90                nop
90                nop
90                nop
```

### 5.3 数学验证

| | 修改前 | 修改后 |
|---|--------|--------|
| 计算公式 | `v24 × 30 / 10` | `v24 × 3 / 10` |
| 数值结果 | `v24 × 3` | `v24 × 0.3` |
| 攻击力变化 | 减去原攻击力的 300% | 减去原攻击力的 30% |
| 最终攻击力 | `atk − 3×atk = −2×atk` → ≤0 | `atk − 0.3×atk = 0.7×atk` |

### 5.4 补丁配置

已集成到 `tks_patches.json`（启动器可选补丁）:

```json
{
    "type": "patch_bytes",
    "id": "broke_weapon_fix",
    "desc": "破兵状态攻击修正：-300%→-30%（sub_43E980 LEA链修复）",
    "pattern": "8B 45 C8 03 C0 8D 04 40 8D 04 80",
    "expect_count": 1,
    "replace": { "3": "8D", "4": "04", "5": "40",
                 "6": "90", "7": "90", "8": "90", "9": "90", "10": "90" },
    "optional": true
}
```

- **模式**: `8B 45 C8 03 C0 8D 04 40 8D 04 80`（11 字节，全二进制唯一）
- **替换**: 将偏移 3–10 的 8 字节替换为 `8D 04 40 90 90 90 90 90`
- **预期匹配数**: 1
- **可选**: 是（用户可在启动器 UI 中勾选/取消）
