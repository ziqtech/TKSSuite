# 原版战斗伤害飘字分段逻辑分析

## 结论

敌人身上显示几次伤害数字，不是由攻击次数字段直接决定，也不是由动画图层数量决定。原版的分段依据是：

> 当前 `TKAct` 动画记录中，`[20]~[27]` 这 8 个条目级参数里，有多少个触发 Tick 能在 `[18]` 的动画 Tick 范围内按顺序匹配成功。

这个数量记为 `N`。进入战斗飘字流程的总伤害会被拆成 `N` 段，并在对应 Tick 依次生成伤害数字。

因此，示例中的行为是：

```text
土崩术：总伤害 120，N=2  →  60、60
狂风术：总伤害 40， N=3  →  14、13、13
普通攻击：N=1           →  只显示 1 段
某些角色普通攻击：N=2   →  显示 2 段
```

这里的“显示 2 次”表示同一个已计算出的总伤害被拆成两次飘字，并不表示攻击动作执行了两次。

## 原版调用链

```text
sub_4434BC
  ├─ 读取 TKAct 条目，初始化/推进动画 Tick
  ├─ 统计 [20]~[27] 中有效的触发 Tick 数 N
  └─ 调用 sub_4400DC 执行该 Tick 序列中的战斗效果
       └─ 按剩余分段数拆分总伤害，并调用 sub_433F04
            └─ 将一次飘字数值加入原版伤害数字队列
```

`sub_433F04` 的反编译代码把传入的数值写入伤害数字队列 `word_9DFC8A` / `word_9DFC90` 等运行时数组；因此，真正造成“出现一次数字”的是该函数被调用并加入一条数字记录，而不是 `TKSkill.atk_count` 的值。

## TKAct 条目级字段

每条 `TKAct` 记录为 784 字节。编辑器把记录中的条目级参数区解析为 `int16[16..39]`，对应文件字节 `32..79`。

| 编辑器索引 | 原版运行时变量 | 记录内偏移 | 原版用途 |
|---:|---|---:|---|
| `[18]` | `word_9D039E` | `+36` | 动画总 Tick；原版按 `0..总Tick-1` 检查触发点 |
| `[19]` | `word_9D03A0` | `+38` | 运行时当前 Tick；播放开始时重置，之后逐 Tick 递增 |
| `[20]` | `word_9D03A2[0]` | `+40` | 第 1 个伤害/效果触发 Tick |
| `[21]` | `word_9D03A2[1]` | `+42` | 第 2 个伤害/效果触发 Tick |
| ... | ... | ... | ... |
| `[27]` | `word_9D03A2[7]` | `+54` | 第 8 个伤害/效果触发 Tick |

`[20]~[27]` 不是“图层 Tick 配额”，也不是攻击次数。它们是动画时间轴上的效果触发位置；伤害、状态或其他战斗效果都可以使用这套触发位置。

## 原版如何统计分段数

`sub_4434BC` 中的关键逻辑等价于以下伪代码：

```c
N = 0;
for (i = 0; i < total_tick; ++i)
{
    if (N < 8 && trigger_tick[N] == i)
        ++N;
}
```

其中：

```text
total_tick  = TKAct[18]
trigger_tick = TKAct[20..27]
```

这段代码有几个必须保留的原版语义：

1. 只检查 `0 <= i < [18]` 的 Tick；等于 `[18]` 的值不会被计入。
2. 最多只统计 8 个触发点。
3. 原版按 `trigger_tick[N]` 这一“当前数组项”匹配，而不是把 8 个字段逐个独立扫描后计数。
4. 要让已经配置的多个触发点全部按预期生效，它们应构成严格递增的有效前缀，并且每个值小于 `[18]`。原版没有在这里额外做排序或空槽校验，所以乱序、重复或超出范围的值不能按“一个字段等于一段”理解。
5. `[19]` 是运行时当前 Tick，不是用于配置分段数量的字段。

当 `[20]~[27]` 的有效匹配数量为 1、2、3 时，原版分别会进入 1、2、3 段的处理路径。

## 原版如何拆分总伤害

在 `sub_4400DC` 的 `441CBE~441D48`，原版按当前已经处理的段数 `index` 和剩余段数拆分进入该路径的总伤害。该段指令使用 `word_9D7046 - index` 作为除数，第一次除法取得商，第二次除法取得余数并加回当前段；随后在 `441D32` 扣除当前段值、在 `441D35` 递增索引，并在 `441D0A/441D27` 调用 `sub_433F04`。对于正生命伤害，可以还原为：

```python
remaining = N - index
part = total_damage // remaining + total_damage % remaining
total_damage -= part
emit(part)
```

也就是：

- 当前段拿到“剩余总伤害除以剩余段数”的商；
- 整数余数一次性加到当前段；
- 从总伤害中扣除当前段后，继续处理下一段。

所以总和始终保持不变。正伤害的典型结果如下：

| 总伤害 | 有效触发点数 `N` | 原版显示值 |
|---:|---:|---|
| 120 | 1 | 120 |
| 120 | 2 | 60、60 |
| 120 | 3 | 40、40、40 |
| 40 | 3 | 14、13、13 |
| 41 | 3 | 14、14、13 |

由于余数加在当前段，不能简单地把每段都写成 `total_damage / N` 后四舍五入；MOD 工具或脚本若要复现原版，必须保留“每次使用剩余值和剩余段数”的算法。

## 原版资源实例核对

以下链路使用 `仓库根目录` 的 v2 编辑器解析方式确认字段关系：`TKSkill` 的 `[6]` 为 `tkact_id`，`[8]` 为 `hp_damage`；`WarPC` 的技能效果映射指向 `TKKon`；`TKKon` 的 `[6]` 为 `tkact_id`，`[8]` 为 `hp_damage`。

### 土崩术

```text
TKSkill[35]
  → WarPC#0[308] = TKKon#28
  → TKKon#28.hp_damage = 120
  → TKKon#28.tkact_id = 28
  → TKAct#28
       [18] = 30
       [20..27] 的有效触发 Tick = [4, 12]
```

有效触发点数为 `N=2`。总伤害 120 按原版分段后，敌人身上显示 `60、60`。

### 狂风术

```text
TKSkill[36]
  → WarPC#0[309] = TKKon#29
  → TKKon#29.hp_damage = 40
  → TKKon#29.tkact_id = 29
  → TKAct#29
       [18] = 35
       [20..27] 的有效触发 Tick = [4, 8, 12]
```

有效触发点数为 `N=3`。总伤害 40 按原版整数分段后显示 `14、13、13`。

### 普通攻击

已核对的两个普通攻击动画实例：

| 角色数据链 | TKAct 有效触发 Tick | `N` | 飘字分段 |
|---|---|---:|---:|
| `WarPC#1[525]=64 → TKKon#64 → TKAct#64` | `[6]` | 1 | 1 段 |
| `WarPC#2[525]=67 → TKKon#67 → TKAct#67` | `[6, 8]` | 2 | 2 段 |

这正是“不同角色普通攻击显示次数不同”的原因：它们引用的 `TKAct` 条目触发 Tick 配置不同。

## 与攻击次数字段的区别

`skill_editor/skill_editor_v2.py` 中的 `TKSkill.atk_count`（字段偏移 `62`）语义是技能/攻击动作的次数描述，例如二连、三连。`WarPC` 中也存在用于角色战斗动作/技能数据的次数类字段。

但是，在本报告分析的 `sub_4434BC → sub_4400DC → sub_433F04` 飘字分段链中，决定 `N` 的直接数据是 `TKAct[20..27]` 的触发 Tick 数组。不能用 `atk_count` 替代这些 Tick，也不能因为 `atk_count=1` 就推断只显示一段伤害。

## MOD 配置建议

在 `act_editor_v2.py` 的“条目级参数”页中，应按以下方式理解字段：

| 字段 | MOD 开发者应如何理解 |
|---|---|
| `[18] 动画总时长` | 原版内部用 Tick 计数的总时间范围 |
| `[19] 当前播放时间（自动）` | 原版自动维护的播放进度；通常不要手工配置 |
| `[20]~[27] 第1~8次生效时间` | 动画中伤害或其他效果生效的时间，决定飘字分段数 |

若需要把一个总伤害显示为两段，必须让对应 `TKAct` 条目存在两个按原版规则有效的触发 Tick；若要显示三段，则需要三个有效触发 Tick。分段数不是通过把 `[18]` 改大、增加图层或修改 `atk_count` 来配置的。

本报告没有把 `TKKon.hp_damage` 的完整伤害计算、命中、抗性、状态效果和其他战斗修正简化为一个臆测公式。上面的“总伤害”指已经进入 `sub_4400DC` 分段步骤的值；本报告只还原其随后如何按 `TKAct` 触发点拆分并加入原版飘字队列。

## 依据文件

只使用了原版逆向工程代码和 `仓库根目录` v2 编辑器的资源解析字段映射：

- `反编译产物/decompile/4434BC.c`
  - `word_9D03A0 = 0`：播放初始化当前 Tick。
  - 遍历 `0..word_9D039E-1` 并匹配 `word_9D03A2[...]`：统计有效触发点。
  - `++word_9D03A0`：推进当前 Tick。
  - 在当前 Tick 匹配触发数组时推进效果事件。
- `反编译产物/disassembly/4400DC.asm`
  - `sub_4400DC` 的效果/伤害处理与多处 `sub_433F04` 调用。
  - `441CBE~441D48`：使用 `word_9D7046 - index` 拆分剩余总伤害，取商并加余数。
  - `441D0A/441D27`：把当前分段值传给 `sub_433F04`；`441D32/441D35`：扣除当前段并推进索引。
  - 对 `word_9D03A2` 的索引寻址，以及按效果事件顺序传递分段值。
- `反编译产物/decompile/433F04.c`
