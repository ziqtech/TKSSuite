# 16:9 宽屏补丁 640 坐标/步长遗留审计

> 审计日期: 2026-09-19  
> 对象: `tks_launcher_gui/patches/widescreen_16_9`  
> 依据: 原版 `TKS.exe`、`反编译产物/decompile`、`widescreen_16_9/patch.json`

## 一、审计目标

姓名输入页连续暴露出三类同源问题:

1. 页面直接画 856 后备表面, 却套了 640 步长 wrapper;
2. 精灵 RLE 仍按 640 平面编码, 直接按 856 行宽解码会横向拉丝;
3. 图片已按页面坐标 `+108`, hover/click 命中却仍使用 raw 鼠标 X。

本次按同样三类风险全量复查, 不再逐页面猜:

- 所有绘制原语调用是否在正确的 640/856 上下文中;
- 所有页面鼠标 X 消费点是否改读 `PAGE_X/PAGE_REC_X/MG_MOUSE`;
- 所有残留 640/1280/0x95b00 常量是否属于明确的 640 虚拟缓冲。

## 二、结论

当前未发现新的同类漏点。补丁现有处理是完整的, 但下列边界约定必须保持。

## 三、精灵绘制原语

### 3.1 不透明精灵 `sub_4544EC`

原版 exe 中共有 187 个直接 `call sub_4544EC` 位点:

- 107 个位点已由实体/战场/UI/小游戏处理器直接接管;
- 其余 80 个位点全部位于普通页面函数链或原语内部, 不属于直接 856 上下文:
  - `sub_42131C` / `sub_4240B8` / `sub_426164` 及其页面子函数由页面 wrapper 切到 640;
  - 姓名页 `sub_42539C` 的 5 个调用已全部接管;
  - `sub_454D90` / `sub_4553A4` 内部的调用只在原语内部走 opaque 分支, 不会绕过已接管的直接 856 调用点。

### 3.2 Alpha 精灵 `sub_454D24`

原版 exe 中共有 101 个直接调用位点。未接管的 51 个位点均属于:

- 普通页面的 `sub_42131C` / `sub_4240B8` / `sub_426164` 函数链;
- `sub_454D90` / `sub_4553A4` 的内部实现。

因此不存在“直接 856 UI 调 alpha 原语但未接管”的路径。

### 3.3 RLE 平面约定

通用处理器 `spr_handler` 固定按 `row = pos / 640`、`col = pos % 640`
解释原始 RLE 流, 再把最终像素写入当前 `g_stride` 目标。姓名页头像、
按钮 hover/按下帧现在都走这条路径。

## 四、鼠标 X 空间

将当前 `patch.json` 的静态替换全部应用到原版 `.text` 后, 再扫描:

- `[0x824278]` 剩余读点只出现在:
  - `_TForm1_FormMouseDown/Move/Up/DblClick/KeyDown/Wheel...` 事件入口;
  - `sub_406CE0` / `sub_4070E0` / `sub_40B710` / `sub_40C8E0`;
  - `sub_411D18` 软件光标;
  - `sub_436F60` / `sub_4388F4` / `sub_43CE30` / `sub_43CF78` 战斗/镜头逻辑。
- `[0x78E25E]` 已无读取残留, 只剩 `sub_411C1C` 的原始写入点。

结论: 页面 hover/click 已不再有 raw X 消费者。上述残留函数消费 raw X
是原设计语义, 包括窗口事件、光标、地图/战场逻辑。

姓名页 `sub_425E14` 已把 4 个 X 比较改为 `PAGE_X`, Y 仍保留 raw。

拾取读点 `0x10B77` 进一步改为 `pickup_read_sync`: 在读取 640 拾取缓冲前,
用当前 raw 鼠标坐标重算 `824280/824284`。否则 `sub_412390` 先于相机/缓冲
更新执行, 会在物件或出入口内出现新鼠标 X + 旧世界坐标的混合判定。

## 五、剩余 640 常量

扫描替换后代码中的 `0x280` / `0x4b000` / `0x95b00`:

- `0x280` 唯一与渲染缓冲相关的残留是 `sub_454944` 的 11 个位点;
- `0x95b00` 唯一残留同样在 `sub_454944`;
- 其余命中是普通结构偏移、机器码巧合或非渲染代码, 不影响后备表面步长。

`sub_454944` 写的是固定 `640x480` 拾取缓冲, 不是 856 后备表面。该缓冲
必须继续使用 640 行距; 补丁已在调用端通过 `pickup_shift` 把实体屏幕 X
减 108, 在消费端通过 `pickup_oob`/`PAGE_X` 对齐, 不能把函数内部 640
替换成动态步长。

## 六、背景与整帧平移

- 页面/GXP 背景由 `gxp_blt_fix` 统一补矩形并居中到 `[108,748)`;
- 小游戏背景由 `mg_blt_left` 左对齐并清右带;
- 地图/战场背景由 `map_bg_blt` 处理窄图居中与宽图视口钳制;
- 结算/奖励页由 `settle_shift` 在帧末整体平移 108, 不在帧内逐个元素
  混用坐标空间。

## 七、后续修改红线

1. 任何直接画 `dword_A2B998` 的页面函数, 不得重新加入 640 页面 wrapper。
2. 直接 856 上下文调用 `4544EC/454D24` 系原语时, 复杂 RLE 帧必须走通用
   JVG 处理器; 不能只改行距常量。
3. 页面元素 X 加 108 后, 同一交互链的 hover/click 读取必须同步改用
   `PAGE_X/PAGE_REC_X`。
4. `sub_454944` 内部的 640 常量属于固定拾取缓冲, 不支持直接动态化。
5. 新页面若新增 raw `[0x824278]` 命中判定, 必须按所在画布空间明确选择
   raw、`PAGE_X`、`PAGE_REC_X` 或 `MG_MOUSE`。
