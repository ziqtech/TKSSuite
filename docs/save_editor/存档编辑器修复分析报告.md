# Save Editor 修复分析报告

基于游戏逆向工程 (运行时转储) 和 sav.9 实际数据验证，修复了编辑器中的三个数据解读错误。

---

## 修复 1: SEG2 团队经济字段偏移量修正

### 问题

编辑器对智慧(0x04 WORD)、仁德(0x06 WORD)的偏移量和数据类型假设错误，导致显示值与游戏不符。

### 验证数据

sav.9 中 SEG2 原始 hex:
```
+0x00: 00 00 F4 01 00 00 32 32 50 00 19 00 00 00 8F 00
```

WarPC 队伍汇总 (从队伍成员的 WarPC 数据计算):
```
角色#0:   wis=50  ben=50  cou=50  med=25
角色#143: wis=0   ben=-5  cou=10  med=0
角色#144: wis=0   ben=-5  cou=10  med=0
角色#145: wis=0   ben=10  cou=10  med=0
─────────────────────────────────────
汇总:     wis=50  ben=50  cou=80  med=25
```

### 修复前后对比

| 字段 | 修复前偏移/类型 | 修复前值 | 修复后偏移/类型 | 修复后值 | 正确值 |
|------|---------------|---------|---------------|---------|--------|
| 金钱 | 0x02 WORD | 500 | 0x02 WORD | 500 | 500 ✓ |
| 智慧 | 0x04 WORD | 0 | **0x06 BYTE** | **50** | 50 ✓ |
| 仁德 | 0x06 WORD | 12850 | **0x07 BYTE** | **50** | 50 ✓ |
| 勇气 | 0x08 WORD | 80 | 0x08 WORD | 80 | 80 ✓ |
| 医术 | 0x0A WORD | 25 | 0x0A WORD | 25 | 25 ✓ |

### 反编译证据

反编译器将地址 0x756884 标记为 `word_756884`，0x756886 标记为 `word_756886`（data_item_size=2）。但物理存档 hex dump 证明实际情况是 BYTE 字段且偏移有 2 字节偏差。反编译器在解析 `[reg + offset]` 寻址模式时可能存在地址错误，物理数据优先。

### 代码修改

`SEG2_CORE_FIELDS` (save_editor.py:88-94):
```python
# 修复前
("wisdom",       0x04, 2, "智慧",  "H", ...),
("benevolence",  0x06, 2, "仁德",  "H", ...),

# 修复后
("wisdom",       0x06, 1, "智慧",  "B", ...),
("benevolence",  0x07, 1, "仁德",  "B", ...),
```

`_refresh_team` 和 `_apply_team` 现使用字段定义的 fmt 参数动态选择 struct 格式。

## 修复 2: WarPC role 字段的真实语义

### 问题

编辑器将 role=0 全部标记为"敌方"（红色），导致连主角（角色#0）都被显示为敌方。

### 验证数据

sav.9 当前队伍 (word_75688C): [0, 143, 144, 145]，全部 role=0。

主角(角色#0)的 role=0 但显然是队伍领导者，证明 role=0 ≠ 敌方。

### 反编译证据

**`sub_40DA00` (0x40DA00) — 入队/离队函数:**

```c
// L39-42: 角色入队
if (word_757F0E[527 * a1] == -1)    // 仅 role=-1 时执行额外初始化
    sub_410674(...);                 // 同伴初始化
sub_422A5C(&unk_82444C, 1, a1);     // 无论 role 值，更新团队汇总
word_75688C[v8] = a1;               // 无论 role 值，加入队伍数组
```

核心逻辑: **任何 role 值的角色都可以加入队伍**，role=-1 仅触发额外的初始化流程。

### 修复方案

角色身份改为三层判断，基于队伍数组 (word_75688C) 而不是 role 字段:

| 条件 | 显示 | 颜色 |
|------|------|------|
| 角色ID在队伍数组中 | "队伍" | 绿色 |
| role=-1 且不在队伍中 | "同伴" | 蓝色 |
| role=0 且不在队伍中 | "敌方" | 红色 |

过滤器也相应调整: "我方" = 队伍成员 + 同伴，"敌方" = 其余。

### 代码修改

`_refresh_warpc_list` (save_editor.py:1244-1295): 新增 `team_set` 从 SEG2 队伍数组构建，优先判断队伍成员身份。

## 修复 3: role 字段在 WarPC.dat 和存档中的差异

### 发现

warpc_editor 读取 WarPC.dat 时显示角色 143/144/145 的 role=-1，但存档中 role=0。

### 反编译证据

**全面搜索结论: WarPC role 字段 (byte offset 6, `word_757F0E`) 在整个游戏反编译代码中仅出现 3 次。**

#### 读取 (2 处)

| 函数 | 行号 | 代码 | 用途 |
|------|------|------|------|
| `sub_40DA00` | L39 | `if (word_757F0E[527*a1] == -1)` | 入队时判断是否需要同伴初始化 |
| `sub_417F84` | L81 | `sub_4175D8(..., word_757F0E[527*a3])` | 角色详情界面显示原始数值 |

#### 写入 (1 处)

| 函数 | 行号 | 代码 | 用途 |
|------|------|------|------|
| `sub_410674` | L40 | `a1[3] = 0` | 同伴初始化完成后将 role 置 0 |

(`a1` 是 `_WORD*` 指针指向 WarPC 角色记录，`a1[3]` = byte offset 6 = role 字段。)

#### 不在以下场景中使用

- ❌ 战斗敌我判定 — 使用队伍数组 `word_75688C` 确定我方
- ❌ AI 目标选择
- ❌ 菜单角色过滤
- ❌ 事件脚本 (`sub_40E65C` CheckTeam 检查 wisdom/benevolence/courage/medicine，不含 role)

### 完整数据流

```
WarPC.dat (源数据文件)         游戏运行时                  存档 (sav.N)
─────────────────────    ──────────────────          ────────────
role = -1                 sub_40DA00 检测到 -1       role = 0
(未初始化同伴模板)   ──→   调用 sub_410674        ──→  (已激活状态)
                          L40: a1[3] = 0
                          L41: 计算升级经验
                          L42: 初始化装备技能
```

### 结论: WORD[3] = current_exp，其中 -1 兼作"未初始化同伴"哨兵

该字段（WarPC byte offset 6 = WORD[3]）本质是 **current_exp（当前累计经验）**，同时以特殊值 **-1** 兼作"可招募同伴模板尚未初始化"的哨兵，而**非**通用的"我方/敌方"分类器：

- **WarPC.dat 中 =-1**: 标记该角色为"可招募同伴模板"，首次入队需执行 `sub_410674` 初始化
- **入队后 =0**: `sub_410674` L40 `a1[3]=0` 将其归零（current_exp 起始 0），同时脱离 -1 哨兵；`sub_40DA00` L39 检查 `==-1` 防止重复初始化
- **战斗中累计**: 战斗结算时剩余经验累加进 WORD[3]（`43B7FC.c:124` `*(v18-2) += v11`，作用于**战斗模板** `word_9D707A`），战后经 `sub_43BF20` 整块写回持久区 `word_757F08`；升级时 `43066C.c:35` `a1[3]=0` 复位
- **敌我判定不使用它**（本节修复 2 成立：敌我由队伍数组 `word_75688C` 判定）

> **跨文档更正**：早期把该字段仅称为"role/身份"并认为"入队后不再承担任何逻辑"并不准确——它对活跃队员持续承载 current_exp。`word_757F0E` 符号只被**直接引用** 3 次（本节所列），是因为战斗中的经验累加发生在战斗模板 `word_9D707A`（WORD[3] 的另一份拷贝）上，再由 `sub_43BF20` 整块写回，故不经 `word_757F0E` 符号直接出现。

### "同伴初始化"的具体内容

初始化由 `sub_410674` + `sub_42234C` + `sub_422BBC` 三个函数协作完成，共初始化以下内容:

#### 一、等级成长模拟 (`sub_410674` L14-33)

**作用:** 模拟角色从等级 1 升级到入队等级的过程，逐级增加基础属性。

```
循环 for level = 1 to (入队等级 - 1):
    根据等级段选择成长率除数:
      level < 21  → v3 = growth_early  (WarPC[264], byte offset 528)
      21 ≤ level < 41 → v3 = growth_mid  (WarPC[265], byte offset 530)
      level ≥ 41 → v3 = growth_late (WarPC[266], byte offset 532)
    
    逐级增加基础属性:
      hp_base  += hp_base / v3 + 1
      mp_base  += mp_base / v3 + 1
      atk_base += atk_base / v3 + 1
      def_base += def_base / v3 + 1
      hit_base += hit_base / v3 + 1
      eva_base += eva_base / v3 + 1
      spd_base += 1  (每级固定 +1, 不受成长率影响)

后处理:
  if hp_base > 9999: hp_base = 9999
  if mp_base > 9999: mp_base = 9999
```

**涉及 WarPC 字段:** hp_base(14), mp_base(18), atk_base(22), def_base(26), hit_base(30), eva_base(34), spd_base(38), growth_early(528), growth_mid(530), growth_late(532)

#### 二、等级与经验设置 (`sub_410674` L39-41)

```
level       = a2         (入队等级)
role        = 0          (标记已初始化)
exp_to_next = 8 × a2² + 92  (升级所需经验, 等级1=100, 等级10=892)
```

**涉及 WarPC 字段:** level(4), role(6), exp_to_next(8)

#### 三、基础属性同步到当前值 (`sub_42234C` L24-33)

将所有基础属性复制到当前属性，然后叠加上装备的加成。

```
atk_cur = atk_base, def_cur = def_base, hit_cur = hit_base, eva_cur = eva_base
spd_cur = spd_base, luk_cur = luk_base, mov_cur = mov_base, wis_cur = wis_base
hp_max  = hp_base,  mp_max  = mp_base
```

**涉及 WarPC 字段:** atk_cur(24), def_cur(28), hit_cur(32), eva_cur(36), spd_cur(40), luk_cur(44), mov_cur(48), wis_cur(52), hp_max(16), mp_max(20)

#### 四、技能/能力字段重置 (`sub_42234C` L34-55)

```c
atk_count      = 1        // 攻击次数
special_flag   = 0        // 特殊能力标志
mp_reduce      = 0        // 内力消耗减少%
magic_def      = 0        // 法伤减少%
exp_bonus      = 0        // 经验增加%
jp_bonus       = 0        // 技能点增加%
move_flags     = 0        // 移动特殊标志
heal_move      = 0        // 移动恢复HP%
mp_move        = 0        // 移动恢复MP%
reaction_group = 0        // 反应组
cause_mask1    = 0        // 攻击导致状态1-16
cause_mask2    = 0        // 攻击导致状态17-32
unknown[102..133] = 0     // 清空 32 字节中间区域
```

**涉及 WarPC 字段:** atk_count(64), special_flag(66), mp_reduce(68), magic_def(70), exp_bonus(72), jp_bonus(74), move_flags(76), heal_move(78), mp_move(80), reaction_group(82), cause_mask1(134), cause_mask2(136)

#### 五、装备属性应用 (`sub_42234C` L57-99)

遍历 4 个装备槽 (equip_idx0~equip_idx3, byte offset 138-145)，对每个装备:

```
当前属性 += TKItem 装备属性加成:
  atk_cur, def_cur, hit_cur, eva_cur, spd_cur, luk_cur, wis_cur, mov_cur
  hp_max, mp_max
  special_flag |= 装备特殊标志
```

如有装备技能 (`TKItem[21] != 0`): 调用 `sub_422BBC` 应用技能效果。

**涉及 WarPC 字段:** equip_idx0~3(138-145), equip_id0~3(146-153), 以及所有当前属性字段

#### 六、技能初始化 (`sub_42234C` L101-112 + `sub_422BBC`)

应用装备技能 (equip_skill0, equip_skill1) 和被动技能 (passive1, passive2):

**`sub_422BBC` 按技能类型分别处理:**

| 技能类型 | 效果 | 影响的 WarPC 字段 |
|---------|------|-------------------|
| type=1 被动加成 | 百分比增加当前属性、atk_count、mp_reduce、exp_bonus、jp_bonus、magic_def、状态效果 | atk_cur, def_cur, hit_cur, eva_cur, spd_cur, mov_cur, hp_max, mp_max, atk_count(64), mp_reduce(68), exp_bonus(72), jp_bonus(74), magic_def(70), 状态区间(102-133) |
| type=2 反应技能 | 设置 reaction_group(1-10) 和触发概率 | reaction_group(82), reaction_trigger(84) |
| type=3 移动技能 | 增加移动、移动标志、恢复效果 | mov_cur(48), move_flags(76), heal_move(78), mp_move(80) |

**涉及 WarPC 字段:** equip_skill0(164), equip_skill1(166), passive1(172), passive2(174), reaction_trigger(84)

#### 七、属性上限钳制 (`sub_42234C` L113-123)

```
if spd_base > 100: spd_base = 100       (sub_42234C L22)
if luk_base > 100: luk_base = 100
if luk_cur  > 100: luk_cur  = 100
if wis_base > 100: wis_base = 100
if wis_cur  > 100: wis_cur  = 100
```

#### 八、HP/MP 上限保护 (`sub_42234C` L125-132 + `sub_410674` L43-44)

```
if hp_max < cur_hp: cur_hp = hp_max     (sub_42234C)
if mp_max < cur_mp: cur_mp = mp_max     (sub_42234C)
cur_hp = hp_max                          (sub_410674 L43)
cur_mp = mp_max                          (sub_410674 L44)
```

### 初始化总结

初始化流程模拟了角色从 1 级自然成长到入队等级的完整过程: 逐级成长属性 → 设置等级经验 → 同步基础值 → 清零技能 → 套用装备加成 → 学习技能 → 钳制上限 → 满血满蓝。本质上,**这个函数充当了"角色生成器"的角色**——将 WarPC.dat 中的模板数据（仅有初始属性和装备配置）转化为一个立即可用的、完成所有等级成长的队伍成员。
