## 一、网格基础

### 尺寸与索引

```
32 × 32 网格
grid_index = Y * 32 + X    (X, Y ∈ [0, 31])
```

**证据**:
- WarWay.dat fread 1024 = 32×32 字节 (sub_42FE70:17)
- 所有网格数组使用 `Y*32+X` 索引 (sub_436114:67-70)
- 遍历用 `while (v2 < 32)` × `while (v3 < 32)` (sub_4355C4:56-60)

### 四套网格

| 数组 | 大小 | 数据来源 | 用途 |
|------|------|---------|------|
| `byte_951942` | 1024B | WarWay.dat[map_id×1024] | **地形网格**: -1=障碍, 0=通行, 1-5=特殊区域 |
| `byte_951D42` | 1024B | 初始化为-1, sub_431428填充 | **单位占用网格**: ≥0=被角色N占用, -1=空 |
| `byte_953154` | 1024B | sub_43D8B0 运行时计算 | **移动范围显示**: ≥0=可达, -1=不可达 |
| `byte_952D54` | 1024B | sub_43D53C 运行时计算 | **寻路路径网格**: -1=未评估, 0=起点, 1=路径 |

## 二、等距投影 (sub_42F9C8)

### 公式

```c
// sub_42F9C8: 网格坐标 → WSC背景图像像素坐标
*a1 -= 10;                                                    // grid_X -= 10
*a2 -= 15;                                                    // grid_Y -= 15
*a1 = dword_4E7DF0 + 56 * grid_X - 56 * grid_Y;              // 背景图像像素X
*a2 = dword_4E7DF4 + 28 * grid_X + 28 * grid_Y;              // 背景图像像素Y
```

展开后（含偏移量）:
```
pixel_X = 359 + 56 × (X - 10) - 56 × (Y - 15)
pixel_Y = 365 + 28 × (X - 10) + 28 × (Y - 15)
```

> **逆向核对（`42F9C8.c:13-17` 逐行一致）**：`*a1-=10; *a2-=15; pixel_Y=28*Y+dword_4E7DF4+28*X; pixel_X=dword_4E7DF0+56*X-56*Y`。等距半宽 56 / 半高 28、(10,15) 偏移均确认；展开常量 359/365 取决于 `dword_4E7DF0/4E7DF4` 运行时值。

**关键常量** (PE `.data` 段编译时常量，运行时无写入):

| 地址 | 名称 | 值 | 含义 |
|------|------|-----|------|
| `dword_4E7DF0` | origin X | **359** | 网格(10,15)在背景图上的像素X |
| `dword_4E7DF4` | origin Y | **365** | 网格(10,15)在背景图上的像素Y |
| `dword_4E7DF8` | offset X | **10** | sub_42F9C8中硬编码为立即数 |
| `dword_4E7DFC` | offset Y | **15** | sub_42F9C8中硬编码为立即数 |
| `dword_4E7E00` | tile full width | **112** | 完整菱形宽 (2×56) |
| `dword_4E7E04` | tile full height | **56** | 完整菱形高 (2×28) |

**证据**: 内存 dump `004E6000--005E6000.txt` 第486-487行:
```
4E7DF0: 67 01 00 00 6D 01 00 00  0A 00 00 00 0F 00 00 00
4E7E00: 70 00 00 00 38 00 00 00
```

**投影系数 56 和 28 为硬编码值，所有 WSC 分辨率通用。**

### 坐标系说明

sub_42F9C8 输出的是 **WSC 背景图像上的像素坐标**，不是屏幕坐标。游戏通过 DirectDraw 视口裁剪显示背景图的一部分:

```
屏幕坐标 = 背景图像像素坐标 - 视口原点 (dword_8242A8, dword_8242AC)
```

视口大小为 640×480 (`dword_4E7CC8` × `dword_4E7CCC`)，从较大的 WSC 背景图中裁剪显示。

### 反向投影 (sub_410848)

```c
// sub_410848: 背景图像像素坐标 → 网格坐标
t1 = (pixel_X - (359 - 112/2)) / 2;           // = (pixel_X - 303) / 2
t2 = pixel_Y - (365 - 56/2);                   // = pixel_Y - 337

sum  = (t2 + t1) / 56;                         // = (X - 10) + (Y - 15) 的近似
diff = (t2 - t1) / 56;                         // = (Y - 15) - (X - 10) 的近似

grid_X = sum  + dword_4E7DF8;                  // + 10
grid_Y = diff + dword_4E7DFC;                  // + 15
```

其中 `112 = dword_4E7E00`（完整 tile 宽度），`56 = dword_4E7E04`（完整 tile 高度）。

## 三、WSC.GRP 背景图层

### 加载

```c
// sub_436BD4:19 — 战场初始化
sub_451600("WSC.IDX", "WSC.GRP");  // 加载背景索引和图片数据
```

### 尺寸

WSC.GRP 包含 83 个背景图条目。WSC.IDX 每个 4 字节(uint32)存储 GRP 文件偏移量。

背景图尺寸（解压后）:
- 1280×960 (约 50 个条目)
- 800×600  (约 28 个条目)
- 1024×768 (约 4 个条目)

WarData.map_id 直接索引 WSC 条目。

### 像素尺寸读取 (sub_42FA50)

```c
// sub_42FA50 — 从 per-map 数据读取背景图像像素尺寸
sub_4B2208(&word_824290, 2, 1, a1);   // 背景宽度 (像素)
sub_4B2208(&word_824292, 2, 1, a1);   // 背景高度 (像素)
// 初始化视口
sub_452658(&dword_8242A8, 0, 0, 640, 480);  // 初始视口 = (0,0,640,480)
```

per-map 数据的文件偏移 = `dword_4FA37C[map_id]`，数据文件指针 = `off_4FA510`。

### 与网格的关系

WSC 背景是预渲染等距战场图。游戏运行时通过 sub_42F9C8 等距投影将网格渲染在背景之上，两者共享同一坐标系（WSC 背景图像像素坐标系）。

### 渲染管线

```
sub_43CA64 (主循环)
  ├─ BltFast: WSC背景 → 后缓冲 (按视口裁剪)
  └─ sub_43A050 (战场渲染)
       ├─ 遍历 32×32 网格
       ├─ sub_42F9C8: 网格→背景像素坐标
       ├─ 减去视口原点 → 屏幕坐标
       └─ 绘制地格/单位/特效
```

## 六、编辑器渲染逻辑

### 投影

编辑器使用与游戏 sub_42F9C8 完全相同的公式，直接映射到 WSC 背景图像像素坐标系:

```python
# 游戏常量: dword_4E7DF0=359, dword_4E7DF4=365, 偏移 10/15
# 这些是 PE .data 段编译时常量 (内存 0x4E7DF0-0x4E7E04)，运行时无写入，所有战场通用
GAME_ORIGIN_X = 359   # dword_4E7DF0
GAME_ORIGIN_Y = 365   # dword_4E7DF4
GRID_OFFSET_X = 10    # dword_4E7DF8 / sub_42F9C8 硬编码立即数
GRID_OFFSET_Y = 15    # dword_4E7DFC / sub_42F9C8 硬编码立即数

def _grid_to_screen(gx, gy):
    """网格坐标 → canvas坐标 (= 背景图像像素坐标 × zoom)"""
    sx = round((GAME_ORIGIN_X + 56 * (gx - GRID_OFFSET_X) - 56 * (gy - GRID_OFFSET_Y)) * zoom)
    sy = round((GAME_ORIGIN_Y + 28 * (gx - GRID_OFFSET_X) + 28 * (gy - GRID_OFFSET_Y)) * zoom)
    return sx, sy

def _scene_to_grid(canvas_x, canvas_y):
    """canvas坐标 → 网格坐标 (逆推 sub_42F9C8)"""
    px = canvas_x / zoom - GAME_ORIGIN_X
    py = canvas_y / zoom - GAME_ORIGIN_Y
    a = (px / 56 + py / 28) / 2   # = gx - GRID_OFFSET_X
    b = (py / 28 - px / 56) / 2   # = gy - GRID_OFFSET_Y
    return round(a + GRID_OFFSET_X), round(b + GRID_OFFSET_Y)
```

**关键**: WSC 背景图通过 PIL 缩放后绘制在 canvas (0,0)，网格坐标经 zoom 缩放后与背景图对齐，因为两者共享同一坐标系。

### 图层顺序

1. WSC 背景（底层，canvas(0,0) 起始，按 zoom 缩放）
2. WarWay 网格（菱形地格，按值着色 + 透明度）
3. 宝物标记（金色方块，trea_xy 坐标）
4. 单位标记（红色=敌军 enemy_xy，蓝色=友军 ally_xy）

### 透明度

通过 tkinter Canvas `stipple` 属性模拟:
- 0%: 无 stipple
- 25%: gray75
- 50%: gray50
- 75%: gray25
- 100%: 无填充(仅边线)

## 七、已知局限

**per-map 像素尺寸数据**:

sub_402BB8 从游戏数据段读取的 per-map 像素尺寸（`word_824290` × `word_824292`）存储在嵌入 TKS.exe 数据段的映射表中，无法从静态 WarData/WarWay 文件获取。编辑器无法获知每张 WSC 背景图的精确像素尺寸。

**影响**: 编辑器将 WSC 背景图绘制在 canvas(0,0)，网格使用游戏固定常量 (359,365,10,15) 投影。当 WSC 背景图的实际像素尺寸与预期不符时，网格与背景的对齐可能存在微小偏差。但由于投影常量是编译时固定的（不随 WSC 尺寸变化），对齐精度取决于 WSC 解码是否正确。
