> 基于 TKS.exe 反编译 (sub_4307CC, sub_431428, sub_436BD4, sub_431094, sub_444BB0, sub_40DA00)

## 一、核心结论

**WarData.dat 中的 enemy_id [34-69] 字段同时定义敌军和 NPC 友军。** 区分机制是通过运行时阵营比特分配 (sub_4307CC:278-298) 实现的。

## 三、阵营分配机制 (sub_4307CC:278-298)

运行时根据 enemy_id 给 word_9DF7C2 追加阵营比特：

```c
if ( word_4EB728 == 68 )             // 特殊战场 #68: 全部0x4000
    *v2 |= 0x4000u;
else
{
    v26 = *v5;  // enemy_id
    if ( v26 == 94 || v26 == 105 || v26 >= 97 && v26 <= 103 )
        *v2 |= 0x2000u;              // 阵营A
    else if ( v26 >= 35 && v26 <= 44 || v26 == 104 || v26 == 92 || v26 == 93 )
        *v2 |= 0x4000u;              // 阵营B
    else if ( v26 == 32 || v26 >= 34 && v26 <= 44 )
        *v2 |= 0x8000u;              // 特殊型
    // 不匹配 → 无阵营标记
}
```

**阵营比特语义：**

| 比特 | 值 | 含义 |
|------|-----|------|
| (无) | 0x0000 | 无阵营标记 — 玩家方可操控角色、NPC友军 |
| bit13 | 0x2000 | 阵营A — 敌方A势力 |
| bit14 | 0x4000 | 阵营B — 敌方B势力 |
| bit15 | 0x8000 | 特殊型 — 第三方/中立 |

**典韋 (enemy_id=5) 和黃蓋 (enemy_id=23) 不匹配任何条件 → 阵营标记=0 → 玩家方。**

> **已核对 `4307CC.c:278-298`**：三条阵营分配分支（0x2000/0x4000/0x8000）与 #68 特例逐条一致；enemy_id 5/23 均不落入任何范围 → 无阵营 bit → 玩家方，结论成立。（原文快照省略了 92/93 附带的 `word_756346 = 1`。）

### 三层排查汇总

| 排查维度 | 典韋(5) | 黃蓋(23) | 許褚(75) | 结论 |
|---------|--------|---------|---------|------|
| WarData enemy_flags | 0x0000 | 0x0000 | 0x0000 | 无法区分 |
| sub_4307CC:278-298 阵营分配 | 不匹配 | 不匹配 | 不匹配 | 无法区分 |
| WarPC 角色数据 | 同敌军结构 | 同敌军结构 | 敌军结构 | 无法区分 |

### 最终结论

**数据层面（WarData.dat + WarPC.dat + sub_4307CC 初始化代码）不存在 NPC 友军与敌军的区分标志。** 区分机制在数据层之上：

1. **游戏事件脚本**：可能在 TKS.exe 数据段或独立脚本中，针对特定战场+特定 enemy_id 定义阵营归属
2. **AI 行为系统**：enemy_group=0 的角色可能有独立的 AI 行为模式，在战斗中不攻击玩家方
3. **战斗初始化后的阵营调整**：sub_431094/sub_444BB0 可以在战斗中途动态修改角色阵营

TKS.exe 反编译代码已穷尽搜索字节级标志位，数据层的区分标志不存在。
