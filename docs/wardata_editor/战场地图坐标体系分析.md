## 一、坐标体系

### 网格定义

战场使用 **32×32 的 XY 坐标网格**：

```
grid_index = Y * 32 + X    (X, Y ∈ [0, 31])
```

**证据（三处独立来源交叉验证）：**

1. WarWay.dat 加载 1024 字节 (sub_42FE70:17)：
   ```c
   sub_4B2208(&unk_951942, 1024, 1, v1);  // fread 1024 = 32×32 字节
   ```

2. 所有网格访问使用 `×32` 行步长 (sub_436114:67-70)：
   ```c
   byte_951942[32 * v7 + 1 + v8]   // 右邻: Y*32 + X+1
   byte_951942[32 * v7 - 1 + v8]   // 左邻: Y*32 + X-1
   byte_951942[32 * v7 + 32 + v8]  // 下邻: (Y+1)*32 + X
   byte_951942[32 * v7 - 32 + v8]  // 上邻: (Y-1)*32 + X
   ```

3. 所有网格遍历用 `while (< 32)` 双重循环 (sub_4355C4:56-60)：
   ```c
   do {
       v2 = 0;
       do {
           // 处理 byte_951942[Y*32 + X]
           ++v2;
       } while ( v2 < 32 );    // X 轴 [0, 31]
       ++v3;
       v6 += 32;                // 行步长 = 32
   } while ( v3 < 32 );         // Y 轴 [0, 31]
   ```

### 网格存储

| 数组 | 大小 | 初值 | 数据来源 | 用途 |
|------|------|------|---------|------|
| `byte_951942` | 1024B | WarWay.dat | sub_42FE70 | **地形网格** |
| `byte_951D42` | 1024B | -1 (空) | sub_431428 初始化 | **单位占用网格** |
| `byte_953154` | 1024B | -1 | sub_43D8B0 | **移动范围显示** |
| `byte_952D54` | 1024B | -1 | sub_43D53C | **寻路/路径网格** |

### WarWay.dat 加载

```c
// sub_42FE70
v1 = fopen("WarWay.dat", "rb");
fseek(v1, word_9537F8 << 10, 0);    // word_9537F8 = map_id (WarData offset 32)

```

每条 WarWay 记录 = 1024 字节 = `map_id * 1024` 作为文件偏移。

> **已核对**：`42FE70.c:16-17` `fseek(word_9537F8<<10); fread(&unk_951942, 0x400)`（1024=32×32）与 `42FDF8.c:16-17` `fseek(498*a1); fread(&byte_9537D8, 0x1F2)`（WarData 498B）逐字节吻合；`byte_952D54`(攻击区,sub_43D53C)、`byte_953154`(效果区,sub_43D8B0) 亦与 TKKon 文档核对一致。

## 二、地形网格 (byte_951942) 值语义

基于 sub_4355C4 和 sub_431428 验证：

| 值 | 有符号 | 语义 | 渲染 | 来源 |
|----|--------|------|------|------|
| 255 | -1 (0xFF) | **永久障碍物** — 不可通行, 不触发特效 | WSC背景透出 (无wm.JVG) | WarWay.dat |
| 0 | 0 (0x00) | **普通可通行地面** — 默认值 | WSC背景透出 | WarWay.dat |
| 1-5 | 1-5 | **特殊区域** — 仅用于 PlaceReq 匹配, **不直接渲染** | WSC背景透出 | WarWay.dat |
| 254..253 | -2..-3 | **临时修改** — 战斗中动态变化, 逐步恢复 | wm.JVG Sprite 15+22 | 运行时修改 |

**注意**: 值 1-5 的渲染与值 0 相同——WSC 背景透出。它们的特殊性仅体现在 sub_431428 的 PlaceReq 系统：宝物和单位的实际放置位置通过匹配这些区域值来确定，而非直接使用 trea_xy/enemy_xy 坐标。

### 临时修改恢复机制 (sub_4355C4:38-60)

```c
for (Y = 0; Y < 32; Y++) {
    for (X = 0; X < 32; X++) {
        if (cell + 1 < 0) {       // cell < -1 (即 -2, -3, ...)
            if (cell >= -2)        // -2 → 重置为 0
                cell = 0;
            else                    // -3, -4, ... → +1 逐步恢复
                cell++;
        }
        // cell = -1 (0xFF) 时: -1+1=0, 条件 false → 永久障碍不变
        // cell >= 0 时: 条件 false → 普通地面不变
    }
}
```

## 四、可移动区域判断

### 移动检查条件 (sub_436114:67-70)

```c
// 检查相邻四方向 (右/左/下/上) 是否可通行:
byte_951942[Y*32 + X+1] >= 0 && (char)byte_951D42[Y*32 + X+1] < 0   // 地形可通行 && 无人占用
byte_951942[Y*32 + X-1] >= 0 && (char)byte_951D42[Y*32 + X-1] < 0   // 左
byte_951942[(Y+1)*32 + X] >= 0 && (char)byte_951D42[(Y+1)*32 + X] < 0 // 下
byte_951942[(Y-1)*32 + X] >= 0 && (char)byte_951D42[(Y-1)*32 + X] < 0 // 上
```

**移动条件 = (地形 ≥ 0) AND (无人占用)**。障碍物(-1)和特殊区域(1-5)均不可通行。

### 移动范围计算 (sub_43D8B0)

```c
// byte_953154 初始化为 -1 (全部不可达)
sub_4B00FC(byte_953154, -1, 1024);

// 起点标记为可达
byte_953154[Y*32+X] = 0;

// 基于移动点数 (v15/v16/v17) 做菱形扩散:
// 检查每个可达格的四方向邻格, 如果地形为 0 (普通地面) 则标记为可达
if (X < 32 && Y < 32 && byte_951942[Y*32+X] == 0)
    byte_953154[Y*32+X] = 0;
```

## 五、障碍区域判断

### 永久障碍

WarWay.dat 中值为 **-1 (0xFF)** 的格 → 不可通行、不可放置、循环更新跳过。

### 单位阻挡

即使地形可通行，如果 `byte_951D42[cell] >= 0`（有单位占据），也无法移动到该格。

### 特殊区域

值 1-5 的区域既不是障碍也不是通行地面, 在移动检查中被视为不可通行 (`byte_951942[cell] == 0` 条件不满足)。但它们是**放置区** — sub_431428 用它们来分配宝物和单位的实际位置。

## 六、宝物埋藏判断

### 宝物放置与 WarWay 区域的关系 (sub_431428:106-281)

```c
// 对每种区域类型 m (1-5):
for (m = 1; m <= 5; m++) {
    // 收集所有 WarWay 值为 m 的格 → 候选列表
    for (Y = 0; Y < 32; Y++)
        for (X = 0; X < 32; X++)
            if (byte_951942[Y*32+X] == m && byte_951D42[Y*32+X] == -1)
                candidates.add((X, Y));

    // 对每个 place_req (trea_xy / enemy_xy) 请求值为 -m 的条目:
    for each place_req slot:
        if (place_req_value == -m)  // 请求区域类型 m
            assign_random_candidate_from_list();
}
```

**宝物不直接埋在 trea_xy 坐标。** trea_xy 是"期望坐标"，实际放置位置由 WarWay 区域值匹配决定。流程是：

1. `trea_xy` 提供期望坐标
2. `trea_lv` (或 `place_req`) 的负值 (-1 到 -5) 指定需要的 WarWay 区域类型
3. 在对应的 WarWay 区域中随机选择一个空格放置宝物

### 等距投影与 wm.JVG 的关系

sub_42F9C8 中的硬编码值 56 和 28 是等距瓦片的数学尺寸:
- `56 = 2 × 28` → 菱形宽高比 2:1
- `word_9D6F6C` (wm.JVG Sprite 15 高度) 的实际像素值应当等于 28 或与之成比例

渲染时 `sub_4544EC(dword_951938, ..., word_9D6F6C + offset, ...)` 使用 wm.JVG sprite 15 的尺寸加上渲染偏移来确定地格精灵的显示大小，确保视觉上地格精灵与等距投影的数学格对齐。

### WSC.GRP + WarWay.dat + wm.JVG 三层模型

战场视觉由三层组成：

```
┌─────────────────────────────────────────┐
│ Layer 1: WSC.GRP (背景图)               │  ← 预渲染等距场景图
│   通过 WarData.map_id 选择对应背景        │     (草地/建筑/地形美术)
│   永久障碍格(WarWay=-1) → 背景图透出      │
├─────────────────────────────────────────┤
│ Layer 2: wm.JVG 地格叠加 (Sprite 15+N)  │  ← 功能性叠加层
│   WarWay≥0 → 不渲染背景覆盖(透出WSC)      │     (可通行格不遮挡背景)
│   WarWay<-1 → Sprite 15+22 障碍覆盖      │     (临时地形修改/特效)
├─────────────────────────────────────────┤
│ Layer 3: wm.JVG 交互高亮 (Sprite 15+N)  │  ← 移动/攻击范围显示
│   byte_952954 渲染网格驱动                │     (蓝色=路径, 绿色=可达)
│   单位精灵 (awt/awk/aa.jvg) 叠加          │     (角色/敌人/NPC精灵)
└─────────────────────────────────────────┘
```

**关键发现**: WarWay = -1 (永久障碍, 0xFF) 在 sub_43A050:161-169 中**不被渲染**——`v1 + 1 < 0` 对 -1 为 false，WSC 背景图直接从障碍格透出。仅 WarWay < -1（临时修改值）才渲染 wm.JVG Sprite 15+22。

### 双重渲染循环

sub_43A050 有两层渲染循环：

**第一层 (行107-142)**: `byte_952954` → 渲染移动/攻击范围高亮
**第二层 (行148-202)**: 遍历 `byte_951942`(WarWay) + `byte_951D42`(单位):
  - WarWay < -1 → Sprite 15+22 (临时障碍)
  - WarWay = -1 → **不渲染** (WSC背景透出)
  - 单位格 → 角色精灵

sub_43DE90:88-123 是 sub_43A050 第一层的镜像，在另一个游戏阶段（地形攻击选择）执行相同的渲染逻辑。

### 渲染调用

所有地形渲染均通过 `sub_4544EC` 调用 wm.JVG 精灵：

```c
sub_4544EC(
    dword_951938,          // wm.JVG 精灵集
    screen_X,              // 屏幕 X 坐标 (经 sub_42F9C8 网格→屏幕转换)
    screen_Y,              // 屏幕 Y 坐标
    sprite_height,         // 精灵尺寸 (基于 word_9D6F6C 的偏移值)
    render_context,        // 渲染上下文
    -1                     // 图层参数
);
```

### 网格坐标 → 屏幕坐标 (sub_42F9C8)

**等距/斜45度投影**。输入 grid_X, grid_Y，原地转换为 screen_X, screen_Y：

```c
// sub_42F9C8:
*a1 -= 10;                                        // grid_X -= 10
*a2 -= 15;                                        // grid_Y -= 15
*a1 = dword_4E7DF0 + 56 * grid_X - 56 * grid_Y;  // screen_X = base + 56(X-Y)
*a2 = dword_4E7DF4 + 28 * grid_X + 28 * grid_Y;  // screen_Y = base + 28(X+Y)
```

投影参数：瓦片宽 56px，瓦片高 28px（菱形等距瓦片）。`dword_4E7DF0/4` 为屏幕基准偏移。

### 屏幕坐标 → 网格坐标 (sub_410848)

鼠标点击/触摸屏幕 → 反向计算所在格：

```c
// sub_410848:
t1 = (screen_X - (base_X - cell_w/2)) / 2;       // 屏幕X → 中间值
t2 = screen_Y - (base_Y - cell_h/2);              // 屏幕Y → 中间值

YX_sum  = (t2 + t1) / cell_size;                  // X+Y = (t2+t1)/格大小
YX_diff = (t2 - t1) / cell_size;                  // Y-X = (t2-t1)/格大小

grid_X = YX_sum + offset_X;                        // 反算X
grid_Y = YX_diff + offset_Y;                       // 反算Y
```

其中 `dword_4E7E04` 为格大小（像素），`dword_4E7E00` 为格宽度。
