# 孝谈三国3终极版 `TKS.exe` 完整修改清单

> 分析对象：`MOD文档/第三方MOD\孝谈三国3终极版\TKS.exe`
>
> 对比基准：`游戏目录/TKS.exe`（原版 2002-11-28）
>
> 分析方法：PE 结构解析、节区映射、逐字节差分、x86 反汇编、Hex-Rays 导出函数对比、导入表与资源表对比。

## 0. 结论摘要

这个 `TKS.exe` 不是简单的数据补丁，而是一个**直接改写的静态二进制 MOD**。它包含：

- 新增 3 个 PE 节区：`.test`、`.Newdata`、`.Silvana`。
- `.text` 中确认有 **65 个改动区**，共修改 **517 个字节**。
- 从 `.text` 进入 `.test` 的 cave 入口共有 **30 个**。
- `.data` 中另有 **4 个改动区、26 个字节**。
- `.rsrc` 中修改主窗体 Caption：`Form1` → `FXTSG`。
- 新增导入 `WinExec` 和 `ShellExecuteA`。
- 主要内容是战斗公式、战后经验、物品掉落、属性/技能/存档处理、脚本判定和伴随程序检测。
- 该版本存在至少一处已确认的错误修改：防御状态被写成 `0x7530`，会误触发 `0x4000` 发光状态位。
- 原报告中“93 处代码修改”“34 个 IAT Hook”“43B954 是金钱地址”“432C3D 把 100 改成 -1”等表述不准确；本清单以重新扫描结果为准。

### 2.1 已确认的 cave 代码细节

#### 技能 222

`0xA7D2A8` 调用 `sub_452AC0(3)`，然后：

| 随机值 | 写入 `word[ebp-2]` | 对应 WarPC 索引 |
|---:|---:|---:|
| 0 | 58 | 94 |
| 1 | 59 | 95 |
| 2 | 60 | 96 |

原版逻辑固定为 58。

#### 技能 133

当技能索引为 `0x85`（133）时：

```asm
mov ax, word_758F9C   ; 角色 ID 4（典韦）的当前智力
add ax, 0x82          ; +130
mov word_9D6C30, ax   ; 覆盖伤害基础值
```

因此技能 133“鬼哭神嚎”的伤害公式被硬编码为：

```text
典韦当前智力 + 130
```

该公式读取固定角色 ID 4，不读取实际施法者。

#### `CheckItem` 等级门槛

`CheckItem` 的“数量 ≥ 比较”分支被改成：

```text
如果检查数量 == 3000：
    主角等级必须 > 20，否则直接返回 false
否则：
    按原版数量比较
```

它不检查物品 ID，也不检查调用者。因此任何脚本中合法的 `CheckItem(任意ID, 3000, 1)` 都会受到该门槛影响。

#### 寻路替换

`0x4353F8` 中的原 `sub_43D0E8` 调用被替换为 `0xA7D9FD`。新代码：

- 从 `0x4EBA37` 复制 9 字节到 `0x9D6D4A`。
- 设置 `word_9D6C88 = 2`。
- 使用 `byte_951D42` 的 32×32 地图格数据搜索路径。
- 使用 `0x952954`、`0x953554`、`0x953654` 等缓冲区保存路径/标记。
- 最多写入 0x80 个路径点。

旧报告中“4.5 KB cave 只是简单 hook”的描述不完整；这实际上包含一段独立的路径搜索/重建实现。

#### 防御状态错误

原版：

```asm
or word ptr [eax*2 + 0x9DF7C2], 0x1000
```

MOD：

```asm
mov word ptr [eax*2 + 0x9DF7C2], 0x7530
```

`0x7530` 包含 `0x4000` 位，而该位用于魔将发光效果。结果是：

- 任何角色执行“防御”都会亮起魔将发光效果。
- `mov` 会覆盖原有状态位。
- 正确写法应是 `or ..., 0x1000`。

## 4. 运行逻辑分类明细

### 4.1 战斗和解算

| 地址 | 修改内容 |
|---|---|
| `0x430C1F` | 随机分支由 `jae` 改为 `jl` |
| `0x430C28` | 原 `count/2` 改为 `count*2` |
| `0x430C36` | 取消原 `add cx, ax` |
| `0x430C41` | 时序值写回并累加，上限 9999 |

`.Newdata` 中的关键字符串：

`.Newdata` 开头还有一段 MOD 宣传文本，内容为“我是不想读书版的衍生版本……”等提示。

### 7.1 实际有效路径

1. `0x403587` 窗体关闭时调用 `ShellExecuteA`：

   ```text
   ShellExecuteA(0, "open", "closesystem.exe", 0, 0, 1)
   ```

2. `0x408027` 和 `0x430C41` 的执行路径会调用 `FindWindowExA` 检测 `YinShiXing2013`。
3. 检测结果后的消息框和 `ExitProcess` 分支是死代码：
   - `0xA7D4E7`
   - `0xA7D551`
   - `0xA7D593`
   - `0xA7D5DA`
4. 这些分支前的 `jmp` 是无条件跳转，检测结果不会阻止游戏运行。
5. 目标 MOD 目录中实际上没有 `system.exe`、`closesystem.exe` 或 `YinShiXing2013.exe`，但静态控制流表明缺失文件不会导致退出。

因此该版本包含伴随程序检测/启动的痕迹，但反篡改检查和退出保护基本被 MOD 自己禁用，实际游戏不依赖这些外部程序。

## 9. 风险和未完全确定项

### 9.1 已确认错误

1. **防御触发发光**
   - `0xA7D260` 将防御状态写成 `0x7530`。
   - 这是可见行为错误，正确值应为 `0x1000`，且应使用 `or` 而不是 `mov`。

2. **PE Checksum 未更新**
   - 代码和节区变化后仍保持原版 Checksum。

3. **等级门槛是全局魔法数字**
   - 所有 `CheckItem(任意ID, 3000, 1)` 都受影响，不是只影响特定剧情脚本。

4. **掉落上限修改过于粗暴**
   - 数量超过 99 时直接从 99 降到 1，而不是正常截断到 99。

### 9.2 高风险但仍需动态验证

- `0xA7D9FD` 的完整寻路算法。
- `0x4307CC` 中“损坏状态字整体清零”导致的长期状态副作用。
- `0x43292C` 中 HP/MP 百分比除数改为 `65535` 的精确战斗效果。
- `0x4458B0` 与 `0x447DAC` 中行动状态和显示状态的耦合。
- `0x4F99C1` 的重复注入代码是否有未知外部调用者。
