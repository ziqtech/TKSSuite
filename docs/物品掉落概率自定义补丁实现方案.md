# 物品掉落概率自定义补丁 — 字节补丁实现方案

## Context

在 TKS Launcher GUI 中增加可选补丁"物品掉落概率自定义"，通过 JSON 文件自定义三个死亡掉落概率。

### 只有一条掉落路径

游戏中有两条掉落结算路径，但**物品掉落概率自定义只需要关心路径 A**：

| | 路径 A（死亡掉落）| 路径 B（探寶技能）|
|---|---|---|
| **函数** | `sub_4400DC` @ `0x4419B7` | `sub_4458B0` @ `0x4474DC` |
| **是什么** | 怪物被玩家击杀时的自动掉落 | action 239 = 探寶技能的效果 |
| **触发** | 攻击动画中 HP≤0 时自动 | 玩家对目标使用探寶技能时 |
| **判定结构** | **独立判定**（三槽各自随机）| 级联互斥（一次随机定一槽）|
| **常规槽** | **100%**（无随机检查，非空必掉）| 80%（三槽全满时）|
| **普通槽** | 20% (`rand(1000) < 200`) | 15% (`50 ≤ v7 < 200`) |
| **稀有槽** | 5% (`rand(1000) < 50`) | 5% (`v7 < 50`) |
| **清零槽位** | 否 | 是 |
| **物品显示** | 否 | 是（`sub_434188`）|
| **可改概率？**| ✅ 这是补丁目标 | ❌ 探寶技能的技能平衡，不应改 |

### 为什么用字节补丁而不是 Cave Hook

路径 A 的原始代码结构已经是**独立判定**：

```
常规槽: 无随机检查 → 100% 掉落（改不了，无需改）
普通槽: cmp ax, 0xC8 (200) → 补丁为 cmp ax, 阈值*10 → 可配置
稀有槽: cmp ax, 0x32 (50)  → 补丁为 cmp ax, 阈值*10 → 可配置
```

修改两个 `cmp` 立即数即可实现自定义概率，不需要 cave hook。Cave hook 方案（当时误以为 action 239 是主要路径）已被废弃。

### 补丁能做什么

| 功能 | 支持 | 说明 |
|---|---|---|
| 自定义普通槽概率 | ✅ | 字节补丁 `0x41A2F` 处的 `cmp ax, 0xC8` |
| 自定义稀有槽概率 | ✅ | 字节补丁 `0x41AA2` 处的 `cmp ax, 0x32` |
| 自定义常规槽概率 | ❌ | 常规槽无随机检查点，降概率需插入指令（cave hook），未实现 |
| 级联模式 | ❌ | 原始已经是独立结构，不支持级联 |

> **常规槽 100% 是不可降的**：路径 A 的常规槽代码中没有任何 `push 1000 / call rand / cmp` 指令。如果需要常规槽 < 100%，把低概率物品放到普通槽或稀有槽即可。

## 字节补丁方案

### 补丁位置

> **逆向核对（`disassembly/4400DC.asm`）**：Path A 死亡掉落三槽逐条已验证——常规槽 `0x4419B7`(无随机)、普通槽 `0x441A19`+`441A2F: cmp ax, 0C8h`(200)、稀有槽 `0x441A8C`+`441AA2: cmp ax, 32h`(50)。本表补丁点 RVA `0x41A2F`/`0x41AA2`（VA 441A2F/441AA2）与之精确对应。

| 补丁点 | RVA | VA | 原字节 | 新字节 | 说明 |
|---|---|---|---|---|---|
| 普通槽阈值 | `0x41A2F` | `0x441A2F` | `66 3D C8 00` | `66 3D XX XX` | `cmp ax, 200` → `cmp ax, pct*10` |
| 稀有槽阈值 | `0x41AA2` | `0x441AA2` | `66 83 F8 32` | `66 3D XX XX` | `cmp ax, 50` → `cmp ax, pct*10` |

普通槽原指令是 4 字节的 imm16 形式 (`66 3D <imm16>`)，直接替换 imm16 即可。

稀有槽原指令是 4 字节的 imm8 形式 (`66 83 F8 <imm8>`)。替换为同长度的 imm16 形式 (`66 3D <imm16>`)，保持指令长度不变（4 字节），不影响后续代码对齐。

**概率计算**：`sub_452AC0(1000)` 返回 `[0, 999]`。掉落条件为 `rand(1000) < threshold`。对于百分值 `pct%`，`threshold = pct * 10`（如 50% → 500 → `0x1F4`）。对 100%，`threshold = 1000 = 0x3E8`——`rand(1000)` 始终 `< 1000`，故始终掉落。

### JSON 配置文件

`configs/drop_probability.json`：

```json
{
  "mode": "independent",
  "regular_pct": 100,
  "normal_pct": 100,
  "rare_pct": 100
}
```

| 字段 | 值域 | 说明 |
|---|---|---|
| `mode` | `"independent"` | 只支持 independent（路径 A 原始结构）。`"cascade"` 会降级 |
| `regular_pct` | 0~100 | **注意**：常规槽无随机检查，实际上总是 100%。此值仅记录期望 |
| `normal_pct` | 0~100 | 普通槽概率，补丁写入 `pct*10` 作为 imm16 |
| `rare_pct` | 0~100 | 稀有槽概率，补丁写入 `pct*10` 作为 imm16 |

## 代码实现

**文件**：`core/patch_engine.py` → `apply_drop_probability()`

**逻辑**：
1. 读取 `drop_probability.json`
2. 验证百分比值（0~100）
3. 计算普通槽和稀有槽的新 `cmp` 立即数（`pct * 10`）
4. 对两个 RVA 进行字节补丁（验证原字节 + 写入新字节 + 更新 code_buf）

**备用文件**：`core/drop_cave.py` — 保留完整的 cave hook 实现（独立 + 级联）以备将来需要插入常规槽随机检查时使用。当前未调用。

## 验证方法

1. **100% 全掉验证**：设 `{regular:100, normal:100, rare:100}` → 每个敌人掉落三件
2. **默认概率验证**：设 `{regular:100, normal:20, rare:5}` → 与原版路径 A 行为一致
3. **JSON 错误处理**：JSON 缺失/格式错误 → 补丁跳过，原版逻辑不受影响
