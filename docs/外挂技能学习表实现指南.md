# 外挂技能学习表 (External Skill Learn Table) 实现指南

## 文档目的

本文档为工程师提供**外挂技能学习表**方案的详细实现步骤与核心代码，指导从零开始开发、集成到现有 TKS 启动器补丁系统中。

**前置依赖**: 方案 B（TKSkill.dat 扩展 + TKSkill 缓冲区重定位）已实施完成。

> **实现现状（2026-10-03）**: 本文所述路径已并入 `tkskill_expand` 统一补丁，落地时采用
> 「逐指令钩子」而非本文示例的整段替换。关键约定：`sub_41E40C` / `sub_42234C` 里被钩的
> `lea` 只算记录基址，钩子必须同样**只返回基址**（技能 ID 由紧随的 `[基址+ID]` 寻址指令
> 累加）；返回「最终地址」会与紧随指令重复累加，使技能书/装备学习全部落到 `base+2×ID`。
> 语义约定见 `技能扩展与存档兼容设计方案.md` §5.2，缺陷与修复过程见
> `启动器补丁逆向核验进度.md` 第 10 批。

## 一、核心架构

### 1.1 系统总览

```
┌────────────────────────────────┐     ┌──────────────────────────────┐
│  WarPC 内存 (每条1054字节)      │     │  ExtSkillTable               │
│  [176..519] = skill_learn[344] │     │  VirtualAllocEx 独立分配       │
│  (索引 0~343, 保持不变)         │     │  布局: [MAX_CHAR][EXT_COUNT]  │
└─────────────┬──────────────────┘     └──────────────┬───────────────┘
              │                                       │
       ┌──────┴───────────────────────────────────────┴──────┐
       │          Cave Hook: skill_learn_accessor             │
       │   if (skill_idx < 344)                              │
       │       → return &warpc[char].byte[176 + skill_idx]   │
       │   else                                              │
       │       → return &ExtTable[char][(skill_idx - 344)]   │
       └─────────────────────────────────────────────────────┘
              │
       ┌──────┴──────────────────────────────┐
       │  边车存档 save/sav.X.ext            │
       │  游戏存档时同步写入 ExtTable 数据    │
       │  游戏读档时从 .ext 恢复             │
       └─────────────────────────────────────┘
```

### 1.2 关键常量

> **逆向核对**：本表常量均已验证——WARPC_BASE `0x757F08`、REC 1054、skill_learn 偏移 176(=WarPC[88] 字节)、`byte_757FB8`=0x757F08+0xB0(0xB0=176)、原始上限 344（`4189BC` 扫描 0-343，见 `tks_launcher/技能列表显示啊！问题分析.md`）。本外挂表方案在此已核实结构上扩展。

| 常量名 | 值 | 说明 |
|--------|------|------|
| WARPC_BASE | 0x757F08 (运行时可能重定位) | WarPC 数据基址 |
| WARPC_REC_SIZE | 1054 (字节) | 每条 WarPC 记录大小 |
| SKILL_LEARN_OFFSET | 176 (字节) | skill_learn 数组在记录内的偏移 |
| ORIG_SKILL_BOUND | 344 | 原始技能学习上限 |
| byte_757FB8 | 0x757F08 + 0xB0 = 0x757FB8 | skill_learn[0] 全局地址 |
| word_9D707A | 战斗 WarPC 副本基址 | 战斗中的独立 WarPC 拷贝 |
| word_7861CA | 0x7861CA | TKSkill.dat 数据基址 (运行时可能重定位) |

### 1.3 ExtSkillTable 内存布局

```c
// 配置参数
#define MAX_CHARS    200    // 最大角色数 (与 WarPC 扩展兼容)
#define EXT_SKILLS   56     // 扩展技能数 (技能索引 344~399)

// 总大小: 200 × 56 = 11,200 字节
// 映射: ExtTable[char_idx * EXT_SKILLS + (skill_idx - 344)]
uint8_t ExtSkillTable[MAX_CHARS * EXT_SKILLS];
```

每个字节语义与原始 skill_learn 完全一致:
- 0 = 不会
- 1~9 = 等待学 (JP 积累中)
- 10 = 可以学 (JP 足够)
- 20 = 已学会(指令技能组)
- 30 = 已学会(子技能)
- 40 = 已消耗(被卸装)

## 二、需 Hook 的目标函数完整分析

### 2.1 sub_41E40C — 物品使用学习技能

**函数地址**: 0x41E40C  
**调用链**: sub_41EFA8 → sub_41E40C  
**功能**: 角色使用物品时，检查 TKItem.use_learn1/use_learn2 字段对应的技能状态并写入

**核心代码** (行99~122):
```c
// v15 = &word_77CBCA[32 * item_idx]  (TKItem 记录指针)
// a2 = 角色索引 (WarPC 索引)
// v15[23] = TKItem.use_learn1 (技能索引)
// v15[24] = TKItem.use_learn2 (技能索引)

// === use_learn1 路径 ===
if ( v15[23] )
{
    if ( v15[23] >= 0 || a2 || byte_757FB8[v15[23]] < 1 || byte_757FB8[v15[23]] >= 20 )
    {
        // 正常路径: 正数技能索引
        if ( v15[23] > 0
             && byte_757FB8[1054 * a2 + v15[23]] >= 1   // ← Hook点A: 读取
             && byte_757FB8[1054 * a2 + v15[23]] < 20 ) // ← Hook点A: 读取
            byte_757FB8[1054 * a2 + v15[23]] = 10;      // ← Hook点A: 写入
    }
    else
    {
        // 特殊路径: 负数索引 + 主角专用 (不需要 hook)
        byte_757FB8[v15[23]] = 10;
    }
}
// === use_learn2 路径 (结构完全相同) ===
if ( v15[24] )
{
    // ... 同上逻辑，使用 v15[24] ...
    if ( v15[24] > 0
         && byte_757FB8[1054 * a2 + v15[24]] >= 1   // ← Hook点B: 读取
         && byte_757FB8[1054 * a2 + v15[24]] < 20 ) // ← Hook点B: 读取
        byte_757FB8[1054 * a2 + v15[24]] = 10;      // ← Hook点B: 写入
}
```

**内存访问模式**: `byte_757FB8[1054 * char_idx + skill_idx]`  
**Hook 策略**: 需拦截 2 个相同结构的分支（use_learn1 和 use_learn2），当 skill_idx >= 344 时重定向到 ExtTable

### 2.2 sub_42234C — 装备初始化 / equip_learn

**函数地址**: 0x42234C  
**调用链**: sub_410674, sub_411E84, sub_422768, sub_43066C, sub_4458B0 → sub_42234C  
**功能**: 装备物品时，检查 TKItem.equip_learn 字段并更新技能状态

**核心代码** (行76~93):
```c
// v9 = &word_77CBCA[32 * item_idx]  (TKItem 记录指针)
// a2 = WarPC 记录指针 (非索引!)
// v9[22] = TKItem.equip_learn (技能索引)

if ( v9[22] )  // 装备物品有 equip_learn 字段
{
    // 地址计算: (BYTE*)a2 + v9[22] + 176 = &a2->skill_learn[v9[22]]
    if ( *((_BYTE *)a2 + v9[22] + 176) == 40 )           // ← Hook点: 读取
    {
        // 状态=40(已消耗): 重新设为 20 或 30
        if ( word_786224[47 * v9[22]] == -1 )
            *((_BYTE *)a2 + v9[22] + 176) = 30;          // ← Hook点: 写入
        else if ( !word_786224[47 * v9[22]] )
            *((_BYTE *)a2 + v9[22] + 176) = 20;          // ← Hook点: 写入
    }
    else if ( *((char *)a2 + v9[22] + 176) >= 1          // ← Hook点: 读取
           && *((char *)a2 + v9[22] + 176) < 20 )        // ← Hook点: 读取
    {
        *((_BYTE *)a2 + v9[22] + 176) = 10;              // ← Hook点: 写入
    }
}
```

**内存访问模式**: `*((_BYTE *)a2 + skill_idx + 176)` — 通过记录指针 + 相对偏移  
**特殊性**: 使用记录指针而非全局数组 + 绝对偏移，hook 时需要先计算出角色索引

### 2.3 sub_41E248 — JP 确认学习 (设 state=20)

**函数地址**: 0x41E248  
**调用链**: sub_41EFA8 → sub_41E248  
**功能**: 玩家在 JP 学习界面确认学习某技能，设置 state=20，扣除 JP，传播子技能进度

**核心代码** (行17~30):
```c
// a2 = 角色索引, a3 = 技能索引

// 1. 设置目标技能状态为 20 (已学会)
*((_BYTE *)&unk_757FB8 + 1054 * a2 + a3) = 20;         // ← Hook点1: 写入

// 2. 扣除 JP
word_757F46[527 * a2] -= word_7861D0[47 * a3] * (250 - word_757F3C[527 * a2]) / 200;

// 3. 遍历技能树传播子技能进度
v7 = 0;
v4 = (__int16 *)(94 * a3 + 7889362);  // TKSkill 记录内的子技能列表
do
{
    // 读取子技能学习状态
    if ( *((char *)&word_757F08[527 * a2 + 88] + *v4) >= 1     // ← Hook点2: 读取
      && *((char *)&word_757F08[527 * a2 + 88] + *v4) < 10 )   // ← Hook点2: 读取
        *((_BYTE *)&word_757F08[527 * a2 + 88] + *v4) += *((_BYTE *)v4 + 2);  // ← Hook点2: 写入

    // 检查子技能是否已达20级 → 父技能设为30
    if ( v4[1] == 20 )
        *((_BYTE *)&word_757F08[527 * a2 + 88] + a3) = 30;     // ← Hook点3: 写入

    ++v7;
    v4 += 2;
}
while ( v7 < 8 );
```

**内存访问模式**: `*((_BYTE *)&word_757F08[527 * a2 + 88] + skill_idx)` = `byte_757FB8[1054 * a2 + skill_idx]`  
**关键**: 此函数同时读写目标技能 (a3) 和子技能 (*v4) 的状态

### 2.4 sub_422EF4 — 装备/卸装技能状态变更

**函数地址**: 0x422EF4  
**调用链**: sub_40CE30, sub_41F844, sub_420844 → sub_422EF4  
**功能**: 更换装备武器时，更新武器关联技能的学习状态

**核心代码** (行83~151):
```c
// a2 = 角色索引, a3 = 原装备物品索引, a4 = 新装备物品索引
// v10 = word_77CBF6[32 * a3] = 原装备关联技能索引

LOWORD(v4) = word_77CBF6[32 * a3];
v10 = v4;
if ( (_WORD)v4 )  // 武器有关联技能
{
    // 分支1: 学会 → 消耗 (state 20→40)
    if ( byte_757FB8[1054 * a2 + (__int16)v4] == 20 )           // ← Hook点: 读取
    {
        byte_757FB8[1054 * a2 + (__int16)v4] = 40;              // ← Hook点: 写入
        // 清除装备技能栏引用...
    }
    // 分支2: 子技能学会 → 消耗 (state 30→40)
    else if ( byte_757FB8[1054 * a2 + (__int16)v4] == 30 )      // ← Hook点: 读取
    {
        byte_757FB8[1054 * a2 + (__int16)v4] = 40;              // ← Hook点: 写入
        // 遍历子技能检查是否还有其他 state=30 的...
        v9 = word_7861D2[47 * (__int16)v4];   // 技能组首技能索引
        v7 = v9 + 1;
        for ( i = (char *)&word_757F08[527 * a2 + 88] + (__int16)(v9 + 1); ; ++i )
        {
            v4 = word_786224[47 * v9] + v9;   // 技能组末技能索引
            if ( v4 < v7 ) break;
            if ( *i == 30 ) ++v8;             // ← Hook点: 读取子技能状态
            ++v7;
        }
        // 如果没有其他 30 的子技能, 清除装备技能栏引用
    }
    // 分支3: 可学 → 等待 (state 10~19→1)
    else
    {
        if ( byte_757FB8[1054 * a2 + v10] >= 10 )              // ← Hook点: 读取
        {
            v4 = byte_757FB8[1054 * a2 + v10];                 // ← Hook点: 读取
            if ( v4 < 20 )
            {
                byte_757FB8[1054 * a2 + v10] = 1;              // ← Hook点: 写入
            }
        }
    }
}
```

**内存访问模式**: `byte_757FB8[1054 * char_idx + skill_idx]`  
**复杂度**: 3 个分支 + 子技能迭代器，共约 6 个读写点

## 三、实现步骤

### 步骤 1: ExtSkillTable 内存分配

**位置**: `tks_launcher_gui/core/warpc_expander.py` 或新模块 `ext_skill_table.py`

```python
"""ext_skill_table.py — 外挂技能学习表内存管理"""
import ctypes
from .memory import (
    _OpenProcess, _CloseHandle, _VirtualAllocEx,
    write_pm, read_pm,
    PROCESS_VM_READ, PROCESS_VM_WRITE, PROCESS_VM_OPERATION,
    MEM_COMMIT, MEM_RESERVE, PAGE_READWRITE,
)

# 配置常量
MAX_CHARS = 200
EXT_SKILLS = 56            # 技能索引 344~399 (可配置)
EXT_TABLE_SIZE = MAX_CHARS * EXT_SKILLS  # 11,200 字节

def allocate_ext_skill_table(child_pid: int, log_func=None) -> int:
    """在游戏进程内分配 ExtSkillTable 并初始化为零
    
    Returns: 分配的内存地址 (0 = 失败)
    """
    log = log_func or (lambda x: None)
    access = PROCESS_VM_READ | PROCESS_VM_WRITE | PROCESS_VM_OPERATION
    hp = _OpenProcess(access, False, child_pid)
    if not hp:
        log("  [ERROR] allocate_ext_skill_table: OpenProcess 失败")
        return 0
    
    ptr = _VirtualAllocEx(hp, None, EXT_TABLE_SIZE,
                          MEM_COMMIT | MEM_RESERVE, PAGE_READWRITE)
    if not ptr:
        log("  [ERROR] allocate_ext_skill_table: VirtualAllocEx 失败")
        _CloseHandle(hp)
        return 0
    
    addr = ctypes.cast(ptr, ctypes.c_void_p).value or 0
    
    # 初始化为全零 (state=0 = 不会)
    zero_buf = bytes(EXT_TABLE_SIZE)
    write_pm(hp, addr, zero_buf)
    
    _CloseHandle(hp)
    log(f"  ExtSkillTable 分配成功: 0x{addr:08X} ({EXT_TABLE_SIZE} 字节)")
    return addr
```

### 步骤 2: 分配 Cave 扩展区域

现有 cave 区域 (1024B) 空间不足以容纳所有 hook 代码。需要额外分配独立的扩展 cave。

```python
# 扩展 Cave 区域大小: 至少 1024 字节 (accessor子程序 + 各hook适配代码)
EXT_CAVE_SIZE = 1024

def allocate_ext_cave(child_pid: int, log_func=None) -> int:

    _CloseHandle(hp)
    log(f"  ExtCave 分配成功: 0x{addr:08X} ({EXT_CAVE_SIZE} 字节)")
```

### 步骤 3: 核心 Accessor 子程序 (x86 机器码)

所有 hook 点共享的通用子程序，根据技能索引返回目标字节的指针。

```
; ═══════════════════════════════════════════════════════
; skill_learn_get_ptr — 通用地址解析子程序
; ═══════════════════════════════════════════════════════
; 调用约定: 使用栈传参 (由各 hook 适配层 push)
;   [esp+4] = char_idx (角色索引, 无符号 16位扩展到 32位)
;   [esp+8] = skill_idx (技能索引, 无符号 16位扩展到 32位)
; 返回:
;   EAX = 指向目标字节的指针
; 保证:
;   不修改 ECX, EDX, EBX, ESI, EDI (由 pushad/popad 在外层保证)
; ═══════════════════════════════════════════════════════

skill_learn_get_ptr:
    push ebp
    mov  ebp, esp
    push ecx
    push edx
    
    mov  eax, [ebp+12]        ; eax = skill_idx
    mov  ecx, [ebp+8]         ; ecx = char_idx
    
    cmp  eax, 344
    jb   .original             ; idx < 344 → 原始 WarPC 路径
    
    ; === 扩展路径 ===
    sub  eax, 344              ; offset = skill_idx - 344
    imul ecx, ecx, EXT_SKILLS ; char_offset = char_idx * EXT_SKILLS (imm32)
    add  eax, ecx             ; total_offset = char_offset + (idx-344)
    add  eax, EXT_TABLE_ADDR  ; eax = &ExtTable[char][idx-344] (imm32 地址)
    jmp  .done
    
.original:
    ; === 原始路径 ===
    imul ecx, ecx, 1054       ; char_byte_offset = char_idx * 1054
    add  eax, ecx             ; + skill_idx
    add  eax, 176             ; + SKILL_LEARN_OFFSET
    add  eax, WARPC_BASE      ; + WarPC基址 (imm32, 运行时填入实际值)
    
.done:
    pop  edx
    pop  ecx
    pop  ebp
    ret  8                     ; 清除 2 个参数 (stdcall 风格)
```

**Python 构建代码**:
```python
import struct

def build_accessor_code(warpc_base: int, ext_table_addr: int,
                        ext_skills: int = EXT_SKILLS) -> bytes:
    """构建 skill_learn_get_ptr 子程序的机器码"""
    code = bytearray()
    
    # push ebp; mov ebp, esp; push ecx; push edx
    code += bytes([0x55, 0x8B, 0xEC, 0x51, 0x52])
    
    # mov eax, [ebp+12]; mov ecx, [ebp+8]
    code += bytes([0x8B, 0x45, 0x0C])       # mov eax, [ebp+12] (skill_idx)
    code += bytes([0x8B, 0x4D, 0x08])       # mov ecx, [ebp+8]  (char_idx)
    
    # cmp eax, 344; jb .original
    code += bytes([0x3D])
    code += struct.pack('<I', 344)           # cmp eax, 344
    # jb 距离在后面计算
    jb_pos = len(code)
    code += bytes([0x72, 0x00])             # jb .original (rel8 待填)
    
    # --- 扩展路径 ---
    ext_start = len(code)
    # sub eax, 344
    code += bytes([0x2D])
    code += struct.pack('<I', 344)
    # imul ecx, ecx, EXT_SKILLS
    code += bytes([0x69, 0xC9])
    code += struct.pack('<I', ext_skills)
    # add eax, ecx
    code += bytes([0x01, 0xC8])
    # add eax, EXT_TABLE_ADDR
    code += bytes([0x05])
    code += struct.pack('<I', ext_table_addr)
    # jmp .done
    jmp_done_pos = len(code)
    code += bytes([0xEB, 0x00])             # jmp .done (rel8 待填)
    
    # --- 原始路径 ---
    orig_start = len(code)
    # 回填 jb 偏移
    code[jb_pos + 1] = orig_start - (jb_pos + 2)
    
    # imul ecx, ecx, 1054
    code += bytes([0x69, 0xC9])
    code += struct.pack('<I', 1054)
    # add eax, ecx
    code += bytes([0x01, 0xC8])
    # add eax, 176
    code += bytes([0x05])
    code += struct.pack('<I', 176)
    # add eax, WARPC_BASE
    code += bytes([0x05])
    code += struct.pack('<I', warpc_base)
    
    # --- .done ---
    done_pos = len(code)
    # 回填 jmp .done 偏移
    code[jmp_done_pos + 1] = done_pos - (jmp_done_pos + 2)
    
    # pop edx; pop ecx; pop ebp; ret 8
    code += bytes([0x5A, 0x59, 0x5D, 0xC2, 0x08, 0x00])
    
    return bytes(code)
```

**预计大小**: ~55 字节

### 步骤 4: Hook 适配层 — sub_41E40C (物品学习)

**Hook 目标**: 拦截 `byte_757FB8[1054 * a2 + v15[23]]` 的读取和写入

**定位方法**: 搜索模式 (在 sub_41E40C 函数范围内):
```
; 正常路径读取: cmp byte ptr [...], 1
; 机器码特征: 80 3C XX 01 (或变体)
; 完整上下文: if(v15[23] > 0 && byte_757FB8[...] >= 1 && ... < 20)
```

**Hook 策略**: 替换整段比较+赋值逻辑为 call cave:

```
; sub_41E40C hook cave (use_learn1 路径)
; 入口条件: v15[23] > 0 已通过原始分支确认
; 需要的寄存器上下文:
;   通过 [ebp-4] 或栈变量获取 v15[23] (skill_idx)
;   a2 在 [ebp+0Ch] (函数参数, __cdecl)

hook_41E40C_learn1:
    pushad
    
    ; 读取 a2 (char_idx) — 函数参数 [ebp+0Ch]
    movsx ecx, word ptr [ebp+0Ch]
    
    ; 读取 v15[23] (skill_idx) — v15 = [ebp-4], v15[23] = v15 + 46
    mov   eax, [ebp-4]
    movsx eax, word ptr [eax+46]
    
    ; 调用 accessor
    push  eax              ; skill_idx
    push  ecx              ; char_idx
    call  skill_learn_get_ptr
    ; EAX = 指针
    
    ; 读取当前状态
    movzx edx, byte ptr [eax]
    
    ; 检查: state >= 1 && state < 20
    cmp   dl, 1
    jb    .skip
    cmp   dl, 20
    jge   .skip
    
    ; 写入: state = 10
    mov   byte ptr [eax], 10
    
.skip:
    popad
    ; 跳转到原始代码的 "跳过写入后" 位置
    ; (需要根据实际编译确定 jmp 目标)
    ret
```

**实际 Hook 安装**: 需要在 sub_41E40C 函数中找到精确的机器码位置，替换为 `E8 rel32` (call) + NOP 填充。由于原始代码的比较+写入可能跨多条指令（约 15~20 字节），有足够空间安装 5 字节 call。

### 步骤 7: Hook 适配层 — sub_4189BC (JP 学习界面) ★最复杂

**问题**: 此函数使用**指针递增**遍历连续内存，无法简单地在单点 hook 中处理。

**推荐方案 (替代简化方案)**: 不 hook 循环内部，而是:

1. **修改扫描上限**: 将 `v12 < 350` 的立即数改为新上限（如 400）
2. **在循环启动前**安装 hook: 当 v12 即将超过 344 时，切换 v8 基址到 ExtTable

**方案 A (推荐 — 最小侵入)**:

在进入 `while` 循环之前，hook v8 的初始化点:
```c
v8 = (char *)&word_757F08[527 * a2 + 88] + v12;   // 原始
```

当 v12 >= 344 时，计算 v8 应指向 ExtTable:
```c
if (v12 >= 344)
    v8 = &ExtTable[a2 * EXT_SKILLS + (v12 - 344)];
else
    v8 = &warpc[a2].skill_learn[v12];
```

**方案 B (更彻底 — 替换整个函数)**:

在游戏进程中分配一个完整的替代函数（约 200 字节 x86 代码），该函数实现与 sub_4189BC 完全相同的逻辑，但在技能索引 >= 344 时从 ExtTable 读取。然后将 sub_4189BC 入口改为 jmp 到替代函数。

**方案 A 实现细节**:

```
; 修改点1: 扫描上限 350 → 400
; 在 sub_4189BC 中搜索: cmp [v12], 350 (imm16: 5E 01)
; 替换为: cmp [v12], 400 (imm16: 90 01)

; 修改点2: 在 v8 递增处 (++v8) hook
; 当 v12 == 344 时需要重设 v8 基址
; hook 代码:
hook_4189BC_iter:
    ; 原始: inc v8 (v8 是栈变量或寄存器)
    ; 替换为:
    inc   [ebp-10h]              ; v8++ (原指令)
    push  eax
    movsx eax, word ptr [ebp-4] ; v12
    cmp   eax, 344
    jne   .no_switch
    ; v12 刚到达 344: 切换 v8 到 ExtTable
    mov   eax, [ebp+0Ch]        ; a2 (char_idx)
    imul  eax, eax, EXT_SKILLS
    add   eax, EXT_TABLE_ADDR
    mov   [ebp-10h], eax        ; v8 = &ExtTable[char][0]
.no_switch:
    pop   eax
    ret
```

**实际编码注意**: 需要通过反汇编确认 v8 和 v12 在栈帧中的精确偏移。从反编译可知:
- v8 = `[esp+18h]` = `[ebp-10h]`
- v12 = `[esp+24h]` = `[ebp-4h]`

### 步骤 8: 战斗系统处理

**核心问题**: 战斗开始时 sub_444FD4 执行 `qmemcpy((void*)(1054*v12+10317946), (const void*)(1054*v11+7700232), 0x41E)` 将 WarPC 记录复制到战斗区域 word_9D707A。ExtTable 数据不在 WarPC 记录内，不会被自动复制。

**解决方案**: 战斗中的 hook (sub_447BA8, sub_438F28) 直接从 ExtTable 读取，不依赖战斗副本。

**理由**: 战斗期间不会学习新技能（skill_learn 状态不会改变），所以 ExtTable 中的数据在整场战斗中是只读的，直接读取安全可靠。

**实现**:
```
; sub_447BA8 / sub_438F28 hook
; 原始: i[1054 * word_9D6F58 + 176] >= 20
; 替换为:

hook_battle_skill_check:
    pushad
    movsx ecx, word ptr [0x9D6F58]   ; char_idx (战斗内索引)
    movsx eax, word ptr [ebp-??]     ; v6/v7 (当前技能索引)
    
    cmp   eax, 344
    jb    .use_battle_copy

    push  eax
    push  ecx
    call  skill_learn_get_ptr
    movzx eax, byte ptr [eax]
    jmp   .compare
    
.use_battle_copy:
    ; 原始路径: 从战斗副本读取

    cmp   al, 20
    ; 设置标志位供后续 jge/jl 判断

```

**注意**: sub_447BA8 的技能范围是 `4*a1+181` 到 `4*a1+185`（最多4个连续索引），sub_438F28 的范围由 `word_786224[47*a1]` 决定。如果扩展技能的子技能索引 >= 344，这些 hook 才会被触发。

### 步骤 9: 边车存档文件 (Sidecar File)

**文件路径**: `save/sav.X.ext` (对应 `save/sav.X`)

**文件格式**:
```
偏移   大小    字段              说明
────────────────────────────────────────────
0      4B     magic             魔数 "TKSE" (0x45534B54)
4      2B     version           版本号 = 1
6      2B     char_count        角色数
8      2B     ext_skill_count   每角色扩展技能数
10     2B     reserved          保留字段 = 0
12     N×M B  data              扩展技能学习状态数组
                                N = char_count, M = ext_skill_count
```

**Python 实现**:
```python
import struct
import os

EXT_SAVE_MAGIC = b'TKSE'
EXT_SAVE_VERSION = 1

def save_ext_skill_data(save_slot: int, child_pid: int,
                        ext_table_addr: int, log_func=None):
    """从游戏进程读取 ExtTable 并写入边车文件"""
    log = log_func or (lambda x: None)
    
    access = PROCESS_VM_READ | PROCESS_VM_WRITE | PROCESS_VM_OPERATION
    hp = _OpenProcess(access, False, child_pid)
    if not hp:
        log("  [ERROR] save_ext: OpenProcess 失败")
        return
    
    # 从进程内存读取 ExtTable
    data, nread = read_pm(hp, ext_table_addr, EXT_TABLE_SIZE)
    _CloseHandle(hp)
    
    if nread != EXT_TABLE_SIZE:
        log(f"  [ERROR] save_ext: 读取不完整 {nread}/{EXT_TABLE_SIZE}")
        return
    
    # 构建文件内容
    header = struct.pack('<4sHHHH',
                         EXT_SAVE_MAGIC,
                         EXT_SAVE_VERSION,
                         MAX_CHARS,
                         EXT_SKILLS,
                         0)  # reserved
    
    ext_path = f"save/sav.{save_slot}.ext"
    os.makedirs("save", exist_ok=True)
    with open(ext_path, 'wb') as f:
        f.write(header + data)
    
    log(f"  [OK] 扩展存档已保存: {ext_path} ({12 + len(data)} 字节)")


def load_ext_skill_data(save_slot: int, child_pid: int,
                        ext_table_addr: int, log_func=None):
    """从边车文件读取数据并写入游戏进程 ExtTable"""
    log = log_func or (lambda x: None)
    
    ext_path = f"save/sav.{save_slot}.ext"
    if not os.path.isfile(ext_path):
        log(f"  [INFO] load_ext: 无扩展存档 {ext_path}, ExtTable 保持零初始化")
        return
    
    with open(ext_path, 'rb') as f:
        raw = f.read()
    
    if len(raw) < 12:
        log(f"  [ERROR] load_ext: 文件过小")
        return
    
    magic, version, char_count, ext_count, _ = struct.unpack('<4sHHHH', raw[:12])
    if magic != EXT_SAVE_MAGIC:
        log(f"  [ERROR] load_ext: 魔数不匹配 {magic!r}")
        return
    if version != EXT_SAVE_VERSION:
        log(f"  [WARN] load_ext: 版本 {version} != {EXT_SAVE_VERSION}")
    
    data = raw[12:]
    expected_size = char_count * ext_count
    if len(data) < expected_size:
        log(f"  [ERROR] load_ext: 数据不完整 {len(data)}/{expected_size}")
        return
    
    # 适配当前配置: 如果存档的 ext_count != 当前 EXT_SKILLS, 需要逐行复制
    access = PROCESS_VM_READ | PROCESS_VM_WRITE | PROCESS_VM_OPERATION
    hp = _OpenProcess(access, False, child_pid)
    if not hp:
        return
    
    if ext_count == EXT_SKILLS and char_count == MAX_CHARS:
        # 完全匹配, 直接写入
        write_pm(hp, ext_table_addr, data[:EXT_TABLE_SIZE])
    else:
        # 逐角色复制 (处理尺寸不匹配)
        copy_chars = min(char_count, MAX_CHARS)
        copy_skills = min(ext_count, EXT_SKILLS)
        for i in range(copy_chars):
            src_off = i * ext_count
            dst_off = i * EXT_SKILLS
            row_data = data[src_off:src_off + copy_skills]
            # 补零到 EXT_SKILLS 宽度
            row_data = row_data.ljust(EXT_SKILLS, b'\x00')
            write_pm(hp, ext_table_addr + dst_off, row_data)
    
    _CloseHandle(hp)
    log(f"  [OK] 扩展存档已加载: {ext_path} ({char_count}×{ext_count})")
```

### 步骤 10: 存档读写 Hook (监控游戏存档事件)

**目标**: 在游戏执行存档/读档时，同步操作边车文件。

**方案 A — 看门狗线程 (推荐)**:

启动器在游戏运行期间维护一个文件监控线程，当检测到 `save/sav.X` 文件被修改时，同步写入 `.ext` 文件。

```python
import threading
import time

class SaveWatchdog(threading.Thread):
    """监控游戏存档操作, 同步边车文件"""
    
    def __init__(self, child_pid, ext_table_addr, log_func=None):
        super().__init__(daemon=True)
        self.pid = child_pid
        self.ext_addr = ext_table_addr
        self.log = log_func or (lambda x: None)
        self.running = True
        self._last_mtimes = {}
        self._init_mtimes()
    
    def _init_mtimes(self):
        for i in range(1, 10):
            p = f"save/sav.{i}"
            if os.path.isfile(p):
                self._last_mtimes[i] = os.path.getmtime(p)
    
    def run(self):
        while self.running:
            time.sleep(1.0)  # 每秒检查一次
            for i in range(1, 10):
                p = f"save/sav.{i}"
                if not os.path.isfile(p):
                    continue
                mt = os.path.getmtime(p)
                if self._last_mtimes.get(i, 0) != mt:
                    self._last_mtimes[i] = mt
                    self.log(f"  [Watchdog] 检测到存档写入: sav.{i}")
                    save_ext_skill_data(i, self.pid, self.ext_addr, self.log)
    
    def stop(self):
        self.running = False
```

**方案 B — Hook sub_410ED4/sub_41103C (更精确但更复杂)**:

在存档写入函数 sub_410ED4 返回前和存档读取函数 sub_41103C 返回后各安装一个 hook。

对于 sub_41103C (读档后恢复):

```
; 或者从全局变量中读取
```

## 四、扫描上限修改详解

### 4.1 sub_4189BC 中的 350 上限

原始代码有 **2 处** 使用 350 作为扫描终止条件:
- 行61: `while ( v13 < 9 && v12 < 350 )`
- 行91/105: `if ( v12 < 350 )` 和 `if ( v12 >= 350 )`

这些在编译后表现为 `cmp reg/mem, 0x15E` (imm16) 或 `cmp reg/mem, 0x015E` (imm32)。

已有的 `skill_scan_bound` 补丁将其改为 344 (0x158)。对于外挂表方案，需要将其**恢复为更大的值**（如 400 = 0x190），使 JP 界面能扫描到扩展技能。

**修改**: 在 `skill_scan_bound` 补丁之后，再应用一个新的补丁将 344 改为 400:
```json
{
    "type": "patch_bytes",
    "id": "ext_skill_scan_expand",
    "desc": "JP界面扫描上限 344→400 (仅在外挂表启用时)",
    "pattern": "66 81 ** FC 58 01",
    "expect_count": 3,
    "replace": { "4": "90", "5": "01" },
    "depends_on": "ext_skill_learn"
}
```

### 4.2 sub_447BA8 / sub_438F28 中的范围

这两个战斗函数不使用全局扫描上限，而是使用技能组的子技能范围:
- sub_447BA8: `v6 = 4*a1+181; v5 = 4*a1+185` (固定4个)
- sub_438F28: `v6 = a1 + word_786224[47*a1]` (从 TKSkill 记录读取)

因此如果扩展技能的技能组定义正确（在 TKSkill.dat 中设置了子技能范围），这些函数会自然地访问到 >=344 的索引，无需修改上限。

### 5.1 编译器输出模式分析

以下是各 hook 点在编译后可能的机器码模式 (基于 Delphi/Borland 32-bit 编译器特征):

| Hook 点 | 关键指令 | 预期机器码模式 |
|---------|---------|---------------|
| sub_41E40C:103 | `cmp byte[...], 1` + `jl` | `80 3C ?? 01` 或 `3C 01` |
| sub_41E40C:104 | `mov byte[...], 10` | `C6 84 ?? ?? ?? ?? ?? 0A` |
| sub_41E248:17 | `mov byte[...], 20` | `C6 84 ?? ?? ?? ?? ?? 14` |
| sub_422EF4:87 | `cmp byte[...], 20` | `80 ?? ?? 14` |

**定位策略**: 使用 `pattern_scan` 在函数入口 RVA 附近（±0x200 字节范围）搜索特征字节序列。

## 八、风险清单与缓解措施

| # | 风险 | 影响 | 概率 | 缓解措施 |
|---|------|------|------|----------|
| 1 | 寄存器冲突 | Cave 代码破坏调用者寄存器 | 中 | 每个 hook 使用 pushad/popad 完全保存恢复 |
| 2 | 栈帧偏移误判 | 读取错误的局部变量 | 中 | 使用 IDA/x32dbg 逐字节验证栈布局 |
| 3 | 竞态条件 (存档) | .ext 文件与主存档不一致 | 低 | 看门狗使用1秒轮询 + 延迟写入 |
| 4 | sub_4189BC 指针模式 | 切换基址时指针计算错误 | 高 | 优先使用方案 A (边界切换), 充分测试 |
| 5 | 不同 EXE 版本 | Hook 点偏移不同 | 中 | 使用 pattern_scan 而非硬编码 RVA |
| 6 | 第三方 MOD hook 冲突 | 同一位置被两个补丁 hook | 中 | check_hook_conflict() 检测 + skip 策略 |
| 7 | ExtTable 内存泄漏 | 游戏退出后内存未释放 | 低 | 进程退出时 OS 自动回收, 无需处理 |

## 九、关键技术决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| Accessor 调用约定 | stdcall (ret 8 清栈) | 避免调用者忘记清栈; cave 中使用更简洁 |
| 寄存器保存策略 | pushad/popad | 简单安全, 虽有性能开销但 hook 频率低 |
| 战斗系统方案 | 直接读 ExtTable | 战斗中 skill_learn 只读, 无需同步战斗副本 |
| 存档同步方案 | 文件看门狗 | 不需要 hook sub_410ED4/41103C 内部, 实现简单 |
| JP界面 hook | 边界切换基址 | 比替换整个函数风险低, 保持原始逻辑不变 |
| Cave 代码位置 | 独立 VirtualAllocEx | 避免与现有 1024B cave 冲突 |
| 扩展技能数 | 可配置 (默认56) | EXT_SKILLS 作为常量, 方便后续调整 |
