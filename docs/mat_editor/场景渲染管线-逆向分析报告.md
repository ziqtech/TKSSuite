## 1. 渲染管线全景

游戏主地图的一帧渲染分为「切场景时的一次性准备」与「每帧执行」两部分：

```
切场景  sub_40C044(scene, x, y, dir)
  ├─ sub_402B88(scene) ──→ sub_411308  加载场景 GRP（背景 Frame A + 碰撞/前景 Frame B）
  │                                     → dword_824288 = L1 前景遮挡深度网格
  │                                     → dword_82428C = L2 地形碰撞类型网格
  └─ sub_405CBC()  收集本场景实体 → 按 (图层 d29, 前景/背景标志, pos_y) 排序 → dword_74D740[]
                   逐实体初始化：sub_406E50 求实体深度 d22；type=10 用 sub_4526D0 写碰撞网格

每帧    渲染驱动函数（sub_409830 等）
  ├─ sub_406444()   按最新坐标重新排序 dword_74D740[]（含 Y 排序 + 前景/背景标志）
  └─ sub_406864(buf)  遍历 dword_74D740[] 顺序绘制：
                       可见性(flags&2) → 阴影(d55) → 主精灵(d24 混合) → [d22>1] 前景遮挡 → 点击掩码
```

- **绘制顺序 = 深度顺序**：先画的在下层（远），后画的在上层（近）。排序结果直接决定实体间的前后遮挡。
- **前景景物遮挡实体**由逐像素深度缓冲（L1）实现，与实体间排序是两套独立机制。
- 全局变量：`dword_51AF40` = 实体表基址（6000×384B，96 dword/实体）；`dword_74D740` = 排序后的渲染索引表；`dword_4E7168` = 可见实体计数；`dword_755B58` = 当前场景 ID。

## 2. 场景数据源：实体表 + GRP 双层

### 2.1 实体表 TKMat.Dat（dword_51AF40）

每个实体 384 字节 = 96 个 int32（dword）。与渲染相关的字段：

| dword | 字节偏移 | 字段 | 渲染用途 |
|------|---------|------|---------|
| d0 | +0 | type | 实体类型（5/10/15/16/20/110/200），0=空槽 |
| d1 | +4 | scene_id | 所属场景；**<0 = 全局实体（游戏中所有场景都显示）** |
| d2 | +8 | flags | 位域，见 §3.3 |
| d10/d11 | +40/+44 | pos_x/pos_y | 世界坐标；pos_y 是 Y 排序键 |
| d18~d21 | +72~+84 | bound_x/y/w/h | 碰撞盒；求实体深度时的采样区域 |
| d22 | +88 | priority | **运行时深度**：脚下 L2 网格最小值（sub_406E50 写入） |
| d24 | +96 | blend_mode | 主精灵混合模式 0~5 |
| d25 | +100 | blend_param | 混合参数 |
| d26/d27 | +104/+108 | sprite_off_x/y | 精灵屏幕偏移 |
| d29 | +116 | layer | **主排序键（图层）**；原版数据恒为 0 |
| d55 | +220 | shadow_frame | 阴影帧全局索引（type 200/20） |

### 2.2 SC.GRP 场景图像：Frame A + Frame B 双层

每个场景背景是一个 GRP image section，含两帧（格式见 `grp_editor_v2.py` 与 `editor_utils/grp_data.py`）：

- **Frame A**：RGB565 + LZSS 压缩 = 可见背景图。
- **Frame B**：RLE 字节对压缩，解压后是**两张逐像素字节图**（各 width×height 字节）拼接：

| 层 | 数据位置 | 语义 | 加载去向 | 作用 |
|----|---------|------|---------|------|
| **Layer 1** | `raw[:W*H]` | **前景遮挡深度** | `dword_824288` | 逐像素采样图：决定景物是否挡住精灵 |
| **Layer 2** | `raw[W*H:2*W*H]` | **地形碰撞类型** | `dword_82428C = dword_824288 + W*H` | 行走网格；同时是实体深度 d22 的来源 |

`42FA50.c:85-90` 铁证：

```c
dword_824288 = sub_410E18(v11, &v13, 0);   // 解压 Frame B → 首地址 = L1
dword_82428C = dword_824288 + H * W;        // 第二张 = L2
// 把 L1 挂到各精灵资源对象的 +28（= a1[7]，逐像素遮挡采样指针），+32 = 行宽
*(dword_951924 + 28) = dword_824288;  *(dword_951924 + 32) = W;
```

> **关键结论**：精灵渲染时逐像素采样的是 **L1（dword_824288）**；实体自身深度 d22 取自 **L2（dword_82428C）**。二者是不同的层，共同构成前景遮挡机制（§5）。

## 3. 实体收集与排序（sub_405CBC / sub_406444）

`sub_405CBC` 在切场景时执行一次（收集+排序+逐实体初始化）；`sub_406444` 每帧执行（仅收集+排序，逻辑一致，多一个 type=16 平手规则）。

### 3.1 收集：本场景 + 全局实体

`405CBC.c:34-43` / `406444.c:29-36`：

```c
if ( *v13 && (v13[1] < 0 || v13[1] == dword_755B58) )   // type!=0 且 (scene<0 或 scene==当前)
    dword_74D740[dword_4E7168++] = 实体索引;
```

- `type != 0`：非空槽。
- `scene_id < 0`：**全局实体**，在所有场景显示（实测原版 3 个：#0 NPC、#1921/#1949 脚本）。
- `scene_id == 当前场景`：普通场景实体。

### 3.2 排序：图层 → 前景/背景标志 → pos_y

排序键分主次两趟（`406444.c:37-94`）：

1. **主键 = d29 图层**（`dword_51AFB4[96*idx]`，偏移 116）升序。
2. **同一 d29 组内**（次键）：
   - 背景标志（`byte[+9] & 0x10` = d2 & 0x1000）→ **最先绘制（最底层）**，且不再参与后续换位。
   - 前景标志（`byte[+9] & 0x20` = d2 & 0x2000）→ **最后绘制（最顶层）**，且不再被换到前面。
   - 其余普通实体 → 按 **pos_y（d11，`dword_51AF6C`）升序**（Y 越小越先画=越靠后，Y 越大越靠前）。
   - type=16 平手补充规则（隐形战斗区，不影响可见渲染）。

伪代码（等价于两函数的冒泡实现）：

```
sort_key(e) = ( e.d29,
                0 if e.flags & 0x1000 else (2 if e.flags & 0x2000 else 1),
                e.pos_y )   # 组 0=背景 / 1=普通(按 Y) / 2=前景
```

> **实测**：原版 TKMat.Dat 全部实体 d29 == 0，故主键退化为空操作，实际排序 = 「背景标志 → pos_y → 前景标志」。d29 保留是为兼容自定义 MOD 的显式分层。

### 3.3 flags（d2）位域中与渲染相关的位

`byte[+9]` 是 d2 的第 2 字节（bit 8~15）：

| 位 | 字节表达 | 含义 | 参与 |
|----|---------|------|------|
| bit1 = 0x2 | `byte[+8] & 2` | 可见 | sub_406864 渲染前置条件 |
| bit2 = 0x4 | `byte[+8] & 4` | 可交互 | 生成点击掩码 |
| bit12 = 0x1000 | `byte[+9] & 0x10` | **背景层**（画在最底） | 排序 |
| bit13 = 0x2000 | `byte[+9] & 0x20` | **前景层**（画在最顶） | 排序 |
| bit14 = 0x4000 | `byte[+9] & 0x40` | **跳过地形遮挡**（billboard） | 前景遮挡开关 |

### 3.4 实体深度 d22 的计算：sub_406E50

排序初始化时对每个实体调用 `406E50.c`；移动实体时 `407070.c:15-18` 也会重算并重排：

```c
// 在 L2 网格（dword_82428C）上扫描实体碰撞盒 [d18..d18+d20, d19..d19+d21]
v3 = dword_82428C + d18 + d19 * 网格宽;
if ( *v3 > 1u && *v3 < v2 ) v2 = *v3;    // 取 >1 的最小值
...
if ( v2 == 0xFF ) v2 = 1;                 // 未找到 → 1
*(a1 + 88) = v2;                          // d22 = 实体深度
```

即 **d22 = 实体脚下碰撞盒范围内 L2 的最小值（>1）；无则为 1**。移动位置时（sub_407070）碰撞盒被重定为「以坐标为中心」：`d18 = d10 - d20/2, d19 = d11 - d21/2`。

## 4. 实体渲染循环（sub_406864）

`406864.c` 按 `dword_74D740[]` 排序顺序逐实体绘制到目标 buffer：

```c
for (i = 0; i < dword_4E7168; ++i) {
    entity = &dword_51AF40[96 * dword_74D740[i]];
    X = entity.d10 - 视口X + entity.d26;     // 屏幕坐标
    Y = entity.d11 - 视口Y + entity.d27;
    frame = entity.d14;                       // 当前帧

    if (entity.flags & 2) {                   // 可见位
        if (entity.d22 <= 1 || (byte[+9] & 0x40)) {   // —— 简单分支（无地形遮挡）
            if ((type==200||type==20) && d55>0)
                sub_458020(Cha.JVG, X, Y, d55, buf, 0,0,-1);  // 阴影（减法）
            switch (entity.d24) { 0..5 → 各混合函数 }         // 主精灵
        } else {                                          // —— 遮挡分支（d22>1）
            if ((type==200||type==20) && d55>0)
                sub_45AA08(...);                          // 带遮挡的阴影
            sub_459EF4(...) / sub_45AA08(...);            // 带前景遮挡的主精灵
        }
    }
    if ((flags&1) && (flags&4))                           // 已启用 且 可交互
        sub_454944(...);   // 写逐像素「实体索引」点击掩码 word_78E276（供鼠标拾取，非可见渲染）
}
```

- **简单 vs 遮挡分支**由 `d22 > 1 且 未置 0x4000` 决定：只有站在 L2 深度 >1 的地形上、且不是 billboard 的实体，才走逐像素前景遮挡（§5）。
- 点击掩码（sub_454944）把可交互实体的不透明像素写成实体索引，供鼠标命中判定——是「拾取」而非「碰撞」，与 L2 碰撞层无关。

## 5. 前景遮挡（L1 逐像素深度）

这是「角色走到树冠/屋檐/柱子后面被部分挡住」的机制，是真正意义上的「前景层」。

### 5.1 算法（sub_459F78）

遮挡分支最终进入 `459F78.c`（16-bit 色）或 sub_45A4C0。核心判定（`459F78.c:126 / :166-167`）：

```c
dword_A5AF0C = a1[7] + world_x + world_y * a1[8];   // a1[7]=L1 前景深度网格, a1[8]=行宽
...
if ( *(BYTE*)dword_A5AF0C < a8 )                     // a8 = 实体深度 d22
    *(WORD*)dst = 精灵像素;                          // 仅当 L1[像素] < 深度 才绘制
// 否则跳过 → 前景景物（更高深度）挡住精灵
```

**遮挡规则**：对每个不透明精灵像素（世界坐标 wx,wy）：

```
若 L1[wx, wy] < 实体深度 d22  →  绘制该像素（精灵在前）
否则                          →  跳过（前景景物在前，挡住精灵）
```

- **深度值越大越靠前（越接近视点）**。站在 d22=D 的实体，被所有 L1≥D 的景物像素遮挡。
- **跨层比较**：像素深度取自 **L1**（`a1[7]=dword_824288`），实体深度取自 **L2**（`d22`=脚下 L2 最小值）。L2 决定实体处在哪个「深度平面」，L1 决定每个景物像素挡不挡它。
- 仅当 `d22 > 1` 时启用；`d22<=1`（站在开阔地）或 `flags & 0x4000`（billboard）走简单分支，精灵整幅绘制不被遮挡。

### 5.2 实测（scene 145，800×600）

- L1 取值 {0, 3, 5}（0=背景无前景，3/5=不同深度的前景景物）。
- 某实体脚下 L2 最小值(>1)=4 → d22=4；其精灵在 L1=5 处被挡（5≥4），在 L1=0/3 处正常绘制。

## 6. 碰撞检测层（L2 地形碰撞 + type=10 SetBlock）

「碰撞层」= GRP Frame B **Layer 2（地形碰撞类型）**，逐像素记录地面可行走/阻挡类型，与前景遮挡是不同的层。

### 6.1 网格来源与查询

- L2 网格挂在 `dword_82428C`（= L1 + W×H），行宽 `word_824290`，行高 `word_824292`。
- 实体深度 d22 由 sub_406E50 从 L2 求得（§3.4）。
- 玩家可行走/交互判定读取该网格：`410B74.c`、`412390.c`。

### 6.2 type=10 运行时改写碰撞网格（SetBlock）

传送点（type=10）可在运行时用 5 段路径线改写碰撞网格。`40DC1C.c`（SetBlock 事件）与 `405CBC.c:101-116`（切场景初始化）：

```c
if ( d62 > 0 )   // 封锁模式：把路径线写成 0
    sub_4526D0(x1, y1, x2, y2, 0, 网格);
else             // 开放模式：写路径编号（d63/d68/d73/d78/d83 的低字节）
    sub_4526D0(x1, y1, x2, y2, *(BYTE*)(a2+252), 网格);
```

`4526D0.c` 是 Bresenham 直线绘制，把字节值沿 (x1,y1)-(x2,y2) 写入网格。d62 字段控制封锁/开放（编辑器中显示为红/绿路径线）。

> 注意：type=10 的路径线只是运行时**局部改写**碰撞网格的手段，碰撞层的主体是烘焙在 GRP 里的 L2；不要把路径线本身当作「碰撞层」。

## 7. 效果叠加（d24 混合模式 / d55 阴影）

主精灵按 d24（+96）走 6 种混合，阴影帧 d55（+220）在主精灵前以减法混合绘制。**完整逐通道算法与证据见姊妹文档《角色阴影与图像混合模式-逆向分析报告.md》**，此处仅列管线摘要（`406864.c:39-69`）：

| d24 | 函数 | 模式 | 公式/效果 |
|-----|------|------|-----------|
| 0 | sub_4544EC | 正常 | alpha 覆盖 |
| 1 | sub_454D24 | 染色 | 按 d25 的 5-bit RGB 分量缩放 |
| 2 | sub_4559D0 | 加法饱和 | `min(dst + src·scale, MAX)`，scale 由 d25 定 |
| 3 | sub_458020→45871C | 减法压暗 | `max(dst − src, 0)` 逐通道 |
| 4 | sub_459168→459854 | 亮度 alpha | α=NTSC 亮度；`dst·(32−α)/32 + src·α/32` |
| 5 | sub_458D08 | 水平翻转 | X 轴镜像 |

- **阴影**：type 200/20 且 d55>0 时，取 Cha.JVG block[0] 的第 d55 帧（1=小 39×23，2=大 65×33），在主精灵前用减法混合绘制。
- 遮挡分支（d22>1）下，混合与前景遮挡叠加：d24=0/1/2→sub_459EF4，d24=3→sub_45AA08（均带逐像素 L1 遮挡）。

## 9. 编辑器实现状态（mat_editor_v2）

`mat_editor_v2.py` + `mat_render.py` + `editor_utils/grp_data.py` 已按上述管线实现地图预览（PIL 预合成 → QGraphicsView）：

| 管线环节 | 实现 | 说明 |
|---------|------|------|
| 实体收集 | ✅ 本场景实体（`d1 == sid`） | 全局实体（d1<0）**按用户要求未显示**，避免 #0 等出现在他场景 |
| 实体排序 | ✅ `_vis_sort_key`：(d29, 背景/前景标志, pos_y) | 复刻 sub_405CBC/sub_406444，两趟合一 |
| 两遍渲染 | ✅ Pass1 精灵（按序）→ Pass2 编辑标注 | 标注（碰撞盒/标签/路径线）绘制在精灵之上 |
| 效果叠加 | ✅ d24 混合 0~5 + d55 阴影（减法） | 复刻 sub_406864 分支 |
| GRP 双层解码 | ✅ `grp_data._decode_section_b` | Frame B → L1/L2 |
| **前景遮挡** | ✅ `composite_occluded`（L1）+ `entity_occlusion_depth`（L2 求 d22） | 复刻 sub_406E50 + sub_459F78：`L1[像素] < 深度` 才绘制；工具栏「前景遮挡」开关，默认开 |
| 碰撞层可视化 | ⛔ **按用户要求不做** | L2 仍加载（供前景遮挡求深度），但不叠加伪彩色 |
| 地形遮挡的阴影分支 | ⚠️ 近似 | 编辑器阴影不随 d22 走遮挡，简化处理 |

关键实现位置：

## 附录：常见误区

| 误区 | 正解 |
|------|------|
| 「碰撞层 = type=10 的路径连线」 | 碰撞层是烘焙在 GRP Frame B 的逐像素 **L2**；路径线只是 type=10 运行时局部改写 L2 的手段 |
| 「前景遮挡靠实体排序实现」 | 实体间前后靠排序；**前景景物挡实体**靠逐像素 L1 深度缓冲（sub_459F78） |
| 「d22 是编辑器里的静态优先级」 | d22 是**运行时**由 sub_406E50 从 L2 求得，切场景/移动都会重算 |
| 「d29 没用」 | 原版恒为 0 但它是引擎的主排序键，自定义 MOD 可用它做显式分层 |
| 「前景遮挡用 L1，实体深度也用 L1」 | 像素采样用 L1，实体深度 d22 用 L2，跨层比较 `L1[像素] < d22` |
