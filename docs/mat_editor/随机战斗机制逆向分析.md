# 随机战斗机制逆向分析

> 逆向依据: 运行时转储 反编译源码逐函数验证
> 验证方法: 反编译 .c 文件中实体指针偏移量 ÷ 4 = dword 索引

---

## 一、核心结论

游戏中的战斗触发只有两条路径，不存在独立于实体的地图级遇敌表：

| 路径 | 触发方式 | word_9DF894 |
|---|---|---|
| sub_4084E0 (type 16) | 碰撞盒接近 + 冷却 + 概率投骰 | = 1 (随机遇敌) |
| sub_40EBD4 case 66 (脚本 War) | 任意实体的脚本执行 | = 0 (脚本战斗) |

---

## 二、战斗入口函数 sub_40EB10

调用者只有两个：`sub_4084E0` 和 `sub_40EBD4`。

```
sub_40EB10(battle_group_id, terrain_param):
  1. sub_44ACE8 — 清除音频状态
  2. sub_409830 — 淡出转场 (白屏)
  3. sub_436BD4 — 战斗初始化 (加载 wardata.dat, warpc.dat, warway.dat)
  4. sub_43CA64 — 战斗主循环 (返回结果: 1=胜利, -1=失败/逃跑)
  5. sub_436DC0 — 战斗清理
  6. 恢复图形状态
```

`sub_436BD4` 只被 `sub_40EB10` 调用，没有其他入口。

## 三、路径一：Type 16 随机战斗区 (sub_4084E0)

> **逆向核对（`4084E0.c` 逐行一致）**：`:17 !dword_755B60`(遇敌总开关)、`:19 dword_755C80&4`(禁遇)、`:21 sub_408108`(碰撞盒)、`:38/42 sub_452AC0(200/140/100)`(难度概率投骰)、`:67 word_9DF894=1`、`:68 sub_40EB10(组ID, d62=offset248 战斗背景)`；callees 含 40eb10/452ac0/408108。（`word_9DF894=1` 亦触发 `4302D8.c:15` 的难度等级微调，见"敌方属性加成"文档。）

### 3.1 触发条件链

```
sub_4084E0(entity_id, entity_data):
  1. dword_755B60 == 0？ → return 0 (全局遇敌开关关闭)
  2. dword_755C80 & 4？ → return 0 (队伍职业禁止遇敌)
  3. !sub_408108(entity, player)？ → return 0 (AABB碰撞盒未重叠)
  4. d61(+244) > 0？ → d61--, return 0 (冷却中)
  5. d50(+200) > 0 且不匹配玩家ID？ → return 0
  6. d51(+204) 方向掩码不匹配？ → return 0
  7. 3组概率投骰 (d52/d53, d54/d55, d56/d57):
     随机数 = sub_452AC0(100/140/200)  ← 受难度标志影响
     随机数 < 概率阈值？ → 选中战斗组
  8. 重置冷却 d61 = d60 (基准值, 难度加成)
  9. 选中？ → word_9DF894 = 1, sub_40EB10(战斗组ID, 战斗背景ID)
```

### 3.2 数据布局 (dword 偏移)

| 偏移 | 字段 | 说明 |
|---|---|---|
| +200 (d50) | 条件匹配 | 0=无条件, 非零须与玩家ID匹配 |
| +204 (d51) | 方向掩码 | bit0-7 对应朝向 1-8, 0=任意 |
| +208 (d52) | 战斗组1-ID | 第1组战斗ID (索引 wardata.dat) |
| +212 (d53) | 战斗组1-概率 | 遇敌概率阈值 (0-100) |
| +216 (d54) | 战斗组2-ID | 第2组战斗ID |
| +220 (d55) | 战斗组2-概率 | 遇敌概率阈值 |
| +224 (d56) | 战斗组3-ID | 第3组战斗ID |
| +228 (d57) | 战斗组3-概率 | 遇敌概率阈值 |
| +240 (d60) | 冷却基准 | 遇敌后冷却重置基准值 |
| +244 (d61) | 冷却计时 | 当前冷却剩余 (每帧递减) |
| +248 (d62) | 战斗背景ID | 传给 sub_40EB10 的第2参数 |

### 3.3 关键机制：滚动概率投骰

**碰撞盒内的遇敌不是一次性检查，而是持续滚动概率。**

主循环 sub_409618 每帧遍历所有活跃实体，对 type 16 调用 sub_4084E0。
sub_4084E0 内部有冷却计时器，控制投骰频率：

```
玩家进入碰撞盒
  ↓
每帧: 冷却 d61 > 0？ → d61--, 不检查遇敌
  ↓ 冷却归零
条件检查 + 概率投骰 (15%~30%)
  ↓ 失败
重置冷却 d61 = d60 (15~30帧)
  ↓
继续移动... 冷却倒计时
  ↓ 冷却归零
再次投骰...
  ↓ 成功 → 触发战斗！(此时玩家可能已移动很远)
```

**示例：冷却=20, 概率=20%**
- 每 20 帧投骰一次，每次 20% 成功率
- 平均需要 ~5 次投骰 = ~100 帧
- 100 帧 × 玩家移动速度 → 玩家已移动数百像素
- 碰撞盒最大 500×400 像素，玩家可能已走到碰撞盒边缘甚至外面
- **感觉上是"走出战斗区后才触发战斗"**

### 3.4 难度影响

dword_755C80 由队伍职业/装备计算 (sub_41F784)：

| 标志位 | 效果 |
|---|---|
| bit 2 (0x4) | 完全禁止随机遇敌 |
| bit 1 (0x2) | 随机范围 0-199, 冷却 +50% |
| bit 0 (0x1) | 随机范围 0-139, 冷却 +30% |
| 无标志 | 随机范围 0-99, 冷却 = 基准值 |

## 四、路径二：脚本战斗 (opcode 66 War)

### 4.1 脚本 VM case 66

```c
case 66:  // War 命令
    word_9DF894 = 0;  // 标记为脚本战斗 (非随机遇敌)
    dword_755AA0 = sub_40EB10(battle_group_id, 0);
    if (dword_755AA0 == 1)
        word_755AB2 += 3;        // 胜利: 跳过跳转
    else
        word_755AB2 += jump_offset;  // 失败: 跳转到指定偏移
```

### 4.2 脚本执行时机

sub_40EBD4 在主循环中对所有有脚本的实体执行：

```c
// sub_409618 行 66-77
if (entity[132])  // 有脚本指针
{
    if (entity[168] == -1)  // 初始化脚本
        sub_4066F0(entity, 0);
    sub_40EBD4(entity_id);  // 执行脚本 (可能包含 case 66)
}
```

任何实体类型 (5/10/15/20/110/200) 只要有脚本且脚本中包含 War 命令，都能触发战斗。

### 4.3 脚本战斗 vs 随机遇敌的区别

| 维度 | 随机遇敌 (type 16) | 脚本战斗 (opcode 66) |
|---|---|---|
| word_9DF894 | = 1 | = 0 |
| 触发方式 | 碰撞盒 + 冷却 + 概率 | 脚本执行时直接触发 |
| dword_755B60 检查 | 需要 = 1 | 不需要 |
| 位置检查 | 需要碰撞盒重叠 | 不需要 |
| 概率检查 | 需要随机数通过 | 不需要 |
| 战斗参数 | battle_group + terrain | battle_group + 0 |
| 逃跑机制 | 不同概率 | 不同概率 |
| 敌人等级 | 可能缩放 (低等级时) | 不缩放 |

### word_9DF894 — 随机遇敌标记

| 位置 | 值 |
|---|---|
| sub_4084E0 行 67 | = 1 (type 16 随机遇敌) |
| sub_40EBD4 行 572 | = 0 (脚本战斗) |

影响：
- sub_4302D8: 低等级时敌人等级缩放
- sub_4458B0: 逃跑概率 / 捕获机制
- sub_447DAC: 逃跑命令行为

### dword_755C80 — 难度标志

由 sub_41F784 根据队伍职业/装备计算，影响遇敌概率和冷却时间。
