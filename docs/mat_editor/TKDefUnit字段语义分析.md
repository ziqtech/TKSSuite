## 各字段详细证据

### f0: 块编号 (block_id) ✓◆

**反编译证据**: 402E88:29 检查 `*(DWORD*)(buf+16*i)!=0` 判空, 未单独读取f0

**数据证据**: 
- DEFINE ID编码: `(f1<<16)|f0`
- 全部1541条非零记录, 其DEFINE ID均存在于TKD.dat (匹配率1541/1539≈100%)
- 值分布: 0=基础(436), 256=主脚本(654), 1-6/257-266=变体

### f1: 实体ID (entity_id) ✓

**反编译证据**: 402E88:31 `v2 = *(int*)(buf+16*i) >> 16` → 索引dword_51AF40[96*v2]

**数据证据**: 1540条非零, 1004个唯一实体, 范围[9,4450], 均在MAT 6000范围内

### f2-f3: 脚本指针 ✓

**反编译证据**:
- 402E88:34 写0 (禁用脚本)
- 402E88:38 写 sub_41425C() 返回值
- 40EBD4:22 读为字节码基址执行指令
- 4119CC:70-73 遍历释放并清零

**数据证据**: 文件值通常为0 (99.2%), 仅13条含预编译值

### f4-f5: 块变体链 (文件静态数据) ◆★

**反编译证据**: 无任何函数访问 (全量decompile搜索确认)

**数据证据**:
- 449条非零 (29%)
- f4 = f0 + 1 (非零时恒成立)
- f5 = f1 (非零时100%一致)
- (f5<<16)|f4 指向的DefUnit记录 100%存在
- 与f6的区别: f4/f5是块变体链(静态), f6是场景执行链(运行时)
- 写入者未知 — 可能是原开发工具链

### f6: 链表next ✓

> **逆向核对**：`4066F0.c:53` `v7 = *((_DWORD*)lpBuffer + 4*v7 + 3)` = `TKDefUnit[v7]` 偏移 +12 = f6（`lpBuffer` 即本文所称 `dword_753500`）。该函数按 a2=0/1/2 选 TKMat 字段 `head=[39/40/41]`、`cur=[33/34/35]`、`max=[30/31/32]`，自 head 沿 f6 遍历 cur 步，结果写入 `a1[44]`(defunit_idx)、`a1[42]`(script_PC)——与 `TKMat分析文档.md` 的 A/B/C 链字段完全吻合；f0/f1/f2-3 亦经 `402E88.c` 核实。

**反编译证据**: 4066F0:53 `v7 = *(DWORD*)(dword_753500 + 16*v7 + 12)` 遍历

**数据证据**: 472条非零, 267个链表头, 值域[52,1540]全有效

### f7: 对齐填充 ◆

**数据证据**: 全部1541条有效记录均为0。f6(next)不超过65535故f7恒为0
