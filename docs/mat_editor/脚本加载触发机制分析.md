# 游戏脚本加载与触发机制分析

> 基于反编译代码 `sub_409618`（主循环）、`sub_408E5C`（玩家交互）、`sub_4081F8`（传送/区域触发）、`sub_408408`（场景事件）、`sub_402E88`（DefUnit 加载）交叉验证。

## 一、主游戏循环 (`sub_409618`)

> **逆向核对**：本节所述 `sub_409618` 类型分发与各目标函数均已独立核实：type 10→`sub_4081F8`（`4081F8.c:32` 传送）、16→`sub_4084E0`（`4084E0.c` 随机战斗）、20/200→`sub_408704`（动画）、`entity[2]&1` 启用位、`entity[132]`(cur_A)≠0 → `sub_4066F0`+`sub_40EBD4`（`4066F0.c` 链步进 + 脚本VM）。全部与其它文档的验证一致。

**证据：`409618.c`**

这是每帧调用的核心函数，决定了所有实体的脚本触发时机。

```
sub_409618() — 每帧执行
  │
  ├── 1. sub_408E5C()           ← 玩家按 A 键交互 (type 200 NPC/type 20 事件)
  │
  └── 2. 遍历所有已启用实体 (for each enabled entity):
        │
        ├── [实体通用] tick 计数器: entity[20]++, 到达 entity[16] 后归零
        │
        ├── [实体通用] resume 状态检查: entity[8] & 0x10
        │
        ├── type 10 (地形块): sub_4081F8()       ← 玩家走入区域触发
        ├── type 15 (障碍物): sub_408408()        ← 碰撞触发场景事件
        ├── type 16 (建筑/门): sub_4084E0()        ← 建筑交互
        ├── type 20 (事件对象): sub_408704()       ← 事件 tick 处理
        ├── type 200 (NPC): sub_408704()           ← NPC tick 处理
        │
        └── [实体通用] 若 entity[132]≠0 (子场景A有脚本):
              sub_4066F0(entity, 0)   ← 计算 d44
              sub_40EBD4(entity_id)   ← 执行子场景A脚本
```

**关键代码（`409618.c:23-77`）：**

```c
for (i = 0; i < dword_4E7168; ++i)
{
    entity_id = dword_74D740[i];
    entity = &dword_51AF40[96 * entity_id];

    if ((entity[2] & 1) != 0)  // ★ 检查 bit0: 实体是否启用
    {
        // ... tick 计数 ...

        // 按类型分支
        if (entity_type == 10)
            sub_4081F8(entity_id, entity);       // 地形块→区域触发
        else if (entity_type == 15)
            sub_408408(entity_id, entity);        // 障碍物→碰撞事件
        else if (entity_type == 16)
            sub_4084E0(entity_id, entity);        // 建筑→交互
        else if (entity_type == 20 || entity_type == 200)
            sub_408704(entity_id, entity);        // 事件/NPC→tick处理

        if (entity[132])  // ★ cur_A > 0 → 子场景A有脚本
        {
            sub_4066F0(entity, 0);              // 计算 DefUnit 索引
            entity[172] = entity[168];          // 保存返回地址
            entity[168] = 0;
            sub_40EBD4(entity_id);              // 执行脚本
        }
    }
}
```

## 二、三种子场景的区别

**证据：`4066F0.c` + `40EBD4.c` End 操作码**

| 子场景 | cur 字段 | max 字段 | head 字段 | End() 递增 | 触发方式 |
|--------|---------|---------|----------|-----------|---------|
| **A** | entity[132] (cur_A) | entity[120] (max_A) | entity[156] (head_A) | End(1) | 主循环自动触发（所有实体类型） |
| **B** | entity[136] (cur_B) | entity[124] (max_B) | entity[160] (head_B) | End(2) | 特定交互触发（碰撞/A键） |
| **C** | entity[140] (cur_C) | entity[128] (max_C) | entity[164] (head_C) | End(3) | 特定交互触发 |

**`4066F0.c` 子场景选择逻辑：**

```c
sub_4066F0(entity, a2)  // a2 = 0=A, 1=B, 2=C
{
    if (a2 == 0) { max=30; head=39; cur=33; }  // 子场景A
    if (a2 == 1) { max=31; head=40; cur=34; }  // 子场景B
    if (a2 == 2) { max=32; head=41; cur=35; }  // 子场景C

    v7 = entity[head];           // 从链表头开始
    for (i = 1; i < entity[cur]; i++)
        v7 = dword_753500[16 * v7 + 12];  // 沿 f6 链走 cur-1 步
    entity[44] = v7;             // 写入 d44 = DefUnit 索引
}
```

**`40EBD4.c` End 操作码的计数器递增：**

```c
case 0:  // End(sub_mode)
    switch (sub_mode) {
        case 1:  entity[132]++;  if > max_A → 0;  break;  // End(1)
        case 2:  entity[136]++;  if > max_B → 0;  break;  // End(2)
        case 3:  entity[140]++;  if > max_C → 0;  break;  // End(3)
        case 0:  /* 不递增, 仅保存/恢复PC */    break;  // End(0)
    }
```

## 四、Entity #2425（許家村地形块）的触发流程

### 实体数据

| 字段 | 值 | 含义 |
|------|-----|------|
| type | 10 | 地形块 |
| scene_id | 106 | 許家村 |
| cur_A | 0 | 子场景A无脚本 |
| cur_B | 1 | 子场景B有脚本，当前位置=1 |
| head_B | 754 | DefUnit 链表头 |
| max_B | 2 | 链共2条 |
| bound (d18-d21) | — | 碰撞盒区域 |

### 完整触发流程

```
每帧主循环 sub_409618()
  │
  ├── entity[2] & 1 ≠ 0        ← 实体已启用
  ├── tick 计数器归零
  ├── entity_type == 10
  │     └── sub_4081F8(2425)
  │           ├── sub_408108(entity_2425, player)  ← AABB 碰撞检测
  │           ├── [可选] char_id 检查 (entity[200])
  │           ├── [可选] flag 检查 (entity[204])
  │           ├── entity[136] ≠ 0  →  cur_B=1, 有脚本
  │           ├── sub_4066F0(entity, 1)  → 计算 d44
  │           │      head=754, cur=1, 走0步 → d44=754
  │           ├── sub_40EBD4(2425)
  │           │      → 执行 DEFINE 158925056 (End(0), 空操作)
  │           │      或 DEFINE 158925057 (Enable(4292)...)
  │           └── sub_40C044(...)  ← 切换场景（如果脚本触发传送）
  │
  └── entity[132] = 0 → 子场景A无脚本，跳过
```

### SetNowDef 修改 cur_B 后的触发

当 `SetNowDef(2425, 2, 2)` 执行后（DEFINE 133169408 中）：

**`40B520.c:39-43`：**

```c
case 2:
    entity[34] = a3;    // cur_B ← 2
    if (entity[34] > entity[31])  // 超出 max_B 则归零
        entity[34] = 0;

```

之后，引擎重新调用 `sub_4066F0(entity_2425, 1)`：
- cur_B = 2，走 1 步：head=754 → f6=755
- d44 = 755 → 执行 DEFINE 158925057

## 五、实体启用/禁用机制

### 启用 (`sub_40C648` — Enable 操作码 25)

```c
entity[2] |= 1;  // bit0 = 启用（参与主循环）
entity[2] |= 2;  // bit1 = 可见（渲染）
```

### 禁用 (`sub_40C5A4` — Disable 操作码 24)

```c
entity[2] &= ~1;  // 清除 bit0（不参与主循环）
entity[2] &= ~2;  // 清除 bit1（不渲染）
```

### 脚本级禁用 (`sub_402E88`)

```c
// 场景切换时，遍历所有 DefUnit 记录
if (entity 不属于当前场景)
    DefUnit_entry[4] = 0;  // 清除编译后的脚本指针 → 脚本不执行
```

## 七、总结

| 问题 | 答案 | 证据 |
|------|------|------|
| 脚本什么时候加载？ | 场景切换时，`sub_40C044` → `sub_402E88` 读取 TKDefUnit.dat 全部加载到 `dword_753500[]` | `40C044.c:47`, `402E88.c:23` |
| 什么时候自动执行？ | 每帧主循环 `sub_409618`，按实体类型分支触发；子场景A对所有类型自动执行 | `409618.c` |
| 多个脚本如何判断执行哪个？ | 通过子场景 cur 值 + `sub_4066F0` 链表遍历计算 d44，每次只执行当前 d44 指向的一个 DEFINE | `4066F0.c`, `40EBD4.c:18-22` |
| 脚本如何切换？ | `End(1/2/3)` 递增 cur 计数器，下次 `sub_4066F0` 重新计算指向下一个 DEFINE；`SetNowDef` 显式设置 cur | `40EBD4.c:56-60`, `40B520.c` |
| #2425 如何触发？ | 玩家走入其 AABB 碰撞区 → `sub_4081F8` 检测 → 执行子场景B脚本 | `4081F8.c:20-28` |
| Enable/Disable 如何影响脚本？ | 实体级禁用(`entity[2] bit0=0`)后完全不参与主循环；脚本级清除(`DefUnit[4]=0`)使其不执行 | `40C648.c`, `40C5A4.c`, `402E88.c:34` |
