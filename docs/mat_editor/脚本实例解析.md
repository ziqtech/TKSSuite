# 脚本实例解析

> **逆向核对**：本文所用脚本命令均已核实——`GetItem(10000,…)`→金钱（`sub_40CE30`，item 10000）、`Disable(-2)`→`sub_40C5A4` 清 flags bit0（-2=当前实体 `dword_75350C`）、`Attribute(-1,11,2)`→`40E11C.c:100` `word_757F00+=2`、`TeamMember(29,1)`→`40DA00.c:20`、`CheckTeam(5,6,-2)`→`40E65C.c:20`、`End(n)`→标记 DEFINE 消费。

## 许家村破庙
```cpp
{;1 #Define
GetItem(10000,1000) // 给玩家添加物品 ID=10000，数量 1000；即金钱+1000
Disable(-2) // 禁用自身实体（-2 代表当前执行脚本的实体，对应 sub_40C5A4 中 a1==-2 → dword_75350C）。清除flags bit0（启用位），实体不再参与后续游戏循环。
End(0) // 结束脚本执行，返回 0
};1 #Define end
```

```cpp
{;1 #Define
Attribute(-1,11,2) // 文王挂签 + 2
End(2)
};1 #Define end
```

Disable(-2) 和 End(2) 的目标不同：

- Disable(-2) — 修改实体状态。调用 sub_40C5A4 清除 flags bit0（启用位），实体彻底退出游戏循环，所有 DEFINE
都不再触发。是"物理删除"。
- End(2) — 只影响当前 DEFINE 的脚本执行。返回值为 2 告诉引擎"此 DEFINE
已消费/已完成"，引擎将其标记为已执行，不再重复触发。但实体本身仍存活，其他 DEFINE（如碰撞、点击）依然有效。

第一个脚本用 Disable(-2) 是因为 GetItem(10000,1000)
后没有任何理由让实体继续存在——它是一个一次性宝箱/拾取物。第二个脚本只用 End(2) 是因为 Attribute(-1,11,2)
只是修改属性，实体本身（比如一个开关）可能还需要响应其他交互。
