# 敌人 AI 施法规则与扩展技能配置指南

核验日期：2026-09-24。

适用范围：原版 TKS 战斗 AI，以及当前 `tks_launcher_gui/main.py` 启动链使用的扩展技能补丁。第三方修改版若改写 AI 或伤害算法，需要另行核对。

依据为游戏导出源码、原始指令、当前补丁和本次排查的数据；未通过 CLI 启动游戏，未修改游戏数据。隔离执行结果不等于完整游戏内实测。

## 一、核心结论

**装备了技能，不代表 AI 必定施放；扩展技能也没有天然高于普攻的优先级。**

原版 AI 先计算普攻评分，再检查两个战斗指令技能槽。技能只有在可参与评估、存在有效目标，并且评分**严格高于当前最佳动作**时，才会替换当前选择。

因此应区分两类问题：

1. **未进入有效候选**：未装备、技能组未学会子技能、资源不足、效果映射无效、实际等级不足等。
2. **进入候选但落败**：技能效果读取正常，却因为伤害、命中、防御、目标或状态等因素，评分不如普攻或其他技能。

如果技能和普攻评分相等，技能不会替换普攻；后遍历的技能与已选技能同分，也不会替换先前选择。

## 二、调用链与数据职责

```text
战斗单位初始化
  → 从 WarPC 复制人物模板
  → 按战场配置重新计算敌人等级和属性
  → 将 WORD[82]、WORD[83] 复制到两个战斗指令技能槽

回合准备 sub_4355C4
  → sub_438AFC 建立动作菜单

自动行动 sub_436678
  → sub_435D68 比较普攻与技能
      → 技能组调用 sub_438F28 展开子技能
      → 解析人物对应的 TKKon 效果
      → sub_4359A4 搜索行动位置和目标
          → sub_43D53C 计算可选目标格
          → sub_43D8B0 计算实际作用目标
          → sub_43E980 计算评分
```

| 数据或编辑器 | 对施法的主要影响 |
| --- | --- |
| `WarData.dat` / 战场编辑器 | 敌人模板、AI 行为值、实际出场等级和位置 |
| `WarPC.dat` / 人物编辑器 | 两个指令技能槽、基础属性、普通攻击效果等 |
| `TKSkill.dat` / 技能编辑器 | 技能组范围、内力和其他资源消耗、行动时序等 |
| `WarPC.dat.tksx` | 扩展技能学习状态、人物专属扩展效果覆盖 |
| `TKKon.dat` / 效果编辑器 | 生命伤害、附加命中、物理标志、距离、面积和目标过滤等 |

修改技能名称、编号或动画，并不会自动提高 AI 评分；提高攻击技能威力，应重点检查它最终解析到的 **TKKon 效果**。

## 三、进入技能评估的条件

### 3.1 AI 行为分支

`sub_436678` 根据当前单位的 `byte_9DF761[unit]` 分流：

| 行为值 | 本次自动行动的处理 |
| --- | --- |
| `10` | 跳过普攻与技能评分，后续进入移动或等待等分支 |
| `100` | 只评估已装入的普通攻击效果，不调用技能比较函数 |
| 其他值 | 调用 `sub_435D68` 比较普攻与技能 |

敌方该值来自 WarData 每条记录偏移 `70..87`。当前编辑器将其保存为 `enemy_lv`，界面标为“等级”，但它不是敌人的实际等级；不能仅凭此列判断敌人是否满足施法等级。

### 3.2 实际等级门槛

评分函数 `sub_43E980` 有以下原版限制：

| 条件 | 结果 |
| --- | --- |
| 实际等级 `<5`，且当前技能编号 `>=0` | 技能评分直接返回 `0` |
| 实际等级 `<10`，且技能编号在 `13..100` | 技能评分直接返回 `0` |
| 当前动作是普攻，内部技能编号为 `-1` | 不受上述技能等级门槛影响 |

扩展技能从 `350` 开始，仍受第一条限制，但不属于第二条的编号区间。

这里读取的是**战斗单位的实际等级**，不是人物编辑器里模板的等级。敌人初始化会通过 `sub_430578` / `sub_4302D8` 重新计算等级和属性；WarData 的 `LvP1`、`LvP2`、战斗调用参数及原版特殊调整都会影响结果。

### 3.3 装备槽与技能组

AI 只遍历两个战斗指令技能槽，不会自动扫描人物所有已学技能，也不会把被动技能、移动技能当作额外的施法槽。

对于组头编号 `S`，若其子技能数量为正数 `N`，原版组展开范围为：

```text
S + 1 到 S + N，连续编号
```

例如，组头 `350` 的子技能数量为 `1`，则展开的技能是 `351`，不是组头350自身。

子技能学习状态必须 `>=20` 才进入组菜单；当前补丁对扩展编号读取外置状态矩阵，并通过战斗槽映射找到正确的人物记录。

**独立指令技能的注意点**：原版 AI 以“子技能数量是否非零”决定是否展开组；`0` 才进入直接效果评估分支。不能将编辑器中 `-1=独立` 的提示直接等同于本条 AI 路径可用：`-1` 仍会进入组展开，且展开范围为空。

### 3.4 内力、资源和可用标志

技能组的子技能在 `sub_438F28` 中检查：

- 当前内力是否足够支付实际消耗；
- 金钱、兽元、灵魂等资源是否满足原版检查；
- 部分原版特殊技能的附加条件。

实际内力消耗由 `sub_438A40` 计算，并非始终等于技能编辑器中的原始数值：角色减耗及符合条件的状态可能降低消耗。原始消耗为0时返回0；非零消耗经过调整后最低为1。

资源比较读取的是原版对应的全局资源变量，不是为每个敌人单独维护的一份资源余额。

**不能把菜单检查概括成所有 AI 技能的统一门槛**：`sub_438AFC` 会设置主菜单技能的资源及状态可用标志，但 `sub_435D68` 的直接技能分支没有读取该技能菜单项的可用标志；技能组子技能分支则明确读取组菜单的可用标志。因此，“技能菜单变灰”和“AI 必定不选这个技能”不能不分路径地画等号。

本次 #200 使用的是组头350及其子技能351，属于会检查子技能可用标志的路径。

### 3.5 效果映射必须有效

进入效果评估时，解析出的 TKKon 编号必须大于0，并指向已加载的有效记录。

当前扩展技能补丁在两个 AI 效果读取位点接入扩展解析：

- RVA `0x35E6A`：直接技能分支；
- RVA `0x35F6C`：技能组子技能分支。

扩展技能的学习状态和人物专属效果覆盖由 `WarPC.dat.tksx` 提供，技能组头与子技能可以有不同覆盖。不能因组头的覆盖为0，就认定所有子技能都无效；也不能因补丁日志显示成功，就认定实际解析出的效果一定正确。

## 四、AI 如何比较评分

### 4.1 先普攻，后技能

`sub_435D68` 首先保存普攻评分，再依次比较技能。只有满足以下条件才更新选择：

```text
技能评分 > 当前最佳评分
```

这不是固定的施法概率，也不是轮流使用普攻与技能。技能编辑器里的“触发概率”不能当作“AI 本回合施法概率”；该比较路径没有按此字段掷骰决定是否使用扩展技能。

降低内力消耗有助于通过资源检查，但不会直接给技能增加一个评分奖励；行动时序也不是本函数中按“伤害÷耗时”计算优先级的依据。

### 4.2 目标、位置与阵营

`sub_4359A4` 在允许移动时搜索可行动位置，不允许移动时使用当前位置，再根据效果的距离、面积和目标过滤评估实际作用目标。

- 没有合法目标时，威力再高也不能得到有效攻击评分。
- 对敌造成伤害会加分，对友方造成伤害会扣分。
- 群体技能可能因同时命中多个敌人获益，也可能因误伤友军失分。
- 治疗、内力变化和状态效果有各自的评分分支，不能套用单体生命伤害的简化公式。

### 4.3 物理标志会同时影响命中和减伤

关键字段是 **TKKon“执行标志”的 bit2，也就是 `0x04`**，效果编辑器对应“物理攻击”复选框。

| 执行标志 bit2 | 普通生命伤害的 AI 评估行为 |
| --- | --- |
| 未设置 | 普通命中评分项取100，不走物理防御减伤分支 |
| 已设置 | 按命中、闪避和相关状态计算命中评分项；普通情形限制在10～95，再计算物理防御减伤 |

这里描述的是已核验的 AI 评分分支，并非宣称所有技能都无条件必中、无视所有抗性或免疫；原版特殊编号、百分比伤害及状态仍可能有专门处理。

物理判定不能仅从技能名称、动画或 TKSkill“攻击类型”推断，应核对最终 TKKon 的执行标志。

对没有特殊修正的普通物理伤害，令 `D` 为进入减伤前的伤害、`F` 为目标有效防御，评分中的伤害估计为：

```text
L = floor(D² / (D + 3F))
U = floor(D² / (D + 2F))
估计伤害 = L + Random(U - L + 1)
```

`Random(n)` 的取值为 `0..n-1`；原版使用整数运算，百分比伤害等特殊分支不能机械套用此式。

因此，物理技能的“攻击力＋20”，经过减伤后可能比不走物理减伤的“攻击力”普攻还弱。

### 4.4 击杀收益会放大普攻优势

在单个对立目标、普通生命伤害、无其他效果和特殊标志的简化情形下：

```text
未达到击杀：评分 = 命中评分项 + 估计伤害
达到击杀：  评分 = 命中评分项 + 3 × 估计伤害
```

这里的评分不是最终显示伤害，也不是“命中概率×伤害”的数学期望。目标当前生命较低时，能够击杀的普攻可能获得显著优势；不能只比较技能面板上的加成。

## 五、人物 #200 的实际排查案例

以下为 2026-09-24 排查时 `游戏目录（改版）` 的数据快照，不代表之后编辑过的数据仍保持这些值。

### 5.1 技能链路

```text
WarPC #200 的指令槽：350、-1
  → 技能组350，子技能数量1
  → 子技能351，扩展学习状态30
  → 人物专属 TKKon 覆盖656
```

组头350的效果覆盖为0，但子技能351的覆盖为656，组内施法链路仍然有效。

| 项目 | 普攻 | 扩展子技能351 |
| --- | --- | --- |
| TKKon | 644 | 656 |
| 生命伤害 | `-1`：攻击力 | `2020`：攻击力＋20 |
| 执行标志 | `0` | `4` |
| 物理命中、防御判定 | 不走普通物理分支 | 走普通物理分支 |
| 附加命中 | 0 | 80 |
| 基础内力消耗 | — | 10 |

### 5.2 两场战斗的原因不同

- **War(1)**：#200 的战场等级参数为 `2..3`；在按该范围生成的场景中，不满足原版5级施法门槛，人物模板的20级不能代替实际战斗等级。
- **War(14)**：战场等级参数为 `12..15`；即使通过等级检查，物理技能仍可能因减伤及击杀收益不如普攻而被淘汰。

### 5.3 隔离执行记录

诊断读取实际人物、技能、效果和扩展状态数据，执行原版属性初始化、评分与技能比较代码，并应用当前技能补丁；构造单个相邻的对立目标，无额外状态及特殊目标标志。随机函数分别取0和上边界，文本、界面、内存填充等叶子调用使用受控替代。

| #200 实际等级 | 对立目标等级 | 普攻评分 | 技能评分（两种受控随机取值） | 最终选择 |
| --- | --- | --- | --- | --- |
| 3 | 1 | 137 | 0 / 0 | 普攻 |
| 12 | 1 | 271 | 140 / 147 | 普攻 |
| 15 | 1 | 298 | 147 / 275 | 普攻 |
| 12 | 10 | 157 | 131 / 138 | 普攻 |
| 20 | 20 | 183 | 137 / 147 | 普攻 |

另行隔离核验已确认，子技能351进入可用候选，且 AI 解析到效果656。上述结果证明存在“技能正常进入候选，但评分低于普攻”的原因，不能扩大成 War(14) 所有队伍、目标和状态下的固定评分。

## 六、如何让 AI 更倾向于扩展技能

### 6.1 先保证候选有效

1. 在战场编辑器检查实际等级来源，不只看人物模板等级；扩展攻击技能需满足原版5级门槛。
2. 在人物编辑器确认指令槽装备正确的组头或独立指令技能。
3. 使用技能组时，确认子技能编号连续、数量正确，且对应子技能的学习状态达到20或以上。
4. 检查子技能内力、其他资源及实际目标条件。
5. 检查人物专属扩展效果覆盖，确认指向已加载的有效 TKKon 记录。

### 6.2 方案一：统一技能与普攻的伤害规则

针对上述 #200 配置，可在效果编辑器打开 **TKKon #656**：

- 取消“物理攻击”，仅清除执行标志的 `0x04` 位，保留其他标志；
- 保留“生命伤害” `2020`，即攻击力＋20。

在双方判定规则一致且无额外限制的普通单目标场景下，技能的伤害优势才不会被物理减伤抵消。

**代价**：改变了技能的伤害定位，不再按普通物理防御减伤。这是配置建议，不是已实施或已实机验证的修复。

### 6.3 方案二：保留物理定位，提高有效威力

若技能设计必须是物理攻击，则保留该标志，调整“生命伤害”：

| 数值 | 本例普通伤害解释 |
| --- | --- |
| `-1` | 攻击力；部分原版技能编号另有特殊处理 |
| `2020` | 攻击力＋20 |
| `2100` | 攻击力＋100 |
| `3100` | 攻击力＋攻击力的100%，即约2倍攻击力 |

可以把 `2100` 作为调试起点，再结合角色成长、目标防御及关卡平衡回调；它不是保证所有战斗都优先施法的通用阈值。

“附加命中”是命中计算的加算项，不是最终命中率；普通物理命中评分项最高95，所以仅把附加命中从80提高到100，可能已经没有收益。

若普攻644本来就应是物理攻击，也可以重新审视它的执行标志，但这会改变所有使用该效果的动作，需要先核对引用范围，不能只为单个人物随意修改共享效果。

### 6.4 不能只靠配置保证每回合施法

降低消耗、提高威力或扩大有效目标范围，都是提高可用性或评分，不是设置“必定施法”。若要求“只要能释放，就无条件优先扩展技能”，需要明确修改 AI 的比较策略，属于玩法规则变更，不能与效果配置调整混为一谈。

本次排查未修改 AI 比较策略，也未修改任何技能或战斗数据。

## 七、建议排查顺序与验证边界

```text
实际战斗等级是否满足门槛？
  → AI 行为值是否进入技能比较分支？
  → 两个指令槽是否正确？
  → 技能组范围及子技能学习状态是否正确？
  → 该路径的资源与可用标志是否通过？
  → 实际解析出的 TKKon 是否有效？
  → 距离、面积、阵营过滤是否产生合法目标？
  → 技能评分是否严格高于普攻及其他候选？
```

不能以“补丁全部应用成功”“技能菜单能够显示”“技能威力数值更大”中的任何一项，直接证明 AI 应当施放技能。

游戏内验证应由用户通过 GUI 启动，分别检查不同实际等级、内力、目标生命、防御和距离的场景；禁止使用废弃 CLI 启动或测试本游戏。源码分析和隔离函数执行只用于定位因果，不替代实机验收。
