# 断头斩无伤害排查与原版伤害公式特判技能清单

> 案例日期: 2026-10-13（游戏目录（改版），存档槽 8）
> 现象: MOD 新增角色使用自定义配置的指令技能，动画正常但**永远没有伤害**
> 结论: **原版对部分技能号在伤害结算 sub_4400DC 里硬编码了专属伤害公式，kon 的 hp_damage 字段被整体覆盖**。断头斩（技能 128）的公式是"装备武器攻击力 × ((施法者等级+2)/3)"——角色没装武器时伤害恒为 0。

## 一、问题现象

- 人物 #201（魏军校尉，MOD 新增角色，测试存档中 Lv5、**未穿任何装备**）学会断头斩（TKSkill #128，type=0 直接指令技能）。
- 配置链: WarPC 效果槽 `field[273+128]=field[401]=646` → TKKon#646（tkact_id 先后指向自制 act 646 / 现成 act 527）。
- 实测: 使用技能后动画可播放（act 527 明显可见；act 646 与普攻动作几乎相同，0 伤害时难以分辨是否播放），但**无伤害数字、目标 HP 不变**。
- 对照: 同一角色**普通攻击动画与伤害完全正常**。

## 二、排查中逐一验证"正常"的环节

以后遇到"自定义技能无伤害"先跑这张清单，全部排除后再进代码找特判：

| 环节 | 验证方法 | 本案结果 |
| --- | --- | --- |
| TKSkill 记录 | skill_editor 字段表逐字段 | `sub_count[90]=0`（直接技能非组头）、`atk_type[92]=0`、其余干净 ✓ |
| 技能装备与学习状态 | 读存档 sav.N（save_editor.load_save_data） | 指令槽 `field[83]=128` ✓；`learn[128]=20`（装备列表取 `[20,40)` 区间，20 是正确的可装备态）✓ |
| WarPC 效果槽 | 存档与 WarPC.dat 模板各读一遍 | `field[401]=646` 两边一致 ✓（队伍成员运行时取**存档**的完整记录，模板改动需重开档/重招募才进存档） |
| TKKon 记录 | kon_editor 字段表 | exec_mode=0x200（半径2菱形）、target_filter=0x100（仅角色+对立）、tkact_id、hp_damage=-1、exec_flags=4（物理）——语义全部有效 ✓ |
| TKAct 记录 | act_editor 字段表 | 总时长 `[2]=20`、触发帧 `[4..11]`、各图层 type/block/frames 与 Aa/Af.JVG 实际块数帧数全部匹配 ✓ |
| 启动器补丁 | 日志 grep `tkkon_expand|tkact_expand` | `基址引用 19/19`、`4/4` 全部重定向 ✓；且 kon/act 646 < 原版 650 条，`prepare_warpc_for_game` 的预截断不影响 ✓ |
| MOD 覆盖 | launcher_config.json 的 mods 启用表 + 日志"合并 MOD 数据"段 | 整合包未启用，仅 wm.JVG/Mu.JVG 界面资源合并 ✓ |
| EXE 一致性 | md5 对比 | I: 与 E: 的 TKS.exe 相同，反编译导出适用于两处 ✓ |

以上全部正常后，问题只剩"代码按技能号走的隐藏分支"。

## 三、关键实验：换 tkact_id 快速二分

把 kon 的 `tkact_id` 改成一个**现成的、视觉差异明显的动画**（本案换成 act 527）再实测：

- 动画跟着变了 → **kon 记录被正常读取、act 管线正常** → 问题锁定在伤害结算一层；
- 动画没变 → kon 没被读到，先回查效果槽/战斗副本链路。

这一步把"动画问题"和"结算问题"干净地分开，是本案的转折点。

## 四、根因：sub_4400DC 按技能号硬编码伤害公式

伤害结算入口 `sub_4400DC` (0x4400DC，反编译导出缺失，用 capstone + PE 节映射直接反汇编)。入口先把 kon 记录从工作副本 0x9D6C28 复制到 0x9D6C50，然后：

```asm
00440914  cmp word [0x9D6C30], 0     ; kon.hp_damage == 0 → 跳过整个 HP 结算
0044092e  cmp word [0x9D6C30], -1    ; == -1 → 替换为施法者攻击属性 field[12] (0x9D7092)
0044095a  movsx edx, [0x9D6C7C]      ; ← 按技能号 switch：
          ;  45 / 53 / 56 / 58 / 101 / 102 / 103 / 104 直接比较
          ;  技能 105..131 → 跳转表 0x4409C6 (26 项)
004409bf  jmp [edx*4 + 0x4409C6]     ; 技能 128 (edx=23) → 0x440D27
```

技能 128 专属分支 (0x440D27) 还原：

```c
// a1 = 施法者战斗槽位
weapon_atk = sub_42F86C(&battle_copy[527*a1]);
//   sub_42F86C: weapon_id = 记录字节 0x8A = WarPC field[69]（武器槽）
//               weapon_id == -1 → 返回 0（没武器 = 0 伤害）
//               否则返回 TKItem[weapon_id].field[11]（0x77CBE0 = TKItem 基址+22，武器攻击力）
level = 施法者 field[2] (0x9D707E);
kon.hp_damage = weapon_atk * ((level + 2) / 3);   // 整除
```

**实证**: 存档 sav.8 中 #201 的 `field[69..72] = -1,-1,-1,-1`（四个装备槽全空）→ 武器攻击力 = 0 → `hp_damage = 0` → 动画照播、无伤害数字。

**普攻为什么正常**: 普攻的"技能号"是 -1，不进这个 switch，`hp_damage=-1` 走替换攻击属性 field[12]（#201 = 41）的通用路径。

## 五、原版伤害公式特判技能号清单

来自 `sub_4400DC` 0x44095A..0x4409C6 的 switch 与跳转表（**这些技能号的伤害不受 kon.hp_damage 控制**）：

| 53 | 0x440ACE | 专属公式 |
| 56 | 0x440AFE | 专属公式 |
| 58 | 0x440B2F | 专属公式 |
| 101 | 0x440B8C | 专属公式 |
| 102 | 0x440BB7 | 专属公式 |
| 103 | 0x440BE5 | 专属公式 |
| 104 | 0x440C1A | 专属公式 |
| 105 | 0x440C4F | 专属公式 |
| 106 | 0x440C83 | 专属公式 |
| 113 | 0x440CB0 | 专属公式 |
| 114 | 0x440CE5 | 专属公式 |

其余技能号 → 0x440EBA 通用路径，kon 的 `hp_damage` 语义（-1 取攻击力 / 固定值 / 百分比）照常生效。
注意: 特判只覆盖 **hp_damage**；kon 的 tkact_id（动画）、选点范围/目标过滤确认仍按 kon 生效，附加命中、执行标志走共用结算路径（未逐一验证）。

## 六、修复与正确用法

1. **给角色装备武器**（推荐，符合断头斩设计意图）。等级系数 `(等级+2)/3` 速查: Lv4~6→×2、Lv7~9→×3、Lv10~12→×4、Lv20→×7、Lv30→×10。
2. **想用 kon 完全自定义伤害** → 换一个上表之外的技能号承载（注意同时迁移名称/说明/学习/装备配置）。
3. 使用特判技能号时，kon 只需要配 tkact_id、选点范围、目标过滤这些"表现层"字段。

## 八、经验教训

1. **"改了 kon 字段没效果" ≠ kon 没生效**。本案 kon 被正常读取（动画字段改了立即生效），唯独伤害字段被技能号特判覆盖。遇到"某个字段怎么改都不起作用"，先查该技能号是否在代码里有硬编码分支，再怀疑配置链。
2. **换 tkact_id 到现成动画**是区分"动画问题 / 结算问题"的最快二分，一分钟定位层级。
3. 反编译导出缺失的函数（sub_4400DC）用 capstone + PE 节映射直接反汇编即可；**switch 跳转表在反汇编输出里会显示成乱指令**（本案 0x4409C6 被反成 `add dword [si], eax`），要按"cmp 上界 + jmp [reg*4+表基址]"的形状识别出表位置，再按 dword 数组提取。
4. 排查顺序建议: 数据文件（编辑器存的**和**存档里的各读一遍）→ 启动器日志（补丁应用明细 / MOD 合并段 / 预截断警告）→ 资源块帧数 → 最后才是进代码找技能号特判。本案前四步各环节其实都没问题，但验证结论沉淀成了第二节的清单，下次同类问题可以十分钟走完。
5. 本案前期还顺带排除了两条容易误判的线: ①启动器对超原始大小的 dat 会**无条件预截断**（`.orig` 备份 + 扩容补丁注入），id < 650 的 kon/act 不受影响，别被日志里的 WARN 带偏；②"加载合集"日志只代表 MOD 包被解析列出，是否启用以 launcher_config.json 的 mods 表和日志"合并 MOD 数据"段为准。
