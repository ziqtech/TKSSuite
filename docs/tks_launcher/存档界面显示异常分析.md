# 存档界面显示异常 - 分析报告

## 问题描述

新增角色后，游戏存档界面出现以下异常：
1. 队伍角色头像全部显示为 WarPC 第 0 个角色
2. 没有按照实际队伍人数显示
3. 金钱数量显示为 0
4. 所在地图显示不正确

## 运行时日志分析

```
ok=True cave=0x08930000 base=0x00400000
warpc_expand=1 new_buf=0x08900000 new_size=152830
addr=29 field=245 size=5 scan=0x00401000-0x00700000
team=[0,-1,-1,-1,-1,-1,]
```

### 关键数据解读

| 项目 | 值 | 含义 |
|------|----|----|
| new_buf | 0x08900000 | WarPC 新缓冲区地址 |
| new_size | 152830 | = 145 * 1054 字节 (145 角色) |
| addr | 29 | 29 处基址引用被修补 ✓ |
| field | 245 | 245 处字段级引用被修补 |
| size | 5 | 5 处大小常量被修补 ✓ |
| team | [0,-1,-1,-1,-1,-1] | 队伍状态: 仅角色 0 |

## 存档系统架构

### 存档文件格式 (save\sav.X)

```
[区块1: TKMat 压缩数据 (地图/场景状态)]
[区块2: 游戏状态压缩数据]
    ├─ 前 3432 字节: unk_755B18 (系统配置)
    ├─ 中 5768 字节: unk_756880 (队伍/金钱/统计)
    │   ├─ word_75688C (+12): 队伍角色索引数组 [6 words]
    │   ├─ word_757EBA (+5690): 胜利次数
    │   ├─ word_757EBC (+5692): 败北次数  
    │   └─ ... 其他运行时全局状态
    └─ 后 WarPC_Size 字节: 角色数据 (修补后 = newSize)
```

### 关键函数

| 函数 | 地址 | 作用 |
|------|------|------|
| sub_410ED4 | 0x410ED4 | 保存存档到文件 |
| sub_41103C | 0x41103C | 从文件加载存档 |
| sub_412688 | 0x412688 | 重新加载/初始化 (含清零全局区) |
| sub_41A080 | 0x41A080 | 存档信息预览渲染 |

### sub_412688 (重新初始化) 流程

```
1. sub_452544(aTkmatDat_0, ...) → 保存 TKMat 到磁盘
2. sub_45343C(aWarpcDat, word_757F08, 150722) → 从磁盘重新加载 WarPC
   [修补后: sub_45343C(aWarpcDat, newBuf, newSize)]
3. sub_4B00FC(&unk_756880, 0, 5768) → 清零全局状态区!
   ⚠️ 包括 word_75688C (队伍), word_757EBA/BC (统计) 等
4. word_75688E~word_756896 = -1 (队伍槽位 1~5 设为空)
5. word_756884~word_75688A = WarPC[0].field_27~30
6. 初始化显示
```

**注意**: 步骤 3 清零了全局区域后, 只部分恢复了数据:
- word_75688C[0] = 0 (未恢复! 被 memset 为 0)
- word_75688C[1..5] = -1 (步骤 4)
- word_757EBA, word_757EBC = 0 (未恢复!)
- word_756888 (金钱) = WarPC[0].field_29 (从角色0读取)

## 根因分析

### 假设 1: sub_412688 清零导致数据丢失 (最可能)

**触发条件**: 游戏在某些状态转换时调用 sub_412688, 执行 `memset(0x756880, 0, 5768)`。

这会清零:
- word_75688C (队伍数组) → 全变为 0
- word_757EBA/BC (胜败统计) → 变为 0
- word_756888 等 → 变为 0

之后只恢复了部分值, 队伍和金钱没有恢复。

**证据**: 日志 `team=[0,-1,-1,-1,-1,-1]` 精确匹配 sub_412688 清零后的状态。

### 假设 2: 存档保存/加载偏移错误

如果存档保存时使用了修补后的 newSize, 但加载时中间区域偏移计算有误, 可能导致 5768 字节全局状态区域读取位置错误。

但从代码分析, 5768、3432、9200 都不在修补范围内, 且是动态计算, 应该正确。

### 假设 3: 字段级扫描误修补

扫描范围 0x401000-0x700000 可能包含非代码区域的数据。但验证结果显示 0x4E6000-0x5E6000 区域无匹配值。需进一步验证 0x5E6000-0x700000 区域。

## 下一步诊断方案

需要在**游戏运行中** (而非启动时) 读取关键全局变量:
1. 在存档界面打开前/后读取 word_75688C (0x75688C, 12字节)
2. 读取 word_757EBA (0x757EBA, 2字节) 和 word_757EBC (0x757EBC, 2字节)  
3. 确认 sub_412688 何时被调用

## 修补建议

如果确认是 sub_412688 清零导致, 需要在清零后增加数据恢复逻辑:
- 从存档文件重新读取全局状态区域
- 或在清零前备份 word_75688C 和 word_757EBA/BC, 清零后恢复
