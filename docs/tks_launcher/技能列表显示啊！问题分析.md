# 新角色"可装备技能列表"出现"啊！"问题分析（v2 终极版）

> 本文档基于游戏 PE 内存 dump 反向逆向严格验证，**不依赖项目内 dat_decoder 解码器的输出**。

## 一、问题现象

通过 `warpc_editor.py` 新增的 3 个角色（索引 143/144/145，截图为颜良/文丑/华雄）在游戏中：

1. 右键菜单 → 切换到"技能"页签
2. 在右侧"装备技能"区点击第 1 / 2 个槽位按钮
3. 弹出的"可装备技能列表"中**首项显示为"啊！"红字**

原游戏自带的 143 个角色没有此问题，仅新增的 143/144/145 才出现。

---

## 二、第一次分析的错误

第一次分析（已废弃）认为根因是用户在 warpc_editor 中误为 TKSkill[0] 设置了"已学"状态，依赖 dat_decoder.py 的 `tkt.get(-name_id)` 推断"TKSkill[0].name_id=0"是无效占位。

实际通过对内存 dump（`运行时转储\memory\006E6000--007E6000.txt`）逐字节解析 350 条 TKSkill 记录，发现：

| idx | name_id | type | 说明 |
|---|---|---|---|
| 0 | **9101** | 0 | 名字 ID 是 9101，不是 0 |
| 1 | 9102 | 0 | 兵法 |
| 2 | 9103 | 0 | 七星陣 |
| ... | ... | ... | ... |
| 343 | 9444 | 3 | (普通攻击/最后一条移动技) |
| **344** | **0** | **0** | **空记录，name_id=0** |
| **345** | **0** | **0** | **空记录** |
| **346** | **0** | **0** | **空记录** |
| **347** | **0** | **0** | **空记录** |
| **348** | **0** | **0** | **空记录** |
| **349** | **0** | **0** | **空记录** |

即 TKSkill 数组容量是 350，但**有效记录只有 344**（idx 0~343），末尾 idx 344~349 是 6 条全零的空记录。第一次分析错误地把 TKSkill[0] 当成无效占位，实际上 TKSkill[0]（name_id=9101）是有效的技能。

## 三、真正的根因（铁证）

### 3.1 sub_4189BC 扫描上限是 350

文件：`运行时转储\decompile\4189BC.c` 第 60~82 行：

```c
v8 = (char *)&word_757F08[527 * a2 + 88] + v12;   // skill_learn[v12]
v7 = (_WORD *)(94 * v12 + 7889358);               // TKSkill[v12].field[2] (type)

while ( v13 < 9 && v12 < 350 )                    // <<< 扫描 v12 = 0~349
{
    if ( (char)*v8 >= v10 && (char)*v8 < v9 && *v7 == v11 ) {
        ...
        *v5 = v12++;  // 加入列表
        ...
    } else { ++v12; }
}
```

`v12 < 350` 让循环扫描所有 350 条 TKSkill，包括 idx 344~349 的空记录。

> **逆向核对**：`4189BC.c:59-61` `v7=94*v12+7889358`(TKSkill[v12].type)、`v8=&word_757F08[527*a2+88]+v12`(skill_learn[v12]=byte176+v12)、`while(v13<9 && v12<350)` 逐行确认；函数内**两处** `v12<350` 循环（:61 / :91）恰对应补丁十六的两个改点（0x18BB5 / 0x18C3F）。TKSkill 94B/条、skill_learn 344B、byte[520-525]=WORD[260-262] 均与相关文档一致。

### 3.2 WarPC.skill_learn 实际只有 344 字节

`warpc_editor.py` 第 50 行（与游戏代码 `WarPC[a].byte[176+v12]` 一致）：

```
[88]-[259] skill_learn — 技能学习状态 (344 技能 × 1 byte; 反编译验证: 不会/等待学/可以学/父技/独立技)
```

- 字段 [88]~[259] 共 172 word = **344 字节**
- 字节范围 byte[176..519]
- 即 `skill_learn[0..343]`，**真正只占 344 个字节**

但 sub_4189BC 中循环 v12 = 0~349 时：

- `v12 = 344` → 访问 `byte[176 + 344] = byte[520]`
- `v12 = 345` → `byte[521]`
- `v12 = 346` → `byte[522]`
- `v12 = 347` → `byte[523]`
- `v12 = 348` → `byte[524]`
- `v12 = 349` → `byte[525]`

### 3.3 byte[520..525] 是启动器补丁专用字段（关键！）

来自 `warpc_editor.py` 第 282~283 行：

```python
("awk_sprite_id",      520, "战场图集索引（补丁专用）",
    "战斗中Awk.JVG/Awt.JVG块号 — 配合运行时补丁使用; ..."),
("portrait_menu_id",   522, "队伍头像ID（补丁专用）",
    "队伍菜单中Mu.JVG精灵块号 — 配合运行时补丁使用; ..."),
```

- `byte[520]` = WarPC field[260] 低字节 = **awk_sprite_id 低字节**（战场图集索引）
- `byte[521]` = WarPC field[260] 高字节
- `byte[522]` = WarPC field[261] 低字节 = **portrait_menu_id 低字节**（队伍头像 ID）
- `byte[523]` = WarPC field[261] 高字节

这正是 `tks_launcher.cs` 补丁二（[补丁二] AwkSprite cave 读 WORD[260]）和补丁三（[补丁三] 队伍头像 cave 读 WORD[261]）用来支持新角色自定义形象/头像的字段。

### 3.4 触发链路（每一步都有运行时数据证据）

```
用户在 warpc_editor 给颜良 (143) 设置:
  awk_sprite_id (WORD[260])  = 例如 32 (0x20)   ← 任何 byte ∈ [20, 39] 都会触发
  portrait_menu_id (WORD[261]) = 例如 22 (0x16)
        ↓
保存后 WarPC.dat 中 byte[520] = 0x20、byte[522] = 0x16
        ↓
游戏启动, sub_4189BC(角色=143, 菜单类型=4或5) 构建可装备技能列表:
  v11 = 0  (type=指令)
  v10 = 20, v9 = 40
        ↓
循环 v12 = 0 → 1 → ... → 343 → 344 → 345 → ...
  v12 = 344: *v8 = byte[176+344] = byte[520] = 0x20 (= 32)
             *v7 = TKSkill[344].word[2] = 0  (空记录的 type 字段)
             条件 (32 >= 20) AND (32 < 40) AND (0 == 0) → 全部满足
             ✗ 触发: 把 idx=344 写入列表 *v5++ = 344
        ↓
sub_418C90 渲染列表项 idx=344 的名称:
  v2 = sub_4067E8(word_7861CA[47 * 344])
     = sub_4067E8(TKSkill[344].name_id)
     = sub_4067E8(0)   ← 因为 TKSkill[344] 是空记录, name_id=0
        ↓
sub_4067E8(0) 在 TKT ID 数组中找不到 0:
  TKT 中所有 name_id 都是 9101+ (TKSkill 名称) 或其它正/负数, 没有 0
  → 走兜底分支 return dword_8242F8 (TKT 字符串区基址, 即第一条字符串)
  → 第一条字符串恰好是 "啊！" (TKT[0] = TkTalk.txt 中 ID=0 的字符串)
        ↓
列表项显示 "啊！"
```

## 四、为什么原 143 个角色不受影响

原 143 个角色全部由游戏官方制作：

- 它们不需要"自定义战场形象/头像"，因为有内置的硬编码精灵索引计算（`portrait + 211` 等）
- 它们的 `WarPC.dat` 中 byte[520..525] = 0x00（默认全零）
- `(char)*v8 = 0` 时 `0 >= 20` 为假，不进入列表
- 因此 idx 344~349 永远不会被 sub_4189BC 加入"已学"列表，"啊！"不出现

新角色 143/144/145：

- 由用户通过 `warpc_editor.py` 创建
- 需要在 `awk_sprite_id` (WORD[260]) 设置自定义战场精灵块号
- 需要在 `portrait_menu_id` (WORD[261]) 设置自定义队伍头像帧号
- 这些值很容易落在 byte ∈ [20, 39] 区间（多数 JVG 帧号小于 50）
- 立刻被 sub_4189BC 误判为"已学了 TKSkill[344..349]"

## 五、修复（已实施，启动器层补丁）

### 5.1 这是 `tks_launcher.cs` 启动器的问题

启动器补丁二/补丁三启用了 `WORD[260]` / `WORD[261]` 的新语义（自定义形象/头像），但 sub_4189BC 中 `v12 < 350` 的循环上限没有相应缩窄到 344，导致这两个字段被误读为 skill_learn 状态。

### 5.2 补丁十六（已加入 StaticPatches）

在 `tks_launcher.cs` 中新增：

```csharp
// [补丁十六] sub_4189BC 可装备技能列表扫描上限 350→344
new Patch {
    RVA = 0x18BB5, Data = new byte[] { 0x58 },
    Desc = "SkillList scan upper bound 350->344 (sub_4189BC main loop)"
},
new Patch {
    RVA = 0x18C3F, Data = new byte[] { 0x58 },
    Desc = "SkillList scan upper bound 350->344 (sub_4189BC page check)"
},
```

#### 5.2.1 反汇编验证

从 PE 内存 dump 提取 sub_4189BC（0x4189BC）的机器码，定位到两处 `cmp word [ebp-04h], 0x015E`（即 `cmp v12, 350`）：

```
0x00418BB1: 66 81 7D FC  5E 01    cmp word [ebp-04], 0x015E    ← 主循环判定
0x00418BB7: 0F 8C 33 FF FF FF    jl   sub_4189BC.loop_start    ← 跳回循环

0x00418C3B: 66 81 7D FC  5E 01    cmp word [ebp-04], 0x015E    ← 第二段翻页判定
0x00418C41: 7D 47                jge  ...
```

`0x015E` = 350（little-endian 编码 `5E 01`），改为 `0x0158` = 344 即可（仅修改低字节 `5E → 58`）。

#### 5.2.2 字节级补丁

| RVA | 原字节 | 改后 | 作用 |
|---|---|---|---|
| `0x18BB5` | `5E` | `58` | sub_4189BC 主循环 `v12 < 350` → `v12 < 344` |
| `0x18C3F` | `5E` | `58` | sub_4189BC 翻页判定 `v12 < 350` → `v12 < 344` |

补丁后 sub_4189BC 严格只扫描有效技能 idx 0~343，永远不会访问 byte[520+]，与 WarPC field[260+] 的字段语义不再冲突。

### 5.3 为什么不修 `warpc_editor.py`

第一次分析错误地修改了 warpc_editor.py（已撤销）。实际上：

- 用户在 warpc_editor 中设置 `awk_sprite_id` / `portrait_menu_id` 是**正常使用启动器补丁二/补丁三**的标准操作，不应该被限制
- 这两个字段必须能自由设置任意 16 位值（包括 [20, 39] 范围）才能匹配 JVG 资源
- 真正的责任方是游戏的 `sub_4189BC`：循环上限应该匹配实际有效 TKSkill 数量（344），而不是数组容量（350）

### 5.4 不能做的"伪修复"

- ❌ **限制 `awk_sprite_id` / `portrait_menu_id` 不能取 [20, 39]**：会让大量合法 JVG 帧号不可用
- ❌ **在 warpc_editor 保存时清零 byte[520..525]**：会破坏新角色自定义形象功能
- ❌ **改 TKSkill[344..349] 的 name_id 为有效 ID**：会让 6 条无意义技能出现在列表中
