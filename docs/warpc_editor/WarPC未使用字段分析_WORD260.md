# WarPC.dat 未使用字段分析 — 战场图集索引存储位置

## 概述

为了给运行时补丁提供可配置的 Awk.JVG/Awt.JVG 武器精灵块号，需要在 WarPC.dat 中找到当前所有角色均为 0、未被任何反编译函数引用、且完全可通过 warpc_editor 持久化保存的字段。

经过反编译引用搜索 + 内存 dump 交叉验证，确认 **WORD[260-262]（字节 520-525）与 WORD[267]（字节 534）** 均为未使用的全零间隙，皆为合格候选。

> **当前实现（以 `warpc_editor.py` 为准，已修正本文早期结论）**：编辑器最终把三个补丁字段落在连续的 WORD[260-262]（见 `warpc_editor.py` 字段布局注释 [260]-[262]）：
> - `[260] awk_sprite_id` — 战场图集索引（补丁专用）
> - `[261] portrait_menu_id` — 队伍头像 ID（补丁专用）
> - `[262] history_text_id` — 历史文本 ID（补丁专用）
>
> WORD[267] 仍是等效的未使用零槽，但**已不再是最终选用位**。下文对全部空槽的候选分析依然成立，仅"选用位"由 [267] 改为 [260-262]。

## 四、最终方案：WORD[267]（字节 534）

### 选用理由

1. **独立间隙** — 位于 growth_late(266) 与 jp_reward(268) 之间，前后字段语义明确
2. **经验证全零** — 内存 dump 三角色确认，与 WORD[260-262] 同样为零
3. **足够存储** — 一个 WORD 存 Awk.JVG 块号（0~255）绰绰有余
4. **编辑器零改动保存** — LZSS 压缩/解压透明处理全部 527 WORD
5. **WORD[260-262] 保留** — 3 个 WORD 留作以后扩展使用（如 Awt.JVG 独立块号、备用）

### 编辑器配置（v1.3）

```
字段名:  awk_sprite_id
偏移:    520 (WORD[260])
标签:    战场图集索引（补丁专用）
```

值为 0 时使用原硬编码公式。非零时补丁读取此值作为武器精灵块号。

## 五、补丁配合

运行时补丁将 `sub_4307CC` 中两处硬编码偏移替换为从此字段读取：

```
原始逻辑:
  PATH 1 (玩家, line 120):  v26 += 6  → Awk.JVG = WarPC索引 + 6
  PATH 2 (敌方, line 236):  v26 += 12 → Awk.JVG = WarPC记录号 + 12

补丁后等效逻辑:
  offset = WarPC[v26].WORD[260];   // 须与编辑器持久化的 awk_sprite_id 偏移(字节520)一致
  v26 += (offset != 0) ? offset : (PATH==1 ? 6 : 12);
```
