# 战斗经验溢出（变为负数）逆向分析

> **逆向证据来源**：攻击结算函数 `sub_4400DC`（0x4400DC–0x442AAE，未反编译，见 `disassembly/4400DC.asm`）、战后经验分配函数 `sub_43B7FC`、战斗初始化 `sub_4307CC`。以下地址、变量名与指令序列均逐条核对无误。

## 分析结论：战斗经验溢出变为负数的根因

### 根本原因：`movsx` 指令对敌人等级字节的符号扩展

**这是最直接、最容易触发的根因。**

在攻击结算函数 `sub_4400DC` 中，目标单位等级 `byte_9DF781[unit]` 被读取时使用 **`movsx`（带符号扩展）** 指令。该数组在战斗初始化时由关卡数据复制而来（见下文触发过程第 2 步）。

**击杀奖励路径（0x4418C3，disassembly/4400DC.asm 第 1665–1693 行）**：
```asm
4418BB: movsx   eax, word_9D7084[ecx*2]   ; 目标单位数据(每单位527字, 偏移0)
4418C3: movsx   ecx, byte_9DF781[edx]     ; ★ 目标等级带符号扩展
4418CA: imul    ecx                        ; × 等级
4418CD: mov     ecx, 3
4418D2: idiv    ecx                         ; / 3
4418E3: movsx   edx, word_9D7084[edx*2]
4418EB: add     eax, edx                    ; + 单位数据
4418F5: add     [ebp+var_48], eax           ; ×1.5 (var_48 = v + v>>1)
4418FF: add     dword_9D6F20[ecx*4], eax    ; 累加到击杀者"个人经验"(int32/角色)
441906: shl     [ebp+var_48], 1             ; ×2
441919: add     dword_9D6F14, edx           ; 累加到"经验池"
```

**伤害附带经验路径（0x441B58，disassembly/4400DC.asm 第 1828–1845 行）** — 受 `byte_9DF761` 条件门控：
```asm
441B3A: movsx   ecx, byte_9DF761[edx]      ; 门控: byte_9DF761[攻击者] == 100 ?
441B44: jnz     short loc_441B77
441B49: movsx   edx, byte_9DF761[eax]      ; 门控: byte_9DF761[目标]  < 10 ?
441B53: jge     short loc_441B77
441B58: movsx   eax, byte_9DF781[ecx]      ; ★ 目标等级带符号扩展
441B5F: imul    [ebp+var_24]               ; × 伤害值(var_24)
441B62: mov     ecx, 3
441B68: idiv    ecx                          ; / 3
441B6D: add     eax, [ebp+var_24]           ; + 伤害值
441B6F: add     eax, eax                     ; × 2
441B71: add     dword_9D6F14, eax           ; 累加到"经验池"
```

> **关键区分**：`byte_9DF761` 与 `byte_9DF781` 是两个不同的每单位字节数组。`byte_9DF761` 用于上述条件门控；真正参与经验公式、导致符号溢出的是 **`byte_9DF781`（单位等级）**。原文档曾混淆二者，此处以反汇编为准更正。

`movsx` 将字节作为**有符号数**解释（范围 -128 ~ +127）。当 MOD 将敌人等级设置为 **≥ 128** 时（如150、200等），该字节被解释为负数：

| 实际等级字节值 | movsx 解释 | 经验公式中 (level+3)/3 | 效果 |
|---|---|---|---|
| 127 (0x7F) | +127 | 43.3 (正常) | 正常经验 |
| **128 (0x80)** | **-128** | **-41.7** | **经验变负** |
| 150 (0x96) | -106 | -34.3 | 大量负经验 |
| 200 (0xC8) | -56 | -17.7 | 负经验 |
| 255 (0xFF) | -1 | 0.67 | 接近零 |

### 触发过程

1. **MOD 设置敌人等级 ≥ 128**: 关卡数据 `byte_953830` 存储敌人等级为原始 byte (0-255)
2. **战斗初始化原样复制**: 在 `sub_4307CC` 第226行 `*v15 = *v9` 直接复制到 `byte_9DF781`
3. **攻击时 movsx 符号扩展**: 等级 ≥ 128 被解释为负数
4. **经验公式产出负值**: `2 × damage × (negative_level + 3) / 3` = 负数
5. **累积到经验池**: `dword_9D6F14 += 负数` → 经验池变负
6. **战后分配无下界检查**: `sub_43B7FC` 第114行仅检查 `> 30000`，**完全没有 `< 0` 的保护**
7. **存入角色数据**: 负经验被写入 `current_exp` (int16)，显示为负数

### 数值实例

MOD 设敌人等级 = 200 (实际被解释为 -56)，角色造成 500 伤害，未击杀：
```
经验 = 2 × ((-56 × 500) / 3 + 500)   ; 对应 imul → idiv 3 → add 伤害 → add eax,eax
     = 2 × (-9333 + 500)
     = 2 × (-8833)
     = -17666
```
每次攻击命中，经验池**减少 17666**。

### 次要原因：exp_bonus 乘法的 int32 溢出

即使敌人等级 < 128（保持正数），当以下条件同时满足时，战后分配阶段也可能产生负经验：

**条件组合**:
- 大量高等级(如 Lv100~127)、高 HP 敌人被同一角色击杀
- 角色拥有较高的 `exp_bonus`（如"鬼才"类特性 ≥ 120%）

**溢出路径** — `sub_43B7FC` 第102-104行:
```c
*v19 += dword_9D6F14;                    // 第102行: 先加"经验池"(击杀分支已限幅 ≤ 30000)
if ( v18[31] )
  *v19 += (v18[31] * *v19 + 99) / 100;   // 第104行: 再按 exp_bonus 放大
```

其中 `*v19` 指向 **`dword_9D6F20[角色]`** —— 每角色的"个人经验累积器"(int32)，在战斗中于 `0x4418FF (add dword_9D6F20[ecx*4], eax)` 处**逐次击杀累加且不限幅**。

> **重要更正**：`dword_9D6F14`(经验池)在击杀分支 `43B7FC.c` 第 79–82 行已被限幅 ≤ 30000，故**溢出的真正载体是未限幅的 `dword_9D6F20`，而非经验池**。第 114 行的 `> 30000` 限幅发生在乘法**之后**，无法阻止乘法阶段的 int32 溢出。

当 `v18[31]`（exp_bonus, int16）× `*v19`（`dword_9D6F20[角色]`, int32）超过 INT32_MAX (2,147,483,647) 时，乘积**溢出翻转为负数**。

**数学验证** (exp_bonus=150%, 个人经验累积=15,000,000):
```
150 × 15,000,000 = 2,250,000,000 > INT32_MAX
溢出后: 2,250,000,000 - 4,294,967,296 = -2,044,967,296
bonus = (-2,044,967,296 + 99) / 100 = -20,449,672
最终经验 = 15,000,000 + (-20,449,672) = -5,449,672 (负数!)
```

此场景需 **`dword_9D6F20[角色]` 累积达到千万级**，对应战斗条件为：约 25~30 个 Lv100+ HP15000+ 敌人被同一角色击杀。属后期高难度 MOD 才可能出现的边界情形。

---

### 为什么原版游戏不会触发

1. 原版敌人最高等级约 57~60，远低于 128 阈值
2. 原版 HP 上限和等级组合下，经验累积不会达到 int32 溢出阈值
3. 原版 exp_bonus 值较低(通常 10~50%)

### 根本修复方向

| 问题 | 修复方式 |
|------|---------|
| 等级 ≥ 128 符号问题 | 经验计算时改用 `movzx`（无符号扩展）替代 `movsx` |
| 乘法溢出 | 在 `exp_bonus × *v19` 前先做上限截断，或使用 64 位中间变量 |
| 缺少下界保护 | 在 `*v19 > 30000` 检查后增加 `if (*v19 < 0) *v19 = 0` |
