# WarPC 掉落物品概率分析

基于 `TKS.exe` 反编译代码对 WarPC 三个掉落槽位的真实概率分析。所有结论已逐行核对反编译源码，验证通过。

> **编辑器标签已于 2026-07-01 恢复**：标签恢复为「必掉落物品 / 高概率掉落 / 低概率掉落」。此前短暂使用的"常规掉落(80%)/普通掉落(15%)/稀有掉落(5%)"标签已被确认仅描述探寶技能（action 239）的成功率，不代表死亡掉落（路径 A）的实际概率。详见第 8 节。

---

## 1. 数据结构

WarPC 每条记录 1054 字节，共 527 个 int16 字段。三个掉落槽位位于：

| 字段名 | 字段索引 | 字节偏移 | 编辑器标签 | 存储内容 |
|---|---|---|---|---|
| `drop_item0` | 270 | 540 | 必掉落物品 | 物品 ID（0=无） |
| `drop_item1` | 271 | 542 | 高概率掉落 | 物品 ID（0=无） |
| `drop_item2` | 272 | 544 | 低概率掉落 | 物品 ID（0=无） |

这三个字段存储的是**物品 ID**（int16），不是概率值。概率逻辑完全硬编码在游戏引擎中。路径 A（死亡掉落）概率：100/20/5；路径 B（探寶技能）概率：80/15/5。

### 1.1 游戏内存数组

每个怪物拥有独立的三个掉落槽位，stride = 527：

| 槽位 | 内存地址 | 填充优先级 | 被写入位置 |
|---|---|---|---|
| 常规槽（第1槽） | `word_9D7296[527 * monsterId]` | 最先填充 | `sub_434510` 写入、`sub_4458B0` 掉落成功后清零 |
| 普通槽（第2槽） | `word_9D7298[527 * monsterId]` | 第二填充 | `sub_434510` 写入、`sub_4458B0` 掉落成功后清零 |
| 稀有槽（第3槽） | `word_9D729A[527 * monsterId]` | 最后填充 | `sub_434510` 写入、`sub_4458B0` 掉落成功后清零 |

### 1.2 掉落结果缓冲区

掉落判定后将物品写入临时结果缓冲区，战斗结束后统一发放给玩家：

| 变量 | 含义 |
|---|---|
| `word_9D6F12` | 掉落计数器，战斗开始时清零（`sub_436BD4`），每掉一件 +1，上限 **64** |
| `word_9D6E12[2 * idx]` | 掉落结果数组——物品 ID |
| `word_9D6E14[2 * idx]` | 掉落结果数组——物品数量 |
| `memset(word_9D6E12, 0, 0x100)` | 战斗开始时清零 256 字节（`sub_436BD4` 第 21 行） |

掉落物品的发放发生在 `sub_43B7FC`（第 146-153 行），遍历 `word_9D6F12` 个条目，逐个调用 `sub_40CE30`（物品获得函数），数量上限 99。

## 2. 槽位分配逻辑

来源：`decompile/434510.c`（`sub_434510`，第 57-72 行）

### 2.1 函数调用链

```
sub_43CA64（主游戏循环）
  └── sub_4355C4（帧更新）
        └── sub_435240（怪物掉落处理）
              └── sub_434510(v4)  ← 我们分析的函数
```

`sub_435240` 在每个游戏帧为当前活动怪物运行，前提是：
1. 怪物仍有剩余资源（`word_9D7084[527 * monsterId] > 0`）
2. 有待处理的掉落坐标（`byte_9537D5 > 0`，由寻路函数 `sub_43E57C` 在怪物移动时填充）

### 2.2 双分支结构

`sub_434510` 内部有一个关键分叉（第 34 行）：

```c
if ( byte_9DF761[word_9D6F58] == 100 )   // 怪物存活（在地图上活跃）
{
    // 分支A：直接将物品排入掉落队列（word_9D6E12/word_9D6E14）
    // 处理物品数量随机化
}
else                                      // 怪物已死亡
{
    // 分支B：将物品 ID 写入持久槽位（word_9D7296/7298/729A）
    // 这些槽位随后由 action 239 在战斗中读取
}
```

**槽位分配（第 57-72 行）位于分支 B**——只有已死亡的怪物才会将物品写入三个持久槽位。存活怪物的掉落物品直接进入队列，不经过这三个槽位。

### 2.3 槽位分配代码

```c
// 分支B：非存活怪物，按优先级填充三个槽位
if ( word_9D7296[527 * word_9D6F58] )          // 常规槽（第1槽）已占用？
{
    if ( word_9D7298[527 * word_9D6F58] )       // 普通槽（第2槽）已占用？
    {
        if ( !word_9D729A[527 * word_9D6F58] )  // 稀有槽（第3槽）空？
            word_9D729A[527 * word_9D6F58] = itemId;  // → 稀有掉落(5%)
    }
    else
    {
        word_9D7298[527 * word_9D6F58] = itemId;       // → 普通掉落(15%)
    }
}
else
{
    word_9D7296[527 * word_9D6F58] = itemId;           // → 常规掉落(80%)
}
```

**分配规则**：按填充优先级从高到低依次填充（常规槽 → 普通槽 → 稀有槽）。怪物定义多个掉落物品时：

- 第 1 个物品 → 常规槽（第1槽）
- 第 2 个物品 → 普通槽（第2槽）
- 第 3 个物品 → 稀有槽（第3槽）

## 3. 掉落概率判定（核心）

来源：`decompile/4458B0.c`（`sub_4458B0` 动作分发器内 `word_9D6C7C == 239` 分支，第 500-536 行）

### 3.1 触发条件

掉落概率判定仅在 `word_9D6C7C == 239` 时触发。**action 239 就是「探寶」技能**（TKSkill 索引 239，名称文本 ID 9340）。当玩家对目标敌人使用探寶技能时，技能引擎（`sub_438F28`）将技能索引 239 入队到动作队列 `word_9D6D1A` 中（`decompile/438F28.c` 第 37 行：`word_9D6D1A[word_9D6C8A] = v7`，其中 `v7` 是技能索引）。随后战斗状态机 `sub_447DAC` 出队并设置 `word_9D6C7C = 239`，`sub_4458B0` 分发执行——即下文的级联掉落结算。

### 3.2 随机数生成

```c
v7 = sub_452AC0(1000);  // 生成均匀随机数，范围 0~999
```

`sub_452AC0`（`decompile/452AC0.c`）封装了自定义 PRNG `sub_452968`（`decompile/452968.c`）：

- **PRNG 算法**：XOR 型 lagged Fibonacci generator（滞后斐波那契生成器），状态表 `word_A2C6AC` 共 249 个 16 位字，索引 `dword_A2C6A8`
- **去偏采样**：使用 rejection sampling 消除模偏差——当 `sub_452968()` 返回值 ≥ `a1 * (0xFFFF / a1)` 时重新采样，确保 `[0, a1-1]` 上的均匀分布

### 3.3 级联判定逻辑

判定顺序：先检查稀有槽 → 再检查普通槽 → 最后检查常规槽。判定优先级与填充优先级相反——越稀有的槽位越先被检查。

```c
v7 = sub_452AC0(1000);                              // 随机数 0~999
v19 = byte_9D6FA4[0];                               // 目标怪物索引

// 第一级：检查稀有槽（第3槽）—— 判定优先级最高
if ( word_9D729A[527 * v19] <= 0 || v7 >= 50 )
{
    // 第二级：检查普通槽（第2槽）
    if ( word_9D7298[527 * v19] <= 0 || v7 >= 200 )
    {
        // 第三级：检查常规槽（第1槽）—— 判定优先级最低
        if ( word_9D7296[527 * v19] > 0 && word_9D6F12 < 64 )
        {
            // 掉落常规物品(80%)
            word_9D6E12[2 * word_9D6F12] = word_9D7296[527 * v19];
            word_9D6E14[2 * word_9D6F12++] = 1;
            v47 = sub_42F8D4(word_9D7296[527 * v19]);   // 查询物品数据
            word_9D7296[527 * v19] = 0;                  // 清空槽位，防止重复掉落
        }
    }
    else if ( word_9D6F12 < 64 )
    {
        // 掉落普通物品(15%)
        word_9D6E12[2 * word_9D6F12] = word_9D7298[527 * v19];
        word_9D6E14[2 * word_9D6F12++] = 1;
        v47 = sub_42F8D4(word_9D7298[527 * v19]);
        word_9D7298[527 * v19] = 0;
    }
}
else if ( word_9D6F12 < 64 )
{
    // 掉落稀有物品(5%)
    word_9D6E12[2 * word_9D6F12] = word_9D729A[527 * v19];
    word_9D6E14[2 * word_9D6F12++] = 1;
    v47 = sub_42F8D4(word_9D729A[527 * v19]);
    word_9D729A[527 * v19] = 0;
}

// 掉落后的表现处理
if ( v47 )
    sub_434188((int)v47, word_9D6F5A, word_9D6F5C);   // 播放物品获得动画/音效
else
    sub_433A38(word_9D6F58, (int)&unk_4EBC5A, 18);    // 显示"无掉落"文字
```

### 3.4 概率换算

判定使用**级联优先制**（互斥），不是独立概率判定。每次使用探寶技能（action 239）只掉落一件物品。这代表了探寶技能"从目标敌人身上摸出特殊战利品，但成功率不高"的机制——5% 摸到稀有物品、15% 摸到普通物品、80% 摸到常规物品。

| 槽位 | 触发条件 | 范围 | 概率 | 填充优先级 | 判定优先级 |
|---|---|---|---|---|---|
| 稀有掉落(5%) | `v7 < 50` | 0 ~ 49 | **50/1000 = 5%** | 最低 | **最高**（最先判定） |
| 普通掉落(15%) | `50 ≤ v7 < 200` | 50 ~ 199 | **150/1000 = 15%** | 中 | 中 |
| 常规掉落(80%) | `v7 ≥ 200` | 200 ~ 999 | **800/1000 = 80%** | 最高 | **最低**（最后判定） |

> **注意**：填充优先级和判定优先级是相反的。稀有槽填充最晚（怪物物品多时才轮到它），但判定时最先检查——这是为了保证稀有物品的 5% 不被其他槽位挤占。常规槽填充最早（怪物第一个物品必定进这里），但判定时最后检查——它作为默认/保底选项。

### 3.5 空槽回退机制

关键是 `||` 短路求值。当判定优先级更高的槽位为空（值 ≤ 0）时，条件直接为真，自动回退到下一级。

| 场景 | 稀有槽(5%) | 普通槽(15%) | 常规槽(80%) | 实际掉落 |
|---|---|---|---|---|
| 三个槽都有物品 | 5% | 15% | 80% | 完整分布 |
| 仅常规槽有物品 | 空→跳过 | 空→跳过 | → **100%** | 必定掉落 |
| 常规+普通有物品 | 空→跳过 | 15% | 85% | 不掉稀有 |
| 常规+稀有有物品 | 5% | 空→跳过 | 95% | 不掉普通 |
| 仅普通+稀有有物品 | 5% | 15% | 空→跳过→80%→空 | 20%概率无掉落 |

## 7. 掉落数量随机化

来源：`decompile/434510.c` 第 36-37 行（存活怪物分支）

```c
if ( word_953932[2 * v6] < word_953934[2 * v6] )
    word_953932[2 * v6] += sub_452AC0(word_953934[2 * v6] - word_953932[2 * v6] + 1);
```

- `word_953932[2 * v6]`：当前掉落数量
- `word_953934[2 * v6]`：最大掉落数量
- 数量在 `[word_953932, word_953934]` 范围内随机

与此相对，action 239 的掉落（`sub_4458B0`）数量固定为 1（`word_9D6E14[2 * word_9D6F12++] = 1`），不走数量随机化。

## 8. 两条掉落路径的关系 (最终结论)

游戏中存在**两条独立的掉落结算路径**，读取相同的 `word_9D7296/7298/729A` 槽位数组，但服务于不同的游戏场景、拥有不同的概率结构和触发时机。

### 8.1 路径 A：死亡掉落（`sub_4400DC` @ `0x4419B7`）

**触发**：玩家攻击击杀怪物时自动运行。位于攻击动画处理函数 `sub_4400DC` 中，由 `sub_4434BC` 调用。触发条件：`HP≤伤害 && byte_9DF761[attacker]==100 && byte_9DF761[monster]<10`。

**概率结构**：**独立判定**——三个槽位各自判断（已逐条核对 `disassembly/4400DC.asm`）：
- 常规槽 `word_9D7296`（0x4419B7）：**无随机检查**（`cmp ...,0`/`jle` 后直接入队，非空且 cnt<64 必掉）→ **100%**
- 普通槽 `word_9D7298`（0x441A19）：`sub_452AC0(1000)` 后 `cmp ax, 0C8h`(200) `jnb 跳过` → `rand < 200` → **20%**
- 稀有槽 `word_9D729A`（0x441A8C）：`sub_452AC0(1000)` 后 `cmp ax, 32h`(50) `jnb 跳过` → `rand < 50` → **5%**
- 随后 `0x441AFF: word_9D7084[unit]=0`（置死）。三槽互不排斥，一次击杀最多掉 3 件。

**特征**：不合格清零、不调用 `sub_42F8D4`/`sub_434188`（无物品显示动画）。一次击杀最多掉落 3 件。

### 8.2 路径 B：探寶技能（action 239 / `sub_4458B0` @ `0x4474DC`）

**触发**：玩家对目标使用「探寶」技能（TKSkill 索引 239，名称文本 ID 9340）。技能引擎 `sub_438F28` 将技能索引 239 作为动作码入队到 `word_9D6D1A`，战斗状态机 `sub_447DAC` 出队后 `sub_4458B0` 分发执行。证据：`sub_438F28` 第 37 行 `word_9D6D1A[word_9D6C8A] = v7`，其中 `v7` 为技能索引。

**概率结构**：**级联互斥**——一次 `rand(1000)` 决定唯一槽位。
- 稀有槽：`v7 < 50` → **5%**
- 普通槽：`50 ≤ v7 < 200` → **15%**
- 常规槽：`v7 ≥ 200` → **80%**

**特征**：会清零已掉落槽位（防重复）、调用 `sub_42F8D4` 查询物品、调用 `sub_434188` 播放掉落动画。每次使用探寶技能只掉落一件物品。空槽时自动回退到下一级。

### 8.3 概率差异总结

| 槽位 | 路径 A（死亡掉落） | 路径 B（探寶技能） |
|---|---|---|
| 常规（第1槽）| **100%** | 80% |
| 普通（第2槽）| **20%** | 15% |
| 稀有（第3槽）| 5% | 5% |

### 8.4 对编辑器标签的影响

由于大多数怪物仅在常规槽配置 1 个物品（普通槽和稀有槽为空），在路径 A（死亡掉落）下常规槽表现为 **100% 必定掉落**。旧标签"必掉落物品"在典型配置下是准确的。路径 B（探寶技能）的 80/15/5 概率是该技能特有的成功率设定，不代表死亡掉落概率。

编辑器标签已恢复为「必掉落物品 / 高概率掉落 / 低概率掉落」，提示中标注了两条路径各自的概率。

## 9. 总结

1. **两条独立路径**：路径 A（`sub_4400DC`，死亡掉落，独立 100/20/5）在攻击击杀时自动运行；路径 B（action 239 = 探寶技能，`sub_4458B0`，级联 80/15/5）由玩家使用探寶技能触发。两条路径读取相同的 `word_9D7296/7298/729A` 槽位。
