# Awk.JVG/Awt.JVG 战斗武器精灵映射机制 — 完整逆向分析

## 概述

战斗中角色渲染分两层：**身体/待机动画来自 Cha.JVG，武器/攻击叠加层来自 Awk.JVG（行动方）或 Awt.JVG（等待方）**。

核心发现：`sub_4307CC` 中存在**两条独立的初始化路径**，分别处理玩家队伍角色和战场敌方角色，使用不同的硬编码公式计算 Awk.JVG/Awt.JVG 武器精灵块号。

## 二、两条初始化路径 — 完整对比 (sub_4307CC)

`sub_4307CC` (4307CC.c) 是战斗模板初始化的核心函数，内部有两个循环，处理截然不同的角色来源：

### 2.1 PATH 1 — 玩家队伍 (4307CC.c:110-191)

遍历 6 个队伍槽位 (`word_75688C[0]~[5]`)，为每个在队角色初始化武器精灵。

```c
v14 = &dword_9DF43A;    // Awt.JVG 精灵数据数组
v11 = word_9D707A;      // 战斗模板数组 (527 WORD/槽)
v18 = word_75688C;      // ★ 来源：队伍成员 WarPC ID 数组

v28 = 0;
do {
    if (*v18 >= 0 && *v21) {
        v26 = *v18;     // ★ 角色的 WarPC 索引 (0~142)

        // 将角色 WarPC 记录完整复制到战斗模板 (1054字节)
        qmemcpy(v11, (const void *)(1054 * v26 + 0x757F08), 0x41Eu);

        sub_432668(v27);  // 装备初始化

        // ★★★ 武器精灵块号 ★★★
        if (v26) {          // 非主角 (WarPC ID ≠ 0)
            v26 += 6;       // → 武器精灵块 = WarPC索引 + 6
        } else {            // 主角 (WarPC ID = 0)
            // 根据当前装备武器类型映射块号
            // 刀(1)→1, 剑(2)→6, 枪(4)→5, 8→4, 16→3, 32→2
            v26 = weapon_type_mapping[...];
            word_9D6C84 = v26;
        }

        // 以 v26 为块号加载 Awt.JVG 和 Awk.JVG 精灵
        *v14 = sub_45410C(dword_951928, v26, 0);       // Awt.JVG
        v14[1] = sub_45410C(dword_95192C, v26, 0);     // Awk.JVG
    }
    ++v28; ++v21; ++v18;
} while (v28 < 6);
```

**公式：非主角玩家 → `武器精灵块 = WarPC索引 + 6`**（硬编码，不从任何配置字段读取）

### 2.2 PATH 2 — 战场敌方 (4307CC.c:220-319)

遍历战斗场景配置的额外敌方 (`word_9537FA[]`)，为每个敌方角色初始化武器精灵。

```c
v5 = &word_9537FA;      // ★ 来源：战斗场景敌方类型配置
v7 = (__int16 *)(1054 * v27 + 10317946);  // 模板写入位置

while (v28 < word_9D6F66) {    // word_9D6F66 = 敌方数量
    if (*v5 > 0) {
        v26 = *v5 + 35;         // ★ 敌方类型 → WarPC记录号
                                 // (敌方类型 0→WarPC35, 1→WarPC36, ...)

        // 将敌方 WarPC 记录完整复制到战斗模板
        qmemcpy(v7, (const void *)(1054 * v26 + 0x757F08), 0x41Eu);

        sub_430578(&word_9D707A[527 * v27], ...);  // 敌方属性随机化

        // ★★★ 武器精灵块号 ★★★
        if (v26 == 36) {        // 特殊：场景背景敌方
            v26 = word_9D6C84 + 42;
        } else {
            v26 += 12;          // → 武器精灵块 = WarPC记录号 + 12
        }

        // 以 v26 为块号加载 Awt.JVG 和 Awk.JVG 精灵
        *(_DWORD *)v12 = sub_45410C(dword_951928, v26, 0);       // Awt.JVG
        *(_DWORD *)(v12 + 4) = sub_45410C(dword_95192C, v26, 0); // Awk.JVG
    }
    ++v28; ++v9; ++v5;
}
```

**公式：战场敌方 → `武器精灵块 = (敌方类型 + 35) + 12 = WarPC记录号 + 12`**

### 2.3 两条路径对照表

| | PATH 1 — 玩家队伍 | PATH 2 — 战场敌方 |
|---|---|---|
| **数据来源** | `word_75688C[slot]` (队伍成员) | `word_9537FA[slot]` (敌方类型配置) |
| **WarPC 记录定位** | 直接使用 WarPC 索引 | `敌方类型 + 35` |
| **武器精灵公式** | `WarPC索引 + 6` | `(敌方类型 + 35) + 12` |
| **主角(ID=0)处理** | 特殊：武器类型映射(1~6) | N/A (敌方不会有 ID=0) |
| **v26==36 特殊** | N/A (玩家不会有记录36) | 使用 `word_9D6C84 + 42` |
| **属性处理** | 直接复制 WarPC 数据 | 复制后调用 `sub_430578` 随机化属性 |
| **适用角色** | 当前队伍的 6 人 | 战斗场景配置的额外敌方 |

### 2.4 硬编码偏移量汇总

| 常量 | 位置 | 含义 |
|------|------|------|
| `+6` | 4307CC.c:120 | 玩家路径：WarPC索引→武器精灵块的偏移 |
| `+12` | 4307CC.c:236 | 敌方路径：WarPC记录号→武器精灵块的偏移 |
| `+35` | 4307CC.c:224 | 敌方类型ID→WarPC记录号的偏移（敌方数据从WarPC 36开始） |
| `+42` | 4307CC.c:230 | 敌方类型36(场景背景)的额外偏移 |

### 3.2 敌方转我方 — 关键验证

用户将 WarPC 85 (颜良) 和 86 (文丑) 从"敌方"(role=0)改为"我方"(role=-1)并招募入队：

| 角色 | WarPC索引 | 作为敌方(PATH 2) | 改为我方(PATH 1) | 块号偏移 |
|------|----------|-----------------|-----------------|---------|
| 颜良 | 85 | 85+12=**97** | 85+6=**91** | 差6块 |
| 文丑 | 86 | 86+12=**98** | 86+6=**92** | 差6块 |

- **改为我方后实际显示**：颜良=91、文丑=92（用户实测，与公式吻合）
- **敌方时使用的块号**：97 和 98（PATH 2 的 +12 公式）
- **用户预期的块号** 87 和 88：不是敌方的 Awk.JVG 武器精灵块号，而是**敌方时 Cha.JVG 身体精灵的块号**（`WarPC[85].WORD[526] + 2`，敌方记录的 WORD[526] 非零，玩家记录为 0）

### 3.3 角色身份转换导致的问题

```
敌方颜良 (WarPC 85)                    我方颜良 (WarPC 85, role=-1)
┌──────────────────────┐              ┌──────────────────────┐
│ PATH 2 (敌方路径)     │              │ PATH 1 (玩家路径)     │
│                      │   改role     │                      │
│ Cha.JVG 身体:        │  ───────→   │ Cha.JVG 身体:        │
│   WORD[526] + 2      │   入队       │   0 + 2 = 2          │
│   = 85+2 = 87 ✓      │              │   (WORD[526]=0)      │
│                      │              │                      │
│ Awk.JVG 武器:        │              │ Awk.JVG 武器:        │
│   85 + 12 = 97 ✓     │              │   85 + 6 = 91 ✗      │
└──────────────────────┘              └──────────────────────┘
```

## 四、其他敌方初始化路径

除了 `sub_4307CC` 中的 PATH 2，敌方还可以通过以下函数动态加入战斗：

### 4.1 sub_431094 — 敌方召唤

```c
// 431094.c:27-32 — 敌方召唤模板初始化

    v8 = v7 + 12;   // ★ Awk.JVG = WarPC记录号 + 12
```

### 4.2 sub_444FD4 — 敌方增援

```c
// 444FD4.c:45-52 — 敌方增援模板初始化
```

**结论：所有敌方路径统一使用 `+12` 偏移，所有玩家路径统一使用 `+6` 偏移。**

## 五、解决方案

### 方案 A — 调整精灵资源位置（推荐，无需修改游戏代码）

将新增角色的 Awk.JVG/Awt.JVG 武器精灵数据放到玩家公式对应的块号：

| 角色 | WarPC索引 | 玩家公式 → 武器块 |
|------|----------|-----------------|
| 颜良 | 85 | 91 |
| 文丑 | 86 | 92 |

**优点**：无需修改游戏二进制。Cha.JVG 身体精灵（由 TKMat 实体的 d51 控制）不受影响。

**缺点**：新增角色越多，块号越分散；如果未来角色在敌方/我方之间转换，块号会变化。

### 方案 B — 运行时内存补丁（已设计，待 IDA 找 cave 空间后激活）

**已完成**：WORD[267] 编辑器集成、反汇编精确定位两个硬编码指令、代码 cave 汇编编写、patch_config.json 和 tks_launcher.cs 模板。

**补丁点**：

| 路径 | RVA | 原始指令 | 原始字节 |
|------|-----|---------|---------|
| PATH 1 (玩家) | `0x30A37` | `add [ebp-6], 6` | `66 83 45 FA 06` |
| PATH 2 (敌方) | `0x31162` | `add [ebp+8], 12` | `66 83 45 08 0C` |

**逻辑**：将 `add` 替换为 `call cave`，cave 中读取 `WarPC[v26].WORD[267]`，非零时用该值，为零时回退默认（6 或 12）。详见 `../tks_launcher/awk_sprite_patch_design.md`。

**待完成**：在 IDA 中找两段 ≥40 字节的连续空闲空间（CC/00 填充），计算 call 偏移填入配置。

### 方案 C — 调整 WarPC 索引排列

将新增角色放到特定 WarPC 索引，使 `索引+6` 自然对应目标 AwkJVG 块号：

例如要使 Awk.JVG = 87：需 WarPC 索引 = 87 - 6 = **81**。

**限制**：WarPC 索引影响存档、脚本引用等，需要同步更新所有关联数据。
