# TKT.dat 控制标签体系 — 逆向工程文档

> 基于游戏可执行文件 `TKS.exe` 的反编译分析。  
> 函数地址均为 PE 内存偏移，对应反编译文件在 `运行时转储/decompile/` 下。

---

## 1. 概述

游戏文本系统使用**嵌入式控制字节**来在文本流中标记排版指令。控制字节嵌入在 Big5 编码的文本流中，解析时按字节值分发到不同的处理逻辑。

### 二进制编码规则

| 字节范围 | 含义 |
|----------|------|
| `0x00` | 条目终止符 (entry terminator) |
| `0x01`–`0x05`, `0x14`–`0x16`, `0x1D` | 控制标签 (见下表) |
| `0x1E` (十进制 30) | 换行分隔符 |
| `0x20`–`0x7E` | ASCII 可打印字符 |
| `0x80`–`0xFF` | Big5 双字节字符首字节 (次字节范围 `0x40`–`0x7E` 或 `0xA1`–`0xFE`) |

### 可读文本表示

编辑器使用 `<TAG_NAME,参数>` 格式来表示控制标签：

- 单字节参数：`<FCOLOR,20>` → 二进制 `0x02 0x14`
- 双字节参数：`<TEXT,257>` → 二进制 `0x14 0x01 0x01`
- 三字节参数(FCOLORD)：`<FCOLORD,255,0,128>` → 二进制 `0x03 0xFF 0x00 0x80`

## 2. 控制标签完整列表

> **编码器逆向核对（`4019D0.c` 已逐条对照）**：`FRESET`=0x01(1–4)、`FCOLOR`=0x02(1–32)、`FSIZE`=0x04(12–48)、`FTYPE`=0x05(1–8)、`TEXT`=0x14(1–0x7FFF，双字节)、`VARNUM`=0x15(1–255)、`VARTXT`=0x16(1–255)、`NAME`=0x1D(1–2)，参数越界由 `if(v13>v9||v13<v10)` 报错——全部与本表一致。`FCOLORD`(0x03) 确**不在**编码器内（`sub_4019D0` 从 0x02 直接跳到 0x04），仅渲染器 `sub_44E49C` 处理，印证 2.3 节结论。（反编译中 FRESET 的匹配串变量名为 `Str2`。）

### 2.1 FRESET — 格式重置 (0x01)

| 字节 | 名称 | 参数范围 | 数据字节数 |
|------|------|----------|-----------|
| `0x01` | FRESET | 1–4 | 1 |

**原始码**：`sub_4019D0` (编码器) 第 70 行：`aFreset` → 编码 `0x01`
**渲染码**：`sub_44E49C` case 1 (第 29–49 行)

#### 参数值详解

| 值 | 含义 | 渲染逻辑 |
|----|------|----------|
| 1 | 全部恢复 | `*(a1+8) = *(a1+16)` (恢复颜色), `sub_44B04C(a1, *(a1+32), 0)` (重设字号), `*(a1) = *(a1+4)` (恢复字体) |
| 2 | 恢复颜色 | `*(a1+8) = *(a1+16)` (仅恢复上一个颜色) |
| 3 | 重新初始化 | `sub_44B04C(a1, *(a1+32), 0)` (重设字号) + 恢复字体 — 等效于值1但不含颜色恢复 |
| 4 | 恢复字体 | `*(a1) = *(a1+4)` (恢复上一个字体类型) |

**渲染上下文结构 (`a1`)**：
- `a1+0`: 当前 FTYPE 索引 (0-based, 即 FTYPE值-1)
- `a1+4`: 上一个 FTYPE 索引 (`v15 = a2+1; *(a1+4) = *(a1)` 详见 case 5)
- `a1+8`: 当前颜色 (DWORD, RGB 或调色板索引)
- `a1+16`: 上一个颜色 (用于 `FRESET,2` 恢复)
- `a1+24`: 字体大小 (FSIZE)
- `a1+28`: 字符宽度 (字号相关)
- `a1+32`: 当前字号 (`sub_44B04C` 参数)
- `a1+60`: 行高

**编码器参数范围** (sub_4019D0)：`v11=1, v10=4`，即参数范围 1–4。

**实际数据使用**：FRESET 440 次 (值 1: 全部恢复, 值 2: 恢复颜色)

### 2.3 FCOLORD — 直接RGB颜色 (0x03)

| 字节 | 名称 | 参数范围 | 数据字节数 |
|------|------|----------|-----------|
| `0x03` | FCOLORD | R,G,B 各 0–255 | 3 |

**渲染码**：`sub_44E49C` case 3 (第 56–60 行)

```c
// sub_44E49C case 3:
*(DWORD*)(a1 + 16) = *(DWORD*)(a1 + 8);  // 保存当前颜色到"上一个"
*(DWORD*)(a1 + 8) = sub_451F08(a2[1], a2[2], a2[3]);  // RGB直接转调色板格式
a2 += 4;  // 跳过 1+3 字节
```

**颜色转换函数** (`sub_451F08`)：
根据屏幕色深 (`dword_A2C244`) 做不同转换：
- case 15 (16位): RGB888 → RGB565
- case 16 (16位变体): RGB888 → RGB565 (不同压缩算法)
- case 24/32 (24/32位): 直接组合 `R | (G<<8) | (B<<16)`

**编辑器表示**：`<FCOLORD,r,g,b>`，其中 r,g,b 为 0–255 的十进制整数。

> **注意**：此标签**不存在于游戏文本编码器** (`sub_4019D0`) 中。编码器使用 `aFcolor`, `aFsize`, `aFtype`, `aText`, `aVarnum`, `aVartxt`, `aName` 等字符串匹配标签名，但不包含 "FCOLORD" 或 "Fcolord"。因此 FCOLORD 只能由游戏引擎内部生成（如硬编码的对话系统），不能通过 TKTalk.txt 文本文件创建。编辑器添加支持是为了完整性和将来可能的用途。

**实际数据使用**：在 TKT.dat 中未发现二进制格式 `0x03` 的可靠使用（0x03 同时也是 Big5 字符的首字节范围中的常见值），但游戏渲染器明确处理了此标签。

### 2.4 FSIZE — 字体大小 (0x04)

| 字节 | 名称 | 参数范围 | 数据字节数 |
|------|------|----------|-----------|
| `0x04` | FSIZE | 12/16/24/32/48 | 1 |

**原始码**：`sub_4019D0` 第 74 行：`aFsize` → 编码 `0x04`
**渲染码**：`sub_44E49C` case 4 (第 61–66 行)

```c
// sub_44E49C case 4:
*(DWORD*)(a1 + 32) = *(DWORD*)(a1 + 24);  // 保存当前字号
v6 = a2 + 1;
a2 += 2;
sub_44B04C(a1, *v6, 0);  // 设置新字号
```

**字号设置函数** (`sub_44B04C`):
```c
if (a2 > 24) {
    if (a2 == 32) { *(a1+24) = 32; goto LABEL_15; }
    if (a2 == 48) { *(a1+24) = 48; goto LABEL_15; }
} else {
    switch(a2) {
        case 24: *(a1+24) = 24; goto LABEL_15;
        case 12: *(a1+24) = 12; goto LABEL_15;
        case 16: *(a1+24) = 16; goto LABEL_15;
    }
}
*(a1+24) = 24;  // 非法值默认为 24
```

**有效字号**：12, 16, 24, 32, 48。**其他值均回退到 24**。

**编码器参数范围** (sub_4019D0)：`v11=12, v10=48`

**实际数据使用**：FSIZE 15 次，值 {16, 24, 32}

**默认字号**：16 (`dword_755B04` 在 `sub_411624` 游戏主渲染器中)

### 2.5 FTYPE — 字体类型 (0x05)

| 字节 | 名称 | 参数范围 | 数据字节数 |
|------|------|----------|-----------|
| `0x05` | FTYPE | 1–8 | 1 |

**原始码**：`sub_4019D0` 第 76 行：`aFtype` → 编码 `0x05`
**渲染码**：`sub_44E49C` case 5 (第 67–74 行)

```c
// sub_44E49C case 5:
v15 = a2 + 1;
*(DWORD*)(a1 + 4) = *(DWORD*)a1;   // 保存当前 FTYPE
*(DWORD*)a1 = *v15 - 1;             // 设置新 FTYPE (转为 0-based 索引)
a2 = v15 + 1;
if (*(DWORD*)a1 > 7u)               // 范围检查: >7 时回退到上一个值
    *(DWORD*)a1 = *(DWORD*)(a1 + 4);
```

**关键说明**：
- FTYPE 值存储为 **0-based 索引**（即 FTYPE=1 → 索引 0, FTYPE=8 → 索引 7）
- 超出范围（值 >8）时回退到上一个 FTYPE 值
- FTYPE 决定使用哪个字体区段（FONT9696 有 8 个区段 × 14915 字形）

**字体族映射** (FONT9696 区段 → 近似系统字体):

|---------|------|----------|-------------|
| 1 | 0 | Mu.jvg 细明体区 | PMingLiU, MingLiU, SimSun |
| 2 | 1 | Mu.jvg 明体区 | MingLiU, PMingLiU, SimSun |
| 3 | 2 | 楷体区 | DFKai-SB, KaiTi |
| 4 | 3 | 宋体区 | SimSun, NSimSun, MingLiU |
| 5 | 4 | UI/黑体区-细 | Microsoft JhengHei, Microsoft YaHei, SimHei |
| 6 | 5 | UI/黑体区-粗 | SimHei, Microsoft YaHei, Microsoft JhengHei |
| 7 | 6 | 仿宋区 | FangSong, KaiTi |
| 8 | 7 | 楷体区-2 | KaiTi, DFKai-SB |

**编码器参数范围** (sub_4019D0)：`v11=1, v10=8`

**实际数据使用**：FTYPE 9 次，值 {4, 5}

**默认FTYPE**：2 (`sub_411624` 游戏主渲染器 offset 0=1 即 FTYPE raw=2)

### 2.6 TEXT — 文本资源引用 (0x14)

| 字节 | 名称 | 参数范围 | 数据字节数 |
|------|------|----------|-----------|

**编码器参数范围**：`v11=1, v10=0x7FFF` (1–32767)

## 3. 文本流布局结构

### 3.1 TKT.dat 文件格式

```
┌──────────────────────────────────┐
│ Header (8 bytes)                 │
│   total_size: uint32_le          │ ← 加密后数据长度
│   record_count: uint32_le        │ ← 条目数量
├──────────────────────────────────┤
│ ID Table (4 × record_count)     │ ← int32 条目 ID
├──────────────────────────────────┤
│ Offset Table (4 × record_count) │ ← uint32 文本偏移
├──────────────────────────────────┤
│ Text Data (XOR 0xFF encrypted)   │
│   每条目: [控制字节+Big5文本] 0x00│ ← 0x00 终止
│   多行: 0x1E 分隔               │ ← 0x1E = LINE_SEPARATOR
└──────────────────────────────────┘
```

**解密**：`decrypted[i] = encrypted[i] ^ 0xFF`（来源：`sub_401E88` 第 397–401 行）

### 3.2 行内控制字节解析流程

```
输入字节流:  [0x05] [0x02] [0x14] [0x01] [0x00] [0xA4] [0x54] ...
              ↑      ↑      ↑      ↺      ↺
           FTYPE=2 FCOLOR=2 TEXT=256(LO) TEXT=256(HI)
                                        Big5 字符 "中"
```

解析规则 (`decode_line`):
1. 若字节 ∈ CONTROL_TAGS → 读取 N 字节参数 (1或2或3)
2. 若字节 < 0x20 且 ≠ 0x1E → 输出 `<RAW,0xNN>`
3. 若字节 ≥ 0x80 → Big5 双字节字符
4. 其他 → ASCII 字符

### 3.3 控制字节数据长度表

| 控制字节 | 名称 | 参数字节数 | 二进制总长 |
|----------|------|-----------|-----------|
| 0x01 | FRESET | 1 | 2 |
| 0x02 | FCOLOR | 1 | 2 |
| 0x03 | FCOLORD | 3 | 4 |
| 0x04 | FSIZE | 1 | 2 |
| 0x05 | FTYPE | 1 | 2 |
| 0x14 | TEXT | 2 | 3 |
| 0x15 | VARNUM | 1 | 2 |
| 0x16 | VARTXT | 1 | 2 |
| 0x1D | NAME | 1 | 2 |

## 4. 编码器详解 (`sub_4019D0`)

编码器将可读文本（TKTalk.txt 格式）转换为二进制流。

### 4.1 标签名与控制字节映射

编码器使用字符串比较来识别标签（`sub_4B02A8` 为字符串比较函数）：

| 标签名 | 控制字节 | 搜索方式 | 参数范围 |
|--------|----------|---------|---------|
| `FRESET` | 0x01 | `sub_4B02A8(v19, aFreset, 7)` | 1–4 |
| `FCOLOR` | 0x02 | `sub_4B02A8(v19, aFcolor, 7)` | 1–32 |
| `FSIZE` | 0x04 | `sub_4B02A8(v19, aFsize, 6)` | 12–48 |
| `FTYPE` | 0x05 | `sub_4B02A8(v19, aFtype, 6)` | 1–8 |
| `TEXT` | 0x14 | `sub_4B02A8(v19, aText, 5)` | 1–32767 |
| `VARNUM` | 0x15 | `sub_4B02A8(v19, aVarnum, 7)` | 1–255 |
| `VARTXT` | 0x16 | `sub_4B02A8(v19, aVartxt, 7)` | 1–255 |
| `NAME` | 0x1D | `sub_4B02A8(v19, aName, 5)` | 1–2 |

> **注意**：编码器**不识别 FCOLORD (0x03)** — 游戏文本文件中没有 `<FCOLORD,r,g,b>` 这样的可读格式。FCOLORD 仅在二进制流中存在，由游戏内部代码生成。

### 4.2 TEXT 标签的双字节编码

TEXT 标签的参数为 2 字节 (v6=1)：

```c
v13 = (unsigned __int8)v14;                              // 低字节
v12 = (unsigned __int8)((unsigned __int16)(v14 & 0xFF00) >> 8);  // 高字节
*v20 = v13;        // 写入低字节
a2 = v20 + 1;
if (v6) *a2++ = v12;  // 如果是双字节参数，写入高字节
```

即：`TEXT值 = 低字节 | (高字节 << 8)`

### 4.3 编码器错误处理

编码器在遇到错误时会调用 `sub_452478(0, "CalTextLen Error #N %s", v8)` 记录错误：

| 错误号 | 含义 |
|--------|------|

## 5. 渲染器详解 (`sub_44E49C`)

### 5.1 函数签名

```c
unsigned __int8 *__cdecl sub_44E49C(
    int a1,           // 渲染上下文结构体指针
    unsigned __int8 *a2,  // 文本字节流指针
    unsigned int a3,  // 当前 X 坐标
    int a4,           // 当前 Y 坐标
```

| 偏移 | 含义 | 初始值 | 相关标签 |

| +28 | 字符宽度 (FSIZE相关) | FSIZE值 | 全宽字符前进量 |
| +32 | 第二字号(保存用) | 同 +24 | FSIZE, FRESET(1,3) |
| +40 | 裁剪区域 X | | |
| +44 | 裁剪区域 Y | | |
| +48 | 渲染方式标志 | | |

| +64 | (保留) | | |

### 5.3 字符渲染流程

```
while (*a2) {
    switch (*a2) {
        case 0x01: FRESET (1-4)
        case 0x02: FCOLOR (palette)
        case 0x03: FCOLORD (RGB)
        case 0x04: FSIZE
        case 0x05: FTYPE
        default:
            if (*a2 == 0x1E) → 换行
            if (*a2 >= 0x80) → CJK双字节字符 (全宽)
            else if (a1[65] == 1) → 特殊全宽模式
            else if (a1[66]) → ASCII半宽压缩模式 (width>>1)
            else → ASCII正常宽度 (width=FSIZE)
    }
}
```

## 6. 简繁转换系统 (`sub_42539C`)

游戏支持根据系统 locale 自动进行简繁转换：

### 6.1 转换触发条件

```c
// sub_42539C:
v6 = sub_4E4FEC();    // 获取系统 locale ID
if (v6 == 2052) {      // 2052 = LCID_CHINESE_SIMPLIFIED
    // 简体中文 locale: 加载 g2b.dat 并转换
    v10 = 8;
    sub_45BC50(v12);    // 步骤1: 初始化转换表
    sub_45BB64(v12);    // 步骤2: 加载 g2b.dat
    sub_45BCE4(v12, text);  // 步骤3: 执行 GB→Big5 转换
}
```

### 6.2 转换流程

当 `locale == 2052` (简体中文) 时：
1. 加载 `g2b.dat` (131072 字节 = 65536 × 2 的 GB2312→Big5 映射表)
2. 对文本中的每个双字节字符，查表转换 GB2312→Big5
3. 这样简体中文系统上也能正确显示（FONT9696 使用 Big5 编码索引）

> **重要发现**：FONT9696 字体文件包含的是**简体中文**字形，但用 Big5 编码作为索引。因此游戏中：
> - TKT.dat 中存储的是 Big5 编码 (繁体 Unicode)
> - FONT9696 查表用 Big5 编码位置
> - 但字形是简体的 (如 Big5 `0xC3F6` → 显示 "关" 而非 "關")
> - 简体 locale 时，游戏将 GB2312→Big5 转换后渲染（简体词→Big5编码→简体字形）

## 7. 渲染子系统

### 7.1 FONT9696 位图字体

**格式** (逆向自 `sub_44B384` 和 `sub_44B208`)：
- 文件头：8 × 14915 = 119320 个 uint32 偏移索引（8 个 FTYPE 区段）
- 字形数据：RLE 压缩 1bpp 位图，3 字节组编码 4 个交替游程

**Big5 字符索引** (`sub_44B384`)：
```c
if (char_code < 0x80) return None;                // ASCII 不在此表
high = (char_code >> 8) & 0xFF;                   // Big5 高字节
low = char_code & 0xFF;                            // Big5 低字节
if (high < 0xA1) return None;                      // 不在 Big5 范围
if (0x40 <= low <= 0x7E) li = low - 64;           // Big5 低字节范围1
else if (0xA1 <= low <= 0xFE) li = low - 98;      // Big5 低字节范围2
else return None;
base = li + 157 * (high - 161);                    // 计算区段内偏移
index = base + 14915 * ftype;                       // 加上 FTYPE 区段偏移
```

**RLE 解码** (`sub_44B208`)：
- 每组 3 字节编码 4 个游程 (6-bit per run)
- bit=0 为笔画(前景), bit=1 为背景
- 最多 96×96 像素

**位图极性**：`bit=1` 为背景, `bit=0` 为笔画 → 渲染时需反转 (`raw = bytes(b ^ 0xFF for b in raw)`)

### 7.2 字符宽度规则 (`sub_44E49C`)

| 字符类型 | 宽度 | 来源 |
|----------|------|------|
| CJK 双字节 | FSIZE (全宽) | `a3 += *(a1+28)` |
| ASCII (正常) | FSIZE (全宽) | `a3 += *(a1+28)` |
| ASCII (半宽标志) | FSIZE/2 | `a3 += *(int*)(a1+28) >> 1` |
| ASCII (强制全宽) | FSIZE | `*(a1+65) = 1; ... a3 += *(a1+28)` |
