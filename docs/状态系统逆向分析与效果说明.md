## 一、状态系统总览

### 1.1 系统构成

| 组件 | 位置 | 说明 |
|------|------|------|
| 状态名称表 | `editor_utils/picker_dialogs.py:22` `STATUS_NAMES` | 31 种状态（索引 0..30），对应 bit 0..30 |
| 状态图标基址 | `editor_utils/picker_dialogs.py:29` `STATUS_ICON_BASE = 242` | Mu.JVG 中状态精灵起始索引 |
| 角色施加状态掩码 | `TKKon.dat` 字段 67/68（`inflict_status_lo/hi`） | 角色攻击时附加的状态位掩码 |
| 角色状态抵抗表 | `TKKon.dat` 字段 51..66（32 字节打包） | 每字节 = 对应状态抵抗率 % |
| 物品导致状态 | `TKItem.dat` 字段 26/27（cause_lo/hi） | 物品使用时施加的状态 |
| 物品解除状态 | `TKItem.dat` 字段 28/29（cure_lo/hi） | 物品使用时解除的状态 |
| 技能状态免疫 | `TKSkill.dat` 字段 34/35（immunity_lo/hi） | 技能使用者免疫的状态 |
| 运行时状态标记 | `byte_9E048E[32 * char_idx + status_idx]` | 战斗中角色的活跃状态（1 = 已施加） |
| 状态槽位数组 | `word_9D707A[527 * char_idx + 43 + slot]` | 每角色 8 个槽位，低字节 = 状态索引+1，高字节 = 剩余回合 |

### 1.2 核心全局变量

| 全局变量 | 大小 | 含义 |
|---------|------|------|
| `byte_9E048E` | 0x400 (1024 字节) | 状态标记数组，每角色 32 字节 |
| `word_9D707A` | 527 × 角色数 | 角色战斗状态结构（含状态槽位） |
| `word_9D6C58` | WORD | 当前技能/攻击的攻击力临时值 |
| `word_9D6C5C` | WORD | 当前技能/攻击的防御相关临时值 |
| `word_9D6C7C` | WORD | 当前技能记录索引（0..343） |
| `word_9D6F58` | WORD | 当前行动角色索引 |
| `byte_9DF781` | 字节数组 | 角色行动限制标记（中毒/燃烧伤害等级） |
| `byte_9D6F84` | 字节数组 | 角色额外状态标记（影响 -3 时附加 +30% 攻击） |

## 三、反编译函数分析

### 3.1 状态图标渲染 — `sub_4188D4`

- **地址**: `0x4188D4`
- **文件**: `decompile/4188D4.c`
- **调用者**: `sub_417F84`（战斗 UI 绘制）
- **功能**: 渲染角色当前活跃状态的图标（最多 8 个，分上下两行）

**关键代码**：

```c
char __cdecl sub_4188D4(int a1, __int16 a2)
{
    char *v3 = (char *)(1054 * a2 + 7700318);  // 角色状态槽位基址
    v5 = 0;  // 已渲染图标计数
    v4 = 0;
    do
    {
        result = (char)v3;
        if (*v3)  // 槽位非空
        {
            result = v3[1];  // 剩余回合
            if (result)
            {
                if (v5 >= 4)  // 第 5..8 个图标: 下排
                    result = sub_4544EC(dword_755AF4, 40 * v5 + 120, 210, *v3 + 241, a1 + 926, -1);
                else          // 第 1..4 个图标: 上排
                    result = sub_4544EC(dword_755AF4, 40 * v5 + 280, 175, *v3 + 241, a1 + 926, -1);
                ++v5;
            }
        }
        ++v4;
        v3 += 2;  // 每槽位 2 字节
    } while (v4 < 8);
    return result;
}
```

**关键推导**：

| 项目 | 公式 | 说明 |
|------|------|------|
| 槽位基址 | `1054 * char_idx + 7700318` | 即 `word_9D707A[527 * char_idx + 43]`（byte 视图） |
| 状态图标精灵索引 | `*v3 + 241` | `*v3` 是状态 ID（1..31），精灵索引 = ID + 241 |
| 槽位上限 | 8 | 每角色同时最多 8 个活跃状态 |
| 槽位结构 | 2 字节 | 低字节 = 状态 ID，高字节 = 剩余回合 |

**对应到编辑器**：`STATUS_ICON_BASE + idx - 130 = 242 + idx - 130 = idx + 112`，这与 `sub_4544EC` 接收 `*v3 + 241` 形成对应关系（`*v3` = `idx + 1`，所以 `idx + 1 + 241 = idx + 242`，与编辑器侧公式一致）。

### 3.2 状态施加处理 — `sub_442D44`

- **地址**: `0x442D44`
- **文件**: `decompile/442D44.c`
- **调用者**: `sub_4432EC`、`sub_4458B0`（技能执行主函数）、`sub_447DAC`
- **功能**: 对角色 `a1` 施加状态 `a2`，含成功率判定、抵抗率扣减、覆盖/续期逻辑

**关键代码**（节选）：

```c
char __cdecl sub_442D44(__int16 a1, __int16 a2, __int16 a3, __int16 a4, __int16 a5)
{
    // a1 = 角色索引, a2 = 状态索引 (0..30)
    // a3 = 成功率 (0 表示使用默认), a4 = 持续回合 (用于 idx 16/28), a5 = 强制标志

    if (word_9D7084[527 * a1] > 0)
    {
        LOBYTE(v5) = byte_9E04AB[32 * a1];
        if (!(_BYTE)v5 || (word_9DFA8E != -1 && word_9DFA90 == 115))
        {
            // 默认成功率 v8
            if (!a5)
                v8 = 2 * word_9D707E[527 * word_9D6F58] / 3 + 15;
            else
                v8 = 100;

            // 修正: algn_9D70D0[1054*a1 + 16 + a2] = 角色对该状态的抵抗率
            if (algn_9D70D0[1054 * a1 + 16 + a2] == 75)  v8 /= 2;       // 抵抗 75% → 成功率减半
            else if (algn_9D70D0[1054 * a1 + 16 + a2] == 50) ...        // 抵抗 50%

            // 骰子判定
            v6 = sub_452AC0(100);  // 0..99 随机数
            if (v6 <= v8)  // 成功
            {
                if (byte_9E048E[32 * a1 + a2])  // 已存在此状态
                {
                    // 找到现有槽位并刷新剩余回合
                    for (i = 0; i < 8; ++i)
                        if (SLOBYTE(word_9D707A[527 * a1 + 43 + i]) == a2 + 1)
                        {
                            HIBYTE(word_9D707A[527 * a1 + 43 + i]) = byte_4EB790[2 * a2];  // 默认回合
                            byte_9E048E[32 * a1 + a2] = 1;
                            if ((a2 == 16 || a2 == 28) && a4 >= 0)
                                byte_9D6F84[a1] = a4;  // 误导/迷恋: 写入目标索引
                            sub_433690(a1, a2, 1, 0, 0);  // 状态生效回调
                        }
                }
                else  // 首次施加
                {
                    // 找空槽位写入
                    for (j = 0; j < 8; ++j)
                        if (!(_BYTE)word_9D707A[527 * a1 + 43 + j])
                        {
                            LOBYTE(word_9D707A[527 * a1 + 43 + j]) = a2 + 1;
                            HIBYTE(word_9D707A[527 * a1 + 43 + j]) = byte_4EB790[2 * a2];
                            byte_9E048E[32 * a1 + a2] = 1;
                            if ((a2 == 16 || a2 == 28) && a4 >= 0)
                                byte_9D6F84[a1] = a4;
                            sub_433690(a1, a2, 1, 0, 0);
                        }
                }
            }
        }
    }
    return v5;
}
```

**关键点**：

| 行为 | 实现 |
|------|------|
| 默认成功率 | `2 × 施加者等级 / 3 + 15`（即等级 60 时达到 55%） |
| 抵抗率修正 | `algn_9D70D0[1054*char + 16 + status]` 等于 75/50 时按比例减少成功率 |
| 默认回合表 | `byte_4EB790[2 * status_idx]` — 每状态 2 字节，存储默认持续回合 |
| 槽位格式 | `word_9D707A[527*char + 43 + slot]`：低字节 = 状态 ID+1，高字节 = 剩余回合 |
| 状态 16/28 特殊处理 | 误导/迷恋记录目标角色索引到 `byte_9D6F84[char]` |

### 3.3 物品解除状态 — `sub_41E40C`

- **地址**: `0x41E40C`
- **文件**: `decompile/41E40C.c`
- **调用者**: `sub_41EFA8`（物品使用主函数）
- **功能**: 物品使用后对目标角色 `a2` 应用全部效果，包括解除状态、属性加成、HP/MP 恢复

**关键代码（解除状态部分）**：

```c
        {
            *v8 = 0;
            for (j = ...) { ... }
            --v12; v8 -= 2;
        }

```

**关键点**：

| 字段 | 含义 |
|------|------|
| `v15[28]` (`cure_lo`) | 物品解除低 16 位状态掩码，bit `i` 对应状态 ID `i+1` |
| `v15[29]` (`cure_hi`) | 物品解除高 16 位状态掩码，bit `i` 对应状态 ID `i+17` |
| 槽位清除后 | 后续槽位前移填补空缺，保证 8 槽位的紧凑性 |

### 3.4 属性重算 — `sub_42234C`

- **文件**: `decompile/42234C.c`

```c
__int16 __cdecl sub_42234C(int a1, _WORD *a2)

    //   a2[7]  = HP 基础      a2[8]  = HP 当前
    //   a2[9]  = MP 基础      a2[10] = MP 当前

    a2[16] = a2[15];
    a2[18] = a2[17];
    a2[20] = a2[19];
    a2[8]  = a2[7];
    a2[10] = a2[9];

    a2[33] = 0; a2[32] = 1; a2[34] = 0;
    a2[36] = 0; a2[37] = 0; a2[35] = 0;
```

### 5.1 破兵状态攻击修正 Bug

#### 5.1.1 问题概述

#### 5.1.2 根因


### 7.1 可编辑 vs 不可编辑

| 属性类别 | 数据位置 | 编辑器可编辑性 |
|---------|---------|---------------|
| 角色状态施加掩码（攻击附加） | `TKKon.dat` 字段 67/68 | ✅ 可编辑 |
| 角色状态抵抗率（32 字节） | `TKKon.dat` 字段 51..66 | ✅ 可编辑 |
| 物品导致/解除状态掩码 | `TKItem.dat` 字段 26..29 | ✅ 可编辑 |
| 技能状态免疫掩码 | `TKSkill.dat` 字段 34/35 | ✅ 可编辑 |

### 7.2 状态编辑器集成

`tks_book/tab_status.py` 已集成状态查看页，提供：

1. **左侧列表**：状态图标、索引、名称、类型（增益/减益）、作用回合
2. **右侧详情**：
   - 大图标 + 名称 + 类型 + 作用回合
   - 影响效果（来自 `STATUS_DESCRIPTIONS` 官方说明）
   - 导致此状态的所有来源（角色/物品）
   - 解除此状态的所有途径（物品/技能）
   - 角色抵抗率（扫描所有角色的 `WarPC[51..66]`）

### 7.3 编辑器建议

1. **状态抵抗率编辑**：在 `kon_editor_v2.py` 中，抵抗率字段建议显示状态名称和图标，使用 `STATUS_NAMES` + `STATUS_ICON_BASE + idx - 130` 公式生成精灵索引。
2. **施加/解除掩码编辑**：使用 `StatusMaskPickerDialog`（位于 `picker_dialogs.py`），16 位一组勾选。
3. **破兵 Bug 提示**：在编辑器中选中"破兵"状态时，可提示用户此状态在原版 exe 中存在攻击修正 Bug，建议通过 `tks_patches.json` 的 `broke_weapon_fix` 补丁修复。
