## 零、总体架构

游戏右键菜单 = **一张全屏背景 (mb.gxp)** + **一批菜单精灵 (Mu.JVG) 按硬编码坐标叠加** +
**FONT9696 点阵文字按硬编码坐标绘制**。

- 顶层调度：`sub_42131C`（菜单主循环）。主菜单态 `arglist[461]==1`，其内用
  `arglist[614865]` 选择子页面（顶部 6 个页签）：

  | 页签 | 索引 (614865) | 渲染函数 | 复刻页号 `_page` |
  |------|--------------|----------|------------------|
  | 状态 | 0 | `sub_417F84` | 0 |
  | 技能 | 1 | `sub_418EE8` | 1 |
  | 物品 | 2 | `sub_419704` | 2 |
  | 装备 | 3 | `sub_419B54` | 3 |
  | 队伍 | 4 | `sub_41A080` | 4 |
  | 系统 | 5 | `sub_41A940` | 5 |

- 每帧渲染链：`sub_41762C`（左侧队伍列表+顶部页签）→ 子页面渲染函数。
- 精灵表面：`dword_755AF4` = Mu.JVG，`dword_755B00` = PFace.JVG，字体对象 `dword_755B08`。

### 复刻渲染分层（关键工程约定）

复刻控件按三层合成，**顺序决定 z-order**：

1. **精灵层**：QPainter 直接把 Mu.JVG 帧画到 QPixmap（背景、面板、页签、图标、选中条）。
2. **文字层**：所有文字先入队（`_txt_queue`），精灵画完后由 `_flush_texts` **统一**用 FONT9696
   逐像素混合到位图上（保证文字压在精灵之上）。
3. **顶层覆盖**：物品说明浮框（框精灵 + 说明文字）在文字层之后**单独再合成一次**，
   保证弹窗层级高于列表文字（否则文字层会盖住框）。

> 坑：若把说明框当普通精灵在精灵层画，文字层 flush 时列表物品名会盖到框上。必须让
> 弹窗作为独立"顶层覆盖"最后画。

## 一、资源与格式基础

### 1.1 mb.gxp — 全屏背景 (GXP 格式)

- 格式：`JGXP` 4 字节魔数 + 48 字节头 + 4 字节解压尺寸 + LZSS 流 + RGB565 像素。
- 尺寸 640×480；宽高存为 `~width`/`~height`（按位取反，需再取反还原）。
- 解码：`lzss_decompress_stream(data[52:48+csize], usize)` → `rgb565_to_rgba`。
- 参考 `gxp_editor_v2.py` / `sub_450264`(GXP加载) / `sub_452B14`(LZSS)。
- 菜单背景固定 `mb.gxp`；存档=`save.gxp`、姓名输入=`Mb_name.gxp`、标题=`TitleMenu.gxp`。

```python
data = open(path, 'rb').read()
w = ~struct.unpack_from("<i", data, 4)[0]
h = ~struct.unpack_from("<i", data, 8)[0]
csize = struct.unpack_from("<I", data, 12)[0]
usize = struct.unpack_from("<I", data, 48)[0]
raw = lzss_decompress_stream(data[52:48 + csize], usize)
rgba = rgb565_to_rgba(raw, w, h)   # → PIL/QImage
```

## 二、渲染基础设施

### 2.1 精灵绘制 — `sub_4544EC` / `sub_454D24`

- `sub_4544EC(surface, x, y, frame, dst, -1)`：**不透明**掩码拷贝（有像素处覆盖）。
- `sub_454D24(surface, x, y, frame, dst, alpha, -1)`：带 alpha 的**半透明混合**，
  内部 `dword_A2C244==16` 时走 `sub_454D90`，否则走 `sub_4553A4`。
- 复刻用统一 `_blit(painter, entry, x, y, alpha32=None)`：`alpha32=None` 不透明；
  给值则 `painter.setOpacity(alpha32/32)`。

### 2.2 半透明混合公式 — `sub_454D90`

`alpha ∈ [1,31]` 时逐像素：`dst = dst*(32-a)/32 + src*a/32`（RGB565 分量各自混合）；
`alpha≥31`（即 32）走 `sub_4544EC` 纯色。复刻按 `a/32` 不透明度近似。

各面板实测 alpha：状态页 帧10=15、帧8=10、帧9=13；技能/物品名字底条=10；选中条=15。

### 2.3 文字调色板 — `sub_451FA0`（权威 32 色）

> 内存转储该段未提交（全 0xFF），改从初始化函数 `sub_451FA0` 逐色扒出。
> 存储经 `sub_451F08` 转 RGB565，**复刻时须按 565 量化**（低位复制扩展）才与屏幕一致。

| 索引 | RGB | 用途 |
|------|-----|------|
| 0 | (0,0,0) | 黑（文字阴影） |
| 1 | (128,128,128) | 灰（技能已学会） |
| 2 | (128,0,0) | 深红（列表选中行） |
| 16 | (244,242,220) | 奶白（正文/数值默认） |
| 17 | (192,192,192) | 浅灰 |
| 18 | (255,0,0) | 红（HP/MP < 一半） |
| 19 | (255,255,0) | 黄（选中名/HP/MP ≥ 一半/金钱） |
| 20 | (0,255,0) | 绿（生命标签/八属性标签） |
| 21 | (0,255,255) | 青（内力标签/核心标签） |
| 22 | (0,0,255) | 蓝 |
| 30 | (52,62,84) | 暗蓝灰 |
| 31 | (255,255,255) | 纯白 |

（完整 0-31 见 `game_status_view.py:GAME_COLORS`；3-15、23-29 为其它主题色。）

```python
def _c565(r, g, b):
    r5, g6, b5 = r >> 3, g >> 2, b >> 3
    return QColor((r5<<3)|(r5>>2), (g6<<2)|(g6>>4), (b5<<3)|(b5>>2))
```

`sub_44B028(font, idx)` 即"设当前文字色为调色板 idx"。

## 三、FONT9696 字体渲染管线（核心）

### 3.1 文件格式与字形寻址 — `sub_44B384`

- 无文件头；`索引表 [8 FTYPE × 14915 字形 × uint32]` = 477,280 字节 + RLE 字形数据区。
- 字形 96×96、1bpp、1152 字节；长度 = `index[i+1] - index[i]`。
- Big5 → 字形索引（`Font9696.big5_to_index`）：
  - ASCII (<0x80) 先经 `word_4EC810` 重映射为 Big5 全角码。
  - `high < 0xA1` 非法；`low 0x40-0x7E → low-64`；`low 0xA1-0xFE → low-98`。
  - `base = li + 157*(high-0xA1)`；最终 `index = base + 14915*ftype`。
- 菜单字用 **FTYPE2 @ 24px**；说明/记事/历史用 **FTYPE0 @ 16px**（`sub_44AF7C(0,16,...)`）。

### 3.2 RLE 解码与位图极性 — `sub_44B208`

- 每 3 字节 → 4 个 6-bit 游程，黑-白-黑-白交替。
- **极性坑**：文件中 `bit=1 是背景、bit=0 是笔画`。用 ASCII 图实证：'生' 字形 1-位占
  7681/9216（大多为背景）。解码后必须 `invert_polarity`（XOR 0xFF）再按"笔画覆盖度"降采样。

### 3.3 降采样（抗锯齿）— `sub_44B5A8`

- 目标字号 `cell = 96/size` 的方块内，`popcount`(查 `byte_4EC1F8`) 统计笔画覆盖度，
  再查"覆盖度→alpha(0..32)"LUT 得到该像素 alpha。
- 合法字号 12/16/24/32/48（`sub_44B04C`），每字号一张 LUT，从内存转储逐字节提取：

| 字号 | LUT 地址 | 条目数 | 说明 |
|------|----------|--------|------|
| 12 | `byte_4EC789` | 65 | cell=8, 覆盖 0..64 |
| 16 | `byte_4EC7CA` | 37 | cell=6, 覆盖 0..36 |
| 24 | `byte_4EC7EF` | 17 | cell=4, 覆盖 0..16 |
| 32 | `byte_4EC800` | 10 | cell=3, 覆盖 0..9 |
| 48 | `byte_4EC80A` | 5 | cell=2, 覆盖 0..4 |

（LUT 数值见 `game_font.py:_LUT`；本质是"覆盖度线性映射到 0..32"。）

### 3.4 文本步进状态机 — `sub_44E49C`

逐字节推进，控制码（同 tkt_editor 体系）：

| 字节 | 名称 | 语义 |
|------|------|------|
| `0x01`+n | FRESET | 1=恢复色+字号+FTYPE / 2=恢复色 / 3=恢复字号 / 4=恢复FTYPE |
| `0x02`+n | FCOLOR | 存旧色→切调色板色 `n-1` |
| `0x03`+rgb | (直接色) | 存旧色→切 `sub_451F08(r,g,b)` |
| `0x04`+n | FSIZE | 存旧字号→切字号 n（非法回退 24） |
| `0x05`+n | FTYPE | 存旧区段→切 FTYPE `n-1`（>7 回退） |
| `0x1E` | 换行 | 行高 = 当前字号 |
| ≥`0x80` | 全角 | 双字节 Big5，步进 = 字号 |
| <`0x80` | 半角 | ASCII，步进 = 字号/2（**空格照常占位步进**） |

> 坑：早期用 `tkt_full_text` + 自写等宽换行，把控制码剥掉、前导全角空格 strip 掉、
> 换行逻辑也错。必须走原始字节 + 本状态机，空格才有占位、FCOLOR 才生效。

### 3.5 像素混合与阴影 — `sub_44D524` / `sub_44C6A4`

- 混合：`alpha<31 → dst*(32-a)/32 + color*a/32`（查 `byte_4EC2F8`，实测 = `c*a/32`）；
  `alpha≥31 → 纯色`。复刻直接操作 QImage(ARGB32, 内存序 BGRA) 逐像素。
- 阴影 `sub_44C6A4`：alpha 图右 2px、下 2px 做最大值膨胀，以**调色板色 0(黑)**画在
  `(x-1, y-1)`。由 `sub_44AF7C` 的参数控制是否启用（如队伍列表选中行文字带阴影）。

### 3.6 宏展开 — `sub_409C60`

渲染前先展开文本中的引用宏（复刻 `_expand_macros`）：

| 字节 | 名称 | 展开 |
|------|------|------|
| `0x14`+2B | TEXT | 引用另一 TKT 条目，递归展开 |
| `0x1D`+n | NAME | 玩家名（n=1 首段）；静态查看填默认名"主角" |
| `0x15`/`0x16`+n | VARNUM/VARTXT | 运行时变量，静态置空 |
| `0x01`-`0x05`/`0x1E` | — | 原样保留，交给状态机 |

### 3.7 字体对象构造 — `sub_44ADB0`

打开 `FONT9696`，默认字号 24；`a1+8/+16` = 当前/备份文字色，`a1+12` = 阴影色（初始调色板 0）。

## 七、经验总结与坑

1. **渲染分层决定 z-order**：文字统一在精灵之后 flush；需要压在文字之上的浮窗（物品说明）
   必须作为独立"顶层覆盖"最后再合成一次。
2. **精灵帧偏移必带**：Mu.JVG 每帧有 `x_off/y_off`，绘制坐标要叠加，否则整体错位。
3. **半透明系数逐个实测**：面板/名字底条/选中条各不同（10/13/15），照抄反编译 alpha 参数。
   物品面板 `frame33` 是不透明（`sub_4544EC`），区别于状态/技能页的半透明面板。
4. **调色板要按 RGB565 量化**：颜色取自 `sub_451FA0` 权威定义，经 565 存储量化后才与屏幕一致，
   不能用截图采样的近似值。
5. **FONT9696 极性**：文件 `bit=1 背景 / bit=0 笔画`，解码后须 XOR 反转再按笔画降采样。
6. **富文本必须走原始字节**：`load_tkt_raw` + `sub_44E49C` 状态机 + `sub_409C60` 宏展开，
   保留空格占位、FCOLOR/FSIZE/FTYPE 控制码、全角缩进、`0x1E` 换行。
7. **定宽字节排版**：`"%-10.10s%4d"` 等按**字节**截断/补空格（Big5 全角 2 字节），
   空格作半宽字符参与步进，使后续字段位置随名字构成浮动。
8. **静态查看 vs 运行时数据**：背包/金钱/战绩/经验是运行时数据——
   技能/物品列表改列"全集按分类"，金钱按上限，经验/统计显示 0 或钳制。
   **存档页例外**：读取 `<game_dir>\Save\N.sav` 索引文件显示实际存档信息
   （队伍/等级/金钱/时间/地点），因为存档索引是独立文件而非运行时内存。
9. **交互零延迟**：纯 Python 字体渲染每帧 0.1-0.6s，任何"计时器+渲染"叠加都会明显卡顿，
   即时交互（右键弹窗）直接在事件里触发刷新。
10. **验证方法**：离屏渲染（`QT_QPA_PLATFORM` 默认即可，勿用 offscreen 否则字体库为空）
    存 PNG 逐页比对游戏截图；用 exe 内存转储逐字节提取数据段常量（调色板、LUT、格式串、标签）。
