# TKAct.dat 方向表数据错误分析

**分析日期**：2026-07-06
**数据文件**：`游戏目录/TKAct.dat`
**分析范围**：全部 650 条记录（598 条非空）

---

## 1. 数据结构

每条记录 784 字节，其中方向表占据 bytes 0-31：

- 4 个方向 × 8 个绘制槽位 = 32 字节
- 每个槽位的值为 **1-based 图层号**（1~8），0 表示空
- 槽位从左到右（z0→z7）对应绘制顺序：**底层 → 顶层**

| 方向 | 含义 |
|------|------|
| 方向0 | 右上 |
| 方向1 | 右下 |
| 方向2 | 左下 |
| 方向3 | 左上 |

---

## 2. 规律发现

通过统计全部 598 条非空记录的方向表数据：

| 规则 | 一致数 | 一致率 | 结论 |
|------|--------|--------|------|
| 方向0(右上) == 方向3(左上) | 589/598 | 98.5% | **应一致** |
| 方向1(右下) == 方向2(左下) | 598/598 | **100%** | **完全一致** |

### 2.1 规律解释

在 2.5D 等距视角游戏中，角色的遮挡关系取决于朝向：

- **"上"方向组**（右上 + 左上）：共享同一绘制顺序——因为角色都面向上方，身体各部位的遮挡关系一致
- **"下"方向组**（右下 + 左下）：共享同一绘制顺序——角色都面向下方，遮挡关系与"上"方向组相反

两组之间的绘制顺序通常互为反转，这就是游戏实现身前/身后遮挡关系的数据源。

---

## 3. 发现的错误

方向1(右下)和方向2(左下) **100% 一致**，没有发现任何问题。

但在方向0(右上)与方向3(左上)的对比中，发现 **9 条记录**存在不一致（占比 1.5%），详细如下：

### 3.1 序号 4 — z0/z1 互换

```
方向0(右上): [ 2  3  1  0  0  0  0  0]
方向3(左上): [ 3  2  1  0  0  0  0  0]  ← z0、z1 互换了
```

- **图层配置**：图层1(type=1), 图层2(type=2), 图层3(type=3)
- **问题**：方向3 的 z0=3、z1=2，与方向0 的 z0=2、z1=3 正好互换
- **修正值**：`[2, 3, 1, 0, 0, 0, 0, 0]`

---

### 3.2 序号 53 — 严重不完整（缺失4个图层）

```
方向0(右上): [ 4  5  1  2  3  6  0  0]
方向3(左上): [ 1  2  0  0  0  0  0  0]  ← 仅填了2个槽位
```

- **图层配置**：6个活跃图层（图层1~6，type=1,2,4,4,4,4）
- **问题**：方向3 仅绘制图层1和2，图层3/4/5/6 全部丢失。对于"左上"朝向，4个锚点图层（type=4）的层级信息完全丢失
- **修正值**：`[4, 5, 1, 2, 3, 6, 0, 0]`

---

### 3.3 序号 76 — z3 错值（图层4重复、图层1丢失）⭐ 用户报告

```
方向0(右上): [ 3  4  5  1  2  0  0  0]
方向3(左上): [ 3  4  5  4  2  0  0  0]  ← z3=1→4, 图层1丢失
```

- **图层配置**：5个活跃图层（图层1~5，type=1,2,2,3,3）
- **问题**：方向3 的 z3 槽位值为 4（图层4），但方向0 此处是 1（图层1）。导致图层4被重复绘制两次，图层1在"左上"朝向完全丢失——这正是用户发现的"左上动画无法播放"的原因
- **修正值**：`[3, 4, 5, 1, 2, 0, 0, 0]`

---

### 3.4 序号 170 — 与序号76完全相同的错误

```
方向0(右上): [ 3  4  5  1  2  0  0  0]
方向3(左上): [ 3  4  5  4  2  0  0  0]  ← z3=1→4, 图层1丢失
```

- **图层配置**：5个活跃图层（图层1~5，type=1,2,2,3,3）
- **问题**：与序号76一模一样的 bug，方向3 的 z3 错写为4（图层4重复，图层1丢失）
- **修正值**：`[3, 4, 5, 1, 2, 0, 0, 0]`

---

### 3.5 序号 224 — z2 错值（图层5丢失、图层1重复）

```
方向0(右上): [ 3  4  5  1  2  0  0  0]
方向3(左上): [ 3  4  1  1  2  0  0  0]  ← z2=5→1, 图层5丢失
```

- **图层配置**：5个活跃图层（图层1~5，type=1,2,2,3,3）
- **问题**：方向3 的 z2 槽位值为 1（图层1），但方向0 此处是 5（图层5）。导致图层5在"左上"朝向丢失，图层1被重复绘制
- **修正值**：`[3, 4, 5, 1, 2, 0, 0, 0]`

---

### 3.6 序号 455 — z2/z4 互换

```
方向0(右上): [ 4  5  1  2  3  0  0  0]
方向3(左上): [ 4  5  3  2  1  0  0  0]  ← z2(图层1)和z4(图层3)互换了
```

- **图层配置**：5个活跃图层（图层1~5，type=1,2,3,3,3）
- **问题**：方向3 的 z2=3、z4=1，与方向0 的 z2=1、z4=3 正好互换。图层1和图层3的绘制顺序颠倒
- **修正值**：`[4, 5, 1, 2, 3, 0, 0, 0]`

---

### 3.7 序号 583 — 缺少图层2

```
方向0(右上): [ 1  2  0  0  0  0  0  0]
方向3(左上): [ 1  0  0  0  0  0  0  0]  ← z1缺少图层2
```

- **图层配置**：2个活跃图层（图层1~2，type=3,3）
- **问题**：方向3 只有图层1，缺少图层2。在"左上"朝向图层2的受击特效不会渲染
- **修正值**：`[1, 2, 0, 0, 0, 0, 0, 0]`

---

### 3.8 序号 624 — 缺少图层5

```
方向0(右上): [ 1  2  3  4  5  0  0  0]
方向3(左上): [ 1  2  3  4  0  0  0  0]  ← z4缺少图层5
```

- **图层配置**：5个活跃图层（图层1~5，type=3,3,3,3,3）
- **问题**：方向3 只填了4个槽位，图层5缺失
- **修正值**：`[1, 2, 3, 4, 5, 0, 0, 0]`

---

### 3.9 序号 623 — 方向1/2/3 全部为空

```
方向0(右上): [ 1  2  0  0  0  0  0  0]
方向1(右下): [ 0  0  0  0  0  0  0  0]  ← 全空
方向2(左下): [ 0  0  0  0  0  0  0  0]  ← 全空
方向3(左上): [ 0  0  0  0  0  0  0  0]  ← 全空
```

- **图层配置**：2个活跃图层（图层1~2，type=3,3）
- **问题**：只有方向0有绘制数据，方向1/2/3 全部为空。这意味着只有在"右上"朝向时特效才可见，其余3个方向都无渲染——这不可能是预期行为
- **修正值**：
  - 方向1(右下)：`[1, 2, 0, 0, 0, 0, 0, 0]`
  - 方向2(左下)：`[1, 2, 0, 0, 0, 0, 0, 0]`
  - 方向3(左上)：`[1, 2, 0, 0, 0, 0, 0, 0]`

## 5. 结论

- **方向1(右下)==方向2(左下)**：598/598（100%）完全一致，无错误 ✅
- **方向0(右上)==方向3(左上)**：589/598（98.5%）一致，发现 **9条记录**存在数据错误 ❌
- 所有错误均表现为方向3(左上)的数据相对于方向0(右上)出现偏差：缺图层、图层号写错、或顺序互换
- 序号 76/170/224 三条记录结构相似（5层，type=1,2,2,3,3），错误模式雷同，疑似同一来源的复制粘贴错误
