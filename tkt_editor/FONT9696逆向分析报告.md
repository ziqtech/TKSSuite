# FONT9696 字体渲染逆向分析报告

> 基于 TKS 游戏反编译源码 (运行时转储) 的完整字体渲染系统分析。
> 涵盖 FONT9696 位图格式、RLE 压缩、BIG5 索引、渲染上下文初始化、控制码分发、
> 以及编辑器预览渲染管道中所有已知问题的修复记录。

## 1. FONT9696 文件格式

### 1.1 文件结构

```
┌─────────────────────────────────────┐
│  索引表 (8 × 14915 × 4 字节)        │  = 119,320 个 uint32 偏移
├─────────────────────────────────────┤
│  RLE 压缩位图数据区                  │  可变长度
└─────────────────────────────────────┘
```

- **8 个 FTYPE 区段**: 每个 FTYPE (1-8) 对应一组 14,915 个字形
- **索引表**: 每 4 字节为一个 uint32 LE 偏移，指向 RLE 数据区
- **FILENAME**: 游戏目录下的 `FONT9696` 文件 (无扩展名)

### 1.2 BIG5 字形索引 (sub_44B384)

```c
// sub_44B384: 字符码 → 字形索引
// ASCII 字符 (< 0x80): 先查 word_4EC810 重映射表
if (char_code < 0x80)
    char_code = word_4EC810[char_code];  // ASCII 重映射

// 低字节索引计算
if (0x40 <= low <= 0x7E)
    li = low - 64;
else if (0xA1 <= low <= 0xFE)
    li = low - 98;   // = low - 0xA1 + 63
else
    return 0;         // 无效

// 行偏移
if (0xA100 <= char_code <= 0xFE00)
    li += 157 * (high_byte - 0xA1);  // Big5 lead byte

// 最终索引 = 行内偏移 + FTYPE × 14915
return li + 14915 * ftype_index;
```

| 参数 | 值 | 说明 |
|------|-----|------|
| `GLYPHS_PER_SECTION` | 14915 | 每个 FTYPE 的字形数 |
| `低字节范围 1` | 0x40-0x7E → `low - 64` | BIG5 常用区低字节 |
| `低字节范围 2` | 0xA1-0xFE → `low - 98` | BIG5 次常用区低字节 |
| `行宽` | 157 | 每个 lead byte 的行宽 |
| `Lead byte 范围` | 0xA1-0xFE | BIG5 双字节高字节 |

**关键**: ASCII 字符在索引前需通过 `word_4EC810` 映射表重编码，该表为游戏运行时数据，编辑器不持有此表。

### 1.3 RLE 压缩格式 (sub_44B208)

```
每 3 字节编码 4 个交替黑白游程:
  b[0] → runs[0] = b[0] & 0x3F                (6 bit, 黑色)
  b[0] → runs[1] = (b[0] >> 6) | (b[1] & 0xF) << 2  (6 bit, 白色)
  b[1] → runs[2] = (b[1] >> 4) | (b[2] & 0x3) << 4  (6 bit, 黑色)
  b[2] → runs[3] = b[2] >> 2                        (6 bit, 白色)
```

- 每个游程 6 bit，值域 0-63
- 位图分辨率: 96×96 像素，1bpp，共 1152 字节 (96×96/8)
- **极性**: bit=1 为**背景**(非笔画)，bit=0 为**笔画**(前景)
- 字形缓冲区: 1152 字节 (`GLYPH_BUF_SIZE`)

> ⚠️ **极性是关键**: FONT9696 位图中 `bit=1` 代表背景而非笔画。
> 解码后必须取反 (`b ^ 0xFF`) 才能得到正确的前景/背景分布。

## 2. 游戏文本渲染系统

### 2.1 渲染上下文结构 (a1 结构体)

`sub_44E49C` 使用一个 136 字节的渲染上下文结构体，各偏移量含义如下:

| 偏移 | 类型 | 含义 | 默认值 | 来源 |
|------|------|------|--------|------|
| +0 | DWORD | 当前 SIZE 值 (FTYPE tag 内部使用) | 0 或 1 | `sub_44AF7C`, `sub_44E49C case 5` |
| +4 | DWORD | 保存的 SIZE 值 (FRESET 恢复用) | 0 | `sub_44AF7C` |
| +8 | DWORD | **当前前景色** (FCOLOR) | dword_A2C528[0] | `sub_44ADB0`, `sub_44B028` |
| +12 | DWORD | 颜色副本 | dword_A2C528[0] | `sub_44ADB0` |
| +16 | DWORD | **保存的前景色** (FCOLOR 恢复用) | dword_A2C528[0] | `sub_44ADB0` |
| +24 | DWORD | **保存的字号** (FTYPE 恢复用) | 24→FSIZE值 | `sub_44B04C` |
| +28 | DWORD | **字符宽度** (advance) | 24→FSIZE值 | `sub_44B04C`: `size >> shift_flag` |
| +32 | DWORD | **保存的字号** (FRESET 恢复用) | 24→FSIZE值 | `sub_44B04C` |
| +36 | DWORD | 色彩位深 (15/16/32) | dword_A2C244 | `sub_44ADB0` |
| +40 | DWORD | 裁剪 X | 0 | `sub_44ADB0` |
| +44 | DWORD | 裁剪 Y | 0 | `sub_44ADB0` |
| +48 | DWORD | 渲染标志 | 0 或 1 | `sub_44AF7C` a4 |
| +52 | DWORD | 行宽限制 | 0 (无限) | `sub_44ADB0` |
| +56 | DWORD | 行高 | =FSIZE | `sub_44B04C`: `*(a1+56) = size` |
| +60 | DWORD | **行进增量** (换行增量) | =FSIZE | `sub_44B04C`: `*(a1+60) = size` |
| +64 | BYTE | 渲染效果标志 | 1 | `sub_44AF7C` a7 |
| +65 | BYTE | **半宽标志** | 见下文 | `sub_44AF7C` a5 |
| +66 | BYTE | **半宽锁存** | 见下文 | `sub_44AF7C` a6 |

### 2.2 渲染上下文初始化 (sub_411624)

游戏启动时建立 3 个全局渲染上下文:

```c
// === 渲染器 1: dword_755B04 (主文本渲染器) ===
sub_44ADB0(v14, dword_A2C244);                // 初始化, 默认 size=24
sub_44AF7C(dword_755B04, 1, 16, 1, 0, 1, 1); // FTYPE_raw=1, FSIZE=16, shift=0, latch=1
sub_44AFF4(dword_755B04, 0, 640, 480);         // 裁剪区域
sub_44B028(dword_755B04, 0);                   // FCOLOR=index 0 (黑色)

// === 渲染器 2: dword_755B08 (辅助渲染器) ===
sub_44ADB0(v13, dword_A2C244);                // 初始化, 默认 size=24
sub_44AF7C(dword_755B08, 2, 24, 1, 0, 0, 0); // FTYPE_raw=2, FSIZE=24, shift=0, latch=0
sub_44AFF4(dword_755B08, 0, 640, 480);
sub_44B028(dword_755B08, 0);                   // FCOLOR=0

// === 渲染器 3: dword_755B0C ===
sub_44ADB0(v12, dword_A2C244);                // 初始化, 默认 size=24
sub_44AF7C(dword_755B0C, 1, 24, 1, 0, 1, 1); // FTYPE_raw=1, FSIZE=24, shift=0, latch=1
sub_44AFF4(dword_755B0C, 0, 640, 480);
sub_44B028(dword_755B0C, 18);                  // FCOLOR=index 18 (暗黄色)
```

| 参数 | 渲染器1 (755B04) | 渲染器2 (755B08) | 渲染器3 (755B0C) |
|------|:-:|:-:|:-:|
| **FTYPE_raw (a2)** | 1 | 2 | 1 |
| **FSIZE (a3)** | **16** | 24 | 24 |
| **flag (a4)** | 1 | 1 | 1 |
| **半宽标志 (a5)** | 0 | 0 | 0 |
| **半宽锁存 (a6)** | **1** | 0 | **1** |
| **效果标志 (a7)** | 1 | 0 | 1 |
| **FCOLOR** | 0 (黑) | 0 (黑) | 18 (暗黄) |

> **重要**: 主渲染器默认 FSIZE=16、半宽锁存=1，意味着 ASCII 字符使用半宽渲染。
> FTYPE_raw=1 对应 `word_4EC810` 重映射后的 FTYPE index 1，即 FONT9696 的第 2 个区段。

### 2.3 sub_44AF7C 参数详解

```c
int __cdecl sub_44AF7C(int a1, int a2, int a3, int a4, char a5, char a6, char a7)
{
    *(a1 + 4) = a2;       // 保存的 SIZE 值 (FTYPE case 5 恢复用)
    *a1       = a2;       // 当前 SIZE 值
    // 若 a2 > 7, 则重置为 0
    *(a1 + 48) = a4;      // 渲染标志
    *(a1 + 65) = a5;      // 半宽标志 (0=全宽, 1=半宽)
    if (a5 == 1)
        *(a1 + 66) = *(a1+65); // 半宽锁存 = 半宽标志
    else
        *(a1 + 66) = a6;      // 半宽锁存 = a6
    *(a1 + 64) = a7;      // 渲染效果标志
    sub_44B04C(a1, a3, 1); // 设置字号并保存到 offset+32
}
```

### 2.4 sub_44B04C 字号设置

```c
int __cdecl sub_44B04C(int a1, int a2, int a3)
{
    // a2 = 字号, a3 = 是否保存到 offset+32
    // 仅接受 12/16/24/32/48, 其他值回退到 24
    switch (a2) {
        case 12: case 16: case 24: case 32: case 48:
            *(a1+24) = a2; break;
        default:
            *(a1+24) = 24; break;
    }
    // 更新所有派生尺寸
    *(a1+60) = *(a1+24);  // 行进增量 = 字号
    *(a1+56) = *(a1+24);  // 行高 = 字号
    *(a1+28)  = *(a1+24) >> *(a1+65); // 字符宽度 = 字号 >> 半宽标志
    if (a3)
        *(a1+32) = *(a1+24); // 保存字号 (FRESET 恢复用)
}
```

> **核心**: `字符宽度 = 字号 >> 半宽标志`。半宽标志=0 时字符宽度=字号 (全宽)，
> 半宽标志=1 时字符宽度=字号/2 (半宽)。

## 3. 控制码分发 (sub_44E49C)

### 3.1 控制码映射

| 字节码 | 名称 | 数据长度 | 值域 | 行为 |
|--------|------|---------|------|------|
| 0x01 | FRESET | 1 | [1,4] | 恢复状态 |
| 0x02 | FCOLOR | 1 | [1,32] | 设置文字颜色 |
| 0x03 | (RGB色) | 3 | - | 直接 RGB565 颜色 |
| 0x04 | FSIZE | 1 | [12,48] → {12,16,24,32,48} | 设置字号 |
| 0x05 | FTYPE | 1 | [1,8] | 设置字体类型 |
| 0x14 | TEXT | 2 | [1,32767] | 文本引用 |
| 0x15 | VARNUM | 1 | [1,255] | 数值变量 |
| 0x16 | VARTXT | 1 | [1,255] | 文本变量 |
| 0x1D | NAME | 1 | [1,2] | 名称引用 |
| 0x1E | — | — | — | 换行 (0x1E) |
| 0x00 | — | — | — | 条目终止 (0x00) |

### 3.2 FRESET 子码

| 值 | 行为 (sub_44E49C case 1) |
|----|---------|
| 1 | 全部恢复: `*(a1+8)=*(a1+16)` (色), `sub_44B04C(a1, *(a1+32), 0)` (号), `*a1=*(a1+4)` (TYPE) |
| 2 | 恢复颜色: `*(a1+8)=*(a1+16)` |
| 3 | 恢复字号: `sub_44B04C(a1, *(a1+32), 0)` |
| 4 | 恢复字体类型: `*a1=*(a1+4)` |

### 3.3 文字渲染行为 (sub_44E49C default 分支)

```c
// 字节 >= 0x80: CJK 双字节字符
if (*a2 >= 0x80) {
    big5_code = (hi_byte << 8) | lo_byte;
    sub_44E290(a1, big5_code, x, y, surface);
    x += *(a1+28);  // 字符宽度 (全宽 = 字号)
    // 换行检查...
}
// 字节 < 0x80 且半宽标志=1: ASCII 已切换模式
else if (*(a1+65) == 1) {
    sub_44E290(a1, *a2, x, y, surface);
    x += *(a1+28);  // 字符宽度 (已被 FSIZE>>1)
}
// 字节 < 0x80 且半宽锁存=1: ASCII 半宽模式
else if (*(a1+66)) {
    *(a1+65) = 1;   // 临时切换半宽
    sub_44E290(a1, *a2, x, y, surface);
    x += *(a1+28) >> 1;  // 半宽 = 字号/2
    *(a1+65) = 0;   // 恢复全宽
}
// 字节 < 0x80 且无半宽: ASCII 全宽模式
else {
    sub_44E290(a1, *a2, x, y, surface);
    x += *(a1+28);  // 全宽 = 字号
}
```

**关键发现**:
- CJK 字符: `advance = *(a1+28) = 字号` **(全宽，与字形实际宽度无关)**
- ASCII 半宽模式: `advance = *(a1+28) >> 1 = 字号/2`
- ASCII 全宽模式: `advance = *(a1+28) = 字号`
- 游戏主渲染器 (755B04) 半宽锁存=1，所以 ASCII 默认半宽

### 4.2 FCOLOR 与 dword_A2C524/dword_A2C528 的关系

- `dword_A2C524` 是 JVG 调色板指针，由 `sub_453BD0` 从 JVG 文件加载
- `FCOLOR` 标签 (case 2) 使用 `dword_A2C524[value]`
- `sub_44B028(struct, index)` 使用 `dword_A2C528[index]`
- 两者是**不同**的调色板，但 `dword_A2C524` 的实际值取决于 JVG 文件内容

## 5. 编辑器渲染管道

### 5.1 字形渲染流程

```
Unicode 字符
    │
    ▼
_unicode_to_big5_code(ch)        ← Python 层，BIG5 编码转换
    │
    ├─ CJK (BIG5 双字节) → Font9696.glyph_image(big5_code, ...)
    │       │
    │       ▼
    │   _char_index(big5_code, ftype)  ← BIG5 → 字形索引
    │       │
    │       ▼
    │   _glyph_raw(idx, ftype)          ← 读取 RLE 压缩数据
    │       │
    │       ▼
    │   _decode_rle(data)               ← RLE 解码 + 极性反转 (XOR 0xFF)
    │       │
    │       ▼
    │   找包围盒 → 缩放到 target_height × target_height 画布
    │       │
    │       ▼
    │   着色 (RGBA 合成)
    │       │
    │       ▼
    │   返回 (居中画布图像, advance=字号)  ← advance=字号, 非 bounding box 宽度!
    │
    └─ ASCII (BIG5 单字节) → _render_fallback_char(ch, size, color, family, half_width=True)
            │
            ▼
        系统字体渲染，advance = 字号/2 (半宽模式)
```

### 5.2 已修复问题列表

| 编号 | 问题 | 根因 | 修复 | 逆向依据 |
|------|------|------|------|---------|
| 1 | 预览区不显示任何字体 | `ord(ch)` 返回 Unicode 码点，BIG5 字体需要 BIG5 编码 | 新增 `_unicode_to_big5_code()` 将 Unicode→BIG5 转换 | sub_44B384: BIG5 双字节编码索引 |
| 2 | ASCII 字符无渲染 | `_char_index()` 对 `< 0x80` 返回 None，无回退 | 新增 `_render_fallback_char()` 系统字体回退 | sub_44E49C: ASCII 走 `sub_44E290` 单独路径 |
| 3 | 字体颜色反转 (前景色变成背景色) | FONT9696 RLE 解码 bit=1 代表背景，代码误当笔画 | `_decode_rle()` 后 `bytes(b ^ 0xFF for b in raw)` 取反 | 位图实测: 86.5% bit=1 = 背景 |
| 4 | 默认字号过大 (24px) | 与游戏主渲染器 FSIZE=16 不匹配 | `DEFAULT_FONT_SIZE = 16` | sub_44AF7C(dword_755B04, 1, **16**, ...) |
| 5 | 默认字体类型错误 (FTYPE=1) | 与游戏默认 FTYPE_raw=1 (即 index 1=MingLiU) 不匹配 | `DEFAULT_FTYPE = 2` | sub_44AF7C: offset+0=1 → ftype index 1 |
| 6 | CJK 标点偏大/偏小 | 游戏引擎 advance=字号 (全宽等宽)，编辑器用 bounding box 宽度 | `glyph_image()` advance=字号，画布=字号×字号 居中 | sub_44E49C: CJK `x += *(a1+28)` = 字号 |
| 7 | ASCII 字符全宽渲染 | 游戏主渲染器 ASCII 半宽 (字号/2) | `_render_fallback_char()` 新增 `half_width` 参数 | sub_44E49C offset+66: 半宽锁存 |
| 8 | BIG5 编码溢出/乱码 | BIG5 双字节中低字节可能落入控制码区间 | `decode_line()` 正确处理控制字节 vs BIG5 的优先级 | sub_4019D0: 控制码先于 BIG5 检查 |

### 5.3 默认渲染参数对比

| 参数 | 编辑器默认值 | 游戏主渲染器 (755B04) | 匹配 |
|------|-------------|---------------------|------|
| FSIZE | 16 | 16 (`sub_44AF7C` a3=16) | ✅ |
| FTYPE | 2 | 1 (raw) → index 1 | ✅ |
| FCOLOR | 32 (白色, #FFFF) | 0 (黑色, dword_A2C528[0]) | ⚠️ 偏离 |
| CJK advance | = fontsize | = *(a1+28) = fontsize | ✅ |
| ASCII advance | fontsize/2 | *(a1+28)>>1 (半宽模式) | ✅ |
| 预览背景 | #0a0a1a (暗色) | 游戏背景 | ✅ |

> FCOLOR 差异是合理的: 游戏在浅色背景上黑色文字，编辑器在暗色背景上白色文字。

## 6. sub_44B208 RLE 解码细节

```c
// sub_44B208: RLE 解码到位图缓冲区
// 输入: 3 字节一组编码 4 个黑白交替游程
// 字形缓冲区大小: 96×96/8 = 1152 字节

void sub_44B208(int a1, unsigned char *rle_data, unsigned char *out_buf) {
    // 找到字形首尾偏移:
    // v6 = 首偏移 (从索引表读 4 字节)
    // v5 = 字形数据长度
    // 从 FONT9696 文件偏移 v6 处读取 v5 字节到 dword_A2A468

    // 调用 RLE 解码器
    // ... 实际解码在 FONT9696 硬件层
}

// RLE 3 字节组格式:
// [b0, b1, b2] → 4 个 6-bit 游程:
//   run[0] = b0 & 0x3F          (黑色)
//   run[1] = (b0>>6) | (b1&0xF)<<2 (白色)
//   run[2] = (b1>>4) | (b2&0x3)<<4 (黑色)
//   run[3] = b2 >> 2              (白色)

// 位图极性:
//   bit=1 → 背景 (白色/透明)
//   bit=0 → 笔画 (前景/着色)
// 编辑器解码后必须 XOR 0xFF 反转极性
```

## 7. 字体类型 (FTYPE) 对应表

游戏中 FTYPE 1-8 对应 FONT9696 的 8 个区段（每个区段 14,915 个字形），字形的视觉风格来自不同的 JVG 字体文件:

## 8. ASCII 字符渲染机制

### 8.1 游戏 ASCII 渲染路径 (sub_44E49C)

```
ASCII 字节 (< 0x80)
    │
    ├─ 半宽标志=1 (a1+65): 全宽渲染, advance=字号
    │
    ├─ 半宽锁存=1 (a1+66), 半宽标志=0:
    │   sub_44E290(a1, char, x, y, surface)
    │   x += 字号 >> 1    (半宽)
    │   半宽标志 归零
    │
    └─ 半宽锁存=0, 半宽标志=0: 全宽渲染, advance=字号
```

### 8.2 ASCII 重映射表 (word_4EC810)

`sub_44B384` 中，ASCII 字码在 FONT9696 索引前先通过 `word_4EC810` 映射表:

```c
if (char_code < 0x80)
    char_code = word_4EC810[char_code];  // ASCII 重映射
```

此表为运行时数据，从 `FONT9696` 文件加载或由游戏初始化设置。编辑器不持有此表，
因此 ASCII 字符使用系统字体近似渲染。

### 8.3 编辑器 ASCII 回退策略

由于缺少 `word_4EC810` 映射表，编辑器对 ASCII 字符使用系统 TrueType 字体回退:

```python
def _render_fallback_char(ch, size, color, family_tuple, half_width=False):
    if half_width:
        # 半宽模式: advance = size // 2
        # 字形居中在 (size//2, size) 的画布中
        ...
    else:
        # 全宽模式: 使用字形边框宽度
        ...
```

回退字体选择优先级:
1. GAME_FONT_FAMILIES 中当前 FTYPE 对应的系统字体
2. Microsoft YaHei, SimHei, SimSun, MingLiU, PMingLiU
3. Windows Fonts 目录下的 .ttc/.ttf 文件
4. Pillow 默认字体

## 9. 修复后的字形渲染参数

### 9.1 CJK 字形 (FONT9696)

```
输入: BIG5 编码 (如 '中' → 0xA4A4)
      FTYPE (1-8) → 区段索引 (0-7)
      target_height (FSIZE: 12/16/24/32/48)
      前景色 (#RRGGBB)

输出:
  - 画布尺寸: target_height × target_height (全宽 em-square)
  - 前进宽度: target_height (全宽, 等于字号)
  - 字形居中于画布
  - 着色: RGBA 合成 (前景色 + alpha 通道)
```

### 9.2 ASCII 字形 (系统字体回退)

```
输入: ASCII 字符
      size (FSIZE)
      颜色
      字体族
      half_width = True

输出:
  - 画布尺寸: (size//2, size)
  - 前进宽度: size // 2 (半宽)
  - 字形水平居中于画布
  - 着色: Pillow ImageDraw.text()
```
