## 一、网格基础

### 尺寸与索引

```
32 × 32 网格
grid_index = Y * 32 + X    (X, Y ∈ [0, 31])
```

**证据**:
- WarWay.dat fread 1024 = 32×32 字节 (sub_42FE70:17)
- 所有网格数组使用 `Y*32+X` 索引 (sub_436114:67-70)
- 遍历用 `while (v2 < 32)` × `while (v3 < 32)` (sub_4355C4:56-60)

### 四套网格

| 数组 | 大小 | 数据来源 | 用途 |
|------|------|---------|------|
| `byte_951942` | 1024B | WarWay.dat[map_id×1024] | **地形网格**: -1=障碍, 0=通行, 1-5=特殊区域 |
| `byte_951D42` | 1024B | 初始化为-1, sub_431428填充 | **单位占用网格**: ≥0=被角色N占用, -1=空 |
| `byte_953154` | 1024B | sub_43D8B0 运行时计算 | **移动范围显示**: ≥0=可达, -1=不可达 |
| `byte_952D54` | 1024B | sub_43D53C 运行时计算 | **寻路路径网格**: -1=未评估, 0=起点, 1=路径 |

## 二、等距投影 (sub_42F9C8)

### 公式

```c
// sub_42F9C8: 网格坐标 → 屏幕坐标
*a1 -= 10;                                                    // grid_X -= 10
*a2 -= 15;                                                    // grid_Y -= 15
*a1 = dword_4E7DF0 + 56 * grid_X - 56 * grid_Y;              // screen_X
*a2 = dword_4E7DF4 + 28 * grid_X + 28 * grid_Y;              // screen_Y
```

简化形式（忽略 -10/-15 偏移）:
```
screen_X = base_X + 56 × (X - Y)
screen_Y = base_Y + 28 × (X + Y)
```

**投影系数 56 和 28 为硬编码值，所有 WSC 分辨率通用。**

### 反向投影 (sub_410848)

```c
// sub_410848: 屏幕坐标 → 网格坐标
t1 = (screen_X - (base_X - cell_w/2)) / 2;
t2 = screen_Y - (base_Y - cell_h/2);

YX_sum  = (t2 + t1) / cell_size;    // X+Y
YX_diff = (t2 - t1) / cell_size;    // Y-X

grid_X = YX_sum + offset_X;
grid_Y = YX_diff + offset_Y;
```

其中 `cell_w = dword_4E7E00 = 112`, `cell_h = dword_4E7E04 = 56`（数据段 dump 确认）。

## 三、WSC.GRP 背景图层

### 加载

```c
// sub_436BD4:19 — 战场初始化
sub_451600("WSC.IDX", "WSC.GRP");  // 加载背景索引和图片数据
```

### 尺寸

WSC.GRP 包含 83 个背景图条目。WSC.IDX 每个 4 字节(uint32)存储 GRP 文件偏移量。

背景图尺寸（解压后）:
- 1280×960 (约 50 个条目)
- 800×600  (约 28 个条目)
- 1024×768 (约 4 个条目)

WarData.map_id 直接索引 WSC 条目。

### 与网格的关系

WSC 背景是预渲染等距战场图。游戏运行时通过 sub_42F9C8 等距投影将网格渲染在背景之上，两者共享同一坐标系。

## 五、WarWay 地形值语义

| 值 | 符号 | 含义 | 渲染 | 通行 |
|----|------|------|------|------|
| 0xFF | -1 | 永久障碍 | WSC背景透出(无wm.JVG) | ✗ |
| 0x00 | 0 | 普通地面 | WSC背景透出 | ✓ |
| 1-5 | 1-5 | 特殊区域(PlaceReq) | WSC背景透出 | ✗ (移动检查`!*v11`需要==0) |
| < -1 | -2.. | 临时修改(恢复中) | wm.JVG Sprite 15+22 | ✗ |

**值 1-5 仅用于 sub_431428 PlaceReq 宝物/单位位置匹配，无独立视觉渲染。**

## 六、编辑器渲染逻辑

### 投影

编辑器使用 sub_42F9C8 的简化形式（省略 -10/-15 偏移，因为编辑器直接控制坐标系原点和缩放）:

```python
def _grid_to_screen(gx, gy):
    tile_w = int(56 * zoom)   # sub_42F9C8: 56*(X-Y)
    tile_h = int(28 * zoom)   # sub_42F9C8: 28*(X+Y)
    sx = origin_x + (gx - gy) * tile_w
    sy = origin_y + (gx + gy) * tile_h
    return sx, sy
```

### 摄像机中心计算

对标 sub_410848 根据通行区域设置摄像机:

```python
# 从 WarWay 可通行区域(>=0) 计算几何中心
for gy in range(32):
    for gx in range(32):
        if warway[gy * 32 + gx] >= 0:  # sub_43D0E8:104
            cx += gx; cy += gy; n += 1
center_x = cx // n
center_y = cy // n

# 将通行区域中心对齐到 WSC 背景图中心
origin_x = bg_center_x - (center_x - center_y) * tile_w
origin_y = bg_center_y - (center_x + center_y) * tile_h
```

### 图层顺序

1. WSC 背景（底层）
2. WarWay 网格（菱形地格，按值着色 + 透明度）
3. 宝物标记（金色方块，trea_xy 坐标）
4. 单位标记（红色=敌军 enemy_xy，蓝色=友军 ally_xy）

### 透明度

通过 tkinter Canvas `stipple` 属性模拟:
- 0%: 无 stipple
- 25%: gray75
- 50%: gray50
- 75%: gray25
- 100%: 无填充(仅边线)

## 七、已知局限

**WSC 背景与网格的精确像素对齐**：

sub_402BB8 从游戏数据段读取的 per-map 像素尺寸（`word_824290` × `word_824292`）和 sub_410848 根据角色位置的摄像机偏移均无法从静态 WarData 数据获取。当 WSC 图像渲染时摄像机中心网格坐标不等于通行区域中心时（如 800×600 图像），网格与背景的精确对齐存在偏差。

这是游戏运行时数据决定的，静态分析无法 100% 还原。
