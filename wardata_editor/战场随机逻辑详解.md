## 2. 随机敌军数量 — `sub_4307CC`

### 2.1 源码 (sub_4307CC.c:200-210)

```c
if ( (byte_9537D8 & 4) != 0 )           // WarData[0] flags bit2
{
    if ( (unsigned __int16)sub_452AC0(1000) >= 0x12Cu )  // 70% 分支
        word_9D6F66 = sub_452AC0(2 * byte_9DF884 - 2) + 3;
    else                                                   // 30% 分支
        word_9D6F66 = sub_452AC0(byte_9DF884 / 2 + byte_9DF884) + 1;
}
else
{
    word_9D6F66 = 18;                    // 固定 18 槽位
}
```

### 2.2 变量说明

| 变量 | 偏移/来源 | 含义 |
|------|----------|------|
| `byte_9537D8` | WarData[0] | flags 字段, bit2 (&4) = 随机敌军数 |
| `byte_9DF884` | sub_4307CC:193 | 有效友军数量 (must_chars 中非0非255的计数) |
| `word_9D6F66` | 全局 | **敌军激活槽位数** — 控制后续所有循环的槽位上限 |

### 2.3 公式展开

设友军数 A = `byte_9DF884` (≥1):

**分支 1 (70% 概率)**: `rand(1000) >= 300`

```
active_slots = rand(2A - 2) + 3
             ∈ [3, 2A + 1]
```

**分支 2 (30% 概率)**:

```
active_slots = rand(⌊A / 2⌋ + A) + 1
             = rand(⌊1.5A⌋) + 1
             ∈ [1, ⌊1.5A⌋]
```

**固定模式** (flags bit2 未设置):

```
active_slots = 18   (全部 18 个敌军槽)
```

### 2.4 实例

| 友军数 A | 70% 分支范围 | 30% 分支范围 |
|---------|-------------|-------------|
| 1 | [3, 3] | [1, 1] |
| 2 | [3, 5] | [1, 3] |
| 3 | [3, 7] | [1, 4] |
| 4 | [3, 9] | [1, 6] |
| 5 | [3, 11] | [1, 7] |
| 6 | [3, 13] | [1, 9] |

### 2.5 影响范围

`word_9D6F66` 控制以下循环的上限:

| 位置 | 循环 | 影响 |
|------|------|------|
| sub_4307CC:220 | `while (v28 < word_9D6F66)` | 只加载前 N 个敌军槽的 WarPC 数据 |
| sub_431428:90 | `while (v3 < word_9D6F66)` | 只对前 N 个敌军槽做固定位置放置 |
| sub_431428:179 | `while (v6 < word_9D6F66)` | 只记录前 N 个敌军槽的最终位置 |

## 3. 场景布置 — `sub_431428`

### 3.1 整体处理流程

```
Step 1 (line 74-87):   友军固定位置 → 标记占用
Step 2 (line 88-105):  敌军固定位置 → 标记占用
Step 3 (line 106-159): 区域放置 Zone 1→5 (遍历 24 个战斗槽: 18敌军+6友军)
Step 4 (line 160-192): 记录所有单位的最终坐标
Step 5 (line 198-282): 宝物固定位置 + 区域放置
Step 6 (line 283-358): 最终化: 重置 WarWay 网格, 记录宝物数据
```

### 3.2 固定位置 vs 区域请求

每个单位/宝物的 X 坐标 (`enemy_xy[i*2]` / `ally_xy[i*2]` / `trea_xy[i*2]`) 语义:

| X 值 | 含义 |
|------|------|
| 0~31 | **固定位置** — 直接放置在 (X, Y) 网格坐标 |
| -1 ~ -5 | **区域请求** — 从 WarWay 对应区域随机选取一格 |
| ≥32 | 无效 (编辑器忽略) |

### 3.3 区域放置算法

源码 (sub_431428:106-159, 简化):

```c
for (i = 1; i <= 5; ++i)           // Zone 1 → 5
{
    // Phase A: 收集当前 zone 的所有候选格
    v13 = 0;
    for (gy = 0; gy < 32; gy++)
        for (gx = 0; gx < 32; gx++)
            if (WarWay[gy][gx] == i && !is_occupied(gx, gy))
                candidates[v13++] = (gx, gy);   // 加入候选池

    // Phase B: 为每个匹配的槽位随机分配
    for (slot = 0; slot < 24; slot++)  // 24 = 18敌人 + 6友军
    {
        if (unit_xy[slot].X == -i)     // 匹配当前 zone
        {
            r = sub_452AC0(v13);        // 随机索引 [0, v13)
            unit_xy[slot] = candidates[r];  // 分配位置
            // 从候选池移除 (shift-left 压缩)
            memmove(&candidates[r], &candidates[r+1], (v13-r-1)*2);
            v13--;
        }
    }
}
```

**关键规则**:
1. **Zone 优先处理**: Zone 1 的所有请求先于 Zone 2 处理，以此类推
2. **不放回抽样**: 每次分配后从候选池中移除，同一 Zone 内不重复
3. **不可重叠**: 被固定位置占用的格不进入候选池
4. **候选不足**: 当候选池为空但仍有请求时，游戏调用 `sub_4B7448` 报错 (编辑器显示为区域请求标记)

### 3.4 占用判定

```c
// sub_431428:72 - 初始化占用网格为 -1 (未占用)
sub_4B00FC(byte_951D42, -1, 1024);

```

## 4. WarWay 网格 — 区域数据源

### 4.1 格式

- 文件: `WarWay.dat`
- 每条: 1024 字节 = 32×32 有符号字节 (int8)
- 100 条记录，索引 = `WarData.map_id`

### 4.2 值语义

| 值 | 含义 | 来源 |
|----|------|------|
| -1 (0xFF) | 永久障碍 — 不可通行, sub_4355C4 更新循环跳过 | sub_4355C4 |
| < -1 | 临时障碍 — sub_4355C4 每回合 +1 直到 0 | sub_4355C4 |
| 0 | 普通可通行地面 | sub_434D7C |
| 1~5 | 特殊区域 — 用于区域放置系统 | sub_431428:106 |

### 4.3 区域编号映射

| WarWay 值 | 区域请求 X | Zone 颜色 (编辑器) |
|-----------|-----------|-------------------|
| 1 | -1 | 棕色 |
| 2 | -2 | 蓝色 |
| 3 | -3 | 紫色 |
| 4 | -4 | 青绿 |
| 5 | -5 | 黄色 |

## 5. 随机数生成器 — `sub_452AC0`

### 5.1 源码

```c
// sub_452AC0.c
int __cdecl sub_452AC0(unsigned __int16 a1)
{
    unsigned __int16 v2;
    if ( !a1 )
        return 0;
    do
        v2 = sub_452968();           // 16位随机数生成
    while ( v2 >= (unsigned __int16)(a1 * (0xFFFF / a1)) );  // 拒绝采样
    return v2 % (int)a1;             // 返回 [0, a1)
}
```

### 5.2 算法

- `sub_452968`: 生成 16 位随机数 (LCG 或系统调用)
- 拒绝采样: 丢弃超出均匀分布范围的值，确保 `[0, a1)` 均匀
- 效果等价于: `random.randrange(a1)` 或 `rand() % a1`

### 5.3 Python 等价

```python
import random
random.randrange(n)  # 等价于 sub_452AC0(n)
```

## 6. 宝物区域放置 — `sub_431428:198-282`

### 6.1 源码逻辑

```c
// 第1步 (line 198-223): 固定位置宝物标记
v7 = 0;
v43 = &trea_id[0];
do {
    if (*v43 > 0 || *(v43 - 30) > 0) {    // trea_id>0 或 trea_sub>0 (仅前10组)
        x = *(v43 - 172);                   // trea_xy X (offset 214+2*i)
        y = *(v43 - 171);                   // trea_xy Y

            if (*(v43 - 30) > 0)
                sub_trea_grid[y*32 + x] = 1;     // 标记副宝物占用
        }
    }

    v43++;

// slots 10-27 只有主物品 (line 218-223)
for (; v7 < 28; v7++) {
    if (trea_id[v7] > 0 && trea_xy[v7*2] >= 0)
        main_trea_grid[trea_xy[v7*2+1]*32 + trea_xy[v7*2]] = 1;
}

// 第2步 (line 224-282): 区域放置
for (m = 1; m <= 5; m++) {           // Zone 1→5
    // 收集候选: WarWay==m 且两个宝物网格均为 -1
    for (gy = 0; gy < 32; gy++)
        for (gx = 0; gx < 32; gx++)
            if (WarWay[gy][gx] == m
                && main_trea_grid[gy*32+gx] == -1
                && sub_trea_grid[gy*32+gx] == -1)
                candidates[v14++] = (gx, gy);

    // 为匹配的宝物槽随机分配
    for (slot = 0; slot < 28; slot++) {
        if (trea_xy[slot*2] == -m) {
            r = sub_452AC0(v14);
            trea_xy[slot*2]   = candidates[r].x;
            trea_xy[slot*2+1] = candidates[r].y;
            // 移除候选
            memmove(&candidates[r], &candidates[r+1], (v14-r-1)*2);
            v14--;
        }
    }
}
```

## 9. 预览刷新机制

- 每次调用 `_redraw_scene()` 都会重新执行 `_resolve_scene_placements()`
- 触发时机: 切换 TreeView 记录、更改图层/缩放设置、拖拽单位后
- 效果: 每次切换战场，敌军数量和区域随机位置都会按游戏规则重新随机
- 拖拽某个单位到新位置后，其 `enemy_xy` 被写入正坐标 → 变为固定位置，后续刷新不再随机
