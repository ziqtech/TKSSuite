## 一、文件总览

### WarData.dat

- **记录大小**: 498 字节/条 (sub_42FDF8: fread→byte_9537D8, 498 bytes)
- **记录数量**: 219 条 (109062 / 498)
- **存储格式**: flat binary, 无压缩
- **加载方式**: sub_42FDF8: fopen/fseek(498×a1)/fread

### WarWay.dat

- **记录大小**: 1024 字节/条 (32×32 有符号字节网格)
- **记录数量**: 100 条
- **加载方式**: sub_42FE70: fseek(word_9537F8<<10)/fread(&unk_951942, 1024, 1)
- **值语义** (sub_4355C4 + sub_431428):
  - `-1 (0xFF)`: 障碍物/不可通行 — 更新循环跳过, 永久不变
  - `0 (0x00)`: 普通可通行地面 — 默认值
  - `1-5`: 特殊区域/放置区 — 触发地格特效

## 三、战场宝物系统完整分析

### 数据结构：一件宝箱 + 两层物品

sub_431428:286-309 的循环揭示：`trea_id` 和 `trea_sub` **共享同一个坐标** (`trea_xy`)，不是两套独立的宝物系统，而是一件宝箱可以放 1~2 个物品：

```
宝物槽 i:
├─ 坐标: trea_xy[2i], trea_xy[2i+1]        ← 主/副共用
├─ trea_id[i]:    主物品 TKItem记录索引      ← 28组全有
├─ trea_qty[2i]:  主物品数量 min (byte)      ← 28组全有
├─ trea_qty[2i+1]:主物品数量 max (byte)      ← 28组全有
├─ trea_sub[i]:   副物品 TKItem item_id      ← 仅前10组, 可选
├─ trea_quant[2i]:副物品数量 min (uint16)     ← 仅前10组
└─ trea_quant[2i+1]:副物品数量 max (uint16)   ← 仅前10组
```

**证据** (sub_431428:286-309)：
```c
v45 = (char *)&unk_95395A;  // offset 386 (trea_id)
do {
    // 同一个 if: trea_id 或 trea_sub 任一存在即进入
    if ( *(__int16 *)v45 > 0 || *((__int16 *)v45 - 30) > 0 )
    {
        v22 = *(v45 - 172);   // X = trea_xy[2*i]
        v29 = *(v45 - 171);   // Y = trea_xy[2*i+1]  ← 同一坐标

        if ( *(__int16 *)v45 > 0 )          // trea_id 存在 → 登记主物品
        {
            byte_952142[32*Y+X] = word_9DFC86;   // 网格A
            byte_9DFA92[5*n] = *v45;              // 记录物品ID
            byte_9DFA93[5*n] = random(Min, Max);  // 随机数量
            byte_9DFA94[5*n] = 0;
            word_9DFC86++;                         // 计数+1
        }
        if ( *((__int16 *)v45 - 30) > 0 )   // trea_sub 存在 → 登记副物品
            byte_952542[32*Y+X] = v9;             // 网格B
    }
    ++v9;
    v45 += 2;
} while ( v9 < 10 );
```

### 两套网格

| 网格 | 大小 | 初始值 | 存储内容 | 用途 |
|------|------|--------|---------|------|
| byte_952142 | 1024字节 | -1 (空) | 主物品登记号(0-27) | 主物品拾取触发 |
| byte_952542 | 1024字节 | -1 (空) | 槽位号(0-9) | 副物品拾取触发 |

### 主物品拾取 (sub_434D7C → sub_434C0C)

sub_434D7C 每回合调用，根据角色状态标志 (`v12[38] & 8`) 分为两条路径：

- **bit8=1 (展示)**: 渲染宝箱闪烁动画 (18帧)，宝物不消失
- **bit8=0 (拾取)**: 调用 sub_434C0C 拾取宝物

sub_434C0C 拾取逻辑：
```c
// 从物品数据表 (40*(trea_id+551)+10290840) 复制40字节属性
qmemcpy(&byte_9D6C28, (void *)(40 * (trea_id + 551) + 10290840), 0x28);
// 物品表中的两个 uint16 字段 × 随机数量
word_9D6C30 *= byte_9DFA93[5 * a3];   // × trea_qty 随机值
word_9D6C32 *= byte_9DFA93[5 * a3];   // × trea_qty 随机值
// 特殊物品双倍处理...
byte_952142[32*Y+X] = -1;              // 从网格移除
```

**注**: `10290840` 处的数据表在内存 dump 中为全零 (运行时初始化填充)，无法验证 `word_9D6C30/32` 的具体语义。能确认的是两个 uint16 值被乘以宝物随机数量。

### 副物品拾取 (sub_434510)

**调用链 (事实)**: `sub_4355C4`(主循环) → `sub_435240`(每回合) → `sub_434510`

```c
v6 = byte_952542[32*Y+X];              // 读副物品网格

if (v6 >= 0)                            // 该格有副物品
{
    if (byte_9DF761[当前角色] == 100)    // 行动槽满
    {
        // QtyMin/QtyMax → 随机数量
        if (QtyMin < QtyMax)
            QtyMin += random(QtyMax - QtyMin + 1);

        if (item_id == 10000)            // 银两
            money += QtyMin;
        else
        {
            sub_42F8D4(item_id);         // 查找物品
            物品数组[n] = item_id;
            数量数组[n] = QtyMin;
        }
    }
    else  // 行动槽未满 → 累积处理, 不直接给物品
    {
        // ...
    }
    if (查到了物品)
        sub_434188(物品数据, X, Y);       // 宝箱动画
    byte_952542[32*Y+X] = -1;             // 移除副物品
}
```

**函数内无玩家输入检查** (无按键检测、无菜单选择)。触发条件仅需: (1) 站在副物品格上, (2) 行动槽满。

### 结论

| 问题 | 答案 |
|------|------|
| 为什么分 trea_id/trea_sub？ | **不是两种宝物类型**。同一宝箱可放1~2个物品：主物品(必选28组) + 副物品(可选前10组)，共享同一坐标 |
| trea_qty (原LvMin/LvMax) | **主物品的数量范围** (byte, 0-255)。游戏中不存在"物品等级"。随机取值后决定获得量 |
| trea_quant (QtyMin/QtyMax) | **副物品的数量范围** (uint16, 0-65535)。拾取时随机取值直接作为背包数量 |
| 主物品如何获得？ | sub_434D7C → sub_434C0C，由角色状态标志 bit8 控制。bit8=1时仅展示动画，bit8=0时拾取 |
| 副物品如何获得？ | 每回合 sub_4355C4→sub_435240→sub_434510 自动检查。站在副物品格上+行动槽满→自动拾取，函数内无玩家输入 |

## 四、敌军/友军系统分析

### 敌军字段 (18 slots)

通过 sub_4307CC 和 sub_444FD4 两个独立函数交叉验证:

| 字段 | 偏移 | 用途 |
|------|------|------|
| enemy_id | 34-69 | WarPC 角色索引 (sub_4307CC:222 `*v5+35`) |
| enemy_lv | 70-87 | 等级 <10 杂兵, >=10 精英 (sub_4307CC:260) |
| enemy_group | 88-105 | AI 编组, 传入 sub_430578 (sub_4307CC:217) |
| enemy_lv_range | 106-141 | 等级参数对 (a3,a4), sub_430578 中计算等级 |
| enemy_xy | 142-177 | 网格坐标 (sub_431428:94-98 标记占用) |
| enemy_delay | 190-207 | 行动延迟 "属性加成" (sub_4307CC:242) |
| enemy_flags | 442-477 | bit0=精英, bit1=特殊, bit13/14=阵营 (sub_4307CC:263) |

### 等级参数 (enemy_lv_range) 详解

`sub_430578(a1, enemy_group, a3, a4, avg_level)`:

```
1. 如果 a3==0: a3=default_lv_p1, a4=default_lv_p2  (使用默认等级参数)
2. 如果 avg_level > 0:
   spread = clamp(|a4 - a3|, 2, 5)                (等级浮动幅度)
   max_level = avg_level + spread
   min_level = avg_level - spread (最小 1)
3. random(min_level, max_level) → sub_4302D8(a1, level, enemy_group)
```

sub_4302D8 将 level 赋值为 `a1[2] = level`，enemy_group 作为属性加成倍率。

### 友军字段 (6 slots)

友军是玩家队伍角色，完整数据 (身份/等级/装备) 来自 WarPC.dat 和游戏存档:

| 字段 | 偏移 | 用途 |
|------|------|------|
| ally_xy | 178-189 | 6对 int8 X,Y 起始坐标 (sub_431428:74-87) |
| ally_facing | 208-213 | 6个朝向值 (War.dll 标签; TKS.exe 反编译未直接引用) |

must_chars [2-7] 决定哪些玩家角色强制参战。

## 六、物品名称查找规则

物品名称需要二级查找 (参照 item_editor.py):

```
TKItem 记录索引 → name_id (TKItem field[2], offset 4) → TKT 文本
```

- **trea_id** (主物品): 存储 TKItem **记录索引** (0-599)
- **trea_sub** (副物品): 存储 TKItem **item_id** (field[0], 游戏内物品ID)

两者查找后得到同一 TKT 文本名称。
