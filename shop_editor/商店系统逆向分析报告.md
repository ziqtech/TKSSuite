# 商店系统逆向分析报告

> 基于 TKS.exe 反编译 (`sub_4233C4`, `sub_4244CC`, `sub_4246D8`, `sub_42485C` 等) + TKShop.dat / TKItem.dat 编辑器源码分析

## 一、数据文件结构

### TKShop.dat (240 条 × 8 字节，LZSS 压缩)

| 偏移 | 类型 | 含义 |
|------|------|------|
| 0 | int16 | `area_id` — 商店区域索引 (0=药店,1=道具,2=武器防具,3=杂货,4=饰品,9=无) |
| 2 | int16 | `item_ref` — TKItem 数组下标 (0-599) |
| 4 | int16 | `condition` — 出现条件: 1=随机抽选, >1=幸运门槛, ≤0=始终 |
| 6 | byte  | `display` — 运行时显示标志 (由 `sub_4244CC` 设置) |
| 7 | byte  | 保留 |

- 加载函数: `sub_45343C("TKShop.dat", &unk_9508A0, 1920)` — 硬编码 240 条 (8×240=1920 字节)
- 记录存储于全局缓冲区 `unk_9508A0`，每条 8 字节，通过 `9767072 + 8*index` 寻址

### TKItem.dat (600 条 × 64 字节 = 32 个 int16 字段，LZSS 压缩)

| 字段索引 | 偏移 | 名称 | 与商店的关系 |
|----------|------|------|-------------|
| [0] | 0 | `item_id` | 物品唯一标识 |
| [1] | 2 | `tab_code` | **商店分类页 (0=药品,1=道具,2=武器,3=防具,4=饰品,5=特殊)** |
| [5] | 10 | `equip_type` | 使用权限位掩码，影响购买可用性判断 |
| [31] | 62 | `price` | 物品价格 |

- 加载函数: `sub_45343C("TKItem.dat", word_77CBCA, 38400)` — 硬编码 600 条 (64×600=38400 字节)
- `tab_code` 存储于全局表 `word_77CBCC[32*i]`（每条记录 32 个 int16，field[1] 即 `[32*i+1]`）

## 二、商店过滤核心逻辑

### 2.1 双重匹配过滤 (sub_4246D8)

商店显示商品需要同时满足三个条件:

```
shop_record.area_id == current_shop_area_id      ← TKShop.dat 的 area_id 字段
AND
word_77CBCC[32 * item_ref] == current_tab_code    ← TKItem 的 tab_code 字段
AND
display == 1                                       ← sub_4244CC 设置的运行时标志
```

关键代码 (`sub_4246D8` 第 25-27 行):
```c
if ( *(_WORD *)v4 == *(_WORD *)(a1 + 56)                    // area_id 匹配
  && *(_BYTE *)(v4 + 6) == 1                                 // display == 1
  && word_77CBCC[32 * *(__int16 *)(v4 + 2)] == *(_WORD *)(a1 + 2 * *(__int16 *)(a1 + 66) + 62) )
                                                              // item.tab_code == current_tab
```

### 2.2 area_id → tab_code 映射 (sub_4233C4 硬编码 switch)

`current_tab_code` 由 `sub_4233C4` 中的 **硬编码 switch** 决定:

```c
// a1[28] = a3 (area_id, 来自脚本 Shop 指令的第3个参数)
switch ( a1[28] )
{
    case 0:  v6 = 0;  v5 = -1;  break;  // 药店     → 只显示 tab_code=0
    case 1:  v6 = 1;  v5 = -1;  break;  // 道具店   → 只显示 tab_code=1
    case 2:  v6 = 2;  v5 = 3;   break;  // 武器防具 → 显示 tab_code=2 和 3
    case 3:  v6 = 0;  v5 = 1;   break;  // 杂货店   → 显示 tab_code=0 和 1
    case 4:  v6 = 4;  v5 = -1;  break;  // 饰品店   → 只显示 tab_code=4
    default: break;                      // 其他     → v6/v5 不赋值 (未定义行为!)
}
a1[31] = v6;   // 主分类 tab_code
a1[32] = v5;   // 副分类 tab_code (-1 = 无副分类)
```

### 2.3 tab 切换与显示

- `a1[66]` — 当前选中的 tab 索引 (0=主分类, 1=副分类)
- `a1[30]` — 买卖模式 (0=购买页显示商店库存, 1=出售页显示玩家背包)
- `a1[33]` — 分页/翻页状态

tab 切换函数 `sub_424ECC`:
```c
a1[30] = a2;          // 切换买卖模式
if ( a1[30] )
    sub_42485C(a1);   // 出售: 按 tab_code 过滤玩家背包物品
else
    sub_4246D8(a1);   // 购买: 按 area_id + tab_code 过滤商店库存
```

### 2.4 出现条件过滤 (sub_4244CC)

在 area_id 匹配后，进一步按 `condition` 字段过滤:

```c
if ( condition == 1 ) {
    // 随机抽选: 随机数判定, 最多同时出现5件商品
    random_val = sub_452AC0(50000);
    // 保留概率最高的5件, 超出时替换概率最低的
} else {
    // 幸运门槛: 概率 = clamp(队伍最高幸运 - condition, 0, 100)%
    luck_diff = max_luck - condition;
    if ( luck_diff < 0 ) luck_diff = 0;
    random_val = sub_452AC0(50000) / 500;  // 0~99
    display = (random_val < luck_diff) ? 1 : 0;
}
```

## 三、关键约束汇总

| 约束 | 位置 | 硬限制 | 说明 |
|------|------|--------|------|
| **area_id → tab_code 映射** | `sub_4233C4` switch | 5 种 (case 0-4) | area_id=5~8 落入 default → v6/v5 未赋值 → 未定义行为 |
| **TKShop 记录数** | `sub_45343C` | 240 条 | LZSS 解压后必须恰好 1920 字节 |
| **TKItem 记录数** | `sub_45343C` / `sub_42F8D4` | 600 条 | 循环 `while (v3 < 600)` 硬编码 |
| **单页最大显示数** | `sub_4246D8` 第 23 行 | 8 件 | `while (v6 < 7 && v5 < 240)` → 最多 8 条 |
| **随机抽选上限** | `sub_4244CC` | 5 件 | `if (v14 >= 5)` 硬编码 |
| **购买数量按钮** | `sub_42359C` | 1/5/99 | 三个固定按钮，硬编码像素坐标 |

## 四、能否仅通过修改 .dat 文件增加商店类型?

### 结论: 不够，必须修改 TKS.exe 二进制

仅修改 TKShop.dat 和 TKItem.dat **无法**实现新增商店类型，原因:

1. **switch 硬编码**: `sub_4233C4` 的 switch 只处理 area_id=0~4，其他值落入 default 分支，`v6`/`v5` 不被赋值，导致 `a1[31]`/`a1[32]` 为垃圾值 → 过滤行为不可预测
2. **tab_code 无独立定义**: tab_code 本身只是 int16 数值，游戏代码没有对 tab_code 做范围检查，理论上可以使用任意值——但没有对应的 area_id 映射，商店不会显示它们
3. **area_id=9 的陷阱**: 虽然编辑器中定义了 area_id=9="无"，但它同样落入 switch default，不可靠

### 已有商店类型的 tab_code 兼容关系

| tab_code | 含义 | 可出现的商店 |
|----------|------|-------------|
| 0 | 药品/消耗品 | 药店 (area_id=0), 杂货店 (area_id=3) |
| 1 | 道具/书籍 | 道具店 (area_id=1), 杂货店 (area_id=3) |
| 2 | 武器 | 武器防具 (area_id=2) |
| 3 | 防具 | 武器防具 (area_id=2) |
| 4 | 饰品 | 饰品店 (area_id=4) |
| 5 | 特殊 | **不会出现在任何商店** ← 设计意图: 任务物品/剧情道具 |

## 五、可行方案

### 方案 A: 二进制补丁 sub_4233C4 (推荐)

在 switch 中添加新 case，例如 area_id=5 → "特殊商店"，显示 tab_code=5 的物品:

**需要补丁的位置**: `sub_4233C4` (地址 0x4233C4) 中的 switch 跳转表或比较链

补丁思路 (以 area_id=5 为例):
```asm
; 在 switch 的 case 5 位置插入:
case 5:
    mov word ptr [a1+62], 5    ; a1[31] = 5 (主分类 = tab_code 5: 特殊)
    mov word ptr [a1+64], -1   ; a1[32] = -1 (无副分类)
    jmp break
```

**完整补丁步骤**:

1. **二进制补丁 TKS.exe**: 在 `sub_4233C4` 的 switch 中添加 `case 5` (以及更多 case 如 6/7/8)
2. **修改 TKShop.dat**: 添加 area_id=5 的记录，引用 tab_code=5 的物品
3. **修改 TKItem.dat**: 为要放入特殊商店的物品设置 `tab_code=5` (已存在，目前不被商店使用)
4. **修改游戏脚本**: 添加 `Shop(脚本号, 0, 5)` 指令打开新商店
5. **可选**: 修改商店 UI 渲染代码，添加新商店的 NPC 对话入口

### 方案 B: 复用现有商店类型 (无需改 exe)

不修改 exe，利用已有的 5 种商店类型:

- 把"特殊物品"的 `tab_code` 改为 0 或 1，放入杂货店 (area_id=3)
- 或改为 4 放入饰品店 (area_id=4)
- **优点**: 无需二进制补丁，仅修改 .dat 文件即可
- **缺点**: 没有独立的商店 UI 入口，物品混在其他商店中

### 方案 C: 复用 area_id=9 (不推荐)

area_id=9 在编辑器中定义为"无"，但落入 switch default:
- `v6`/`v5` 不被赋值 → `a1[31]`/`a1[32]` 保留旧值或栈垃圾
- 行为不可预测，可能崩溃或显示错误商品
- **不推荐**

## 六、推荐的新增商店规划 (方案 A)

以"特殊物品商店"为例:

### 6.1 数据规划

| 组件 | 操作 |
|------|------|
| TKItem.dat | 将要放入特殊商店的物品 `tab_code` 设为 5 |
| TKShop.dat | 新增记录，`area_id=5`, `item_ref` 指向目标物品 |
| TKS.exe | `sub_4233C4` switch 添加 `case 5: v6=5; v5=-1` |
| 游戏脚本 | 添加 `Shop(脚本号, 0, 5)` 触发新商店 |

### 6.2 可扩展的 area_id 规划

| area_id | 用途 | tab_code | 说明 |
|---------|------|----------|------|
| 0 | 药店 | 0 | 已有 |
| 1 | 道具店 | 1 | 已有 |
| 2 | 武器防具 | 2,3 | 已有 |
| 3 | 杂货店 | 0,1 | 已有 |
| 4 | 饰品店 | 4 | 已有 |
| 5 | 特殊商店 | 5 | **新增** — 显示 tab_code=5 的特殊物品 |
| 6 | 自定义商店A | 6 或复用 | **新增** — 需新建 tab_code 或复用已有 |
| 7 | 自定义商店B | 7 或复用 | **新增** |
| 8 | 自定义商店C | 8 或复用 | **新增** |
| 9 | (空/无) | — | 保持原样，不使用 |

### 6.3 注意事项

1. **tab_code 与背包分类的关系**: `tab_code` 不仅影响商店过滤，还影响背包 UI 的分页显示。新增 tab_code 值 (如 6/7/8) 需要确认背包 UI 是否会为它们创建新页面
2. **TKShop 记录上限**: 240 条是硬限制。新增商店需要从现有记录中腾出空间，或使用空槽 (area_id=0 且 item_ref=0 的空记录)
3. **TKItem 记录上限**: 600 条是硬限制。空槽 #560-#599 (40 条) 可用于新增物品
4. **购买数量限制**: 单页最多 8 件商品是硬编码，无法仅通过 .dat 修改突破
5. **二进制补丁的定位方式**: 需要先确认 switch 是跳转表 (jump table) 还是线性比较链 (if-else chain)，这决定了补丁的插入方式
