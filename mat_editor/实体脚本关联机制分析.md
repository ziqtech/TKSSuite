## 关联机制

### 1. 核心：d44 不在文件中存储，由 sub_4066F0 运行时计算

**证据：`4066F0.c`**

```c
int __cdecl sub_4066F0(int a1, int a2)  // a1=实体指针, a2=子场景(0=A,1=B,2=C)
{
    // 根据子场景选择 head 和 cur 字段
    if (a2 == 0) { v4 = 39; v3 = 33; }   // head_A, cur_A
    if (a2 == 1) { v4 = 40; v3 = 34; }   // head_B, cur_B
    if (a2 == 2) { v4 = 41; v3 = 35; }   // head_C, cur_C

    // 有效性检查
    if (entity[v5] <= 0 || entity[v3] <= 0 || entity[v5] < entity[v3]) {
        entity[44] = -1;   // 无效 → d44=-1
        entity[42] = -1;
        return a1;
    }

    // 从 head 出发, 沿链表走 cur-1 步
    v7 = entity[v4];                    // 取链表头
    for (i = 1; i < entity[v3]; i++)
        v7 = dword_753500[16 * v7 + 12];  // next = offset 12

    entity[44] = v7;  // ★ 运行时写入 d44 ★
}
```

对于实体 #4292：
- 子场景A：head_A=192, cur_A=1 → 不走循环，**d44=192**
- 子场景B：head_B=194, cur_B=1 → 不走循环，**d44=194**

### 2. TKDefUnit.dat 链表结构

**证据：TKDefUnit.dat 原始数据**

```
TKDefUnit[192]: dw0=0x10C40000 f1(entity_id)=4292 f0=0   f6(next)=193
TKDefUnit[193]: dw0=0x10C40001 f1(entity_id)=4292 f0=1   f6(next)=0
TKDefUnit[194]: dw0=0x10C40100 f1(entity_id)=4292 f0=256 f6(next)=0
```

每条记录 offset 0 的 DWORD = `(entity_id << 16) | block_id`：
- 高 16 位 (f1) = MAT 实体 ID
- 低 16 位 (f0) = DEFINE 块编号

| DefUnit索引 | offset 0 (hex) | 实体ID | 块号 | next | 对应DEFINE |
|-------------|---------------|--------|------|------|-----------|
| 192 | 0x10C40000 | 4292 | 0 | 193 | DEFINE 281280512 |
| 193 | 0x10C40001 | 4292 | 1 | 0 | DEFINE 281280513 |
| 194 | 0x10C40100 | 4292 | 256 | 0 | DEFINE 281280768 |

### 3. DEFINE ID 编码公式

```
DEFINE ID = (entity_id << 16) | block_number

281280512 = (4292 << 16) | 0      → 基础DEFINE
281280768 = (4292 << 16) | 256    → 許渚加入
```

### 4. 脚本执行

**证据：`40EBD4.c:18-22`**

```c
word_755AB2 = dword_51AF40[96 * a1 + 44];           // 读 d44
if (word_755AB2 < 0) return -1;                      // -1 → 无脚本, 直接返回
dword_755A94 = *(DWORD*)(dword_753500 + 16 * word_755AB2 + 4);  // 取编译后字节码
```

sub_4066F0 先计算并写入 d44，然后 sub_40EBD4 读取 d44 获取脚本指针执行。

## 运行时完整流程

```
玩家对实体 #4292 按A键
  → 交互系统调用 sub_4066F0(实体4292, sub=A或B)
    → v7 = head_A(192), 不走循环, 写入 d44 = 192
    → 或 v7 = head_B(194), 不走循环, 写入 d44 = 194
  → sub_40EBD4(4292)
    → word_755AB2 = entity[44] = 192 (或194)
    → dword_755A94 = dword_753500[16*192 + 4] ← 编译后字节码
    → 执行 DEFINE 281280768 脚本:
        TalkB(4292, 25638, ...)   → 許褚说话
        MenuTalk(25658, 1)        → 弹出菜单
        TeamMember(5, 1)          → 許褚加入队伍

```

| `head_A` | [39] | 192 | 子场景A的 DefUnit 链表头 |
| `head_B` | [40] | 194 | 子场景B的 DefUnit 链表头（指向許渚脚本） |
| `head_C` | [41] | 0 | 子场景C的 DefUnit 链表头 |

| `cur_A/B/C` | [33]/[34]/[35] | 1/1/0 | 各子场景链的当前位置 |

**查看方法**：取 head_A 或 head_B 的值（192 或 194），去 defunit_editor 中查找 TKDefUnit.dat 对应索引，高16位即为实体ID，低16位编码 DEFINE 块号。DEFINE ID = (实体ID << 16) | 块号。

## 子场景系统

每个 MAT 实体最多支持 3 个子场景（A/B/C），每个子场景有独立的 DEFINE 链：

- **head_A/B/C**：链表起始节点（TKDefUnit 索引）
- **max_A/B/C**：链表中 DEFINE 条目总数
- **cur_A/B/C**：当前在链表中的位置（1-based）

`SetNowDef(entity, sub, index)` 通过修改 cur 值来切换 DEFINE，实现"同一 NPC 在不同剧情阶段说不同话"的效果。sub_4066F0 根据新的 cur 值重新遍历链表，更新 d44。
