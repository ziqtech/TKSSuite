## 3. 阴影的混合模式：硬编码减法混合 sub_45871C

### 3.1 调用链追踪

```
sub_406864:38
  → sub_458020(dword_755AF0, X, Y, d55, buffer, 0, 0, -1)
                                        a6=0  a7=0
    → 判断: a6(=0) != a7(=0)? → false
            a6(=0)?           → false (0 is falsy)
    → 跳过 if(a6 != a7 || a6) 分支
    → 进入底部:
        if ( dword_A2C244 == 16 )
            sub_458130(...)   // 16-bit 色彩模式
        else
            sub_45871C(...)   // ← 实际走这里（8-bit 或 15/16-bit 其他模式）
```

**阴影始终调用 `sub_458020(a6=0, a7=0)`，路径固定，无任何配置参数。**

### 3.2 sub_45871C 的逐通道减法算法

`decompile/45871C.c:118-134` — 对 RGB565 像素逐通道执行：

```c
// 读取源像素（精灵）和目标像素（背景）
v17 = *(WORD *)(sprite_pixels + palette_index);  // src pixel (RGB565)
v15 = *(WORD *)dst_buffer;                        // dst pixel (RGB565)

// ★ 红色通道 (bits 15-11): dst.R = max(dst.R - src.R, 0)
if (src.R >= dst.R)
    v13 = 0;                    // 钳位到0
else
    v13 = dst.R - src.R;        // 减法

// ★ 绿色通道 (bits 10-5): dst.G = max(dst.G - src.G, 0)  
if (src.G >= dst.G)
    v11 = 0;
else
    v11 = dst.G - src.G;

// ★ 蓝色通道 (bits 4-0): dst.B = max(dst.B - src.B, 0)
if (dst.B <= src.B)
    v9 = 0;
else
    v9 = dst.B - src.B;

// 重组并写回
*(WORD *)dst_buffer = v9 | (v11 << 5) | (v13 << 10);
```

**算法公式**（逐通道、独立计算）：

```
dst.R' = max(dst.R − src.R, 0)
dst.G' = max(dst.G − src.G, 0)
dst.B' = max(dst.B − src.B, 0)
```

### 3.3 阴影精灵颜色在减法下的实际效果

| 精灵像素颜色 | 算法效果 | 视觉效果 |
|------------|---------|---------|
| RGB(~8, ~12, ~8) 接近黑 | `dst − 8 ≈ dst` | 几乎不改变背景 → **透明** |
| RGB(~49, ~48, ~49) 深灰 | `dst − 49` | 略微压暗背景 |
| RGB(~82, ~81, ~82) 中灰 | `dst − 82` | 中等压暗 |
| RGB(~115,~117,~115) 浅灰 | `dst − 115` | 明显压暗 |
| RGB(~156,~154,~156) 亮灰 | `dst − 156` | 大幅压暗 → **阴影最深处** |
| RGB(~165,~162,~165) 最亮灰 | `dst − 165` | 最深阴影 |

阴影精灵是一个**灰色渐变椭圆**：中心区域亮灰 → 显著暗化地面，边缘区域深灰/黑 → 渐变至透明。配合精灵自身的 alpha 通道（alpha=0 处不参与混合），形成自然的脚底阴影效果。

### 3.4 对比 act_editor.py 中的混合模式标注

`act_editor.py:23-24` 对 mode=3 的标注与此一致：

```python
# mode=3 (sub_45871C L118-134): per-channel 减法钳 0
#       dst.RGB = max(dst - src, 0)          # 非 RGB/3 阴影!
#       黑色 src 不改变 dst, 亮色 src 压暗 dst → "挖洞变暗".
```

## 5. 主精灵的混合模式：d24/d25 参数控制

### 5.1 switch 语句

`sub_406864:39-69` — 对主精灵渲染，按 **d24**（字节偏移 96）走不同混合函数：

```c
switch ( d24 )
{
    case 0:
        sub_4544EC(sprite, X, Y, frame, buffer, -1);
        break;
    case 1:
        sub_454D24(sprite, X, Y, frame, buffer, d25, -1);
        break;
    case 2:
        sub_4559D0(sprite, X, Y, frame, buffer, d25, 0, -1);
        break;
    case 3:
        sub_458020(sprite, X, Y, frame, buffer, 0, 0, -1);  // → sub_45871C 减法
        break;
    case 4:
        sub_459168(sprite, X, Y, frame, buffer, -1);         // → sub_459854 亮度 alpha
        break;
    case 5:
        sub_458D08(sprite, X, Y, frame, buffer, -1);         // 水平翻转
        break;
}
```

### 5.2 各模式详解

| d24 | 函数 | 混合模式 | 参数 d25 | 效果描述 |
|-----|------|---------|---------|---------|
| 0 | sub_4544EC | 正常贴图 | — | 像素直接覆盖（含 alpha 裁剪） |
| 1 | sub_454D24 | 染色/闪烁 | 颜色索引 | 按 d25 色值偏色精灵；d25=0 或 >31 时不变 |
| 2 | sub_4559D0 | **加法饱和** | 缩放因子 | d25=0 或 >31 → 全加法 `min(dst+src, MAX)`；1~31 → `min(dst+src*d25/32, MAX)` |
| 3 | sub_458020→45871C | **减法压暗** | — | 同阴影算法 `max(dst-src, 0)`，逐通道 |
| 4 | sub_459168→459854 | 亮度 alpha | — | α=NTSC_Y(src) 转 5-bit；`dst*(32-α)/32 + src*α/32` |
| 5 | sub_458D08 | 水平翻转 | — | X 轴镜像绘制 |

### 5.3 带变换分支的模式

`sub_406864:83-114` — 当 d22 > 1 且无 0x40 标志时，进入变换分支：

- d24=0/1/2 → sub_459EF4（带变换的染色/加法）
- d24=3 → sub_45AA08（带变换的减法）
- d24=4/5 → 无对应，fall through

### 5.4 d24/d25 的来源

搜索全部反编译代码，未找到写入 d24（实体偏移 96）的代码。这意味着 **d24 和 d25 可能是 TKMat.dat 中的持久数据字段**，由编辑器设定、游戏引擎读取，而非运行时动态修改。这两个字段目前在 `mat_editor.py` 中**完全未暴露**——不在任何 BASIC/POS/ANIM/SCRIPT/INTERACT/RUNTIME 字段组中。

## 8. JVG 精灵渲染函数 sub_458020 的路由逻辑

`decompile/458020.c` — 完整的混合模式路由：

```c
unsigned __int16 __cdecl sub_458020(
    int a1,            // JVG 句柄
    int a2, int a3,    // 屏幕 X, Y
    __int16 a4,        // 全局帧索引
    int a5,            // 渲染目标 buffer
    unsigned __int16 a6, unsigned __int16 a7,  // 混合参数
    int a8)            // 调色板/变体索引
{
    if ( a4 >= JVG总帧数 ) return;

    if ( a6 != a7 || a6 )     // a6 和 a7 不同，或 a6 非零
    {
        if ( a6 )              // a6 非零
        {
            if ( a7 )          // a6 和 a7 都非零
                return sub_454D24(...);   // → mode 1 (染色)
            if ( a6 <= 31 )
                return;        // 无效组合
        }
        else if ( a7 <= 31 )   // a6=0, a7≤31
            return;            // 无效组合

        return sub_4559D0(...);           // → mode 2 (加法)
    }

    // a6 == a7 == 0 (阴影走的路径)
    if ( 色彩模式 == 16 )
        return sub_458130(...);           // 16-bit 模式渲染
    else
        return sub_45871C(...);           // → mode 3 (减法)
}
```

**路由表**：

| a6 | a7 | 路由函数 | 混合模式 | 谁用 |
|----|----|---------|---------|------|
| 0 | 0 | sub_45871C (或 sub_458130) | **减法** (mode 3) | 阴影、d24=3 的主精灵 |
| >0 | >0 | sub_454D24 | 染色 (mode 1) | d24=1 |
| 0 | >31 | sub_4559D0 | 加法 (mode 2) | d24=2 (a6=d25, a7=0) |

### 9.2 差距分析

| 项目 | 原游戏 | 编辑器 | 差异 |
|------|--------|--------|------|
| 阴影混合 | 逐通道减法 `max(dst−src, 0)` | alpha 贴图（半透明灰覆盖） | 视觉效果不同：减法混合下浅灰像素压暗深色背景更自然；alpha 混合在亮色背景上阴影可能过淡 |
| 主精灵混合 | d24 控制 6 种模式 | 始终直接贴图（相当于 d24=0） | NPC 的发光特效（d24=2 加法混合）无法预览 |
| 大小阴影选择 | 硬编码角色数据表偏移 526 | 精灵宽度 >50px 启发式 | 对小尺寸宽角色可能误选大阴影 |

### 9.3 完全还原的可行方案

如需完全还原游戏效果，需要将地图预览改为 **PIL 预合成** 方案（类似 `act_editor.py` 的 `_composite_subtract` / `_composite_additive`）。流程：

```
1. PIL 加载背景图（SC.GRP 解出 → RGB）
2. 按 Y 排序实体
3. 对每个实体：
   a. 取阴影帧 → PIL 转 RGBA
   b. 用减法混合公式合成到背景 composite 上
   c. 取主精灵帧 → 按 d24 选择混合公式 → 合成到 composite
4. 转 PhotoImage → Canvas 显示
```

但这需要对整个地图渲染流程重构，且每一帧（动画、拖拽）都需重新合成，性能需评估。
