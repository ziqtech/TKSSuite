# NPC离队后回到原位机制 — 完整逆向分析

## 概述

当玩家从队伍中让角色离队（右键菜单→离队→Y确认），游戏会将对应的 NPC 重新显示在地图原位置。本文档基于反编译代码完整追溯此机制的调用链、数据结构和实现细节。

---

## 一、离队的完整调用链

```
玩家右键队伍成员 → 弹出菜单 (装备/武功/状态/离队)
  → 选择"离队" (menu_type=4)
    → sub_420844 case 4 (420844.c:58)
      → sub_41DFDC(a1, memberIndex, 3)  (41DFDC.c:9-17)
        → 设置 a1[922]=6 (离队状态)
        → 设置 a1[6]=3   (确认类型=离队)
        → 设置 a1[2]=memberIndex

  → sub_42131C (42131C.c:16-20)
    → sub_41E034(a1)    ← 渲染确认界面
    → sub_41EFA8(a1)    ← 等待用户输入

  → sub_41EFA8 (41EFA8.c:41-44)
    → 用户按 Y 键 (dword_78E26E==89) → case 3
      → sub_41EEC0(a1, memberIndex)   ← ★ 真正执行离队
```

### sub_41EEC0 — 离队核心函数 (41EEC0.c)

```c
int __cdecl sub_41EEC0(int a1, __int16 a2)
{
    // 1. 从队伍总属性中减去该角色贡献 (攻/防/轻/内)
    sub_422A5C(a1, -1, word_75688E[a2]);

    // 2. 减少队伍人数计数
    --a1[1229726];   // 队伍人数 -1
    --a1[1229744];   // 相关计数 -1

    // 3. ★ 启用地图实体 — 让NPC回到游戏世界
    sub_40C648(word_758116[527 * word_75688E[a2]]);

    // 4. 队伍数组移位 (去除离队角色, 后面队员前移)
    v4 = a2 + 1;
    v3 = (WORD*)(2 * (a2 + 1) + 7694478);
    while (v4 <= a1[1229726]) {
        *(v3 - 1) = *v3;   // 前移
        ++v4; ++v3;
    }
    // 5. 末尾置空
    word_75688E[a1[1229726]] = -1;

    // 6. 更新UI
    sub_421EE0(a1);
    sub_421CC4(a1, 0);

    // 7. 重置状态
    a1[1229782] = -1;
    a1[922] = 1;
    *(_BYTE *)a1 = 0;
}
```

## 二、核心数据结构

### 2.1 角色→实体的映射关系

```
WarPC.dat                               TKMat.dat
┌──────────────────────────────┐       ┌─────────────────────────┐
│ 角色数据 (527 WORD/角色)      │       │ 实体数据 (96 DWORD/实体) │
│                              │       │                         │
│ offset 263 (WORD) ──────────┼──→   │ entity_id               │
│   = 地图实体ID               │       │   [1] scene_id  场景     │
│                              │       │   [10] x        坐标X   │
│ word_757F08[527*角色ID+263]  │       │   [11] y        坐标Y   │
│                              │       │   [2] flags    标志位   │
└──────────────────────────────┘       └─────────────────────────┘
```

**地址计算：**
- `word_757F08` = 角色数据基址 (WarPC.dat 加载目标)
- `word_758116` = `word_757F08` + 2×263 = 偏移 526 字节
- `word_758116[527×角色ID]` = 该角色对应的地图实体ID
- 实际语法: `word_757F08[527×角色ID + 263]`

**验证：原版许褚**
- WarPC 角色 ID = 5
- `word_757F08[527×5 + 263]` = 4292
- 4292 即许褚在 TKMat.dat 中的实体ID

### 2.2 队伍数组

| 地址 | 大小 | 含义 |
|------|------|------|
| `word_75688C[6]` | 6×2字节 | 队伍成员ID (index 0=队长不可离队, 1~5=队员) |
| `word_756884` | 2字节 | 队伍总攻击力 |
| `word_756886` | 2字节 | 队伍总防御力 |
| `word_756888` | 2字节 | 队伍总轻功 |
| `word_75688A` | 2字节 | 队伍总内力 |

### 2.3 sub_422A5C — 队伍属性调整 (422A5C.c)

```c
// a2 == 1: 入队时累加
word_756884 += word_757F3E[527 * a3];  // 攻击
word_756886 += word_757F40[527 * a3];  // 防御
word_756888 += word_757F42[527 * a3];  // 轻功
word_75688A += word_757F44[527 * a3];  // 内力

// a2 == -1: 离队时扣减
word_756884 -= word_757F3E[527 * a3];
word_756886 -= word_757F40[527 * a3];
word_756888 -= word_757F42[527 * a3];
word_75688A -= word_757F44[527 * a3];
```

## 三、实体 Enable/Disable 机制

### sub_40C648 (Enable — 脚本 Event 25, 40C648.c)

```c
v2 = &dword_51AF40[96 * entityID];
v2[2] |= 1u;   // bit0 = 启用 (参与主循环 tick)
v2[2] |= 2u;   // bit1 = 可见 (参与渲染)
```

### sub_40C5A4 (Disable — 脚本 Event 24, 40C5A4.c)

```c
v2 = &dword_51AF40[96 * entityID];
v2[2] &= ~1u;  // 清除 bit0 (不参与主循环)
v2[2] &= ~2u;  // 清除 bit1 (不渲染)
```

### 实体标志位 (entity[2] flags)

| 位 | 值 | 含义 | 反编译证据 |
|----|-----|------|-----------|
| bit0 | 1 | 启用（参与主循环 tick） | 409618.c:23 |
| bit1 | 2 | 可见（参与渲染） | 40C648.c:29 |
| bit2 | 4 | 可交互（鼠标拾取） | 40BEDC.c/40C648.c |
| bit3 | 8 | 提示标记 | 40B650.c |
| bit4 | 0x10 | 忙碌（交互执行中） | 408E5C.c:27,53 |
| bit5 | 0x20 | 恢复标记 | 408E5C.c:55,77 |

**注意：Enable/Disable 只修改标志位，完全不修改实体坐标。** 实体坐标 (d10=X, d11=Y, d01=scene) 始终保持在 TKMat.dat 中定义的原始值。

## 五、游戏启动与存档数据流

### 新游戏启动 (sub_412688, 412688.c)

```
sub_452544("TKMat.dat", dword_51AF40, 2304000)   ← 加载6000实体 (384B/条)
sub_45343C("WarPC.dat", word_757F08, 150722)     ← 加载143角色 (1054B/条)
```

`word_758116[527×ID]` 的值来自 WarPC.dat 每个角色记录的偏移 263 (WORD)。

### 读档 (sub_41103C, 41103C.c)

```c

```

存档文件偏移 9200 → 150722 字节角色数据 → 覆盖 `word_757F08`。离队后读档继续有效，因为角色数据持久化在存档中。

## 六、新增NPC为何离队后不出现

### 问题根因

`word_757F08[527×新角色ID + 263]` 这个字段未正确设置。

离队时 `sub_41EEC0` 调用：
```c
sub_40C648(word_758116[527 × 角色ID])
         ↓
sub_40C648(word_757F08[527×角色ID + 263])
```

如果该字段为 0（默认），则 `sub_40C648(0)` 尝试启用实体 #0。实体 #0 通常是一个空槽（type=0），游戏主循环直接跳过它，导致 NPC 不出现。

### 解决方案

在新角色的 WarPC.dat 记录中，将**偏移 263 (WORD) = 字节偏移 526** 设置为该角色对应的 NPC 实体 ID（即在 TKMat.dat 中创建的实体索引）。

| 字段 | 偏移(WORD) | 偏移(字节) | 值 |
|------|-----------|-----------|-----|
| entity_link | 263 | 526 | NPC实体在 TKMat.dat 中的 ID |

**例如：** 如果新角色 WarPC ID=85，对应 NPC 实体 ID=5000：
- `word_757F08[527×85 + 263] = 5000`
- WarPC.dat 中角色 #85 的字节偏移 526 处写入 `0x1388` (5000 的小端序)

### 验证方法

在 warpc_editor 中查看该字段（已在 v1.1 的"核心属性→基本信息"中显示），确认为正确的实体ID。

或者通过 team_diag.py 查看运行时内存：
```python
# 读取 word_757F08[527*charID + 263]
entity_id = read_memory(word_757F08_addr + 527*charID*2 + 526)
```
