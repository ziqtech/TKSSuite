# TKDefUnit.dat 在游戏中的实际作用

严格依据反编译代码 `sub_402E88`, `sub_40C044`, `sub_40EBD4`, `sub_4066F0`, `sub_41103C` 的完整调用链追踪。

---

## 核心定位：场景单位激活配置表

TKDefUnit.dat 是一个**中间桥接层**，连接"地图上的实体"与"驱动实体的脚本"。它在每次场景切换时重新加载，决定当前场景中哪些 NPC/单位处于激活状态并可以执行脚本。

**不是** NPC 数据库（那是 TKMat.Dat 的职责），**不是**脚本存储（那是 TKD.dat 的职责），**不是**文本表（那是 TKT.dat 的职责）。

---

## 一、调用链证据

### 1.1 场景切换 → 重载 DefUnit

```
sub_40C044 (场景切换, 0x40C044)
  ├── dword_755B58 = a1          // 设置当前玩家实体
  ├── sub_402B88(a1)             // 停止旧实体处理
  ├── sub_405CBC()               // 按实体类型初始化渲染
  ├── sub_402E88()               // ★ 重新加载 TKDefUnit.dat ★
  ├── sub_407070(entity, x, y)   // 设置实体坐标
  └── sub_4077E4(entity, layer)  // 设置绘图层
```

**证据**: `sub_40C044.c` 第 15-55 行。

### 1.2 sub_40C044 的所有调用者

| 调用者 | 地址 | 场景 |
|--------|------|------|
| `sub_412688:48` | 0x412688 | 游戏启动，初始场景 |
| `sub_41103C:52` | 0x41103C | 从文件加载新场景（SCxxx.grp） |
| `sub_40EBD4:208` | 0x40EBD4 | 脚本 case 19 触发场景切换 |
| `sub_4081F8:30` | 0x4081F8 | 实体交互触发场景切换 |
| `sub_40D2D0:112-124` | 0x40D2D0 | 名称输入界面 |

### 1.3 sub_402E88 的处理逻辑

```
sub_402E88 (0x402E88):
  1. 分配 80000 字节缓冲区 (5000条 × 16B)           // dword_753500 = sub_4AE430(80000)
  2. 清零全部缓冲区                                   // sub_4B00FC(buf, 0, 80000)
  3. 从 TKDefUnit.dat 读取原始数据到缓冲区            // sub_452544("TKDefUnit.dat", buf, 80000)
  4. 遍历 5000 条记录:
     ├── 若前4字节(DWORD)为0 → 整条清零 (空槽)       // if (!*(DWORD*)(buf+16*i))
     ├── 提取实体ID v2 = f1 (高16位)                 // v2 = *(int*)(buf+16*i) >> 16
     ├── 检查实体表 dword_51AF40[96×v2 + dword_4E6EF0]:
     │   ├── 若实体有效且非当前玩家 → 清除 offset 4, 跳过
     │   └── 否则:
     │       ├── sub_402BE8() 解析 TKD.dat DEFINE 段
     │       └── sub_41425C() 创建脚本对象 → 存入 offset 4
     └── 完成
```

**证据**: `sub_402E88.c` 第 15-43 行。

### 1.4 脚本执行如何使用 DefUnit

```
sub_40EBD4 (脚本解释器, 0x40EBD4):
  1. 从实体表读取 DefUnit 索引:
     word_755AB2 = dword_51AF40[96×a1 + 44]          // 实体表[44] = DefUnit 记录号
  2. 从 DefUnit 读取脚本指针:
     dword_755A94 = *(DWORD*)(dword_753500 + 16×word_755AB2 + 4)  // offset 4
  3. 以脚本指针为基址读取 uint16 操作码:
     opcode = *(WORD*)(dword_755A94 + 2×word_755AB2)
  4. 分发 82+ 种操作码:
     ├── case 1/2/34: 生成对话实体 (sub_40A220)
     ├── case 19: 切换场景 → sub_40C044 → sub_402E88 重载 DefUnit
     ├── case 40: 给物品 → TKItem.dat
     ├── case 41: 显示文本 → TKT.dat
     ├── case 45: 队员变更 → WarPC.dat
     ├── case 48: 修改属性 → WarPC.dat
     └── case 66: 启动战斗 → WarData/WarWay.dat
```

**证据**: `sub_40EBD4.c` 第 15-600 行。

## 二、三层数据结构的关系

```
                    ┌─────────────────────┐
                    │    TKMat.Dat        │  ← 地图网格, 初始化实体表
                    │  200×240格×48B      │     sub_412688:21 加载
                    └──────────┬──────────┘
                               │ 写入 dword_51AF40
                               ▼
               ┌───────────────────────────────┐
               │   dword_51AF40 (实体表)        │  ← 6000条, 每条384B (96 DWORD)
               │                                │
               │  [0] = 实体类型 (5/10/20/110/200)
               │  [1] = 场景归属 (-1=全部场景)
               │  [10]= X坐标  [11]= Y坐标      │
               │  [42]= 脚本PC                   │
               │  [44]= DefUnit记录索引 ────────┼──→ 指向 TKDefUnit.dat 记录
               │  [39]= 链表头A [40]=链表头B    │
               │  [41]= 链表头C                  │
               └──────────┬────────────────────┘
                          │ [44] 存储 DefUnit 记录号
                          ▼
               ┌───────────────────────────────┐
               │   TKDefUnit.dat (激活配置)      │  ← 5000条 × 16B
               │                                │     sub_402E88 加载
               │  f1 = 实体ID ──────────────────┼──→ 索引回实体表 (双向关联)
               │  f6 = 链表下一节点              │     sub_4066F0 遍历
               │  [+4] = 脚本对象指针 (运行时)   │     sub_41425C 创建
               └──────────┬────────────────────┘
                          │ [+4] 脚本指针
                          ▼
               ┌───────────────────────────────┐
               │   TKD.dat (事件脚本)            │  ← DEFINE { 操作码序列 }
               │                                │     sub_402BE8 解析
               │   sub_40EBD4 解释执行           │     82+ 种指令
               └───────────────────────────────┘
```

双向关联：
- **实体表 → DefUnit**：实体表[44] 存储初始 DefUnit 记录索引
- **DefUnit → 实体表**：DefUnit 的 f1 字段存储实体 ID，索引回实体表

## 三、核心机制总结

### 3.1 激活映射

DefUnit 的 f1 字段决定**哪些实体**在当前场景中是"活跃的"。sub_402E88 遍历所有记录，对每个非空记录检查其对应的实体表条目是否存在且有效。若有效，则为该实体创建脚本对象；若无效，则清除该 DefUnit 记录。

**证据**: `sub_402E88:29-41`

### 3.2 脚本绑定

DefUnit 的 offset 4（f2-f3, uint32）运行时存储脚本对象指针。该指针由 `sub_41425C` 创建，指向从 TKD.dat DEFINE 段解析出的脚本字节码。`sub_40EBD4` 读取此指针作为字节码基址，从中读取 uint16 操作码并分发执行。

**证据**: `sub_402E88:38`（写入）, `sub_40EBD4:22`（读取）, `sub_4119CC:72`（释放时确认）

### 3.3 链式组织

DefUnit 的 f6 字段形成链表，将同一 NPC 在不同状态/位置下的配置串联。实体表存储 3 个独立的链表头（索引 39/40/41），对应 3 个子场景（A/B/C）。`sub_4066F0` 遍历链表找到当前应执行的 DefUnit 条目。

**证据**: `sub_4066F0:53`（链遍历）, `sub_40EBD4` case 0（子场景计数器）

### 3.4 场景隔离

每次场景切换时，`sub_40C044` 调用 `sub_402E88` 重新加载 TKDefUnit.dat。旧缓冲区中的脚本对象指针在 `sub_4119CC` 中被遍历释放。这确保每个场景只激活与该场景相关的单位。

**证据**: `sub_40C044:47`（调用 sub_402E88）, `sub_4119CC:66-80`（释放）

## 四、字段语义最终确认

| 字段 | 偏移 | 语义 | 证据 |
|------|------|------|------|
| f0 | 0 | 未证实 | 反编译仅检查 DWORD(f0\|f1<<16)==0 |
| **f1** | **2** | **实体ID** | sub_402E88:31 `>>16` → 索引实体表 |
| **f2-f3** | **4-7** | **脚本指针 (运行时)** | sub_402E88:38 写入, sub_4119CC:72 释放 |
| f4 | 8 | 未证实 | 无函数访问 offset 8-11 |
| f5 | 10 | 未证实 | 无函数访问 offset 8-11 |
| **f6** | **12** | **链表下一节点** | sub_4066F0:53 DWORD 遍历 |
| f7 | 14 | DWORD 对齐 | 全部为 0 |

## 五、生命周期

```
游戏启动
  │
  ├── sub_412688: 加载 TKMat.Dat → 初始化实体表 dword_51AF40
  ├── sub_40C044(1, 400, 340, 4): 初始场景切换
  │     └── sub_402E88: 加载 TKDefUnit.dat → dword_753500
  │           └── 遍历记录, 为有效实体创建脚本对象
  │
  ├── [玩家移动/交互]
  │     └── sub_4081F8: 实体交互 → sub_40C044 切换场景
  │           └── sub_402E88: 重新加载 TKDefUnit.dat
  │
  ├── [脚本触发场景切换]
  │     └── sub_40EBD4 case 19 → sub_40C044 切换场景
  │           └── sub_402E88: 重新加载 TKDefUnit.dat
  │
  └── 游戏退出
        └── sub_4119CC: 释放所有脚本对象 + DefUnit 缓冲区
```

**每次场景切换都重新加载 TKDefUnit.dat。**
