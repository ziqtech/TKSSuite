## 反编译证据

### `sub_4081F8` — 传送点触发函数

```c
// 4081F8.c:15-34
int __cdecl sub_4081F8(int a1, int a2)  // a1=entity_id, a2=entity_ptr
{
    // 1. AABB 碰撞检测：玩家是否走入传送点区域
    if (!sub_408108(entity, player))
        return 0;

    // 2. 条件检查
    if (entity[200] > 0 && player[88] != entity[200])  // d50: 角色要求
        return 0;
    if (entity[204] &&                                   // d51: 访问掩码
        (entity[204] & (1 << (player[52] - 1))) == 0)
        return 0;

    // 3. 执行子场景B脚本（如果有）
    if (entity[136]) {                                   // cur_B > 0
        sub_4066F0(entity, 1);
        sub_40EBD4(a1);                                  // 执行脚本
    }

    // 4. 切换场景 → 传送！
    //    ↓ 字节偏移 208=52*4=d52, 212=53*4=d53, 216=54*4=d54, 224=56*4=d56
    sub_40C044(
        *(WORD*)(entity + 208),   // ★ d52 低16位 → 目标场景ID
        *(WORD*)(entity + 212),   // ★ d53 低16位 → 目标X坐标
        *(WORD*)(entity + 216),   // ★ d54 低16位 → 目标Y坐标
        *(WORD*)(entity + 224)    // ★ d56 低16位 → 目标朝向
    );

    // 5. 传送后微调位置
    if (entity[240] || entity[244])           // d60, d61
        sub_40701C(player, entity[240], entity[244]);  // 备选传送坐标
    else
        sub_407A74(player, entity[224]);              // 朝向微调
}
```

### `sub_4077E4` — 朝向设置（NPC 方向模式）

```c
// 4077E4.c:18-37
if (*entity == 200) {          // ★ 仅对 type=200 (NPC) 生效
    if (entity[53] == 4)       // d53 = 方向模式 4
        frame = base + fpd * ((dir - 1) >> 1);
    else if (entity[53] == 8)  // d53 = 方向模式 8
        frame = base + fpd * (dir - 1);
    else                       // 静态
        frame = base;
}
```

**关键：`d53` 仅在 entity type=200 时被解释为方向模式。** 对于 type=10（传送点），d53 被 `sub_4081F8` 解释为目标 X 坐标。

## 字段语义更正

### d52, d53, d54, d56 — 类型相关多义字段

| 字段 | 当前编辑器标签 | type=200 (NPC) 语义 | type=10 (传送点) 语义 | 反编译证据 |

| d50 | char_id 所需角色ID | 角色图片/条件角色 | **传送条件：所需角色ID**（一致） | `4081F8.c:15` |

### 4. 方向模式字段的正确位置

实际的方向模式（dir_mode: 0/4/8）对于 type=200 NPC 来说确实是 d53，但它的语义仅在 `sub_4077E4` 中生效——且仅当 entity type=200 时才被使用。编辑器应保留此字段但在 tooltip 中注明类型条件。

## 编辑器改进建议（不在本次范围内）

长远来看，mat_editor 应该根据 entity type 动态显示不同的字段组：

- **type=10（地形块/传送点）**：显示碰撞盒 + 目标场景/坐标/朝向 + 条件
- **type=200（NPC）**：显示动画集 + 方向模式 + DefUnit 链
- **type=20（事件对象）**：显示事件参数
- **type=5（入口）**：仅显示坐标

当前所有类型共用一个字段列表的方式无法正确表达类型相关的字段语义。
