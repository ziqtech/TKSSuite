## 二、完整执行流程（`sub_408B30` 逐行逆向）

### 2.1 前置检查：是否已拾取（第 22 行）

```c
if ((*(_BYTE *)(a2 + 9) & 1) != 0)     // d2 bit8 == 1 ?
    return sub_40B1B4(11, 18, 30, 1, 0, 1);  // SysTalk: "该物品已经拿过了"
```

- `a2 + 9` 读取 d2 的第 2 个字节（小端），等价于检查 `d2 & 0x100`
- **d2 bit8** 是"已拾取"标记位，由 d52=0 模式的代码设置（见 2.3 节）
- 若已设置，直接返回错误提示，不生成物品

### 2.2 物品生成：三组独立掉落（第 24-66 行）

每组独立计算，结构完全对称。以组1 为例：

```c
// 组1: 物品ID随机范围 [d53, d54]
if (*(a2 + 212)) {                              // d53 > 0 ? (有配置)
    if (d53 >= d54)                              // Xmin >= Xmax ?
        v11 = d53;                               // → 固定为 d53
    else
        v11 = d53 + sub_452AC0(d54 - d53 + 1);  // → 随机 [d53, d54]

    // 组1: 数量随机范围 [d55, d56]
    if (d55 >= d56)
        v8 = d55;                                // → 固定为 d55
    else
        v8 = d55 + sub_452AC0(d56 - d55 + 1);   // → 随机 [d55, d56]
}

// 组2: [d57~d60] → v10(物品ID), v7(数量)
// 组3: [d61~d64] → v9(物品ID),  v6(数量)

// ★ 调用 GetItem 添加物品到库存
if (v11 && v8)  sub_40CE30(v11, v8, 1);  // GetItem(物品ID, 数量, show_msg=1)
if (v10 && v7)  sub_40CE30(v10, v7, 1);
if (v9  && v6)  sub_40CE30(v9,  v6, 1);
```

**随机规则总结：**

| 条件 | 行为 |
|------|------|
| Xmin == 0 | 该组未配置，跳过 |
| Xmin == Xmax | 物品 ID 固定 |
| Xmin < Xmax | 物品 ID 在 `[Xmin, Xmax]` 范围内随机 |
| Ymin == Ymax | 数量固定 |
| Ymin < Ymax | 数量在 `[Ymin, Ymax]` 范围内随机 |
| X>0 且 Y>0 | 调用 `GetItem(X, Y, 1)` 加入库存 |

### 2.3 行为模式处理（第 67-87 行）

```c
v3 = *(a2 + 208);   // d52 (行为模式)
v4 = v3 == 0;        // d52 == 0 ?
v5 = v3 - 1;         // d52 - 1

if (v4) {            // ★ d52 = 0: 随机掉落模式
    *(a2 + 8) |= 0x100;              // d2 bit8 = 1 (标记为"已拾取")
    
    if (*(a2 + 200)) {               // d50 > 0 ? (启用拾取后动画)
        // 自增动画帧，钳位到 frame_count-1
        if (d16 <= ++d17)             // frame_count <= ++frame_cur ?
            d17 = d16 - 1;            // → 钳位
        d14 = d17 + d51;              // frame_idx = frame_cur + 动画基偏移
    }
    // 实体保持可见，但 bit8 阻止重复交互

} else if (!v5) {    // ★ d52 = 1: 清除标志模式
    *(a2 + 8) &= ~1;  // 清除 flags bit0 (禁用实体)
    *(a2 + 8) &= ~2;  // 清除 flags bit1 (隐藏实体)
    return;            // 实体消失
}

// d52 >= 2: 无特殊行为，正常返回
```

**行为模式对比：**

| d52 值 | 物品生成 | 实体状态变化 | d2 bit8 | 适用场景 |
|--------|---------|------------|---------|---------|
| **0** | ✓ | 设置 bit8，可选播放动画 | 设为 1 | 可重复出现的拾取点（此游戏未使用） |
| **1** | ✓ | 清除 bit0+bit1（禁用+隐藏） | 不变 | 一次性收集品（晶礦节点等） |
| **≥2** | ✓ | 无变化 | 不变 | 无消耗的可重复交互机关 |

## 四、d52=0 模式的 d50/d51 动画机制（代码已有但未使用）

虽然此游戏中无 d52=0 实体，但代码逻辑完整。当 d52=0 且 d50>0 时：

```
拾取后每帧:
  d17 (frame_cur) += 1
  if d17 >= d16 (frame_count) → d17 = d16 - 1
  d14 (frame_idx) = d17 + d51
```

效果：实体在被拾取后播放一个动画循环（比如宝箱从关闭变为打开状态），然后保持在最后一帧。**d2 bit8 被设置后，玩家无法再次交互**，但实体依然可见。

配置示例（此游戏中不存在，仅为说明）：
```
d50 = 1     ← 启用动画
d51 = 10    ← 动画起始帧为 10
d16 = 5     ← 共 5 帧动画
→ 拾取后: frame_idx 从 10 递增到 14，然后停在 14
```
