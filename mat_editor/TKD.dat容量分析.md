# TKD.dat 容量分析

## 文件格式

TKD.dat 是 **XOR 0xFF 加密的 Big5 纯文本**，包含游戏事件脚本（DEFINE 块）。
文件无 header、无条目计数、无固定字段长度，完全由文本内容决定大小。

## 编辑层面：无限制

编辑器的加载/解析/保存流程完全动态，不硬编码条目数：

| 环节 | 代码位置 | 机制 |
|------|----------|------|
| 加载 | `script_editor.py:31-49` | 全量读取 → XOR 0xFF 解密 → Big5 解码，无条目数限制 |
| 解析 | `script_editor.py:116-178` | 正则匹配 `DEFINE <id>` ... `};` 动态发现所有块 |
| 保存 | `script_editor.py:52-63` | Big5 编码 → XOR 0xFF 加密 → 写入，无大小校验 |

## 游戏引擎层面：硬编码 5000 条上限

**证据：反编译代码 `402E88.c`**

```c
// 402E88.c 第20-23行
dword_753504 = 5000;                                    // 硬编码容量
dword_753500 = sub_4AE430(80000);                       // 分配 5000×16=80,000 字节
sub_4B00FC(dword_753500, 0, 16 * dword_753504);         // 清零
sub_452544(aTkdefunitDat, dword_753500, 16 * dword_753504); // 读取 TKDefUnit.dat

for (i = 0; ; ++i) {
    if (i >= dword_753504) break;  // 硬上限: 5000
    // ... 逐条目解析 DEFINE、编译脚本 ...
}
```

DEFINE 表 `dword_753500` 结构（`03_脚本与事件系统.md:14`）：

```
dword_753500[16 * event_id] — DEFINE表 (TKD.dat, 5000条目)
```

每条 16 字节：

| 偏移 | 大小 | 内容 |
|------|------|------|
| 0 | 4B | 实体索引 (高16位=场景ID, 低16位=实体类型) |
| 4 | 4B | 编译后脚本字节码指针 (0=禁用) |
| 8 | 4B | 保留/填充 |
| 12 | 4B | 链表下一节点指针 (DEFINE 链遍历用) |

## 当前使用量

| 项目 | 数值 | 来源 |
|------|------|------|
| 硬编码上限 | **5000** 条 | `402E88.c:20` |
| 当前 DEFINE 块 | **1539** 个 | `游戏脚本数据.md:8`、`TKS_地图数据驱动机制分析.md:15` |
| 剩余可用 | **~3461** 个 | 计算值 |

## 相关全局变量容量限制

除了 DEFINE 表，脚本 VM 还有以下硬编码容量（来自 `03_脚本与事件系统.md`）：

| 变量 | 地址 | 容量 |
|------|------|------|
| 脚本变量 | 0x755E80 | 256 WORD |
| 开关 | 0x755E10 | 32 WORD |
| 选择结果 | 0x755E50 | 24 WORD |
| 全局标志 | 0x756080 | 1024 WORD |
| 队伍 | 0x75688C | 6 WORD |

## 结论

- **TKD.dat 文件本身**可以自由增加 DEFINE 块，编辑器完全支持
- **游戏引擎 (TKS.exe)** 有硬编码的 **5000 条上限**（`dword_753504`），内存固定分配 80,000 字节
- 当前使用 1539/5000（约 31%），仍有约 **3461 个空位**
- 若未来需超过 5000 条，必须 **patch TKS.exe**：修改 `dword_753504` 的值并扩大 `sub_4AE430()` 的分配参数
