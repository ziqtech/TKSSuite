# 角色脚底阴影 — 逆向分析完整报告

## 概述

原游戏中，使用 Cha.JVG 的角色（type=200 NPC/角色 或 type=20 事件对象）会在脚底渲染一个椭圆形阴影。阴影在主精灵**之前**绘制，因此显示在角色下方。

---

## 1. 阴影数据源：Cha.JVG block[0]

### 1.1 实测数据

| 文件路径 | |
|----------|--|
| Cha.JVG | `逆向工作区/Cha.JVG` |

| 全局帧索引 | Block | 局部帧索引 | 尺寸 | 偏移 (x_off, y_off) | 用途 |
|-----------|-------|-----------|------|---------------------|------|
| 0 | block[0] | frames[0] | 1×480 | (-320, -300) | 工具/占位帧（非阴影） |
| 1 | block[0] | frames[1] | 39×23 | (-20, -11) | **小阴影** |
| 2 | block[0] | frames[2] | 65×33 | (-33, -16) | **大阴影** |

- block[0] 共 3 帧，全局索引 0/1/2
- Cha.JVG 共 178 个 block，block[1] 起为角色精灵动画

### 1.2 帧索引是全局的

`sub_458020`（JVG 精灵渲染函数，地址 `0x458020`）在 `decompile/458020.c:22` 中的检查逻辑：

```c
if ( a4 < *(_DWORD *)(a1 + 24) )  // a4 = 帧索引, a1+24 = JVG 总帧数
```

帧索引 `a4` 直接比对 JVG 文件的总帧数，不区 block——**帧索引是全局的**，跨所有 block 顺序编号。

## 2. 主渲染路径：sub_406864（addr `0x406864`）

### 2.1 代码位置

`decompile/406864.c`，行 37-38（标准渲染分支）：

```c
if ( (dword_754810 == 200 || dword_754810 == 20)
    && *(int *)(dword_75480C + 220) > 0 )
    sub_458020(
        dword_755AF0,       // Cha.JVG 句柄
        dword_7547FC,       // 实体屏幕 X（= d10 - 视口偏移）
        dword_754800,       // 实体屏幕 Y（= d11 - 视口偏移）
        *(_WORD *)(dword_75480C + 220),  // 阴影帧索引 = d55
        a1, 0, 0, -1);
```

行 72-78（带变换的渲染分支）：逻辑相同，调用 `sub_45AA08` 替代 `sub_458020`。

### 2.2 关键变量映射

| 代码变量 | 实体记录字段 | 说明 |
|---------|-------------|------|
| `dword_755AF0` | — | Cha.JVG 全局句柄（`sub_411624` 加载） |
| `dword_75480C` | `&dword_51AF40[96*id]` | 实体记录基址 |
| `dword_75480C + 220` | d55（字节偏移 220） | 阴影帧全局索引 |
| `dword_754810` | d0（实体类型） | 200=NPC, 20=事件对象 |
| `dword_7547FC` | d10（X 坐标）| 减去视口偏移后的屏幕 X |
| `dword_754800` | d11（Y 坐标）| 减去视口偏移后的屏幕 Y |

### 2.3 渲染顺序

```
sub_406864 循环体内:
  1. if d55 > 0 → sub_458020(阴影)     ← 先绘阴影
  2. switch(d24) → 主精灵渲染           ← 后绘角色
```

阴影在主精灵之前入渲染队列，因此永远显示在角色**下方**。

## 3. d55 的设置：SetShadow 事件（opcode 22）

### 3.1 代码位置

`decompile/40C428.c`（函数 `sub_40C428`，addr `0x40C428`）：

```c
int __cdecl sub_40C428(__int16 a1, __int16 a2)
{
    v3 = &dword_51AF40[96 * a1];      // 实体记录指针
    if ( *v3 != 200 && *v3 != 20 )     // 仅 type 200/20
        return error;
    v3[55] = a2;                       // d55 = 阴影帧索引
    return a2;
}
```

### 3.2 事件分发

`decompile/40EBD4.c:231` — 事件脚本执行器的 case 22：

```c
case 22:  // SetShadow
    sub_40C428(
        *(_WORD *)(dword_755A94 + 2 * word_755AB2 + 2),   // 实体ID
        *(_WORD *)(dword_755A94 + 2 * word_755AB2 + 4));  // 阴影帧索引
```

d55 由**游戏事件脚本**在运行时设定，不是实体数据文件的持久字段。

## 4. 战斗场景阴影：sub_43339C（addr `0x43339C`）

### 4.1 代码位置

`decompile/43339C.c:68`（及其他 12+ 个战斗渲染函数中相同模式）：

```c
sub_458020(
    dword_755AF0,                       // Cha.JVG
    v13,                                // 屏幕 X
    v12 - 27,                           // 屏幕 Y - 27（阴影高于脚底）
    word_9D7496[527 * v18] + 2,        // 阴影帧 = base + 2
    v11, 0, 0, -1);
```

### 4.2 阴影帧计算公式

```
阴影全局帧索引 = word_9D7496[527 * character_id] + 2
```

- `word_9D7496[527 * id]` = 该角色的阴影基准值
- `+2` = 偏移到 block[0] 的实际阴影帧
  - 基准值 = -1 → 阴影帧 = 1 → block[0].frames[1]（小阴影 39×23）
  - 基准值 = 0 → 阴影帧 = 2 → block[0].frames[2]（大阴影 65×33）
- Y 坐标固定偏移 **-27 像素**

### 4.3 与主渲染的区别

| | 主渲染 (sub_406864) | 战斗渲染 (sub_43339C) |
|---|---|---|
| 阴影帧来源 | d55（运行时脚本设定） | `word_9D7496[id] + 2`（数据表） |
| 角色精灵来源 | 同一 Cha.JVG block[d51] | 另一 JVG 句柄（`dword_951928`） |
| 适用场景 | 地图探索 | 战斗界面 |

## 5. 角色数据表与阴影基准值

### 5.1 数据表结构

`decompile/43BF20.c:40-41`：

```c
qmemcpy((void *)(1054 * v2 + 7700232), v6, 0x41Cu);  // 复制角色配置 1054 字节
word_758324[527 * v2] = v6[526];                       // 偏移 526 处 = 阴影基准值
```

| 属性 | 值 |
|------|-----|
| 内存地址 | `0x757F08`（十进制 `7700232`） |
| 记录大小 | 1054 字节/角色 |
| 记录数量 | 32 个 |
| 阴影字段偏移 | 526（`__int16`） |
| 存储位置 | PE `.data` 段（区间 `006E6000--007E6000`） |

### 5.2 数据来源

该表**编译在游戏主程序（.exe）的静态数据段中**，不是独立的外部文件。游戏开发时将角色属性（阴影大小选择等）硬编码进了二进制。

## 6. 编辑器中的实现

### 6.1 可行实现

`mat_editor.py` `_vis_draw_entity` / `_vis_draw_entity_highlighted`：

```python
# 触发条件：type=200/20 + 使用 Cha.JVG + block[0] 存在 ≥3 帧
if (tval == 200 or tval == 20) and jvg is self._cha_jvg and jvg.block_count > 0:
    blk0 = jvg.blocks[0]
    if blk0.frames and len(blk0.frames) >= 3:
        # 阴影帧选择：原游戏通过角色数据表驱动，此处以精灵宽度近似
        # block[0].frames[1] = 小阴影 (39×23)
        # block[0].frames[2] = 大阴影 (65×33)
        shadow_fi = 2 if char_sprite_width > 50 else 1
```
