# TKMat.dat 字段逆向验证流程

> 验证目标：确认 mat_editor.py 中 96 个 DWORD 字段的真实语义
> 数据来源：游戏目录/TKMat.dat（6000 实体 × 384 字节）
> 源码来源：运行时转储/decompile\

## 验证三步法

### 第一步：数据分布扫描

```python
# 统计每个字段的值分布，快速判断是否为保留字段或运行时残留
counts = {}
for i in range(6000):
    off = i * 384 + dword_index * 4
    v = struct.unpack_from('<i', raw, off)[0]
    counts[v] = counts.get(v, 0) + 1
```

| 分布特征 | 判定 |
|---------|------|
| 全零（6000=0） | 未使用字段 |
| 绝大多数为零，少量非零 | 设计参数（仅部分实体需要） |
| 主要为 -1 和 0 | 初始化标记（如脚本 PC） |
| 大量不同值 | 有意义的设计数据 |
| hi16/lo16 有规律 | 运行时指针或 packed 值 |

### 第二步：源码关键字搜索

在反编译源码中搜索字段的**字节偏移**和**数组索引**：

```
# 字节偏移法（通用）
grep -r "\+ <byte_offset>" decompile/
# 例：d[15] = byte+60 → grep "\+ 60\b"

# 实体指针法（精确匹配实体结构）
grep -r "a2 \+ <offset>" decompile/40*.c
grep -r "dword_75528C \+ <offset>" decompile/40*.c
grep -r "dword_75480C \+ <offset>" decompile/40*.c

# 数组索引法（dword 数组访问）
grep -r "\[<index>\]" decompile/40*.c
grep -r "51AF40\[96.*\+ <index>\]" decompile/
```

**关键判断：区分实体结构与非实体结构。**
实体结构通过 `dword_51AF40[96 * entity_index]` 访问，非实体结构（如精灵资源、UI 控件）使用其他基址。搜到的 `+60` 引用必须确认调用上下文是否为实体操作。

### 第三步：逆向逻辑推导

找到引用后，分析代码逻辑确认字段语义：

1. **读取点**：字段在哪里被读取？传给了什么函数？→ 确定"用途"
2. **写入点**：字段在哪里被写入？由什么命令设置？→ 确定"来源"
3. **计算关系**：字段与其他字段的数学关系（加减乘除、位运算）→ 确定"语义"

### 典型案例

**案例：d[15]（交互距离）的发现过程**

1. 数据扫描：发现 64 为最常见值（1241 实体），0 次之（4022 实体）
2. 源码搜索：`grep "\+ 60\b"` 命中 sub_40818C.c
3. 逻辑分析：sub_40818C 是碰撞检测函数，`d[15]` 作为距离阈值
4. 调用追踪：被 sub_408E5C（点击交互）和 sub_4099B0（接近走动）调用
5. 结论：交互距离，0=无限制，64=标准 NPC，200+=远距特殊实体

**案例：d[36]/d[37]（运行时引用）的排除过程**

1. 数据扫描：d[36] 有 436 个非零值，hi16 = entity_index
2. 源码搜索：`grep "\+ 144\b"` 命中 41BA5C.c 等
3. 上下文验证：41BA5C.c 不使用 `dword_51AF40` 实体数组，是精灵资源结构
4. 实体函数搜索：在所有 40*.c 实体逻辑函数中无引用
5. 结论：运行时残留，非设计参数
