# Type=20 事件对象 — 字段逆向分析报告

## 1. 逆向追溯链

```
sub_409618 (主循环)
  └─ type=20 → sub_408704 (动画帧推进 + 音效事件)
  └─ 不经过 sub_4081F8(type10) / sub_408408(type15) / sub_4084E0(type16)

sub_406864 (渲染)
  └─ type=20/200 共用阴影帧 d55、混合模式 d24

sub_405CBC (初始化)
  └─ d64 → sub_45410C(Ani.JVG, block) 加载动画精灵
  └─ d65 = sub_45410C 返回值 (动画句柄)
```

## 2. 关键区别：type=20 ≠ type=200

| 特征 | type=20 事件对象 | type=200 NPC |
|------|-----------------|-------------|
| anim_set (d9) | **4 (Ani.JVG)** 全部 | 1 (Cha.JVG) 或 4 |
| d70 (移动模式) | 全部为0，不走路 | 0=静止 / 1=行走 |
| d50-d63 | 全部为0，不使用 | 部分使用 |
| d71-d95 | **音效事件** | NPC 行为事件 |

旧注释 "type=20 与 type=200 语义相同" 是错误的。

## 3. 音效事件系统 — 汇编铁证

sub_408704 中的 11 对音效事件检查。反编译器将其简化为 `sub_451780(1)`，遗漏了关键参数传递。

### 汇编原文 (d80/d81 事件对)

```asm
408703: mov  eax, [ebp+0xC]        ; eax = 实体指针 a2
408706: mov  edx, [eax+0x140]      ; edx = d80 → 音效ID (非零检查)
40870C: test edx, edx              ; d80 == 0 则跳过
40870E: jz   skip
408716: mov  eax, [ecx+0x44]       ; eax = d17 (当前帧计数器)
408719: mov  ecx, [edx+0x144]      ; ecx = d81 → 触发帧号
40871F: cmp  eax, ecx              ; d17 == d81 ?
408721: jne  skip                  ; 帧未到则跳过
40872F: mov  edx, [edx+0x140]      ; edx = d80 → 传给 PlaySound 的第3参数!
408735: call sub_451780            ; PlaySound(sound_mgr, 0, d80, 1)
40874C: call sub_451C38            ; StopSound(sound_mgr, 0, d80, 0)
```

**结论：偶数 dword (d80/d82/...) = 音效ID，奇数 dword (d81/d83/...) = 触发帧号。**

## 4. 事件对布局：为什么 d71-d76 在 d80-d95 前面？

### 代码执行顺序

```
1. 先检查 d80-d95 (8对) → 事件 #1~#8
2. 后检查 d71-d76 (3对) → 事件 #9~#11
```

### 内存布局

```
d71-d76  偏移 0x11C-0x130  ← dword 索引小，但代码后检查
d77-d79  偏移 0x134-0x13C  ← 间隙，完全不检查
d80-d95  偏移 0x140-0x17C  ← dword 索引大，但代码先检查
```

### 推测原因

结构体演进的历史痕迹：最初只预留了 d80-d95 这 8 对主事件槽（紧接 d68/d69 动画参数）。后续需要更多槽位时，发现 d71-d79 区域空闲，将额外 3 对塞入。引擎按「主槽位先、扩展槽位后」的硬编码顺序检查。

**编号规则：按引擎执行顺序，非 dword 索引排序。事件1-8 = d80-d95，事件9-11 = d71-d76。**
