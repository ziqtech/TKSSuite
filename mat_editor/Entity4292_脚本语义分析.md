### Note(200, 2) 详细分析

**反编译证据 — `40DBF4.c`（Note 函数，操作码 46）：**

```c
int __cdecl sub_40DBF4(unsigned __int16 a1, __int16 a2)
{
    if (a1 < 0x3E8u)                    // 索引范围 0-999
    {
        word_7568D8[(__int16)a1] = a2;  // 写入 Note[索引] = 值
        return (__int16)a1;
    }
    return result;  // 注：超出范围时返回未初始化值（疑似 bug）
}
```

**关键发现：`word_7568D8` 全局仅被 `sub_40DBF4` 写入，无任何反编译函数读取它。**

搜索了全部 decompile 目录、disassembly、strings.txt、pointers.txt：
- `pointers.txt` 中唯一引用位于 `0x40DC0F`（即 `sub_40DBF4` 自身内部）
- 没有 "CheckNote" 操作码
- 没有渲染函数引用此地址

可能的解释（**均无证据，仅供参考**）：
1. 读取函数未被反编译 — 游戏的任务日志 UI 可能直接读取此数组，但渲染函数未在 dump 中
2. Note 值仅用于存档，由游戏引擎在特定阶段读取（反编译遗漏）
3. Note 是原开发工具的元数据，游戏引擎不读取

**可确认的：** `Note(200, 2)` 向 `word_7568D8[200]`（地址 0x7568D8 + 200×2 = 0x756A68）写入值 2。数组容量 1000 WORD。

## 二、DEFINE 281280513 — "2 #Define"（許褚状态标记）

```

{;2 #Define
```

### 逐行分析

| 行 | 指令 | 反编译证据 | 语义 |
|----|------|-----------|------|
| 1 | `DEFINE 281280513` | — | DEFINE ID = (4292<<16)\|1，对应 TKDefUnit[193]，f6链从[192]指向此条 |
| 2 | `{;2 #Define` | — | 块开始 |
| 3 | `SetFlag(119,1)` | `40CB08.c:13` `word_756080[119] = 1` | 全局标志 #119 设为 1（許褚事件标记为"活跃中"） |
| 4 | `End(0)` | `40EBD4.c:61-71` case 0: 保存PC→entity[172], 恢复entity[168]→PC, 若无效则 `sub_4066F0` | 执行结束，返回调用者 |

### 综合含义

此 DEFINE 紧接第一个脚本执行，将 flag 119 设为 1，标记許褚事件已激活。flag 119 是許褚剧情的阶段标记：
- **0** = 初始（未触发）
- **1** = 活跃中（进入场景已触发，等待玩家交互）
- **2** = 已完成（对话结束/已招募）

后续脚本 `CheckFlag(119,2,0)` 会检查此标志以决定是否执行許褚交互。
