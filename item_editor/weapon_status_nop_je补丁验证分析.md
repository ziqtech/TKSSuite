# weapon_status_nop_je 补丁验证分析

## 概述

> ⚠️ **状态**: 此补丁已于 2026-07-02 从 `tks_patches.json` 移除。`weapon_cause_mask_hook_v2` 本身已解决武器 cause_mask 在普通攻击时不注入状态队列的 BUG，无需此补丁。

`weapon_status_nop_je` 曾是 TKS Launcher 中"战斗与技能"组的一个 `patch_bytes` 类型补丁。其设计意图是让 `weapon_cause_mask_hook_v2` 补丁（武器 cause_mask 注入）"稳定生效"，但实际效果并非 100% 附加，而是将概率判定从"攻击者速度随机公式"切换为"受击者状态抗性查表"——既不是补丁声称的效果，也不是必要的修改。

**移除理由**：hook 注入的武器 cause_mask 到达 `sub_442D44` 时携带 `a5=0`（BSS 初始值），走原版速度随机公式（2×速度/3+15，15~99%），状态已正常施加。此补丁多余且有副作用。

**补丁操作**: `74 7D`（`je +0x7D`） → `90 90`（NOP）

## 2. 原始汇编分析

**来源**: `反编译产物/memory\00401000--00481000.txt` 第 16876-16877 行

```asm
; 地址 0x442E50 ~ 0x442E67
442E50: 66 C7 45 FE 55 00    mov  word ptr [ebp-2], 0x55   ; 上一分支 v8=85
442E5B: 66 83 7D 18 00       cmp  word ptr [ebp+18h], 0    ; ★ 比较 a5 == 0 ?
442E60: 74 7D                je   0x442EDF                  ; ★ a5==0 → 跳到随机公式分支
442E62: 66 C7 45 FE 64 00    mov  word ptr [ebp-2], 0x64   ; a5≠0 → v8=100
; ... 后续使用 sub_452AC0(100) 随机 roll，≤v8 则应用状态
```

**补丁后**:
```asm
442E5B: 66 83 7D 18 00       cmp  word ptr [ebp+18h], 0    ; 比较 a5 == 0
442E60: 90 90                nop                            ; ← 被 NOP, a5==0 时不再跳转, 落入 if(a5) 分支
442E62: 66 C7 45 FE 64 00    mov  word ptr [ebp-2], 0x64   ; 落入路径A: 先置 v8=100
; 随后仍执行 442D44.c:33-40 的抗性调制: 抗性==75→v8=25, ==50→v8=50
```

## 3. 反编译逻辑分析

**来源**: `反编译产物/decompile\442D44.c`

```c
char __cdecl sub_442D44(__int16 a1, __int16 a2, __int16 a3, __int16 a4, __int16 a5)
{
    // a1 = 状态受击实体, a2 = 状态槽(0..31), a5 = 概率分支选择(来自数据表 v11[4])
    
    // ★ 外层守卫: 受击者该状态槽的抗性字节 == 100 → 直接早退, 不施加状态
    if ( algn_9D70D0[1054 * a1 + 16 + a2] != 100 )   // 受击者抗性 ≠ 100 才继续
    {
        // ... 前置条件检查 ...

        if ( a5 )                          // ★ 补丁影响的分支点
        {
            // ── 路径 A: a5 ≠ 0 (固定查表分支) ──
            v8 = 100;
            if ( algn_9D70D0[1054 * a1 + 16 + a2] == 75 )
                v8 = 25;                  // 受击者抗性 75 → 25%
            else if ( algn_9D70D0[1054 * a1 + 16 + a2] == 50 )
                v8 = 50;                  // 受击者抗性 50 → 50%
        }
        else
        {
            // ── 路径 B: a5 == 0 (速度随机公式分支, 补丁 NOP 后不再执行) ──
            v8 = 2 * speed / 3 + 15;      // 基于攻击者速度
            if ( algn_9D70D0[1054 * a1 + 16 + a2] == 75 )
                v8 /= 2;                  // 受击者抗性 75 → 概率减半
            else if ( algn_9D70D0[1054 * a1 + 16 + a2] == 50 )
                v8 = 2 * speed / 3 + 15 - v8 / 4;  // 受击者抗性 50 → 概率降低 1/4
        }
        
        // ... 后续使用 v8 作为概率阈值 ...
        v6 = sub_452AC0(100);             // 随机数 0~99
        if ( v6 <= v8 )                   // 概率判定
        {
            // 应用状态效果
        }
    }
}
```

### ⚠️ 关键修正：`algn_9D70D0[...]` 是"受击者状态抗性"，不是"武器重量"

文档早期版本曾将该字段命名为 `weapon_weight` 并按"武器重量(75=轻武器/50=中武器)"解释，**此为无证据臆测，现予以纠正**：

| 核查项 | 事实 |
|--------|------|
| 反编译器实际符号 | `algn_9D70D0[1054 * a1 + 16 + a2]`（`442D44.c:24,33,37,45,49,55,59`） |
| `weapon_weight` 在导出目录出现次数 | **0 次**（仅存在于本文档自身，已删除） |
| 寻址解码（反汇编 `memory/00401000--00481000.txt:16865-16877`） | `byte @ 0x9D70E0 + 1054*a1 + a2`，即实体基址偏移 `0x62(98) + a2` |
| `a1` 的含义 | **状态受击实体**（`442D44.c:18` 检查 `word_9D7084[527*a1]>0` 即受击者存活；三处调用方均传 `word_9D6F58` 当前行动者/受击者） |
| 字段性质 | 按受击实体 × 状态槽(0..31) 索引的单字节数组，是**目标对该状态槽的抗性等级**，与武器无关 |
| 静态内存印证 | `0x9D70D0–0x9D70FF`（实体0 的这 32 字节）全为 `0xFF`（`00966000--009E6000.txt:28948-28950`），即未设置抗性时为 0xFF（脆弱） |
| 游戏属性体系 | "攻击/防御/命中/闪避/速度/幸运/移动/悟性"（`warpc_editor_v2.py`），**不存在"武器重量"** |

### 受击者抗性字节对 v8 的影响

| 受击者该状态抗性字节 | 外层守卫 | 路径A (a5≠0, 补丁后走此) | 路径B (a5==0, 原版) |
|:---:|:---:|:---:|:---:|
| 100 | **早退, 不施加** | — | — |
| 75 | 继续 | v8 = 25 | v8 = (2×速度/3+15) / 2 |
| 50 | 继续 | v8 = 50 | v8 = 2×速度/3+15 − v8/4 |
| 其它 / 0xFF | 继续 | **v8 = 100** | v8 = 2×速度/3+15 (15~99%) |

### 原版两条路径的差异

| 路径 | 触发条件 | v8 计算方式 | 说明 |
|------|----------|------------|------|
| **a5 ≠ 0** | 调用方传入 a5=1 | 按受击者抗性查表（100/50/25） | 固定值，与攻击者速度无关 |
| **a5 == 0** | 调用方传入 a5=0 | `v8 = 2×攻击者速度/3 + 15`（再受抗性调制） | 基于攻击者速度的随机概率 |

### 速度与概率的对应关系（a5==0 路径，抗性=0xFF 时）

| 攻击者速度 | 公式计算 v8 | 实际概率 |
|-----------|------------|---------|
| 1 | 2×1/3 + 15 ≈ 15 | ~15% |
| 15 | 2×15/3 + 15 = 25 | 25% |
| 30 | 2×30/3 + 15 = 35 | 35% |
| 60 | 2×60/3 + 15 = 55 | 55% |
| 90 | 2×90/3 + 15 = 75 | 75% |
| 127 | 2×127/3 + 15 ≈ 99 | **99%（永远不到100%）** |

**设计意图**: 速度越高的角色，越容易通过武器附加状态。但即使速度上限 127，概率也只是 99%，保留了 1% 的随机不确定性。

## 7. 补丁效果总结

### 7.1 解决的问题

启用 `weapon_status_nop_je` 后，`weapon_cause_mask_hook_v2` 注入的武器 cause_mask 走 a5≠0 的固定查表分支（而非原版 a5==0 的速度随机公式）。最终施加概率由**受击者该状态槽的抗性字节**决定：抗性=0xFF/其它时为 **100%**，抗性=75 时为 25%，抗性=50 时为 50%，抗性=100 时仍被外层守卫拦截不施加。

### 7.2 与原版的差异

| 方面 | 原版游戏 (a5==0) | 补丁后 (落入 a5≠0 分支) |
|------|---------|--------|
| 武器状态附加概率 | `2×攻击者速度/3+15`，再受抗性调制 (15%~99%) | 按受击者抗性查表：100/50/25/不施加 |
| 攻击者速度的影响 | 高速角色更易附加状态 | **速度不再影响附加概率** |
| 受击者抗性的影响 | 调制速度公式结果 | **直接决定 v8 取值** |
| 抗性=100 的目标 | 不施加（早退） | **仍不施加**（外层守卫未变） |
| 随机性 | 速度公式 + roll 判定，有不确定性 | 抗性≠100/75/50 时为 100%（roll 仍存在但 v8=100 必过） |
| 影响范围 | 仅 a5==0 的调用者 | 所有 sub_442D44 的 a5==0 调用者 |

> ⚠️ 修正：补丁**并非无条件 100% 附加**。受击者抗性字节为 75/50/100 时，补丁后概率分别为 25%/50%/不施加。仅当抗性为其它值（含未设置的 0xFF）时才为 100%。

### 7.3 副作用

由于 `sub_4432EC` 不仅处理武器 cause_mask，还处理来自 **防具、饰品、技能** 等所有来源设置的 cause_mask 位，`weapon_status_nop_je` 会影响所有这些来源的状态附加概率——使它们从"速度随机公式"统一改为"按受击者抗性查表"。

## 8. 可能的改进方案

### 方案 A：修改 `word_9E0290` 数据表

在 `word_9E0290` cause_mask 映射表中，将武器相关条目的第 5 字段（`v11[4]`，即 sub_442D44 的 a5 参数）改为非零值，使武器状态走 a5≠0 的查表分支，而其他来源的 a5 保持 0（保留原版速度随机性）。

> 注：a5≠0 分支同样受受击者抗性调制（100/50/25/不施加），并非无条件 100%。

**优点**: 不需要 `weapon_status_nop_je` 补丁，精确控制每个 cause 来源
**缺点**: 需要解析 `word_9E0290` 表结构，确定每个 entry 对应的具体 cause

### 方案 B：增强 cave hook 逻辑

在 `weapon_cause_mask_hook` 的 cave 代码中，除了设置 `word_9D6C3C/9D6C3E`，额外写入一个自定义标志变量，然后在 `sub_442D44` 中额外 hook 检查该标志，识别"这是武器 cause"并采用自定义概率公式（注意 v8 上限为 100，需钳位）。

**优点**: 可以自定义概率公式（如保留速度加成并提升基础概率）
**缺点**: 需要额外 hook 和 cave 空间

### 方案 C：保留方案（当前做法）

保持 `weapon_status_nop_je` 不变，接受武器状态走 a5≠0 查表分支（抗性≠100/75/50 时为 100%）。

**优点**: 实现简单
**缺点**: 失去速度随机性；对高抗性(75/50)目标概率反而可能比原版速度公式更低
