# weapon_status_nop_je 补丁验证分析

## 概述

`weapon_status_nop_je` 是 TKS Launcher 中"战斗与技能"组的一个 `patch_bytes` 类型补丁。其目的是让 `weapon_cause_mask_hook_v2` 补丁（武器 cause_mask 注入）能稳定生效，但代价是牺牲了原版游戏的随机性——所有武器攻击 **100%** 附加状态效果。

本文档从逆向工程角度完整验证该补丁的作用、逻辑链、以及与原版游戏的差异。

---

```json
  "desc": "武器附加状态修复：NOP掉 sub_442D44 中 a5==0 的条件跳转，使状态概率始终走100%分支",
  "pattern": "74 7D 66 C7 45 FE 64 00",
  "expect_count": 1,
  "replace": { "0": "90", "1": "90" }

```

**补丁位置**: `sub_442D44` @ `0x442E60`

**补丁操作**: `74 7D`（`je +0x7D`） → `90 90`（NOP）

## 3. 反编译逻辑分析

**来源**: `反编译产物/decompile\442D44.c`

```c
char __cdecl sub_442D44(__int16 a1, __int16 a2, __int16 a3, __int16 a4, __int16 a5)
{
    // ... 前置条件检查 ...
    
    if ( a5 )                          // ★ 补丁影响的分支点
    {
        // ── 路径 A: a5 ≠ 0 (100% 分支) ──
        v8 = 100;
        if ( weapon_weight == 75 )
            v8 = 25;                  // 轻武器: 25%
        else if ( weapon_weight == 50 )
            v8 = 50;                  // 中武器: 50%
    }
    else
    {
        // ── 路径 B: a5 == 0 (随机概率分支, 补丁 NOP 后不再执行) ──
        v8 = 2 * speed / 3 + 15;      // ★ 基于攻击者速度的公式
        if ( weapon_weight == 75 )
            v8 /= 2;                  // 轻武器: 概率减半
        else if ( weapon_weight == 50 )
            v8 = 2 * speed / 3 + 15 - v8 / 4;  // 中武器: 概率降低 1/4
    }
    
    // ... 后续使用 v8 作为概率阈值 ...
    v6 = sub_452AC0(100);             // 随机数 0~99
    if ( v6 <= v8 )                   // 概率判定
    {
        // 应用状态效果
    }
}
```

### 原版两条路径的概率对比

| 路径 | 触发条件 | v8 计算公式 | 说明 |
|------|----------|------------|------|
| **a5 ≠ 0** | 调用方传入 a5=1 | `v8 = 100`（或 25/50） | 固定概率，通常 100% |
| **a5 == 0** | 调用方传入 a5=0 | `v8 = 2×速度/3 + 15` | 基于攻击者速度的随机概率 |

### 速度与概率的对应关系（a5==0 路径）

| 攻击者速度 | 公式计算 v8 | 实际概率 |
|-----------|------------|---------|
| 1 | 2×1/3 + 15 ≈ 15 | ~15% |
| 15 | 2×15/3 + 15 = 25 | 25% |
| 30 | 2×30/3 + 15 = 35 | 35% |
| 60 | 2×60/3 + 15 = 55 | 55% |
| 90 | 2×90/3 + 15 = 75 | 75% |
| 127 | 2×127/3 + 15 ≈ 99 | **99%（永远不到100%）** |

**设计意图**: 速度越高的角色，越容易通过武器附加状态。但即使速度上限 127，概率也只是 99%，保留了 1% 的随机不确定性。

## 7. 补丁效果总结

### 7.1 解决的问题

启用 `weapon_status_nop_je` 后，`weapon_cause_mask_hook_v2` 注入的武器 cause_mask **必定**导致状态附加（因为 sub_442D44 的 v8 始终为 100），即每次普通攻击都 100% 触发武器上配置的全部状态效果。

### 7.2 与原版的差异

| 方面 | 原版游戏 | 补丁后 |
|------|---------|--------|
| 武器状态附加概率 | 基于攻击者速度的随机值（15%~99%） | **100%** |
| 速度属性的角色差异 | 高速角色更容易附加状态 | **速度不再影响状态附加概率** |
| 随机性 | 有一定不确定性（最高99%） | **完全确定性** |
| 影响范围 | 仅 a5==0 的调用者 | **所有 sub_442D44 的 a5==0 调用者** |

### 7.3 副作用

由于 `sub_4432EC` 不仅处理武器 cause_mask，还处理来自 **防具、饰品、技能** 等所有来源设置的 cause_mask 位，`weapon_status_nop_je` 会影响所有这些来源的状态附加概率——使它们全部变为 100%。

## 8. 可能的改进方案

### 方案 A：修改 `word_9E0290` 数据表

在 `word_9E0290` cause_mask 映射表中，将武器相关条目的第 5 字段（`v11[4]`，即 sub_442D44 的 a5 参数）改为非零值，使武器状态走 a5≠0 的 100% 分支，而其他来源的 a5 保持 0（保留原版随机性）。

**优点**: 不需要 `weapon_status_nop_je` 补丁，精确控制每个 cause 来源
**缺点**: 需要解析 `word_9E0290` 表结构，确定每个 entry 对应的具体 cause

### 方案 B：增强 cave hook 逻辑

在 `weapon_cause_mask_hook_v2` 的 cave 代码中，除了设置 `word_9D6C3C/9D6C3E`，额外写入一个自定义标志变量，然后在 `sub_442D44` 中额外 hook 检查该标志，识别"这是武器 cause"并采用不同的概率公式（如 `v8 = max(100, 2×速度/3 + 15)`）。

**优点**: 可以自定义概率公式（如加速 100% 但保留速度加成）
**缺点**: 需要额外 hook 和 cave 空间

### 方案 C：保留方案（当前做法）

保持 `weapon_status_nop_je` 不变，接受所有武器状态 100% 触发。

**优点**: 实现简单
**缺点**: 失去随机性和角色差异化
